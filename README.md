# wt-media-workspace

Governance repository for the WT Media cross-repo project.

## Responsibility

This repository is the current governance source for:

- product facts;
- engineering facts;
- human-readable cross-repo contract governance;
- durable decision records;
- active delivery records;
- skill source files;
- release matrix and workspace preparation scripts.

Runtime code is owned by `wt-media-cloud`, `wt-media-agent`, and `wt-media-desktop`. Their checkout paths come from `config/repository-map.yaml`.

## Directories

- `AGENT-INDEX.md`: the governance source for repository boundaries, context loading, delivery, and change rules.
- `AGENTS.md` and `CLAUDE.md`: parallel Codex and Claude Code entries with a short project overview and task starting point.
- `.ai/CURRENT_CONTEXT.md`: the only AI execution snapshot, generated by `scripts/prepare_ai_workspace.py`. Do not edit it by hand and do not keep a second copy at the execution root.
- `config/repository-map.yaml`: related repository path map.
- `config/skills-distribution.yaml`: the only declaration of where skill copies are distributed. `scripts/sync_skills.py` reads it and holds no target list of its own.
- `scripts/lib/workspace_config.py`: standard-library reader for the two configuration files.
- `scripts/prepare_ai_workspace.py`: regenerate the execution snapshot.
- `scripts/wt.py`: the sole CHG and scenario CLI; it dispatches `status`, `chg`, `dev`, and `test`.
- `scripts/chg/`: the three CHG verbs and their shared preconditions, called by `scripts/wt.py`.
- `scripts/docs/check.py`: documentation governance checker.
- `scripts/dev/local_env.py`: local environment implementation behind `bin/control.sh`.
- `scripts/verify/`: repository verification entries and gates.
- `scripts/README.md`: per-file script index, placement rules, and old-to-new path map.
- `scripts/verify/verify_ai_workspace.py`: verify entry references, snapshot uniqueness, and repository configuration agreement.

- `docs/README.md`: documentation tree index, classification, lifecycle, and validation rules.
- `docs/product`: current effective product baseline.
- `docs/engineering`: current effective engineering baseline.
- `docs/contracts`: human-readable Cloud, Agent, and Desktop contract governance.
- `docs/decisions`: durable decision records and reasons.
- `delivery/active`: current implementation process records.
- `delivery/LEDGER.md`: active delivery index, not a historical archive.
- `skills`: single source for Codex and Claude skills.
- `config`: skill distribution, contract map, and release matrix.
- `scripts`: workspace preparation and validation scripts.
- `templates/delivery`: CHG, checkpoint, and evidence record templates.

## Rules

- Do not store Cloud, Agent, or Desktop runtime code here.
- Do not store production secrets here.
- Do not make runtime repositories depend on this repository at build or runtime.
- Do not edit generated `.codex/skills` or `.claude/skills` copies by hand.
- Do not use a `docs/` tree outside this repository as the source of truth for new implementation decisions; the execution root `wt-media/` carries none.
- Do not store OpenAPI, schema, DTO, or event definitions here when a provider repository owns them.
- Do not create `changes/active`; use `delivery/active/<change-id>/change.md`.
- After final outcomes are reflected in stable baselines and Git, move the completed record out of `delivery/active/` and `delivery/LEDGER.md` into `delivery/completed/`. The record itself is kept as-is — never deleted, rewritten, or merged. See `delivery/completed/README.md` for the archive boundary.

## Verification

From `wt-media-workspace`:

```text
python3 scripts/verify/verify_m0_config.py
python3 scripts/verify/verify_delivery_governance.py
python3 scripts/verify/verify_ai_workspace.py
python3 scripts/verify/verify_skills.py
python3 scripts/verify/verify_product_master_alignment.py
python3 scripts/verify/verify_m2_acceptance.py
python3 scripts/docs/check.py
uv run --with pyyaml==6.0.3 --no-project python -m unittest discover -s tests -q
```

Run the checks relevant to the current change. The unit tests import PyYAML; the default
`python3` may not have it, hence the `uv run --with` form. `verify_m2_acceptance.py` additionally
needs the three sibling runtime repositories checked out, and `scripts/verify/verify_m0_local.sh`
runs the above plus the Cloud, Agent, and Desktop build and test suites.

From the same directory, with sibling runtime repositories present:

```text
sh scripts/verify/verify_m0_local.sh
```

Regenerate the execution snapshot after changing the active CHG:

```text
python3 scripts/prepare_ai_workspace.py --change <CHG>
```

## CHG and scenario CLI

Run from this repository with Python 3; the Python entry is the sole formal CLI so Windows and macOS do not need separate Make aliases.

```text
python3 scripts/wt.py status
python3 scripts/wt.py chg start CHG-YYYYMMDD-NNN [--plan]
python3 scripts/wt.py chg resume CHG-YYYYMMDD-NNN
python3 scripts/wt.py chg verify CHG-YYYYMMDD-NNN [--plan]
python3 scripts/wt.py dev fast|repo|integration|e2e|real [--repo wt-media-cloud] [--plan]
python3 scripts/wt.py test fast|repo|integration|e2e|real [--repo wt-media-cloud] [--plan]
```

`start` checks archived dependencies against recorded commits in each repository's local `main`, checks Git state and local `origin/main`, and selects `chg/<CHG-ID>` without creating a worktree. An old archive without reviewable commit evidence blocks start; put the reviewed per-repository SHAs in the new CHG's optional `dependency_merge_commits`. `resume` regenerates the local context and prints the checkpoint, references, branch, status and diff summary. `verify` uses risk, affected repositories and optional `verify_scenarios` from the CHG; it also reminds the executor to verify the CHG's own acceptance criteria.

| Scenario | `dev` | `test` |
| --- | --- | --- |
| `fast` | No environment start | Each repository's existing fast tests; the four repositories do not currently define an identical fast set |
| `repo` | Selected repository `bin/control.sh start` | Selected repository test entry; Workspace also runs governance gates, `scripts/docs/check.py`, and `verify-control.sh` |
| `integration` | Start Cloud and Agent using their controls | Existing M1 cross-end entry; its behavior is a known blocker (port override, contract revision, Desktop test entry) and is not claimed to pass |
| `e2e` | Workspace `bin/control.sh start` | Workspace `bin/control.sh verify` |
| `real` | Print real-environment preparation | Print the external-effect and manual-evidence checklist |

`--plan` prints the commands without starting services or running tests. `integration`, `e2e` and `real` are cross-repository scenarios; omit `--repo` for them. Real acceptance remains recorded in the CHG evidence. The optional `.ai/WORK_STATE.md` is local and ignored; `checkpoint.md` is optional and is the handoff record when a CHG needs one.
