# Manual acceptance checklist

## 时间

2026-07-24

## 验收目标

验证 CHG-20260724-028 是否达到：

```text
普通运营在真实 Desktop 中完成本机可信绑定
→ 对已绑定浏览器窗口的单个媒体账号发起真实账号检查
→ 账号身份、登录状态和最近检查时间回写 Cloud
```

本清单只覆盖本 CHG：单个媒体账号检查与身份回填闭环。

不验收批量检查、Cookie写入/读取、CK上号、代理写入、通用任务中心。

## 一、环境启动验收

- [ ] Cloud API 可用：`http://127.0.0.1:18080/api/v1/health` 返回 `status=ok`。
- [ ] Cloud 使用本地验收 Cookie 配置：`WT_MEDIA_SESSION_COOKIE_SECURE=false`。
- [ ] Desktop Web 可用：`http://127.0.0.1:5174/login` 能打开。
- [ ] Desktop `/api` 代理指向 Cloud `18080`，登录接口返回统一 JSON，不出现“服务器返回格式错误”。
- [ ] Local Agent 可用：`http://127.0.0.1:8765/api/v1/status` 可返回状态。
- [ ] Local Agent 状态中 `bitbrowser_status=normal`。
- [ ] Local Agent 能读取真实 `main_user_id`。
- [ ] 真实 Tauri Desktop 壳已启动，不是在普通浏览器中验收本机敏感操作。

## 二、登录与会话验收

- [ ] 使用普通运营账号登录 Desktop：`operator01 / operator123`。
- [ ] 登录成功后进入 Desktop 页面。
- [ ] 如提示“当前账号已在其他位置登录”，点击“替换旧会话并登录”后能成功进入系统。
- [ ] 登录后不会再出现“服务器返回格式错误”。
- [ ] 管理员或高级运营登录 Desktop 时应被阻止进入本机执行业务页面，并提示使用 Cloud Web。
- [ ] 退出登录后回到登录页。
- [ ] 退出登录后，旧页面不能继续发起本机敏感操作。

## 三、本机可信绑定验收

- [ ] 进入 Desktop「环境状态」页面。
- [ ] 页面展示 Cloud 登录用户为当前普通运营。
- [ ] 页面展示 BitBrowser 为可用。
- [ ] 页面展示已读取当前 BitBrowser 主账号。
- [ ] 点击「绑定当前比特浏览器账号」或「刷新本机可信状态」。
- [ ] 如果当前 BitBrowser 主账号与用户已绑定主账号一致，绑定成功。
- [ ] 成功后页面展示类似：“当前电脑已完成可信绑定，可以执行本地浏览器相关操作”。
- [ ] 本机存在 Cloud 未同步的 BitBrowser 窗口时，不应阻断本机可信绑定。
- [ ] 如果切换到错误 BitBrowser 主账号，绑定/刷新必须失败，并提示账号不一致。
- [ ] 绑定失败时，不应清空用户、账号、窗口或 Cloud 镜像数据。

## 四、Cloud Web 与 Desktop 边界验收

- [ ] Cloud Web 只展示 Cloud 已保存业务数据。
- [ ] Cloud Web 不展示扫描 BitBrowser、打开窗口、读回窗口、检查账号等本机操作入口。
- [ ] Desktop 才展示依赖 Local Agent / BitBrowser 的操作入口。
- [ ] Desktop Vue 不直接访问 Local Agent 动态凭据，本机敏感操作通过 Tauri/Rust 执行。

## 五、浏览器窗口 / Diff 相关边界验收

本 CHG 不完整验收 Profile Diff，只验收与本机可信绑定相关的边界。

- [ ] 本机可信绑定不会因为 BitBrowser 中存在 Cloud 未同步窗口而失败。
- [ ] 未同步窗口应留给后续 Profile 扫描 Diff 处理。
- [ ] “取消变更”只放弃本次扫描 Diff，不修改 Cloud，也不写 BitBrowser。
- [ ] “关闭”只关闭弹窗/抽屉，不代表接受、取消或恢复。
- [ ] “恢复 Cloud 配置”必须写回 BitBrowser 并读回验证，不能只提示成功。

## 六、单个媒体账号检查验收

前置：选择一个满足条件的媒体账号：

```text
普通运营本人账号
业务状态 enabled
已绑定授权浏览器窗口
绑定窗口未归档
当前 Desktop 已完成本机可信绑定
```

- [ ] 进入 Desktop「媒体账号」页面。
- [ ] 打开账号详情。
- [ ] 对符合条件的账号，可以看到「检查账号」入口。
- [ ] Cloud Web 中同一账号不展示「检查账号」本机操作入口。
- [ ] 点击「检查账号」后，页面进入执行中或可感知的处理中状态。
- [ ] 检查由 Desktop → Tauri/Rust → Local Agent → BitBrowser 同步执行。
- [ ] 检查成功后，Cloud 回填平台 UID。
- [ ] 检查成功后，Cloud 回填账号名称/昵称。
- [ ] 如平台能读取头像，Cloud 回填头像。
- [ ] 检查成功后，登录状态更新为正常或等价成功状态。
- [ ] 检查成功后，最近检查时间更新。
- [ ] 页面刷新后能看到最新账号身份和登录状态。

## 七、失败场景验收

- [ ] 未绑定浏览器窗口的账号不能发起检查，并提示需要先绑定窗口。
- [ ] 禁用账号不能发起检查。
- [ ] 非当前运营授权范围内账号不能发起检查。
- [ ] 当前电脑未完成可信绑定时，不能发起检查。
- [ ] BitBrowser 不可用时，检查失败并显示运营能理解的原因。
- [ ] 窗口未登录账号时，检查结果不能假成功。
- [ ] 窗口登录了其他同平台账号时，提示账号不一致，不能静默覆盖原账号身份。
- [ ] 检查失败不清空账号台账、标签、备注、绑定关系、Cookie 字段或已有身份字段。

- [ ] 本机可信绑定正常；
- [ ] Cloud Web / Desktop 边界符合 Milestone；
- [ ] 单个媒体账号检查可在 Desktop 发起；
- [ ] 成功结果能回写 Cloud 并在页面展示；
- [ ] 失败场景不会产生假成功或破坏已有数据；
- [ ] 验收过程没有出现需要新增产品决策的阻塞问题。
