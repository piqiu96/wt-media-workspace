## 业务与页面设计

继续使用现有任务/批次/计划框架，以platform区分真实规则。同批次只选同平台本人账号；计划仍可组合已开放平台的多个批次，保留10%衔接、启动冻结和原批快捷处理。

| 内容 | 设计要求 |
| --- | --- |
| 标题/简介 | 标题与可选简介分开，原百度description仍按既有发布标题解释；不把简介硬塞同一字段，不静默截断。字数/换行/空格/表情边界实测 |
| 标签/分区/参与话题 | 标签独立于简介和话题；分区保存平台真实标识和名称；话题选填，未实现账号关联能力不显示假成功 |
| 创作声明/来源 | 按当前页可用选项及内容事实确认，转载来源等条件字段完整；创作者内容标识和权利授权不混为旧“原创/转载”二选一，不自动声称原创 |
| 广告与可见范围 | 129广告成片核对营销声明/商业推广的实际要求；公开才可计入公开成功，仅自己不冒充公开。付费投放/交易功能不在本次范围 |
| 封面 | 核实当前实际比例/尺寸/大小和推荐封面/空间封面的关系；已有调查为4:3及16:9，需当前复验，不沿用百度3:4必填。复用图片与模板，生成结果必须与当前输入一致 |
| 默认值/AI | Cloud统一配置提供分区、标签、可见性等新建默认；单条明确值优先；草稿/已保存内容不被新默认覆盖。沿原型配置区补齐，AI按选中字段生成→审阅→采用，声明由内容事实确认 |
| 执行/人工现场 | 浏览器自动完成上传、填表、核对及提交；验证码/短信/扫码等真实卡点保留原现场与任务状态，继续沿原attempt，不重复投稿 |
| 结果 | 准备完成、已提交受理、审核中、明确退回、公开、未知分别保留；精确稿件对应账号和本次任务后才关联作品/统计 |

默认不增加分P、合集维护、合作投稿、充电、章节/字幕编辑、投放后台或互动采集。当前投稿页若新增阻塞性必填，纳入必要发布能力；普通可选运营功能不因控件存在就全部扩张。

## 架构、模块、接口与事务

1. **Cloud固定平台规则。** 在既有publish模块增加百度/B站能力与规则映射；建议新增只读GET /api/v1/publication/platform-rules（名称为提案，非已存在），输出已开放平台、规则修订、必要字段/限制、封面规格及新建默认。固定注册，不建设通用动态表单/工作流平台。未验收的B站可在指定验收配置中测试，面向普通生产开放须本轮真实闭环通过。
2. **Cloud提供方先行。** 更新contracts/cloud-api/v1/publication*.openapi.yaml与publication-plan/batch、cloud-agent-api/v1/publications.openapi.yaml、相关content/错误定义，再生成Agent/Desktop消费。内容按平台区分，复用公共资源与确认；扩展B站标题/简介/分区/标签/声明/条件来源与必要封面引用，保持旧百度解释及旧快照。ID/URL按平台分别验证，百度数字ID限制不全局取消；B站稿件标识以实际回执验证后选择稳定canonical标识，保存必要原始回执，不从标题或最新作品猜测。
3. **Cloud业务实现。** 内容生成/批量配置/封面、保存/编辑、资格/资源盘点、start事务、领取资格、提交前校验、原稿核验/人工resolve、可信作品关联和统计全部消费同一规则。保存零任务/零占用，start一次性任务/占用/授权；平台占用唯一键复用，Profile互斥跨平台，外部IO不进入数据库事务。必要JSON/引用扩展用正式migration和兼容测试，不建第二套任务/计划表。
4. **Agent平台能力。** 新增platforms/bilibili/publisher及publication_check，复用Publisher/PublishControl与PublicationReference/Observation接口；平台客户端在clients/bilibili，CDP/Cookie在services/browser。runner/bootstrap移除硬编码百度分支但不下放Cloud业务规则。上传/封面/声明和最后表单读回必须成功；上传身份同时支持匹配网络响应或当前成功视频与本次所选File对象的精确绑定，不能因缺少特定网络事件拒绝已正常上传的视频；最终提交前走原before_submit许可及本地停止复查。
5. **一次副作用与核验。** 最后点击后响应不明确保留unknown/reviewing与占用，outbox补报同一attempt，不重放提交；依据原稿件标识核验审核/退回/公开及UID/时间，审核中不算公开。跨批/跨平台共享Profile只允许一处工作，关闭现场需真实依据。
6. **共用Vue与Desktop。** 任务、批次内容准备/批量配置/详情、计划按规则补字段与按钮；保留原型布局及所有已确认导航。Desktop只消费契约和打包Playwright平台适配，不复制业务前端，不另建本机FFmpeg流程。

## 按顺序的9步实施

1. 实际打开本人B站Profile，核实UID、上传与投稿页、封面/标签/分区/声明/营销/来源条件；记录当前字段和最小可发布案例，固定原型输入。此步不能据“发布按钮可点”认定投稿成功。
2. 定版提供方契约、平台规则/默认及数据兼容方案，更新工程设计与消费者生成；Contract差异在代码前解决。
3. 完成Cloud规则、资源资格、内容/文件引用、原子start、领取/resolve与结果投影的失败用例和实现，确保百度回归通过。
4. 完整实现B站Publisher/原稿Checker及runner/bootstrap装配、阶段报告/outbox、停止与现场恢复，先过受控浏览器及异常用例。
5. 完整实现共享Vue所有入口，B站字段、AI/封面、批量准备、状态/动作、计划返回同一体验，更新Desktop消费与包内驱动。
6. 逐项完成后端/Agent/前端自测清单与双端构建：权限、必填边界、Profile不足/共用互斥、接口修订、重复点击、断网、超时、停止/暂停/恢复、审核/退回/未知/迟到结果。修复到通过后才能进入最终E2E。
7. 强制准备新环境和DMG，以129新模式视频跑下述真实端到端路径；每条固定任务/attempt/账号/成片/稿件映射，受控故障与真实公开证据分开。
8. 工程师主动打开浏览器及平台后台/公开作品完成最终走查，再在新安装包逐页复核计划和批次；问题自行修复→相关自测→E2E重跑→走查，直到可用。
9. 提PR、修复审查问题、完整CI/自测核对、合入各仓main，重新核对新包组合与最终走查；归档证据，交用户整体签收。若后续合入改变运行代码，重新构建并复核，不交付旧包。

建议B站正常路径约5条独立真实稿件（单条1＋独立批次2＋两批计划2），必须使用不同可用成片并检查平台内容适用性；不复用已占用成片来伪造新路径，也不以重复同视频投递制造覆盖数。实际测试数据准备复用129产出，记录使用范围，不自动删除已公开作品或历史证据。

**最终必须自行打开浏览器**：读取B站创作中心中本次精确稿件的账号/状态，打开对应公开作品检查可播放、内容/封面/标题正确，回到系统核对任务、批次、计划数量及作品关联，再检查截图与页面返回。只跑headless脚本、curl或SQL不能替代最终人工式运营走查。Cloud Web与安装版均验收，operator01沿用会话已确认凭据、不重置，密码不写入代码或交付文档；真实短信/验证码需要账号持有人处理时保留现场并如实报阻断，不绕过、不标PASS。
