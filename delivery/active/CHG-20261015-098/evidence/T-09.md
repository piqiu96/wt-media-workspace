## 用户裁定（2026-10-16，第五轮）

用户按第四轮交付的真实页面给五条，逐条追问后拍定：

1. 「对于排队中/成功/失败都不能再次进去到已选素材」→ 追问后：「未使用状态的数据【只有是没有真正产生数据的】」，失败/排队中/成功都属于已使用状态；已取消「算已使用过，要再次运行直接在任务页点击重试即可」。形态：**未使用过 = 该 (策略,素材) 从未有过任何任务记录；已使用过 = 四条计数任一 > 0**；已使用过行**只读且无按钮**（撤掉第四轮的「再生成一版」）。
2. 「已选素材筛选框需要默认按照发布时间倒序排列」→ 候选列表默认 `published_at` 降序；筛选行新增排序字段：发布时间倒序（默认）/ 点赞倒序。
3. 「需要把素材的点赞量、收藏量同步过来」→ 数据链路已全通（采集入库 → 素材接口 → 详情抽屉已展示四项）；本轮补创建抽屉候选行与「我的素材」两列，并按追问选「再加排序」。
4. 「现在合成任务全部都在排队中并不会执行，是后台程序未启动？」→ 是：compose-worker 没跑，也不在任何发布/部署清单里；选「本机手工跑」，清单缺口登记待裁定，本轮不修。
5. 「已取消的任务是否应该支持重新执行？」→ 支持，名称统一为既有的「重试」（不引入「重新执行」）；人工重试 = 重新获得完整自动容错配额，执行编号不回退。
6. 追加裁定：自动调度 collides 一律跳过（任何任务记录 → `previously_run`）；mid-implementation 追加「人工重试放宽到所有失败」（`execution_uncertain` 除外，它有自己的管理员核对通道）。

**两处如实更正**：第四轮口述的「3/3 重试会产生僵尸」不成立（重试 UPDATE 里本来就有 `max_attempts = max_attempts + 1`）；「重置计数」不能字面清零（`compose_task_attempts` 有 `UNIQUE(task_id, attempt)`，清零会改写历史行），实现为**编号单调 + 预算重定基**：`max_attempts = attempt_count + 3`。
