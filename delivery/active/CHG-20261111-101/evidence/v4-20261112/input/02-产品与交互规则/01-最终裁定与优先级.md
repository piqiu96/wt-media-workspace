# 已确认的最终裁定（Codex 高优先级执行约束）

**优先级：本文件的已裁定规则 > `02-产品与交互规则/` 其余细则 > `04-操作弹窗定稿/` > `03-高保真视觉基线/` > `06-历史走查证据/`。**

## 已确认、不得倒退
1. 发布任务列表、快速发布、任务详情保留用户选定蓝白简洁后台视觉；不要推倒重做。
2. 快速发布为**一页**，没有「第 3 步预检」和三步向导；内联字段检查即可，创建任务不立即执行。
3. 新建页 01 为**选择平台、类目、账号**：平台→类目→账号依赖选择；选账号必须弹窗筛选同类目账号，展示账号等级和当日剩余可发布数。
4. 新建页 02 依据平台动态展示不同发布字段；标题默认从素材带入，封面默认从素材带入。AI 填写是显式独立按钮。
5. 封面处理**恰好三种**：替换图片；当前素材图 + 模板 + 文字；图片库图 + 模板生成。含「封面短语」字段（模板加文字时），点击「生成封面」才开始生成。**不做封面实时生成/实时预览**；保留右侧发布效果参考预览（仅展示当前已保存/已生成结果，不因每次输入触发图片生成）。
6. 详情为**只读**：状态区 → 上方独立、整行**横向平铺任务摘要** → 下方独立的「**发布内容**」 → 执行历史；去掉「当前执行进度」「执行尝试」「安全提示」三个独立模块；没有固定右侧任务摘要栏。只读详情绝不出现「保存并关闭」。
7. 详情操作统一放**右下角**（关闭 + 当前允许的任务动作）；列表操作遵循状态矩阵，避免过多平铺和禁用假按钮。
8. 10 个状态：待执行、排队中、执行中、等待人工、结果待确认、平台审核中、发布失败、已发布、已取消、已放弃。**确认失败一律改称「发布失败」**，但要审视既有状态枚举映射，不能盲目改坏持久化兼容性。
9. 8 个正式动作：**详情、编辑、执行、取消、去处理、核实结果、重试、复制**；不设「启动」「安全重试」「继续执行」等用户可见动作名。**暂停本期不做**。
10. **复制只在四个明确终态**提供：发布失败、已发布、已取消、已放弃。复制新建任务，不复制状态、ID、执行日志、资源锁；不自动执行。
11. 重试弹窗**极简**：任务名、平台/账号、上次失败原因、一次重试后果说明、取消/确认重试。**不展示四项绿色校验卡、原尝试详细参数或无意义的表单字段**；安全检查在服务端执行。
12. 核实结果四结论（已发布、平台审核中、发布失败、无法判断）。「确认已发布」以**最终公开作品链接**为核心字段；平台确实不可获得时，只在平台支持且有**唯一作品 ID + 可靠成功证据**时可替代；系统补录标记；任务与作品管理关联去重。未知结果时不得重试/复制。
13. 取消不代表撤回外部投稿，也**不等于立即释放资源**；执行中不可确定安全时不能直接已取消。人工处理完成后仅继续原执行尝试，疑似已提交则结果核实。
14. 既定关系为「发布计划 → 发布批次 → 发布任务」；快速发布可创建**独立任务**；不得把独立任务直接挂到发布计划上，不得为独立任务强制建批次。

## 尚未获用户单独裁定的后台细节（禁止擅自升格成产品新能力）
- 「已取消 → 已放弃」的具体资源释放入口/自动机制：遵守仓库既有明确流程；若未实现，则保留既有状态，不以新增“放弃并释放”前台按钮或取消后自动释放替代。记入实施风险清单。
- 不同平台内容字段、长度、素材适配限制：先读取仓库已有平台配置；缺平台规则时使用通用组件 + 明确待配置项，不能凭原型假造硬性平台限制。
- 停止中的取消是否能完成：由执行器实时证据决定，不能让前端单独断言。
- 账号等级/配额的口径：使用已有账号管理系统真实字段，不能把图中的等级、次数当作接口常量。

## 视觉图与最终规则冲突时如何处理
- 用户选定的列表参考图中「执行中→安全重试」是过时示例：必须按本规则移除。
- 用户选定的详情参考图为左右结构的早期概念，**最新裁定为任务摘要单独整行放在发布内容上方**；使用另附较新详情图参考，不复刻旧右栏。
- 早期弹窗 V3 把重试做得太复杂：**以最终精简重试图为准**，V3 旧图和旧 HTML 只作历史对照。
- 图片中的样例任务、时间、数据和百分比都是视觉占位，不能写死成业务数据。
