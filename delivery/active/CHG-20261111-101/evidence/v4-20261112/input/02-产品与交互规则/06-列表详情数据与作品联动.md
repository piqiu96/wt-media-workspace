# 列表、只读详情、作品管理联动

## 列表
- 标题、筛选器、状态概览卡（用户选定视觉）、任务表格、分页。
- 搜索：任务 ID/标题；筛选：平台、状态、账号/创建人、时间范围，类目可在高级筛选中，紧凑排列。
- 表格：任务 ID、发布内容缩略图/标题、平台与账号、状态、必要的当前状态说明、创建/更新时间、操作。
- 第一层操作：`详情`（始终有入口）；当前状态的主要动作；其余合法操作放`更多`。`复制`只在四终态，`重试`只在发布失败，`执行`替换启动。
- 不向用户展示状态不明/审核中的假 100% 成功率，不把平台进度压成虚构百分比；可展示当前阶段文案。
- 标题列尽可能不截断，支持 tooltip；不可用操作隐藏或解释原因而非点击无反馈。搜索空态有「清空筛选 / 快速发布」。
- 列表 checkbox 如存在必须有对应批量操作和权限，若没有批量能力，先移除 checkbox；不可假装支持批量执行/取消。

## 详情（只读）
- 采用统一页面骨架：页面标题+任务 ID → 当前状态简述/步骤（有真实阶段才显示）→ **独立「任务摘要」整行横向平铺** → **独立「发布内容」整行** → 执行历史 → 右下角操作区。
- 禁止左右两列固定分配「发布内容 | 任务摘要」，禁止任务摘要放在发布内容下方；不恢复「当前执行进度」「执行尝试」「安全提示」三个独立模块。
- 发布内容区显示**快照**（与当前执行尝试绑定）；完整快照可在信息区内展开，只读，不新增「查看原始日志」动作。
- 没有任何执行历史时显示“任务尚未执行”，不渲染空表。异常优先展示原因/可用下一步，顶部状态真实、不要以绿色预检暗示可以重试。
- 右下角为“关闭”及当前合法操作；不出现保存并关闭、操作堆栈。已发布作品链接作为详情内关联信息，只有有效 URL 才可点击。

## 结果核实与作品管理
- 确认已发布须取得最终公开作品 URL（优先）；无 URL 的例外需可靠作品 ID+发布证据和平台规则允许；不可用账号主页/投稿页代替。
- 保存核实后按平台 + 作品唯一 ID / 规范化作品 URL 关联作品实体，必须幂等去重；作品管理关联状态与链接是否补录可见。
- 不能以「审核中」或「已提交」表示「已公开」。作品采集、互动管理等能力只在作品身份可验证、平台支持、账号权限允许且关联成功时可用。
- 原任务和每次执行尝试的内容快照、结果证据、核实人/时间应可追溯；别将旧尝试覆盖成最新内容。

## 设计系统与适配
- 以项目公共页面设计规范为准：蓝白中性色、紧凑桌面表格、统一按钮尺寸与状态色、弹窗宽度分级、正文优先可读。以 1512px 为主桌面验收，1200px 下不重叠；窄屏按现有项目策略适配。
- 图片原型是**布局参考**，不是接口数据/字符长度规范；不要因静态图不合理而编码假数值。
