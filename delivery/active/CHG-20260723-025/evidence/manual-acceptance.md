## 1. 验收前提

人工验收需要在真实 Desktop 环境进行：

- Cloud 服务可访问；
- Desktop 已登录普通运营账号；
- Desktop 已通过 M2-A 本地身份校验；
- Local Agent 正常运行；
- BitBrowser 可访问；
- 当前用户、Desktop 节点、Local Agent、BitBrowser `main_user_id` 匹配。

## 2. 验收步骤

### Cloud Web 边界

1. 使用浏览器打开 Cloud Web；
2. 进入“浏览器窗口”页面；
3. 检查页面只展示 Cloud 已保存窗口信息；
4. 确认 Cloud Web 不展示：
   - 扫描本机窗口；
   - 新建窗口；
   - 打开窗口；
   - 关闭窗口；
   - 删除窗口；
   - 接受本地变化；
   - 恢复 Cloud 配置。

### Desktop 扫描闭环

1. 使用 Desktop 登录普通运营账号；
2. 进入“浏览器窗口”页面；
3. 点击“扫描本机窗口”；
4. 确认 Desktop 通过 Rust / Local Agent 读取 BitBrowser 当前窗口；
5. 确认 Cloud 返回只读 Diff；
6. 确认页面可以看到 Diff 分类，或看到“无差异”结果；
7. 确认扫描结果提示“不会同步或覆盖 Cloud 浏览器窗口”；
8. 确认“接受本地变化”“恢复Cloud配置”为禁用或后续提示，不可执行。

### 只读副作用

1. 扫描前记录 Cloud 已保存浏览器窗口数量和关键字段；
2. 扫描后再次刷新 Cloud 已保存浏览器窗口列表；
3. 确认正式 Cloud Profile 镜像、授权关系、媒体账号绑定没有被扫描自动修改。

### 异常提示

至少选择一种异常场景验证：

- Local Agent 不可用；
- BitBrowser 不可用；
- 本地身份未绑定或不匹配。

期望：页面显示运营能理解的失败原因，不写入正式镜像。
