# CHG-20261118-104：M6-B 原尝试核实与安全重试

## Change

真实执行在浏览器入场前因报告序号衔接失败，原任务已如实保存为 uncertain。接入 PRD/Spec 已明确的核实与安全重试，使运营能记录核实依据；只有确认原账号没有可发布稿件、原现场已结束，才能将未知结果转为失败，再沿用原任务重试。保留原回报、资源占用及审计，不用新任务绕开未知现场。

Cloud 先提供 resolve/retry 和所属用户原尝试只读契约、事务与审计；新增迁移 105 将核实记录扩大为 TEXT，完整保留原有上限内的原因及依据；共用 Vue 继承现有核实弹窗和失败重试入口；Agent 补报核对原尝试的 hash 与现场处置，不读取当前任务的新结果来释放旧占位；Desktop 同步提供方版本锁。补齐新鲜尝试协调器、心跳、持久化提交检查及实际关闭核实的故障测试，修复真实暴露的准备序号衔接。协调器仅接收显式平台适配器，本单元不装配自动领取循环，不宣称已实现百度上传或最终提交。

实际页面只记录“仍无法判断”：百家号稿件核对被安全验证阻塞，不据此确认未发布或点击重试。百度真实表单适配、自动领取、最终提交与回执继续归 M6-B 下一单元；公开作品核实、补录、终止/放弃及人工现场继续仍归 M6-C。未进行真实投稿，不新增产品能力。

延续用户本轮临时串行堆叠授权，四仓基于 CHG-103；标准 start 因前置仍 Active 拒绝，按已明确授权继续并生成当前快照，不改治理限制、不自动合并。真实测试仍仅使用已授权系统账号与成片；不修改真实记录伪造通过。

## Done When

- 核实与重试服从现有角色、团队及类目范围；版本或当前尝试变化、原 UID 不匹配、现场未结束时拒绝确认失败。可如实保留 uncertain。
- 核实保留原结果和 hash，完整记录依据与审计；审计失败全部回滚。未知不能直接重试；失败重试复查原资源与授权，保留原任务、内容、占用及历史，只在新领取时新增尝试；并发只成功一次。
- Agent 只补报同一份本地原结果；当前任务已推进后仍按原尝试读回处置，不能用新任务状态确认旧现场。报告成功不等于可重新投稿；确认处置后也保留重放屏障。
- 新鲜尝试协调器的故障测试覆盖提交许可丢失、点击响应丢失、关闭未证实、结果断网及补报后崩溃；不得重新进入浏览器或重放点击。实际端口与 BitBrowser 读回均证实关闭才算现场结束。
- Cloud / Desktop 开发入口实际核实弹窗、取消、缺失依据、保存 uncertain、原结果保留及旧版本拒绝均留证；本轮不将模拟回执或数据库测试当作真实发布成功。
- 适用自动化、隔离数据库迁移、构建、契约及正式治理检查通过；四仓独立堆叠 PR，M6 保持 IN_PROGRESS。平台安全验证与未实施的自动投稿清楚记录为后续事项。
