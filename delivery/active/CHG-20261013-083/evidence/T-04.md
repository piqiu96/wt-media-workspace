# T-04 Worker 运行时

- 日期：2026-10-14
- 实施：`internal/jobs/compose_worker.go`（新，主循环）+ `cmd/compose-worker/main.go`（验证壳升级为领取循环，`-input` 保留 M4-C4 验证模式）+ `internal/config`（并发/租约/心跳/超时/轮询/恢复 6 旋钮 + node_id）+ 生命周期 store 过期租约回收（requeue / 终态失败）+ `execution.go` 被 context 杀死的运行按死因分类。

## 循环行为（每条被用例钉住）

| 行为 | 用例 |
| --- | --- |
| 领取→执行→成功；运行目录清空；心跳在跑 | 成功用例（断言 workspace 根无残留、renewed≥1） |
| cancel_requested 轮询→受控终止→仅此后 ConfirmComposeCancel；不 requeue | 取消用例 ×2（执行中 + waiting 中） |
| 续租被拒→终止尝试、不确认取消 | 丢租约用例 |
| wait_input 原地重试：不重新领取、不烧 attempt（attempt 计在 claim） | 3 次尝试 claim 仍为 1 |
| wait_input 超时→预算内 requeue（task_timeout）；预算尽→终态失败（否则成「pending 且不可领取」滞留态） | 双分支用例 |
| retry outcome→回到领取队列（slot 间歇即退避） | 重领用例 |
| 恢复扫描：启动即扫 + 周期扫；预算内 requeue、预算尽终态失败（lease_expired） | 扫描用例（80 requeue / 81 failed） |
| 配置非法拒绝启动，零领取 | settings 校验用例 + config 7 例 + `config-check` 对真实配置树 PASS |

## 关键裁定

- **恢复扫描可无条件 requeue 的前提是 compose.Lock**：单实例锁保证本机不可能有第二个 worker 在跑该任务的 FFmpeg，租约过期即前任进程已死（spec §5.3「能确认 FFmpeg 子进程不存在」在本形态下由锁给出）。多 worker 分布式形态不在 M4。
- **被 context 杀死的运行按死因分类**（cancel_requested→cancelled；DeadlineExceeded→临时 task_timeout；其余→业务 execution_failed）：不读 FFmpeg 遗言，凭 worker 侧事实分类。
- **EnsureInputPrepared 签名带 task**：准备任务以任务创建人名义发起（transfer 行的 RequestedBy），worker 不冒充别人。
