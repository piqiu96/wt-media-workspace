# T-06 Cloud Web/Desktop 共用策略页面与客户端

- 起点核对：`ComposeStrategyPage.vue` 与 `shared/api/compose.js` 已在此前会话写好但未提交、路由未翻。本会话先对照 T-01 合同与 T-05 路由逐项核对页面假设：六条端点路径一致、角色字符串（`operator`/`senior_operator`/`admin`）与 `identity/model` 一致、`canManage` 与 Service 层 `canManageStrategies` 同规则、模板/游戏/策略 JSON 字段名（`compose_template_id`、`compose_template_version`、`config` 等）与 model 标签一致；发现页面调用的 `client.listGames()` 在 compose 客户端缺失（会直接 TypeError）。
- 失败验证：新增 `web/src/shared/api/compose.test.js`，先跑出红——`client.listGames is not a function`，同时钉住八个方法与合同路径的映射（GET/POST 集合、GET/PUT 详情、POST copy、PATCH status、模板目录、团队、游戏端点）。
- 实现：compose 客户端补 `listGames()`（`/api/v1/games`，与素材/内容池页共用端点）；两端 `router.ts` 的 `compose-strategy` 从 `ComingSoon.vue` 指向 `modules/compose/pages/ComposeStrategyPage.vue`；`routerParity.test.js` 的 CHG079 占位守卫（断言 ComingSoon）改写为双端指向同一真实页面且不含 ComingSoon 的守卫。
- 页面行为与验收对应：高级运营/管理员见新增、编辑、复制、启停入口，管理员创建时另选团队；普通运营只读（写入口隐藏，真正授权判定在 Service 层）；模板下拉只来自已入库且启用的版本，编辑时模板版本固定展示；停用模板不可新绑定由服务端 409 兜底。页面遵循站级约定测试（filter-field 左标题、t-drawer 显式页脚），由既有站级扫描覆盖。
- 验证：
  - `npx vitest run`（在 `web/` 下）：56 文件 510 用例全绿，含改写后的双端 parity 守卫、新 compose 客户端测试与三条站级约定扫描。
  - `npm run build:cloud` 与 `npm run build:desktop` 均构建通过（chunk 体积告警为既有现象）。
  - `git diff --check` 通过；改动仅限 compose 模块、compose 客户端及两端路由/parity 测试。
