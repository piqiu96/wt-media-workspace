## 实施

- `service/task.go`（新增）：
  - 具名哨兵：`ErrComposeTaskInvalid`/`ErrComposeTaskForbidden`/`ErrComposeTaskNotFound`/`ErrComposeTaskNotCancellable`（对应 15214~15217，映射在 T-04 Handler 落）；模板不可用复用 `ErrStrategyTemplateUnavailable`（15213）。
  - 命令级门（先于逐素材处理、零写入）：策略可读（运营读不到停用策略 → not found）且 active、绑定模板版本经 `executor.BasicCutV1()` 比对可用（同 `validateConfig` 判据）、`config_override` 与策略 config 深合并后过同一 schema 校验器；request_key 8~64 字符、批内不重复、items 1~50。
  - 逐素材：request_key 先于一切素材校验解析——已存在且归属本人 → 幂等返回既有任务（重试不受其后 usage 移除影响）；他人占用 → forbidden。素材校验具名失败（不存在/越队 forbidden/游戏与策略不匹配 invalid），部分失败不回滚。
  - 写入经 `CreateForUsage`：usage 校验与插入同事务（§5.4.5 移出后不允许新建的竞态口径），`written=false` 以 invalid 具名。
  - 取消：读与取消同一可见性门（admin 全局、senior 队内、operator 仅本人）；非 pending 先行具名 409；条件 UPDATE 失败后重载——任务还在且非 cancelled → not-cancellable，消失 → not-found。
  - 列表：admin 全局、senior 队+游戏域、operator 额外限 `created_by`；状态枚举外值具名 invalid。
- `repository/task_mysql.go`：
  - 抽出 `composeTaskInsertWithAudit`（指针入参，GORM 回填 ID）；`MaxAttempts` 缺省 3 与时间戳落位随插入助手，两条写入路径共用。
  - `createForUsage`：事务内 `findActiveUsage` → 置 `material_usage_id` → 插入+审计；无 active usage 时零写入返回 `found=false`。
  - `cancelComposeTaskAudited`：条件 UPDATE（仅 pending）+ `audit_logs`（actor 取消者）同事务；rows 0 时无审计零写入。取代 T-02 的裸 `cancelPendingComposeTask`（审计为 change.md 明确要求，旧函数与其用例移除，覆盖由新用例承接）。
  - `findComposeTaskByKey`：`uq_compose_tasks_request_key` 读回。
- `appendComposeTaskAudit` 增加 actorID 参数（创建=创建者，取消=取消者）。

## 限制

- per-item 失败的信封形状（`errcode`/`error`/`message` JSON）由 T-04 Handler 按哨兵映射；service 层 `CreateComposeTaskFailure.Err` 携带具名哨兵。
- 素材可见性、游戏一致性等前置读在事务外（与策略服务既有形态一致）；usage 读写竞态已由 `CreateForUsage` 事务闭合。
