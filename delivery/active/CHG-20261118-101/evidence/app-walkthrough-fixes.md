## 封面图片

根因：Desktop CSP 的 `img-src 'self' https:` 不允许本机配置的 HTTP Cloud 能力路径。浏览器读取相同封面正常，安装版显示图片替代文本。文件能力路径由 Cloud 检查有效性后跳转对象存储，不应绕过该路径。

修改：Desktop 从已配置 `cloud.base_url` 解析纯 origin，精确加入图片策略；不把 IPC/connect 列表、账号密码、URL 路径或查询参数放进图片策略，不增加通配 HTTP 许可。业务前端仍使用既有文件能力路径。

验证：先加入回归检查，原实现 3 项失败（缺少 Cloud 图片 origin）；修改后 Rust 全套 540 PASS、6 ignored、0 FAIL，`git diff --check` 通过。本次安装包复验结果在本记录后续补充。

## 发布时间

根因：现有公共时间格式化、日期范围和本地预约转换依赖客户端默认时区，导致同一时间在 Cloud 浏览器与安装版显示不同。发布工程设计规定运营日期使用 `Asia/Shanghai`。

范围：发布页面显示、创建日期筛选、预约输入与编辑回填统一使用该业务时区；公共显示组件按参数显式接入，其他页面保留既有行为。不得全局覆盖浏览器时区。

修改：公共 `formatDateTime` 支持显式传入时区，默认行为保持不变。发布模块独立完成北京时间的显示、预约回填/转 UTC、日期范围起止转换；无效日期拒绝提交。首版增加的列表说明、创建日期和预约标签中的重复时区文字，已按用户反馈移除，时区处理保留。

验证：原公共格式化在跨时区回归中先失败；修复后共用前端 137 个文件、1018 项测试全 PASS，新增检查覆盖 UTC、奥克兰、洛杉矶，未接入页面仍按原默认时区显示；还覆盖跨年范围、清空、无效日期、零时间值。定向复验 14 项 PASS。真实任务 3 的原始时间为 `2026-11-18T05:48:10.817692+08:00`；对同一接口返回值，在 UTC、奥克兰、纽约三种客户端环境均显示 `2026/11/18 05:48`，见[真实时间读回](app-walkthrough/fixes-real-time-readback.json)。这不是浏览器点击验收。
