## 2. 动手前核实的三个事实（都不是推断）

1. **`加入合成` 没有端点。** 全仓 `git grep -n "加入合成"` 只命中规范与（当时的）注释；
   `/compose` 在两个 router 里都指向 `shared/ui/ComingSoon.vue`（「该模块正在建设中」）。
   所以这一颗按钮做成**跳转**，不做成一次提示「已加入合成」的假提交——后者会让运营
   回合成页里找这条素材，而那里什么都没有。
2. **`使用状态` 只有两档。** `material_usages.status` 的 `CHECK` 是 `active / removed`，
   Business Schema `MaterialUsage` 同样两档。用户提示词里的第三档「已中断」在库里没有
   对应取值，本任务不实现、不猜（登记在 `change.md` §3）。
3. **抽屉正文那「四段」是建议，不是删除令。** 提示词第十节写「建议分为四个区域」，四段
   里没有一处安排素材 ID 与游戏该去哪，而这两样在旧的「基本信息」卡里。**没有删**：
   素材 ID 是运营要复制去别处查的那串数字。处理是——官方那四段按提示词列出的次序排
   在前（当前进度 / 使用情况 → 文件信息 → 来源信息 → 来源内容统计），把「基本信息」
   整卡挪到最后一段。用户走查时若认为该删，删的是一张卡而不是一条链路。

## 4. 实现

- `labels.js`：新增第三个状态维度 `USAGE_STATUSES = ['active', 'removed']` 与
  `usageStatusLabel` / `usageStatusTone`（缺值 `-`、未知值原样透出，与另两组同规矩），
  以及 `nextStepHint`（前端提示文案，不发请求、不改状态；已放弃的关系先指向恢复）。
- `shared/api/materials.js`：`restoreUsage(usageId)` → `POST /material-usages/{id}/restore`。
- `MyMaterialsPage.vue`：副标题改成「已加入的素材，在这里下载、补充文件并进入后续生产」；
  列换成 `素材 ID | 素材 | 文件状态 | 使用状态 | 加入时间 | 操作`（6 列不变），
  「素材」格副行由来源平台改为 `游戏 · 作者`（`cellSubline`）；`toRows` 带上
  `usage_status: usage.status`；行操作按两个维度分支，最多 3 颗、全部平铺；
  「移出」→「放弃使用」；新增 `giveUp` / `restore` / `goToCompose`；
  打开详情时把关系那一维随行递过去（单条素材接口不知道「我」和它的关系）。
- `MaterialDetailDrawer.vue`：hero 的 Badge 组加使用状态（只在读得到时出）；
  正文首段换成「当前进度 / 使用情况」（文件状态、使用状态、加入时间、下一步），
  其下同卡虚线分开仍是使用情况的五个事实；基本信息整卡挪到末段；页脚在我的素材
  上下文按状态给动作（恢复使用 / 加入合成 / 重新下载 / 重试或下载 / 放弃使用），
  素材库上下文不变。
