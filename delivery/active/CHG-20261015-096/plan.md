# CHG-20261015-096 实施计划

1. 在现有生命周期 Repository 测试中先证明：`pending` 技术重试可被第二个 Worker 立刻领取。增加 `next_attempt_at` 迁移、模型和扫描列；重排事务写入由尝试次数决定的有界退避，领取 SQL 只选择到期行，人工重试清空等待时间。
2. 固定失败分类：只对已经确认执行结束、可重试的网络/对象存储/超时错误重排；校验失败、业务错误和 `execution_uncertain` 终止。保留逐次尝试和领取代次约束。
3. 将 staging key 隔离到领取代次；用受控清理记录和恢复扫描处理删除失败。只允许删除 `compose-staging/` 中属于当前任务/代次的键；正式对象仅在确认提交事务没有落地时按精确键清理。
4. 以真 MySQL、多 Worker、真实 FFmpeg 和对象存储故障注入对照状态、尝试、时间和存储键；复跑相关 M5-C3/C4 回归。每个 Task 先红后绿、检查 diff、记录证据、更新 checkpoint，再独立提交 Cloud 与 Workspace。
