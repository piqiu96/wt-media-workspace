# CHG-20261028-099：运营资源（社媒账号 / 浏览器窗口 / 代理）重构

## Change

对社媒账号、浏览器窗口和代理三个核心功能块做一次完整收敛：清理混用字段和无用状态，统一启停与第三方数据命名，压缩临时扫描模型；窗口代理改为 Desktop 发起本机执行、Cloud 创建意图并收敛结果；保留团队权限、真实检测、配额、失败重试和三角色边界。

最新原型与正式前端规范继续作为页面视觉和交互基线，但不覆盖数据/接口事实。CHG107（游戏目录改为扁平业务类目）必须先完成，CHG099 再继续社媒账号及运营资源页面。

当前现状、目标模型、文档清理和任务顺序见[plan.md](plan.md)。

## 已确认的业务裁决

1. 术语统一“比特”“系统托管 / 比特自管”；ID 独立成列，操作不超过 5 项时平铺。
2. 普通运营和高级运营只能在本人 Desktop 上操作本人资源；高级运营查看成员及管理员查看时不提供代操作本机能力。
3. 一个窗口可关联多个平台账号，每平台一个；代理配额按窗口计。
4. 代理按团队共享；服务端校验团队和角色，页面隐藏不构成权限边界。
5. 代理连接检测归 Cloud；动态地址提取使用运营本机网络。
6. 同步只处理当前运营自己的窗口；新窗口勾选后才认领，归属冲突不自动转移。
7. 不再次执行存量代理清理迁移；不把数据清理当作视觉对齐手段。
8. 打开窗口后必须先关闭再停用；停用后打开、关闭、编辑不可用。
9. 批量操作采用现场进度与结果，失败仅重试失败项。
10. 托管代理以比特更新接口的明确成功响应为成功依据；明确拒绝按失败处理。明确成功的批量或单项设置须在同一 Cloud 结算事务中更新正式代理关系和窗口最近确认的代理配置，列表立即显示新状态，再次同步不应把这次写入当作新差异。写入可能已发送但结果不确定时，先读取并核对实际配置，再裁定后续操作，不能直接认定失败并盲目重试。授权测试窗口的真实比特应用、未知结果核实、正常解绑及本机 Cloud 目标网络已验证；用户裁定本轮暂不测试真实供应商提取，其他部署环境亦未现场验收。
11. 启停统一 `enabled`；比特镜像统一 `bit_`，平台事实统一 `platform_`，检测统一 `last_check_`。
12. 不建设通用操作表、检测历史表、敏感任务表或强制审计事件表。
13. Cookie 读取改为 Desktop 同步执行并回报 Cloud；删除旧异步 Cookie 任务入口和通用 `tasks` 表。
14. 本人 Desktop 进入浏览器窗口页面或刷新页面自动读取一次运行状态，页面右上角提供唯一“刷新运行状态”；不轮询、失败不自动重试，原因只以 Toast 提示。未知状态禁止打开/关闭；普通资料重载不扫描，同步结果复用，进行中的读取合并。Web 及查看他人窗口不调用本机。手动成功 Toast 显示实际读取数量，自动成功不弹提示；失败按未绑定、账号不一致、比特未连接、本机服务不可用和其他错误分别提示。
15. “核实窗口缺失”使用居中对话框与简洁分组信息；无关联账号时不渲染空表格。保留窗口与账号历史、不自动删除的业务语义不变。
16. 比特扫描未找到的窗口暂保留 Cloud 记录、账号关系和历史。日常窗口列表新增独立“窗口状态”列与可清空筛选：仅有“已找到 / 未找到”两个选项，不选择时显示全部；状态取最近一次成功同步，不表示实时运行或确认删除。窗口状态列放在运行状态列之前，筛选顺序同理。未找到窗口可在列表查看与核实，独立“清理已删除窗口”入口承担批量清理；只有该类记录显示“删除”，普通窗口不显示。运营确认窗口确已在比特删除后，可单项或批量清理：物理删除窗口业务记录、解除关联账号、释放托管代理名额，账号本身及无凭据操作审计保留。未清理的缺失窗口重新出现时恢复正常展示；已清理的窗口重新出现时作为新窗口待认领，不恢复旧关联。同步结果区将本次涉及的异常和仍未处理的历史缺失分开标识；历史项不重复计入“本次新增”，也不单独弹出新异常提示，可在结果区人工重试核实或删除。若比特返回零窗口，当前本机接口无法独立证明所登录的主账号身份，必须拒绝将全部记录批量标记缺失，并提示人工核实；只有获得可信的独立主账号事实后才能扩展这一分支。
17. 代理 ID 统一为数据库自增整数主键和 API 整数 ID；存量代理与窗口正式/预留关系必须通过映射迁移，不得清理或重建业务数据。管理员团队筛选使用名称或 ID 输入，运营和高级运营不展示团队筛选。
18. 代理列表只展示地区，不展示供应商或供应商筛选；供应商保留在新增/编辑和代理详情中，避免重复占用列表空间。
19. 窗口列表的代理信息可查看详情：系统托管资源用只读侧栏展示资源、检测、有效期、额度和当前窗口的配置关系；比特自管且有实际地址时用只读居中弹窗展示最近同步的协议、地址与时间；直连没有代理详情，不呈现点击入口。缺失窗口的代理信息标为最近同步记录，不冒充实时配置。查看详情不触发写入或检测，不展示认证秘密；“管理代理”仍是独立操作。

## 最终落地范围

| 范围 | 最终要求 |
| --- | --- |
| 社媒账号 | 平台账号/检查/Cookie 字段分层，列表不读取 Cookie 大字段，启停和第三方字段命名统一 |
| 窗口列表/详情/表单 | 完整多平台关系、BitBrowser 镜像和 Cloud 运营字段分离、自适应键值、备注、同步认领、失败重试 |
| 代理列表/详情/表单 | 团队范围、连接信息与复制、来源选择、本人 Desktop 动态提取/Cloud 保存检测、启停/到期/检测/额度分离、占用阻断、最近检测原因 |
| 选择与确认 | 候选筛选、空/无匹配/不可用区分、关联账号就近展开、风险显式说明、返回保留上下文 |
| 批量与反馈 | 真实计数、逐项原因、仅失败重试、未知先核实；导入按勾选提交并处理重复/无效行 |
| 工程边界 | Vue 唯一源码在 Cloud web；Desktop 只作为 Tauri/Agent 执行桥；Workspace 不进入运行时 |

## Done When

- CHG107 已合入，所有当前业务字段和页面统一使用 `category_id/category_ids`。
- Cloud 数据模型与命名收敛完成：三块业务只保留计划中列出的 7 张领域表，不新增通用 operation/历史/审计/敏感表。
- 社媒账号列表不读取 Cookie 大字段；窗口的比特镜像、实际代理、正式关系和临时额度预留可分别读回；代理启停、检测、额度和进行中占用一致。
- 代理写入不再由 Cloud 直接访问本机 Agent；Desktop 经 Tauri 调用 Agent，并覆盖明确成功、明确失败、超时/断开后的核对、旧 Agent 和安全重试。
- 动态代理提取由本人 Desktop 调本机 Agent；Cloud 仅接收提取结果并保存、检测。网页端/管理员不执行本机提取；已保存供应商链接仅在授权的本机操作中读取。
- 同一窗口不同目标并发、两个窗口抢最后名额、失败时预留释放和同步确认额度复核均通过真实 MySQL 与隔离服务验证。
- 三块页面及三角色、Cloud/Desktop、加载/空/异常/未知/禁用/忙碌/窄容器符合最新原型和正式前端规范。
- 真实比特开关、字段修改、代理应用、Cloud 检测和目标网络验收完成；未完成项如实标注，不以 fixture、HTTP 成功或页面提示替代。
- 当前文档、ADR、OpenAPI 和 business schema 与实现一致；被取代的中间裁决和重复实现说明已清理。
- 旧 `/media-accounts/{id}/cookies/read` 异步入口与 `/cloud-agent/tasks/*` 通用任务接口退役，`tasks` 表删除；Cookie 同步读取仍保留 Profile 互斥与结果读回。

## 明确排除

不接入比特标签或窗口业务标签；不恢复窗口分配、批量任务中心或父子重试任务；不新增通用层级/标签/工作流模型。审核、提交、合并、发布分别处理。用户于 2026-10-30 确认 CHG099 已走查完毕，并指定先把前置 CHG107 合入远端 `main`，再合入 CHG099；合并前逐仓核对差异和 CI，本轮不发布。

## 范围裁定

- **Q-01（已裁定）**：用户确认动态提取归属纳入 CHG099，一并完成。Desktop 调 Agent 从运营本机网络提取；Cloud 保存结果并检测。旧 Cloud→Agent 提取入口退役，不得以 Cloud 运行环境代替本人 Desktop。
- **Q-02（已裁定）**：用户决定本轮暂不测试真实动态代理供应商链接。实现与隔离验证保留在本 CHG，供应商网络现场验收如实标为延期，不能据此宣称完整现场 PASS。
- **Q-03（已裁定，按 2026-10-30 最新反馈修订）**：移除“窗口记录”筛选，不增加双标签；改为“窗口状态”列及“已找到 / 未找到”两选项筛选，空值显示全部，列及筛选均放在运行状态之前。单项按钮统一“删除”，仅出现在 `local_missing` 行；批量删除从独立清理入口及同步待处理区进入。历史缺失在同步结果中标为“历史待处理”，不计入本次新增；可重试核实或人工确认后删除。人工确认已在比特删除后，逐条事务解除账号关联、重置登录核验、释放托管代理关系、物理删除窗口记录，并写入无凭据审计。普通窗口无删除。待确认代理操作阻断清理；批量逐项返回结果，不重试成功项。本轮不删除现有运营数据。
