# CHG-20261028-099：浏览器窗口与代理管理体验优化（V3 第 1 期）

## Change

让运营在「浏览器窗口 / 代理管理」两个页面上按角色与环境看到正确的动作和状态，把代理从全局资源池改为按团队共享，把检测从本机执行改为 Cloud 服务端执行，并补齐窗口停用、批量开关窗、配置不一致与代理生命周期（启停 / 到期 / 配额 / 删除）的阻断与恢复语义。

依据：`/Users/aqiuye/.codex/visualizations/2026/10/26/01a1799f-9a86-7302-9201-4df31f7e9c3d/browser-proxy-design/需求优化执行稿-Codex-V3.md`（下称 V3）与《DeepSeek实施Prompt-V3》。最初视觉稿用于理解信息关系与状态覆盖。2026-10-28 用户进一步批准 frontend 公共视觉规范优化14项：后续视觉重构以已批准原稿视觉目标与修订后的 `docs/standards/frontend/` 共同验收，范围与例外按 Task 10 记录；业务、权限和真实执行语义不变。

用户已确认的四项裁决（2026-10-28）：

1. 高级运营在桌面端对本人窗口拥有与普通运营相同的本机能力（覆盖 2026-10-27「本机路由仅普通运营」的守卫），查看成员时仍隐藏本机动作。
2. 存量代理数据在迁移中整体清理，新代理必须带团队；不做存量回填。
3. 同步窗口只处理当前运营自己的窗口；新发现的未登记窗口默认不认领，需在扫描结果中勾选确认才建立归属，已被他人持有时列为归属冲突。
4. 本期一个 CHG 覆盖两个页面的全部改动；自测覆盖关键链路，纯展示项由人工走查。

## Done When

- 窗口列表与详情使用「比特 / 代理方式 / 系统托管 / 比特自管」措辞；ID 独立成列；本人桌面端行操作 ≤5 且全平铺；网页版、管理员、高级运营查看成员时无运行状态与本机动作。
- 窗口「分配」入口与 `assign-owner` 接口删除；首次同步新窗口默认不认领，未勾选不写入，他人已持有时显示归属冲突。
- 已打开窗口不能停用；停用后打开 / 关闭 / 编辑不可用；批量打开 / 关闭在状态混选时同时禁用并提示。
- 窗口详情并排显示系统托管值与比特实际值，标出协议 / 地址 / 端口 / 认证差异与最近核实时间。
- 代理按团队可见：普通 / 高级固定本人团队，管理员可筛团队；列表无团队列，详情显示团队并可复制认证用户名密码；服务端拒绝跨团队读写。
- 代理检测由 Cloud 服务端直接发起，不依赖本机 Agent；结果区分正常、连接失败、认证失败、超时、参数无效；旧连接结果不覆盖新连接。
- 代理资源启停使用列内开关且仅管理角色可改；到期单独展示且不自动解除关联；被引用资源服务端拒绝删除；配额不得低于正式占用并防并发超额。
- 代理导入先预览（原行号、有效 / 重复 / 无效、勾选），提交只导入勾选项；计数满足「总数 = 成功 + 失败 + 跳过 + 处理中 + 未处理 + 待确认」。
- 同步、批量开关窗、批量设置代理、导入、检测共用同一个「进度 → 结果 → 失败重试」现场组件；处理中不可关闭，强制结束后不继续调度。
- 自动化验证通过：`go test ./internal/modules/proxy/... ./internal/modules/profilebinding/... ./internal/modules/mediaaccount/...`、`npm run test`（web）中相关用例。
- Desktop 窗口编辑经本机 Agent 写入并读回后，Cloud 才更新窗口字段；读回不一致按字段报告「未核实」。

## 范围

- Cloud：`proxy`、`profilebinding`、`mediaaccount` 后端与迁移；`web/src/modules/profiles`、`web/src/modules/proxy`、共享组件与 Desktop 角色守卫；`cloud-api` 代理与窗口合同。
- Desktop：窗口编辑调用 Local Agent 的 profile-update，并逐字段核实写入结果。
- Workspace：产品第三章（角色、窗口、代理）、工程检测归属、ADR-0025、合同索引、本 CHG 与 Evidence。

## 明确不做

- 不恢复旧批量任务中心、任务编号、父子重试任务或恢复整次报告。
- 不做动态提取迁移（仍按 D04 使用本人桌面能力）。
- 不做 BitBrowser 标签（“比特标签”）接入：Agent 允许字段与 Cloud 合同目前都没有该字段，需补齐合同后另立 CHG。
- 不实现窗口业务标签字段（V3 W01 要求删除）。
- 不改其他模块的正式任务、审计与发布执行。

## 任务

### Task 1：正式定义回写

- 产品第三章 §3.4.7 角色与桌面环境、§3.5 代理团队归属 / 状态与到期 / 检测 / 导入 / 配额 / 删除。
- 工程：代理检测从 Agent 迁到 Cloud 服务端的归属与错误映射；新增 ADR-0025；同步 `cloud-api` 代理与窗口合同、合同索引修订号。

### Task 2：代理团队与生命周期（Cloud）

- 迁移：清理 `proxy_configs`，`browser_profiles.proxy_id` 置空（外键 ON DELETE SET NULL 兜底）；新增 `team_id`、`name`、`tags_json`。

### Task 3：服务端检测

- Cloud 直接对 `protocol/host/port` 发起探测，区分 `ok` / `conn_failed` / `auth_failed` / `timeout` / `invalid_params`；按连接版本保存，迟到结果不覆盖新连接。

### Task 4：导入现场

- 预览不写库：原行号、有效 / 重复 / 无效、可勾选；提交只导入勾选的有效行；服务端再查重并跳过。

### Task 5：窗口角色、停用与批量

- 删除分配入口；同步新窗口勾选认领与归属冲突；高级运营备注维护；停用前置关闭；批量开关混选禁用；详情配置不一致。
- 窗口编辑经 Desktop 的 `local_agent_profile_update` 写入并逐个字段读回；读回不一致时返回 `unconfirmed`，不谎报成功。

### Task 6：现场处理组件
