# 窗口与代理 UI 整改执行计划

## 任务理解

接续现有 DeepSeek 实现，按用户 2026-10-28 最新指令优化两个真实业务页面。交互参考 V3，视觉遵循现有 Token 与内容生产/内容挖掘的资源页面结构；公共改进做成可运行、可预览的候选，提交人工 Review，不合并或发布。

## 当前事实与约束

Cloud / Desktop 共用 `wt-media-cloud/web`；当前 Cloud 与 Desktop 工作区干净，均在本 CHG 分支。Workspace 两份未跟踪社媒分析报告与本次无关，保留。沿用已确认本人权限、团队代理、服务端检测和现场结果语义，不重新评估后端。不运行数据清理迁移或外部比特操作。

| 现状 | 目标 | 必要改动 |
|---|---|---|
| 两页行操作成排描边按钮，五按钮列占用大 | 低权重文字动作，权限/禁用/Loading 不变 | opt-in `ResourceRowActions`，扩展 `opColumnWidth` 的 text 选项，默认消费者不变 |
| 代理全部筛选展开、固定团队占用输入位置 | 搜索与高频筛选优先，低频地区/供应商折叠且可发现 | 仅调整代理筛选展示，沿用原查询函数与团队作用域 |
| 两页勾选栏临时拼装，窗口栏错误套用行操作 max-content 样式 | 统一全宽选择数、动作、清除与原因提示 | `ResourceSelectionToolbar` 在两个页面使用 |
| 详情单列网格、表单长串字段缺少层级 | 与策略页一致的分区标题、辅助说明、两列只读信息和分组表单 | `ResourceSection` 在两页详情和表单使用，保留字段与接口 |
| 现场结果窄弹窗、无完整过程列表、数字为散文 | 当前步骤、七类计数、逐项结果、真实重试/核实入口 | 优化已有 `OperationProgressDialog` 展示；不改执行调度 |
| 细节仅看源码、缺少页面证据 | 可比较的实际 Vue 组件截图和审核说明 | 隔离浏览器中以明确测试数据验证页面布局和交互，不冒充真实服务验收 |

## 计划修改

1. 保存修改前两页及参考页面截图，形成可复现布局检查。
2. 公共组件：`web/src/shared/ui/resource/{ResourceRowActions,ResourceSection,ResourceSelectionToolbar}.vue`；宽度函数增加可选文字操作模式；已有消费者默认不变。验证操作语义、槽与可访问性、窄屏与 Loading 不溢出。
3. 页面：`modules/profiles/pages/ProfilesPage.vue`、`modules/proxy/pages/ProxyPage.vue` 接入公共块，整理抽屉表单/详情、筛选与表格。业务函数默认冻结。
4. 进度：已有 `shared/ui/feedback/OperationProgressDialog.vue` 展示所有项目与七类计数、清晰状态与自动结果。验证不可关闭与失败/待确认动作。
5. 按涉及范围运行 Vitest、双入口构建、浏览器布局与交互检查；更新 Evidence 与公共规范实现落点，产出前后对比审核页。必要的验证修复跟随步骤进行。

## 明确不修改

不修改 Go、数据库/迁移、Contract、Agent、Tauri、权限模型、资源关系或配额业务。不推广公共候选到无关页面，不重写原型，不补本 CHG 明确排除的比特标签。保留现有 ID 独立列、≤5 动作平铺、只读详情无底部业务按钮。

## 冲突与未确认项

无阻断性业务决策。公共候选仅用于本次两个页面，文档标记推广待人工审核。完整真实比特端到端验收沿用原 CHG 待人工项，不以隔离 UI 测试替代。CHG 保持 VERIFYING，待用户视觉评审，不宣称全 CHG 完成。

## 第二轮：弹层与提示（用户截图反馈，2026-10-28）

用户已授权更大胆地优化公共组件和规范，实施到可评审结果。采用按任务与信息量选择容器：4 字段窗口新建 / 3 字段编辑、运营备注、普通运营代理资料编辑使用居中自适应高度 Dialog；代理完整配置、导入、同步、含关系表的详情保留 Drawer。创建与编辑同等复杂度使用相同容器；不统一强行全部改 Dialog，也不全站迁移。解决交互规范 §9.1 与 AdminUI §6.1 的既有冲突，说明新旧兼容。

1. `ResourceOverlay.vue`：基于 TDesign Dialog / Drawer 的显式公共容器，统一标题、宽度、内部滚动和 Footer；Dialog 520 / 640 / 880 按场景显式传入，Drawer 延续本地详情宽度级别。忙碌时阻止 X / Esc / 遮罩关闭，保存动作由调用者提供。`ResourceForm.vue`：统一表单 label 与提示纵向堆叠，避免截图中的说明挤在输入右侧。
2. `ResourceNotice.vue`：普通解释为无底色轻提示；明确操作风险用低干扰风险摘要且保留完整含义；真正加载 / 提交失败继续用现有 FeedbackAlert。`ResourceEmptyState.vue`：空列表只给一个标题、一个下一步和恢复入口，不再同时堆空表格与重复警告。
3. 两个页面接入：短表单去掉重复“基础信息”标题；代理选择空资源 / 筛选无结果 / 有资源但不可用分别表达，零关联账号不显示影响提示，有关联时保留范围与名称；风险确认保留必要后果。长抽屉说明按字段、按状态呈现，常识性说明移入按需帮助。公共改动是 opt-in，接口、权限与外部执行语义不变。
4. 在已有隔离浏览器验证中先复现短表单非居中、帮助行错位和重复空态；修改后检查窗口新建 / 编辑 / 空分组、权限差异、代理空资源 / 筛选无结果 / 不可用 / 已选及保存风险、详情和长表单、处理中不可关闭。窄屏核对内容和操作可滚动到达；复跑相关 Vitest、双入口构建和文档校验。
5. 独立保存新代码和规范，更新现有评审页为本轮新增场景及截图，并将上一轮保留为对照。最终仍待人工评审，不合并 / 发布，不改变完整 CHG 待验事实。
