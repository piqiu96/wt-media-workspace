## 1. 里程碑目标

运营可以从素材库把素材加入“我的素材”，选择合成策略创建任务；Cloud 在运营电脑离线时仍能准备源视频、执行真实 FFmpeg、上传对象存储并生成成片；运营随后可以预览、下载或进入发布管理。

```text
material
→ material_usage
→ compose_task（创建时保存配置快照）
→ Cloud Compose Worker + FFmpeg
→ composite_output
→ file_transfer_task
→ 运营电脑本地文件 / 去发布

compose_template（技术模板，按版本发布）
→ compose_strategy（业务配置，绑定固定模板版本）
→ compose_task（保存模板版本与实际配置，不再读取最新策略）
```

M4 不包含定时自动创建合成任务；自动调度属于 M5。

2026-10-14 用户调整交付顺序：M4-H2 的真实页面走查和人工签收暂缓，待 M5 各 CHG 完成后统一走查。M4 仍为 `IN_PROGRESS`，既有机器证据不冒充用户验收；此项暂缓不阻止 M5 的开发与逐 CHG 机器验收。

一次选择多个素材仍逐素材创建多个独立 `compose_task`。未来的任务归并只用于列表展示和筛选，可由任务名称或分组 code 标识；不合并执行、状态、重试或成片。本轮 M4-F 不预设分组字段。

页面走查以 [AdminUI 页面规范](../../docs/standards/frontend/AdminUI页面规范.md) 和[用户反馈规范](../../docs/standards/frontend/用户反馈规范.md)为准。[合成策略](../../assets/images/ui/content-production/compose-strategies-reference.png)、[合成任务](../../assets/images/ui/content-production/compose-tasks-reference.png)、[我的成片](../../assets/images/ui/content-production/my-outputs-reference.png)三张图只供布局参考，不能据图扩大业务状态和数据模型。

## 4. 闭环卡 M4-A：素材库与我的素材

### 用户目标

运营能判断哪些素材可以用于生产，把素材加入自己的生产集合，并在需要时准备或下载原视频。

### 前置条件

- 用户已登录且拥有素材对应的团队/游戏范围；
- `material` 有来源链接与来源快照；
- Cloud 和 Local Agent 分别具备受控的 Cloud 文件准备、本地文件落地能力。

### 用户操作顺序

1. 打开“内容生产 → 素材库”；
2. 查看来源和视频状态；
3. 点击“加入我的素材”；
4. 在“我的素材”查看新关系；
5. 可选：查看详情中的作者主页、平台原视频页面、文件大小和云端视频链接；
6. 可选：在“我的素材”点击“下载”，在顶部下载中心分别查看正在下载和最近完成；
7. 可选：移出后恢复同一素材关系。

### 系统与外部动作

- Cloud 校验权限和素材可用性；
- 原子创建或恢复 `material_usage`；
- 用户下载原视频时创建 `file_transfer_task`，交由本地执行程序保存到运营电脑；
- Local Agent 使用短时受控下载信息写入运营电脑，校验大小/Hash 并回报进度；
- 合成前准备原视频时复用 `file_transfer_task`，由云端执行，不另建一套文件任务。

### 成功必须同时满足的事实

- 同一用户、同一素材只有一个有效 `material_usage`；
- 素材进入库时未下载视频仍是合法事实，页面准确显示 `not_downloaded`；
- 下载中心的进度、速度、剩余时间和完成结果来自真实传输；
- 下载成功后本地文件存在且完整性校验通过；
- 素材列表有真实封面缩略图和素材 ID；作者主页、平台原视频页面、文件大小与稳定云端视频 URL 仅在详情中展示；
- 交互对齐 `docs/standards/frontend/前端交互规范.md`（2026-09-30 走查三轮，用户裁定）：素材库不提供下载入口（行与详情抽屉），下载只在“我的素材”提供，`failed` 行主操作文案为“重试”；行操作统一“详情”、每行单一主操作；按钮不超过 5 个全部平铺（§5.6，2026-09-30 用户补充裁定），超过 5 个才把低频收敛进“更多”；
- 云端视频 URL 只对有权限且已准备完成的素材生成，且对象存储访问配置允许公开读取；
- 下载中心把未完成任务与终态任务分开展示，终态包含成功、失败和取消；
- 移出/恢复不删除历史关系 ID、任务或成片；
- 无权限素材不能被查看、加入或下载。

### 失败时禁止出现的假成功

- 只创建 `material_usage` 就显示源视频已就绪；
- API 返回 200 但未创建关系或下载任务；
- 下载任务标记成功但文件不存在、字节不足或 Hash 不一致；
- 重复点击产生多条有效关系；
- 取消任务后临时文件被当作完整文件打开。

## 5. 闭环卡 M4-B：人工 Cloud 合成

### 用户目标

运营在“合成任务”页新建任务（素材从“我的素材”里选），无需保持 Desktop 在线，即可得到可播放、可追溯的成片。

### 前置条件

- M4-A 已验收；
- 至少一个可用 `compose_strategy`，绑定的模板版本和对应执行代码仍可用；
- Cloud Worker 的 FFmpeg / FFprobe、临时目录和对象存储健康。

### 用户操作顺序

1. 在“合成任务”页点击“新建合成任务”，在抽屉里从“我的素材”中选一条或多条素材；
2. 选择 `compose_strategy` 并确认允许覆盖的参数；
3. 创建任务；
4. 在“合成任务”查看排队、阶段、进度和结果；
5. 成功后进入“我的成片”预览、下载或去发布。

### 系统与外部动作

- Cloud 为每个素材创建独立 `compose_task`，保存模板代码、整数版本和应用覆盖参数后的不可变 `config_snapshot`；
- Worker 只按任务快照选择对应版本的执行代码，不在运行时读取最新策略；
- 源视频未就绪时创建/复用 Cloud 文件准备任务；
- Worker 原子领取任务、持有租约并写 heartbeat；
- Worker 执行 FFprobe 输入校验、FFmpeg 合成、FFprobe 输出校验和对象存储上传；
- Cloud 在文件校验与对象存储落盘后事务创建 `composite_output`。

### 成功必须同时满足的事实

- HTTP 创建请求快速返回，不同步等待 FFmpeg；
- 同一任务同时只有一个 Worker；
- 来源素材、`material_usage`、模板版本、任务配置快照和成片可互相追溯；
- 成片文件真实存在、可播放且对象存储校验通过；
- Desktop 退出不影响 Cloud 任务继续完成；
- 页面状态与数据库、Worker 执行和对象存储事实一致。

- 提交任务只提示“已提交”，进行中和失败留在任务状态与详情；单条任务的取消、重试按当前状态和权限显示。操作不超过 5 个时平铺，超过 5 个时低频操作进入“更多”。

### 失败时禁止出现的假成功

- 源视频未就绪仍直接运行 FFmpeg；

- 页面有演示成片但对象存储无真实文件。

## 6. 闭环卡 M4-C：下载与发布衔接

### 用户目标

运营在全局下载中心统一管理原素材和成片下载，并把成片带入第六章发布流程。

### 前置条件

- 至少一个可下载 `material` 或 `composite_output`；
- Desktop、Local Agent 和本地保存目录可用。

### 用户操作顺序

1. 点击顶部“下载”打开右侧 Drawer；
2. 查看进行中与最近完成；
3. 取消失败/不需要的任务，或重试失败任务；
4. 成功后打开文件/目录；
5. 从“我的成片”点击“去发布”。

### 系统与外部动作

- Cloud 创建并持久化 `file_transfer_task`；
- Local Agent 下载、原子落盘并上报进度和 Hash；
- “去发布”把 `composite_output` 引用传入发布管理，但不提前创建成功发布事实。

### 成功必须同时满足的事实

- 原素材和成片共用相同下载任务和 Drawer；
- Cloud 不保存运营电脑绝对路径；
- 本地文件删除不删除 Cloud 素材或成片；
- 下载成功不创建 `publication`；
- 发布入口能读取成片来源和文件事实。
- 我的成片列表与详情能预览视频、展示文件信息和来源／策略／任务追溯，并按状态提供下载、归档、去发布；下载成功反馈以本地文件校验落盘为准。

### 失败时禁止出现的假成功

- 前端模拟进度而执行器没有传输；
- 清理下载记录同时删除素材、成片或本地文件；
- 下载完成被标记为已发布；
- Cloud 尝试直接写运营电脑文件系统。

### 素材文件缺失自愈（2026-10-22 走查整改，M4-H2 第六轮）

2026-10-21 走查中合成任务 319/320/321 均因「源文件不见了」失败：素材 154/160/159 的 `video_status=ready` 与 `source_object_key` 均在，但对象存储中对应对象已不存在。本轮按用户裁定补齐消费前校验与一次自愈，并**修正第五轮「不可重试」在本场景的读法**：`input_missing`/`input_invalid` 仍是人工重试入口的终态分类，但合成任务在判定它们之前，本次领取内会先自动重新准备一次素材。

| 裁定 | 落地 | 边界 |
| --- | --- | --- |
| `ready` 只是投影，消费前必须确认对象存在 | 合成、用户下载、预览三条链路读取前 `Stat` 正式对象；不存在才进入自愈/拒绝，不再直接 404 | 不改 `video_status` 四态枚举；新增 `ready → downloading` 的受控回退 CAS（key + `video_prepared_at` 双条件） |
| 合成遇到 `ready` 但对象丢失：自动补一次 | 每次领取一份 `ComposeInputGate`，最多请求一次准备并等待；准备仍不可用则终态 `input_missing`；人工重试得到新的一次机会 | 同一领取内不重复请求、不重复下载；等待中仍是 `running + waiting_input` |
| 素材 `failed`：自动重试准备一次 | 合成领取发现 `failed`/`not_downloaded`/ready 无 key 时请求准备；准备结束仍失败则终态 `input_invalid` | 与第五轮「终态不可重试」不冲突：那是指判定后的人工重试入口 |
| `ready` 但没有源页地址 | 不创建必然失败的准备任务：合成立即 `input_missing`；用户下载/预览明确拒绝（409） | 不伪造「再试一次」入口 |
| 用户下载 stale ready | 对象存在直下；不存在且有源地址 → 创建一次云端准备并挂到下载任务，准备完成后运营电脑直连下载；无源地址 → 明确拒绝 | Cloud 不中转文件字节；预览不签发 404 链接 |
| 准备过程平台临时地址过期 | 同一准备任务内重新解析、再下载一次；地址不存在/租约丢失/提交失败不重试；上下文取消不写终态 | 失败写入以 `FailTask` 生效为前提 |
| 上传完整性 | Content-MD5（`SendContentMd5`）+ `Stat` 大小；取消「上传后回读再比 SHA256」 | 需实测目标存储确实校验 Content-MD5；Garage 若不校验则记为仅大小校验 |
| 清理边界 | 合成 attempt 结束删除 Cloud 本地 run 目录与临时对象（素材 `.staging`、成片临时）；正式素材、正式成片保留 | 崩溃残留启动清扫、对象存储生命周期治理不在本轮 |
