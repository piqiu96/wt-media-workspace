## 从一组资源到批次结果

| 要回答的问题 | 本阶段交付 |
| --- | --- |
| 用户目标 | 一次准备并执行多条发布，局部异常可处理，停止后不重复发布 |
| 前置能力 | M6 的任务、结果处理与防重复提交可靠；资源盘点可区分不可用、读取失败、零与未知；账号/Profile 互斥可用 |
| 用户操作 | 资源配置 → 内容配置 → 结果总览 → 明确接受缺口并创建 → 确认执行范围 → 跟进任务/处理异常 → 必要时停止发布并核实在途结果 |
| 系统与平台动作 | 确认资源只锁映射；正式创建才统一生成任务并取得占用；Agent 按时间、间隔、账号和 Profile 条件自动提交；局部失败不阻断无关账号 |
| 同时成立才算完成 | 一批真实任务产生可核实的公开结果；部分创建与部分执行均经过明确确认并保留原目标；原账号恢复、验证码处理、未知核实和安全失败重试均可继续；停止只阻止新派发，在途有真实结论且不恢复旧队列 |
| 必须排除的假成功 | 全批接口返回成功但只有部分记录；少创建即下调目标；未知任务自动跳过或重发；同 UID 多窗口或跨平台共用 Profile 绕过串行；执行结束即显示目标达成 |
