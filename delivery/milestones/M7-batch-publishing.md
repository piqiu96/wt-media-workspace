## 从一组资源到批次结果

| 要回答的问题 | 本阶段交付 |
| --- | --- |
| 用户目标 | 一次准备并执行多条发布，局部异常可处理，停止后不重复发布 |
| 前置能力 | M6 的任务、结果处理与防重复提交可靠；资源盘点可区分不可用、读取失败、零与未知；账号/Profile 互斥可用 |
| 用户操作 | 资源配置 → 内容配置 → 结果总览 → 明确接受缺口并创建 → 确认执行范围 → 跟进任务/处理异常 → 必要时停止发布并核实在途结果 |
| 系统与平台动作 | 确认资源只锁映射；正式创建才统一生成任务并取得占用；各账号所属用户的 Agent 按时间、间隔、账号和 Profile 条件自动提交；局部失败不阻断无关账号 |
| 同时成立才算完成 | 同批不同用户账号均由各自 Agent 产生可核实的公开结果，越权领取被拒绝；单个用户 Agent 离线保留待办，不转交他人，其他可用任务可继续；部分创建与部分执行均经过明确确认并保留原目标；原账号恢复、验证码处理、未知核实和安全失败重试均可继续；停止只阻止新派发，在途有真实结论且不恢复旧队列 |
| 必须排除的假成功 | 只验证同用户账号就宣称混合归属通过；跨用户代执行；全批接口返回成功但只有部分记录；少创建即下调目标；未知任务自动跳过或重发；同 UID 多窗口或跨平台共用 Profile 绕过串行；执行结束即显示目标达成 |

## 候选 CHG 与内部顺序

| 候选 | 工作内容及仓库 | 直接依赖 | 可独立验证的完成条件 |
| --- | --- | --- | --- |
| M7 批次发布闭环 | Cloud/Agent/Desktop；资源与内容批量配置、创建、执行、停止、公开统计及综合验收 | M6 `DONE` | 混合归属真实批次公开与安全停止通过，目标和缺口不隐藏，Web与安装版验收通过 |

本阶段规划一个完整的“百度批次发布闭环”CHG，依赖M6 `DONE`后再激活；不提前为页面、API或调度器拆多个CHG。内部依次完成：

1. 真实资源盘点/配对、三段配置、部分创建确认、批次续编与原子创建；保留目标及缺口，混合归属任务按账号所属用户确定执行用户。
2. 将M6已交付的AI、图片库、模板渲染和内容确认扩展到按需批量配置；只处理所选字段，保留人工稿，流中断只重试未完成项，旧响应/并发变化不能覆盖新内容。不重新建设第二套工具。
3. 执行范围确认、到时与间隔、账号/Profile串行和受控并行、局部故障及停止收尾；不同所属用户的Agent只领取本人任务，离线不转交他人。
4. 在Web和安装版从资源配置走到真实公开结果与安全停止；目标30、创建28、公开28时，目标仍30、缺口2、成功率约93.33%；审核中不计公开成功。

AI与模板的单任务生产能力不再推迟到本阶段。M7复用M6完整任务状态处置、真实封面及原结果补报，不另建执行器。资源配对沿用PRD V1，不引入质量等级维护或等级匹配。
