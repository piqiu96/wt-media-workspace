## 1. 里程碑目标

高级运营配置并启用 `compose_strategy.schedule` 后，Cloud Scheduler 在正确时间、正确时区和数量上限内幂等创建 `compose_task`；Worker Pool 在受控并发和资源边界内自动生成 `composite_output`，并能从进程退出、heartbeat 中断、超时和临时依赖失败中恢复。

```text
compose_strategy.schedule
→ Cloud Scheduler
→ 幂等创建 compose_task
→ Worker Pool
→ composite_output
```

M5 不创建 `production_rule`、`compose_pool_item`、成片池、成片领取或 MQ。

调度一次命中多个素材时仍逐素材生成独立任务。M5-C4 的“批次结果归集”仅指基于计划时间、策略或将来明确的分组标识汇总展示结果，不把多个任务合成一个执行实体，也不引入核心批次表。

合成策略计划的页面表达参考已落地的挖掘策略：手动执行、每 N 分钟、每天 HH:MM，展示时区与下次执行时间。两类策略各自维护业务配置，不共享任务或调度数据。[合成策略参考图](../../assets/images/ui/content-production/compose-strategies-reference.png)只作为布局参考。

首版素材范围固定为策略创建人的“我的素材”中仍有效、属于策略团队和游戏的素材；已经由该策略成功生产过的素材跳过。失败或取消的任务不算“已生产”，但待执行和执行中的同策略素材不能重复入队。页面明确展示这个范围，不提供尚无业务定义的自定义筛选表达式。用户于 2026-10-14 确认此口径。

挖掘策略的自动转素材发布时间过滤已在[内容发现产品基线](../../docs/product/M3-content-mining-v2.md#4-挖掘策略)记录为 M3 验收后的独立增量；它不属于 `compose_strategy.schedule`，也不作为 M5 自动合成的隐式前置条件。后续单独交付时只让通过过滤的来源进入现有点赞／收藏判断。

## 4. 闭环卡 M5-A：策略调度

### 用户目标

高级运营能够让一条已有合成策略按业务节奏自动生产，同时明确控制素材范围、单次上限和每日上限。

### 前置条件

- 策略模板和参数已在 M4 人工任务中验证；
- 用户拥有策略业务范围的高级运营权限；
- 云端的时区与定时执行配置有效。
- 策略创建人的“我的素材”仍有有效素材关系；素材必须属于策略团队和游戏。

### 用户操作顺序

1. 打开“内容生产 → 合成策略”；
2. 编辑自动执行设置；
3. 选择时区、时间/周期、素材范围、单次上限和每日上限；
4. 启用该策略的自动执行；
5. 查看下一次执行时间；
6. 到期后查看自动创建的任务和运行统计；
7. 可暂停自动执行或手动“立即执行”。

页面对周期提供业务选项，不开放 Cron 文本；启用或编辑计划不立即执行。手动“立即执行”是独立动作，不改变下一次计划时间。表单只提供已由服务端合同支持的字段，字段错误就近展示。

列表和详情分别展示策略是否可用、自动执行是否启用；两种状态不能合成一个标签。计划详情以周期、时区、下次执行时间、素材范围和数量上限为主，最近运行结果放在关联信息中。

### 系统与外部动作

- 云端校验设置并保存到 `compose_strategy`；
- 定时程序检查哪些已启用的策略到了运行时间；
- 按权限范围、素材可用性和上限筛选候选素材；
- 跳过该策略已成功生产的素材，且不为尚在队列或执行中的同策略素材重复创建任务；
- 对同一策略、同一计划时间和同一素材，只允许创建一次任务；
- 为符合条件的素材分别创建待执行的 `compose_task`，并保存下一次计划时间；
- “立即执行”复用同一任务创建入口，不同步合成。

### 成功必须同时满足的事实

- 启用自动执行后，策略在选定时区的预期时间触发；
- 禁用策略不触发；
- 同一计划时间被反复检查、定时程序重启或多个程序同时检查时，不会重复创建任务；
- 单次与每日上限真实生效；
- 每个候选素材独立创建或记录跳过原因；
- 定时程序只负责创建任务，不负责下载视频、合成或保存成片。

### 失败时禁止出现的假成功

- 只保存定时设置、尚未到点执行，就显示自动生产已完成；
- 调度进程未运行但页面显示“运行中”；
- 同周期重复生成多条任务；
- 超限任务先创建再静默删除；
- 定时程序绕过任务队列，直接处理视频。

### 对应 CHG

- M5-C1（计划配置和页面读回）、M5-C2（真实调度与幂等）机器验证通过；用户页面走查待最终统一签收。

## 4a. 闭环卡 M5-B1：引导视频合成模板

高级运营在策略中填写一个可下载的 HTTPS 引导视频地址，选择“插入引导片段”或“画中画”，设置插入位置与时长，创建人工任务或启用自动计划后能得到可播放成片。任务保存地址快照；链接由运营维护，失效或内容变化会影响任务执行。转链接另由独立运营工具负责。普通运营使用已启用策略创建任务。

策略保存时检查地址格式；任务执行时限制下载目标、跳转和大小，并探测视频格式及可用时长。地址失效或媒体无效时不得产生成功成片。`basic_cut` v1 与历史任务继续按原定义执行。新增模板的执行代码通过真实 FFmpeg 测试后才发布对应模板记录。

插入模式参考 `wt-media-flow` 的前段、引导段、后段拼接与末尾插入处理；画中画参考原视频背景、引导视频叠加、原视频前后段连续播放。首版保留固定、可解释的参数，不迁移参考项目的目录批量、自动发布、随机去重、贴纸、尾部动画、水印或外部平台规则。

对应 CHG：M5-C2a（CHG-20261014-093，机器验收通过）。最终页面视觉签收仍与 M4/M5 一起走查。

## 5. 闭环卡 M5-B：Worker 资源控制与恢复

### 用户目标

系统可以无人值守批量生产，但不会超过 Cloud 资源上限；Worker 或依赖短暂失败后，任务能安全恢复且不会双执行。

### 前置条件

- M5-A 已验收并能创建真实 `pending compose_task`；
- Worker 并发、租约、heartbeat、超时和最大重试配置有效；
- 具备受控故障注入和资源监控环境。

### 用户操作顺序

1. 高级运营查看自动任务列表和策略运行统计；
2. 技术查看队列、Worker 和资源指标；
3. 对失败任务查看原因、重试或取消；
4. 在结果不明确时人工处置。

### 系统与外部动作

- Worker 原子领取任务并创建租约；
- Worker Pool 限制同时运行数量；
- 执行中周期续租和 heartbeat；
- 超时触发受控终止，不遗留 FFmpeg；
- 可重试技术失败退避重排；
- 租约过期任务在确认旧执行停止后恢复；
- 业务失败和结果不明确停止自动重试。

首版若只能确认租约过期，无法确认旧 FFmpeg 已停止，则转为明确的待人工处置失败事实，禁止自动重排。M5-C6 再提供人工核对与处置入口；不能用租约到期本身推断进程已经退出。

M5-C6 人工处置口径（2026-10-15 用户确认）：仅管理员在任务详情核实旧 FFmpeg 已停止且没有已提交成片后，记录可核对的依据，才能对同一 `execution_uncertain` 任务发起一次人工重试；该确认与重新排队必须是一个受保护的事务。无法核实则保持 `failed / execution_uncertain` 待处置，不开放普通重试。页面不得把管理员的声明冒充系统自动确认，也不得暴露原始命令、凭据或签名地址。

### 成功必须同时满足的事实

- 实测最大并发不超过配置；
- 同一任务任何时刻最多一个执行者；
- Worker 崩溃后任务不会永久卡在 `running`；
- 达到重试上限后稳定进入 `failed`；
- 取消与超时后真实 FFmpeg 进程已经退出；
- 对象存储临时键和临时目录可恢复清理；
- 运行统计与任务、尝试和错误事实一致。

### 失败时禁止出现的假成功

- 只靠进程内锁宣称分布式唯一领取；
- heartbeat 停止后立即启动第二个执行者而不确认旧进程；
- 数据库状态取消但 FFmpeg 继续运行；
- 重试覆盖历史错误或无限循环；
- 资源不足时绕过并发上限。

### 对应 CHG

- M5-C3（CHG-20261014-094）、M5-C4（CHG-20261015-095，批次结果归集）、M5-C5（CHG-20261015-096，技术退避与存储清理）、M5-C6（CHG-20261015-097，结果不明确的管理员核对与处置）机器验收通过；真实时间全链和用户页面走查仍归 M5-C7。

## 6. 闭环卡 M5-C：自动生产综合验收

### 用户目标

高级运营能从策略页面确认一条自动计划真正按时生成了可播放成片，并在常见故障后继续稳定运行。

### 前置条件

- M5-A、M5-B 已完成；
- 有真实素材、真实对象存储和可验证的 Cloud 资源指标；
- M4 人工链路仍保持通过。

### 用户操作顺序

1. 创建或复制一条策略并设定近期计划时间；
2. 启用并等待真实 Scheduler 触发；
3. 查看批量任务、部分失败与成功成片；
4. 暂停策略并确认不再生成任务；
5. 查看 Worker 重启与失败重试后的最终结果；
6. 在“我的成片”预览并下载一条自动生成成片。

### 系统与外部动作

- Scheduler、Worker 作为独立进程实际运行；
- 任务按计划创建并按并发限制执行；
- 成片写入对象存储并进入普通“我的成片”查询；
- 下载继续复用 M4 `file_transfer_task`，不增加领取或成片池对象。

### 成功必须同时满足的事实

- 从策略启用到成片下载的整条链路使用真实时间、数据库、FFmpeg、对象存储和 Local Agent；
- 自动与人工成片使用同一 `composite_output`；
- M4 人工生产和下载回归通过；
- Cloud Web 与 Desktop WebView 显示同一正式状态；
- 用户人工签收完成。

### 失败时禁止出现的假成功

- 用手动接口代替定时触发却宣称 Scheduler 通过；
- 只创建任务、不生成文件就宣称自动生产完成；
- 通过 Mock FFmpeg 或内存对象存储代替真实依赖；
- 自动成片进入另一套列表或另一张成片表；
- 测试结束后残留无限重试或失控 Worker。

### 对应 CHG

- M5-C7（待建立）。
