## 独立目标与前置

独立用户目标和成功事实以对应闭环卡为准，不扩展至其他阶段。

前置：M3-C1 / CHG-20260915-046；V2-Q01 博主名称/账号/主页定位及作品列表接口具备。

范围：博主搜索、候选身份确认、稳定作者 ID、作品列表/分页、选择入池。

## 明确不做

作者策略与持续监控、所有作品默认入池、按昵称盲配作者、仅 ID 支持冒充完整搜索。

## 顺序任务

### Task 1：核实博主定位能力

- 工作：分别核实名称查找、账号定位、主页解析与真实作品列表，明确歧义与接口缺口。
- 验收：三个输入类型逐项取证；缺能力不能宣称全支持或猜测身份。

### Task 2：交付身份到作品页面

- 工作：在内容池博主搜索入口展示候选/确认与真实作品，复用临时查询机制。
- 验收：同名作者能区分；昵称变化不改变身份；查询不创建监控策略。

### Task 3：接通选择入池

- 工作：复用分页/确认凭证、统一来源服务及错误恢复。
- 验收：未选作品不入池；与其他入口发现同作品仍唯一；不自动转素材。

### Task 4：阶段验收

- 工作：名称/账号/主页各取真实样本，覆盖同名、无结果、分页失败、权限与重复导入。
- 验收：查询、选择入池、人工转素材可读回。原为「C1 和 C2 均通过才完成 M3-C」；C2 暂停后，M3-C 由 C1 完成，本项随恢复时再启用。

## Evidence 与提交边界

每项记录输入/角色、预期、实际、PASS/FAIL、环境版本、相关 ID 与脱敏截图。fixture/mock 与真实接口证据分开；HTTP 成功、任务创建、代码存在都不能替代业务读回。

Cloud 负责业务 API/数据库/Web 及正式合同；Agent 负责渠道执行适配；Desktop 复用 Web 不复制业务；Workspace 负责决策、治理索引和 Evidence。按提供方先行与消费者验证顺序，分别在各仓提交。

有待决产品规则或缺真实依赖时不激活；不得为通过验收私自降级范围。若实施设计仍超出该独立闭环，激活前继续拆分，不横跨 A～E 全部实施。
