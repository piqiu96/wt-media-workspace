## 顺序任务

### Task 1：锁定首轮与增量合同

- 工作：把已确认的首轮范围、分页覆盖/上限、置顶和后补作品处理写入合同与用例。
- 验收：覆盖范围明确；初始化失败和达到上限不伪装完成。

### Task 2：接通首轮任务

- 工作：稳定作者 ID、任务快照、作品列表及统一入池，状态统计复用 E1。
- 验收：首轮行为与用户确认一致，能真实读回；未完基线不推进成功游标。

### Task 3：接通后续周期与恢复

- 工作：按作品 ID 去重判新，处理改昵称、重复页、同时间作品和分页中断。
- 验收：跨入口唯一；已忽略/已转素材状态不复活；重试不重复累计。

### Task 4：真实作者闭环验收

- 工作：首轮任务→实际后续周期→可核验新增作品→内容池→人工素材转换。
- 验收：真实新增证据与 mock 测试分开；任务/来源/素材对应且错误可恢复。

## Evidence 与提交边界

每项记录输入/角色、预期、实际、PASS/FAIL、环境版本、相关 ID 与脱敏截图。fixture/mock 与真实接口证据分开；HTTP 成功、任务创建、代码存在都不能替代业务读回。

Cloud 负责业务 API/数据库/Web 及正式合同；Agent 负责渠道执行适配；Desktop 复用 Web 不复制业务；Workspace 负责决策、治理索引和 Evidence。按提供方先行与消费者验证顺序，分别在各仓提交。

有待决产品规则或缺真实依赖时不激活；不得为通过验收私自降级范围。若实施设计仍超出该独立闭环，激活前继续拆分，不横跨 A～E 全部实施。
