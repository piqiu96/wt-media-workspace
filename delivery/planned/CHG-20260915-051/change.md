## 独立目标与前置

独立用户目标和成功事实以对应闭环卡为准，不扩展至其他阶段。

前置：A、B、C1、D、E1 各段真实/基础门槛全部通过，待决项落定；环境版本和角色样本齐备。C2（博主搜索）与 E2（作者策略）已暂停，不属本 CHG 前置，也不在走查范围。

范围：两个人工入口（分享链接、关键词搜索）、关键词策略、任务与内容池/素材追踪、只读运行视图、权限/故障恢复/M2 回归和用户签收。

## 明确不做

前序遗漏功能建设、验收期新建或改造自动转素材（它属 M3 已交付能力，本 CHG 只验证）、生产/发布/文件链路、静态模拟图冒充真实业务流转。

## 顺序任务

### Task 1：冻结验收环境和矩阵

- 工作：明确组件版本、渠道能力、角色/组/游戏样本、迁移与脱敏证据目录。
- 验收：每项前置都有证据；无外部权限不得操作真实样本，不在报告写凭据。

### Task 2：走通全部入口

- 工作：链接/关键词主动入池，关键词真实定时入池，随后分别人工转素材（含自动转素材命中项与未命中项）。
- 验收：入池和转素材分开取证；所有入口复用唯一来源与素材；三页面无视觉/权限分裂。

### Task 3：验证只读运行视图及恢复

- 工作：基于真实策略、触发、任务、来源和素材显示业务流转；回归并发、拒绝、限流/重启和 M2。
- 验收：没有新增工作流实例/编排；未发生的素材转换不画成完成；M2 已验收能力无回归。

### Task 4：用户验收与归档

- 工作：汇总自动化、真实接口/数据库、Cloud Web/Desktop 走查及失败恢复，记录用户结论。
- 验收：全部退出项通过且用户确认后才标 M3 DONE；缺陷回前序 CHG 修复再验收。

## Evidence 与提交边界

每项记录输入/角色、预期、实际、PASS/FAIL、环境版本、相关 ID 与脱敏截图。fixture/mock 与真实接口证据分开；HTTP 成功、任务创建、代码存在都不能替代业务读回。

Cloud 负责业务 API/数据库/Web 及正式合同；Agent 负责渠道执行适配；Desktop 复用 Web 不复制业务；Workspace 负责决策、治理索引和 Evidence。按提供方先行与消费者验证顺序，分别在各仓提交。

有待决产品规则或缺真实依赖时不激活；不得为通过验收私自降级范围。若实施设计仍超出该独立闭环，激活前继续拆分，不横跨 A～E 全部实施。
