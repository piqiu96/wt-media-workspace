## 1. 独立结果

一个用户只能有一台明确绑定的 Desktop 设备。同机重启、重新登录、替换会话或 Agent 重启后自动取得新的会话节点授权；更换电脑必须先在个人信息页手动解绑，再在新电脑手动绑定。用户可维护昵称、选择系统头像并查看设备与 BitBrowser 绑定摘要，右上角可进入个人信息或退出登录。

## 2. 产品事实与状态边界

- **设备绑定**是 Cloud 的持久用户事实：未绑定 / 已绑定某设备。Desktop 安装实例生成并保护 Ed25519 私钥，Cloud 以公钥指纹识别设备，注册节点时验证当前一次性票据的签名。Cloud 一次只接受该用户的一个活跃设备。
- **Agent 节点**是当前登录会话的执行授权：会话被替换、登出或旧节点被废止后不可再领新操作；新会话在相同设备上自动注册新节点。节点失效不等于设备解绑。
- **BitBrowser 主账号**是另一个持久绑定：必须能读取并确认当前主账号标识；不一致时阻断本机执行。设备解绑不解除主账号；主账号解除沿用管理员已有入口。
- **本机依赖健康**只影响可执行性。Agent、BitBrowser 或打包依赖暂不可用时给出具体原因和恢复入口，不因此解除设备绑定。
- **解绑影响**：旧设备节点立即失去新操作权限；旧电脑原有本地文件和索引保留，Cloud 数据和历史保留；新电脑无法直接读取旧电脑上的本地文件。确认弹窗用明确文字强提示。旧电脑再次登录不能自动夺回新设备绑定。
- 个人资料：昵称默认用户名，可修改；头像默认系统头像，可从预设头像选择，无图片上传。顶部显示头像和昵称，菜单“个人信息 / 退出”；退出结束当前会话并回登录页。
- 旧版本统一使用常量 `desktop-local-device`，不能据此识别真实设备，因此升级后首次本机使用需要一次显式设备登记；此后同机无需反复绑定。

## 3. 仓库与契约范围

| Owner | 改动 |
| --- | --- |
| Workspace | 本 CHG、M2-F、第三章 PRD、ADR-0018 |
| Cloud | 用户昵称/头像与设备绑定持久化；资料和绑定状态/解绑 API；带设备证明的节点注册、设备核验、任务授权；共用 Vue 个人信息页、顶部菜单、同机自动续接与下载前恢复 |
| Desktop | 安装实例密钥的持久保存和签名；Tauri 注册桥传递真实设备身份与证明 |
| Agent | 首版不改业务运行时代码；仍持有会话节点授权与运行状态，不保存设备绑定事实 |

Provider 先更新 Cloud OpenAPI 和兼容性版本，再更新 Desktop 消费者与 `contracts.lock.json`。API 不向 WebView、Agent 或 Cloud 发送设备私钥。Cloud Web 只展示 Cloud 设备事实与发起解绑，不宣称本机 Agent 已运行，也不能直接绑定本机设备。

## 4. 有序任务与验收

1. Cloud 迁移、模型、Repository/Service/Handler 和 OpenAPI：持久设备绑定、显式解绑、签名验证、不同设备拒绝、已解绑节点拒绝；资料编辑与回读。
2. Desktop 生成持久安装密钥，向 Cloud 提供公钥、设备 ID 和当前票据签名；确认正常重启密钥不变、文件权限符合平台要求。
3. 共用 Vue 增加个人信息页、系统头像、顶部入口与退出；Desktop 登录、Agent 重启和下载前自动续接；设备错误与 BitBrowser 错误分别提示。
4. 运行单元与契约测试，覆盖相同设备重启/新会话、不同设备被拒、解绑后换绑、旧节点失效、签名错误、主账号不符、依赖故障；运行 Cloud/Agent/Desktop 的集成验证。
5. 使用真实 MySQL、打包 Desktop、Agent 和 BitBrowser 做手工走查，确认旧文件未删除、新设备不可直接访问；用户走查签收后才关闭。
