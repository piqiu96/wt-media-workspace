# CHG-20261001-072 实施计划

本计划依据 [change.md](change.md) 和 [ADR-0018](../../../docs/decisions/0018-stable-device-binding-and-session-renewal.md)。当前代码草稿、验证结果和接手风险记录在 [checkpoint.md](checkpoint.md)。激活、提交与验收仍遵守 Workspace 单活跃 CHG 规则。

## 1. 技术方案

1. Cloud 在用户行持久保存唯一活跃设备的公钥指纹、公钥、脱敏名称及绑定/最近验证时间。首次绑定需 Desktop 显式 `bind_device=true`；已绑定设备持当前一次性票据签名可自动登记当前会话节点；不同公钥拒绝。Cloud 注册、运行时上报与本机任务授权统一检查设备绑定，解绑事务清除绑定、废止旧节点并写审计。
2. Desktop 在稳定应用数据目录保存一份安装实例 Ed25519 密钥。Rust 用密钥对当前票据与设备 ID 签名；Vue 和 Agent 只接收公开摘要，Cloud 只接收公钥与签名。会话替换和 Agent 重启只更新节点凭据，不重写设备绑定。
3. Cloud 共用 Vue 将设备事实、当前设备匹配、会话节点、Agent/BitBrowser 健康分别展示。个人信息页可以编辑昵称和系统头像、显式绑定或解绑；顶部菜单进入页面与退出。登录恢复、Agent 重启恢复及所有本机执行入口遵守相同的前置授权。
4. Cloud OpenAPI 是提供方契约，Desktop `contracts.lock.json` 跟随；Agent 保持现有节点凭据协议。Brand/Login 相关改动由独立 [CHG-073](../CHG-20261001-073/change.md) 管理。

## 2. 实施顺序

1. 复核现有 worktree diff 与活动 CHG，确认草稿没有覆盖其他人的代码；阅读 Cloud/Desktop 仓局部规则。
2. 校验 Cloud 两个迁移、用户资料和设备事务；补强 Repository/Service/Handler/契约测试，特别是换设备、伪造证明、并发绑定、解绑旧节点和持续授权门禁。
3. 校验 Desktop 密钥持久性、权限、异常恢复、签名协议；核对与 Cloud 真实契约相同。
4. 完成共用 Vue 交互与所有本机入口的自动续接，运行 Cloud/Web/Desktop 构建及定向测试。
5. 真实 MySQL、打包 Desktop、Agent、BitBrowser 走查，记录请求/响应与 UI 证据，确保旧文件保留且新设备不可访问旧本地文件。用户签收后再按交付规则关闭。

## 3. 验收矩阵

| 场景 | 预期 |
| --- | --- |
| 首次登录无设备 | 个人信息页显式绑定；真实 BitBrowser 主账号校验通过后显示成功 |
| 同机重启、重登、替换会话、Agent 重启 | 旧节点失效，新会话节点自动恢复，无手动再绑定 |
| 另一电脑登录或伪造签名 | 个人信息页可见 Cloud 绑定摘要，本机执行拒绝，旧绑定不被覆盖 |
| 显式解绑再换电脑 | 旧节点失效；新设备可手动绑定；旧本地文件和 Cloud 历史保留，新设备无本地旧文件访问 |
| BitBrowser 主账号不符或依赖暂不可用 | 对应执行被阻断且有明确恢复提示，设备事实仍保持 |
| 昵称与头像编辑、退出 | 本人资料回读一致；顶部立即更新；退出结束会话并回登录页 |
