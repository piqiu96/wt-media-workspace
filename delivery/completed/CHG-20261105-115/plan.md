# 实施顺序与验证

本 CHG 的可见闭环为：管理员／高级运营保存多组成片策略，立即执行前查看真实选材与预计产量，确认后创建同一真实批次下的多组多份任务；Worker 继续按最终参数快照执行。

1. `model/strategy_rules.go`：先排除、三值指标与证据；先证明缺失值误判的失败，再通过判断表测试。
2. `model/output_settings.go`、`service/strategy.go`、`repository/strategy_mysql.go`：组内独立默认值、平台与份数校验、每组执行器校验；历史配置适配与配置不共享引用测试。
3. `migrations/087…090`、`model/batch.go`、`repository/execution_preview.go`、`schedule_mysql.go`：只读预览、确认重验、幂等、真实批次及展开；真实 MySQL 事务验证 2 条素材 × (2+3) 份=10 任务，以及过期／重放／重叠执行。
4. 提供方 OpenAPI／Schema／枚举／错误码与共用 Vue 策略页；组件及客户端回归、两端构建、真实浏览器检查新增／编辑／预览。
5. 独立规则与接口审查，修复指纹中的展示字段、零值来源证据、无效旧配置空批次等问题，再回归与 PR。

数据库变更只增加真实批次；成片设置留在策略 JSON。Worker 的并发、租约与取消仍采用原来的事务保护。人工任务统一批次、任务详情与使用筛选由依赖 CHG116 承接；成片页面由 CHG117 承接；全部真实合成与下载验收由 CHG118 收口。本 CHG 不将原型演示视为运行证据。
