# B6 收口判断

日期：2026-07-25

## 判断结论

`CHG-20260725-030` 的既定范围已经完成：

- 媒体账号台账字段、筛选、分页和可执行原因已收口；
- 新增账号入口、绑定窗口识别信息和 Desktop/Cloud 边界已收口；
- 账号行打开/关闭窗口已复用 Desktop → Tauri/Rust → Local Agent → BitBrowser 路径；
- “检查/同步账号信息”已覆盖人工登录后回填场景；
- 自动测试和构建已通过。

但 M2-B 不能直接进入 M2-C。Milestone `M2-B 浏览器窗口与媒体账号真实闭环` 的完成标准明确包含：

```text
单个/批量账号检查真实回填平台身份、头像、登录状态和最近检查时间
```

当前代码与 Evidence 只证明单个账号检查/同步闭环；未证明批量账号检查、逐项状态、部分成功、失败项重试或批量页面反馈。

## 批量检查边界判断

批量账号检查不是 B6 内的小范围收口，原因：

- 需要批量发起、逐项串行执行和逐项回填结果；
- 需要展示批量统计、部分成功、失败原因和失败项重试；
- 需要避免同一 Profile 或账号并发本地敏感操作；
- 需要处理 Desktop/Agent 中断后的结果确认；
- 不应复用 Cloud 通用异步 task 冒充账号检查成功。

因此应单独创建 B7，而不是在 B6 尾部补丁式实现。

## 建议下一步

- 关闭 B6：媒体账号单项操作与检查/同步收口。
- 激活 B7：M2-B7 批量账号检查与 M2-B 综合收口。
- B7 完成后再判断 M2-B 是否可以进入 M2-C。

## 状态枚举备注

当前代码保留历史内部状态值：

- 登录状态：`unknown`、`normal`、`not_logged_in`、`expired`、`account_mismatch` 等；
- 页面做用户可读文案映射。

Milestone 中的 `unchecked`、`logged_in`、`mismatch`、`check_failed` 是产品语义口径。是否迁移数据库状态枚举会影响历史数据、API 兼容和测试，应放入 B7 Start Gate 中一起判定，避免在 B6 收口时扩大变更面。
