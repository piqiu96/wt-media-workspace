## 问题定位与回归

原关联详情真实报错为 MySQL 1054：查询引用了已不存在的 `ma.name`。现改用平台昵称 `platform_name`，其次平台账号 ID，前端最终以系统账号 ID 兜底。真实页面已返回 7 位用户与 4 个账号。

删除保护原先遗漏无外键的独立合成批次；来源内容／挖掘策略类目外键为 SET NULL，删除会丢失历史归属。现补事务内引用检查，其余已有外键保护及错误映射保持不变。类目停用仍沿用用户授权／账号关联的既有边界，没有扩大停用限制。

团队名称原按字节限制 64，较长中文名被误拒；现与输入框和数据库 varchar 字符长度一致。65 字符仍拒绝，创建和重命名均覆盖。

新增行为回归：操作锁覆盖确认阶段及失败释放、未保存关闭取消／提交中禁止关闭、关联失败后重试成功、忽略过期关联响应；SQL 回归覆盖当前账号名称字段、独立批次阻止团队删除、历史类目引用阻止删除并回滚；服务测试覆盖中文名 64／65 字符边界。相关回归在修复前出现预期失败，修复后通过。

构建保留现有大包警告；本轮未引入构建失败。最初一次构建命令误在 Cloud 根目录执行，因该处无 package.json 失败，改为上述 `--prefix web` 后两项均成功。

最终提交后已通过 `bin/control.sh start` 重新构建环境：Cloud、Agent、采集 worker、合成 worker／scheduler、BitBrowser、5173／5174、Desktop 资源、DMG 新鲜度和管理员登录冒烟在打包启动前全部通过，前端构建标记为 `0.1.0+165f367`。最初一轮环境检查因构建期间产生提交导致新鲜度不通过，随后固定最终提交重建解决；并发运行的 CHG 检查曾读到正在重建而暂时不存在的 Desktop 资源。打包应用启动后移交 Agent 端口，后续检查发现打包应用未提供 Agent 监听，故不能宣称原生环境就绪；改用同一环境实现的 `up` 命令恢复托管 Agent，保留 Web 验收环境，再串行执行交付检查。该处理不修改 Agent／Desktop 运行时代码，原生 Agent 接管留待独立验证。
