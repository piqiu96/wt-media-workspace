- 日期：2026-10-13
- Cloud commit：`1f1eb64`

## 实施

- `model/task.go`：`ComposeTask` + 状态枚举（pending/running/success/failed/cancelled）；JSON 标签对齐合同（快照列 `config_snapshot_json` → `config_snapshot`）；worker 专属列（request_key/租约/heartbeat/输出键等）`json:"-"` 不出合同面。
- `repository/task_mysql.go`：
  - `createComposeTaskAudited`：任务行 + `audit_logs`（target_type `compose_task`，summary 含 material/template 事实）单事务；`MaxAttempts<=0` 时落 3——GORM 显式写全列，列 DEFAULT 不会生效（sqlmock 对照实测：未默认时 max_attempts 被写成 0）。
  - `cancelPendingComposeTask`：单条条件 UPDATE（`WHERE id=? AND status='pending'`），rows-affected 0 即非 pending/不存在，由 Service 读回具名。
  - `listComposeTasks`：范围（team/game IN）+ 状态/策略/创建者过滤，`ORDER BY id DESC LIMIT 200`。
  - `findActiveUsage`：事务内读本人 active 使用关系，创建校验与写入同视图。
- 快照列读回经 `json.Valid` 校验；NULL 的领取/时间列还原为指针。
