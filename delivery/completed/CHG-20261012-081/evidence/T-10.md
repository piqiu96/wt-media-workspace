# T-10 个人信息补运营分组与游戏范围

- 日期：2026-10-13
- Cloud commit：`da42edf`
- 背景：用户走查追加修订（`change.md` §7 第 4 条）——运营无法从自己的页面看出合成策略归属哪个分组。

## 实施

- 「个人信息」基本信息卡静态区（用户名/角色之后）新增「所属分组」「游戏范围」两行，两端共用页自动同源。
- 数据来源：`/auth/me` 的 `team_name` 与 `game_ids`（T-07 实测该接口已下发这两字段）；游戏 ID 经素材库页同款 `/games`（`usersApi.listGames({status:'enabled'})`）映射为名称，games 拉取失败不阻塞整页（退化为显示 ID）。
- 管理员不受限：分组显示「—」、游戏范围显示「全部游戏」；运营显示分组名与「游戏 A、游戏 B」；无授权时「—」。

## 验证

| 检查 | 实际 |
| --- | --- |
| `npx vitest run` | 56 文件、510 用例全 PASS |
| `npm run build:cloud` / `build:desktop` | PASS |
| `/auth/me` 字段（T-07 实测） | 含 `team_name`、`game_ids`，页面无需后端改动 |

## 限制

- GUI 级确认（分组名/游戏名实际渲染）在用户统一走查时进行。
