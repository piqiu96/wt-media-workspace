## 1. 移除 content_type（合同 → 存储 → 页面全链）

- 合同：openapi `ComposeStrategy`/`CreateComposeStrategy`/`UpdateComposeStrategy` 及 business-schemas 同步摘除 `content_type`（required 与 properties），openapi 版本升 `2026.10.13.1`；四份 YAML 解析通过。
- 迁移：`20261013_052_drop_compose_strategy_content_type.sql` DROP 列；开发库 `./scripts/migrate.sh up` 实跑「1 applied, 54 total」，`information_schema` 复核列数 0。
- 代码：model、service（输入结构、`validateStrategyFields` 收敛为仅名称）、repository（列清单/INSERT/UPDATE/Scan）全链摘除；相关测试同步。
- 真实 API 复验（重启至修订代码的 server，重登录 admin）：
  - 不带 `content_type` 创建 → HTTP 201，读回字段集无 `content_type`；PUT 同样通过。
  - 携带旧字段 `content_type` → HTTP 400 `compose_strategy_invalid`（`json: unknown field "content_type"`，请求体解码拒绝未知字段）。
- PRD §5.5.4 基线回写：策略按模板 schema 声明的参数填写，不再含内容类型。

## 2. 表单分模块、模板 schema 驱动

- 执行器 `BasicCutV1()` schema 为每个参数增补 `title`（开始秒数/结束秒数）；schema 仍是执行器校验与发布用合同，`title` 只作展示元数据。
- 页面弹窗分「基础信息」（名称、团队[管理员]、游戏、模板）与「模板参数」两节；模板参数区由所选模板 `schema.properties` 动态渲染（integer→数字输入并套 `minimum`、string→文本、boolean→开关，标签取 `title`，必填取 `required`），页面不写死字段清单；后续模板（开头片段、插入等）发布新 schema 后表单自动跟随。
- 模板行刷新：schema 变更后开发库旧行与代码定义不再一致（`sameJSON` 守卫会判 409），按「发布是唯一写入者」原则删旧行重发布 → `id=6 code=basic_cut version=1 status=active`（自增游标移动，如实记录）；模板列表 API 实测返回带 `title` 的 schema。
- 编辑防护：绑定模板已停用时 schema 不在目录中，参数区从既有 `config` 反推字段（config 写入时已按 schema 校验，字段集一致），标签退化为参数名。

## 3. 启停外置
