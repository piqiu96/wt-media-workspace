# Task 3：三角色权限交集证据

> 日期：2026-07-22

## 规则

| 角色 | Cloud 数据范围 | 本地敏感操作 |
|---|---|---|
| 管理员 | 全部用户、分组、游戏和 Cloud 业务对象 | 不代替普通运营操作其本机 Cookie/窗口 |
| 高级运营 | 同组与授权游戏交集 | 不读取他人 Cookie，不执行他人本地任务，不删除他人 Profile |
| 普通运营 | 本人与授权游戏交集 | 仅本人本机资源 |

## 自动验证

| 验证 | 实际结果 | 状态 |
|---|---|---|
| Identity 范围矩阵 | 管理员全部、高级运营同组、普通运营本人，再与游戏范围求交集 | PASS |
| Media Account | 高级运营可管理同组授权游戏的既有 Cloud 账号，但不能代建账号或读取明文 Cookie | PASS |
| Profile 默认列表 | 管理员全部、高级运营同组、普通运营本人 | PASS |
| Profile 修改边界 | 高级运营只读同组 Cloud 状态；删除和本地 open/close 等操作限制为所有者或管理员/所有者规则 | PASS |
| 审计列表 | 仅管理员可读取 | PASS |

## 运行中 Cloud API 验证

使用隔离 MySQL 与 `127.0.0.1:18080` 临时 Cloud 实例，创建脱敏验收分组、管理员、高级运营和两个普通运营用户后验证：

| 场景 | 实际结果 | 状态 |
|---|---|---|
| 管理员登录、创建两个分组和三类用户 | 返回成功；管理员无分组，其他用户有对应分组和 `game-a` | PASS |
| 普通运营创建本人账号 | 账号保存 `user_id=3`、`team_id=1`、`game_id=game-a` | PASS |
| 高级运营默认读取同组账号 | 仅返回同组普通运营账号 | PASS |
| 高级运营替他人创建账号 | HTTP `403` | PASS |
| 跨组普通运营读取或更新同组外账号 | HTTP `403`；管理员回读原账号仍为 `enabled` | PASS |
| 高级运营默认读取 Profile | 仅返回同组 Profile | PASS |
| 管理员默认读取 Profile | 返回两个分组的 Profile | PASS |
| 高级运营删除他人同组 Profile | HTTP `403` | PASS |
