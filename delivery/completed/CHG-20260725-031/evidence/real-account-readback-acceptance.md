# 真实平台身份回填端到端验收清单（M2-B 收口最后缺口）

日期：2026-08-05
CHG：CHG-20260725-031（M2-B7 批量账号检查与 M2-B 综合收口）
目的：补齐 M2-B 完成标准中唯一未端到端证明的项——**单个/批量账号检查真实回填平台身份、头像、登录状态和最近检查时间**。控制流已由自动测试证明，此处验证"真实读回的数据正确"。

## 前置条件（需要用户准备）

| # | 项 | 说明 |
|---|---|---|
| P1 | 真实可登录的 B站 **或** 百家号测试账号 | 免费注册或借用；验收完成后可在窗口内退出登录，不影响日常使用 |
| P2 | 正确平台的 BitBrowser 窗口 | 当前数据存在 bilibili 账号绑定到百家号窗口的平台不匹配，需新建正确平台窗口并绑定，或在已有窗口登录对应平台 |
| P3 | 环境就绪 | `wt-media-workspace/scripts/m2b-local-acceptance.sh all` + `verify` PASS（当前已满足） |
| P4 | 打包 Desktop 已挂载启动 | 最新 DMG 内嵌 8/5 前端 |

## 验收步骤与预期结果

### C1 准备：创建/修正平台匹配的账号绑定

1. 在 BitBrowser 中新建一个窗口（或复用正确平台窗口）。
2. 在 Cloud「媒体账号」页创建测试账号，平台选 B站 或 百家号，并绑定到上述窗口。
3. **预期**：账号 `browser_profile_id` 指向正确平台窗口；窗口业务状态 enabled；账号平台与窗口平台匹配。

### C2 单项检查：登录前（失败路径）

1. 不对窗口做平台登录，直接对该账号执行「检查/同步账号信息」。
2. **预期**：返回明确失败或"未登录"状态，不回填伪造身份；失败原因在页面可见。

### C3 单项检查：真实登录后（成功路径）

1. 在 BitBrowser 中打开该窗口，**人工登录 B站/百家号**，保持窗口打开。
2. 再次执行「检查/同步账号信息」。
3. **预期（M2-B 核心价值）**：Cloud 账号记录回填 `platform_account_id`、昵称、头像、`login_status=normal`、最近检查时间；且与窗口内真实账号一致。
4. **预期**：重复执行结果一致（读回确定性）。

### C4 批量检查

1. 选择 ≥2 个账号（至少 1 个已登录成功路径 + 1 个未登录/不可执行失败路径）发起批量检查。
2. **预期**：
   - 成功项真实回填平台身份；
   - 失败/跳过项显示独立原因，不拖累其他项（部分成功不回滚）；
   - 统计区展示总数/成功/失败/跳过。

### C5 失败项精确重试

1. 对批量结果中的失败项点击「重试」（仅重跑失败项）。
2. **预期**：只重跑失败项；成功后状态更新为成功，其他项不受影响。

### C6 GUI 复验 A3/A4（本清单顺带覆盖）

1. 打包 Desktop「浏览器窗口」页：新建窗口 → 新窗口出现在列表（ID/seq/名称/分组）。
2. 多选窗口 → 批量打开/关闭 → 运行状态列随操作切换，无"已创建任务"式假成功。
3. Diff 处理：接受本地变化 / 恢复 Cloud 配置（如有该入口）→ 读回一致。
4. 登录后进入 Agent 状态页 → 显示正常（修复 8/4 待办项）。
