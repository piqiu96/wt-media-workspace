## 3 优先收敛的评审问题

优先级是本报告的修订顺序：P0 表示进入开发前必须讲清或会破坏核心结果；P1 表示首个相关闭环交付前应补齐；P2 表示效率优化，不阻断首轮闭环。不是对现有软件的线上故障评级。

### R01 P0 生成份数与差异版本仍未形成一致规则

**位置与现象：**最新设计 §5.2 已提醒“相同配置只增加数量”不代表差异处理，但 §5.3、S05 和验收仍以两行数量 5＋3 表达八个差异版本。现有执行器只按具体参数生成，不会因为编号不同自动形成内容差异。[D1、C6]

**运营影响：**用户以为得到可分给八个账号的不同内容，实际上可能得到多份画面相同的文件；同时绕过了“同文件同平台一次”的初衷，增加合成和存储成本。

**建议：**一行版本方案默认对应一套明确片段组合；需要五个差异版时，提供“复制版本方案”，分别选择片头／引导／片尾。数量大于 1 可以保留，但明确显示“同配置生成 N 份”，展示“预计文件 N 个、不同配置 M 组”。相同配置不自动增加差异数，不静默替用户缩减数量，也不新增自动剪辑算法。

**验收：**同一素材、相同参数、数量 5，应标为一组配置五份文件；真正五个不同组合应能逐版看出差异。配置不同也只说明制作参数不同，不承诺平台认定为不同内容。

### R02 P0 人工归本人还需要策略使用权与接手权限配套

**位置与现象：**最新设计 §5.4、§11.1 改为人工归创建人，但当前普通运营只能读取指定给自己的策略；任务后端仍取策略负责人。仅修改任务负责人字段，无法完成“甲使用乙负责的策略、产出归甲”。转交给 B 后，当前成片按负责人读取的规则也会使 B 看不到资产。[D1、D2、D6、C1、C4、C7]

**建议：**分别定义“谁能维护策略”“谁能使用策略”“自动产出交给谁”，不要由一个负责人同时承担三种含义。推荐允许同团队、符合业务范围的运营使用明确可共享的策略；含专属引导的策略显示适用限制。人工默认归自己，自动继承指定负责人。管理角色现有代创建是否保留，应在 PRD 明确，不能无意删除已支持场景。

转交按具体成片的平台用途发生；接收人获得该文件必要预览与发布使用权，能看到足够的版本／引导说明，不因此获取原负责人的全部素材和任务。已停用或离开团队的接收人，其未安排用途由管理人重新分配。转交后是否允许接收人再次转交也需统一，建议允许在同一团队和相同可用范围内转交并留记录。

**验收：**甲可找到被允许共享的策略；人工成片归甲，自动成片归乙；B 接收小红书用途后能预览并发布，A 仍能追踪结果但不能再安排该用途；跨团队不可见。历史归属不随规则迁移。

### R03 P0 同文件同平台一次需要明确约束范围

**位置与现象：**最新设计 §6.3 同时出现“默认一次”和成功后不得换账号重发；发布原型仍提供“每条内容发布到每个所选账号”。同配置重新生成或重复上传，还可能得到新的成片 ID。[D1、P2、P3]

**建议：**本轮普通流程统一为“同一文件资产在同一平台只保留一个有效发布安排；成功后不再自动进入该平台候选”。移除普通路径中的全账号广播选项。取消未提交安排后释放；失败、暂停、结果待确认仍保留；平台删除／下架不自动恢复未使用。

需明确这首先解决团队重复安排，不等于对视频内容完成去重。建议对完全相同文件提示已有资产及使用情况，默认复用已有记录；视觉相似判断暂不引入。确需同平台重新发布的例外作为独立产品选择，不通过换负责人或重新上传暗中实现。

**验收：**F 的 B站用途已安排时另一计划不能再保存有效安排，小红书仍可安排；换负责人不重置记录；重复上传能识别已存在的相同文件或明确说明尚不能识别。

### R04 P0 草稿与有效安排必须在所有入口使用同一规则

**位置与现象：**设计 §6.3 已提出草稿不占用、可执行安排占用，但 §7.2 又要求“有效行先启动、无效行保留”。计划、普通发布、暂停和局部保存之间缺少完整的结果说明。[D1、P2、P3]

**建议：**只把真正保存为发布任务的有效行计为已安排；草稿行不占用。提交回执同时显示“已安排 18、待补充 2、因已有安排未保存 1”，原页保留失败输入。再次提交只处理剩余行。计划暂停不释放，取消尚未提交的行才释放；已提交结果未知的行进入核实。

**验收：**两人打开同一候选后分别提交，只形成一条有效安排；失败方在原行看到占用人和任务入口。部分成功后刷新或重试，不重复创建成功行，也不丢失待补充行。

### R05 P0 排期要统筹账号已有安排并处理逾期任务

**位置与现象：**设计 §7.2 已要求跨计划检查；原型 `model.js` 的排期占用只读取当前计划部分已执行任务，尚未纳入其他计划和普通发布。界面将质量优先与每日容量组合，但没有解释内容可能因等待优质账号延后多天。[D1、P1]

**建议：**账号当日已有有效安排和成功发布统一占用日额度；当前计划调整先移除自身被替换的未执行安排再重排。显示“本计划新增／已有占用／剩余容量／预计完成日期”。账号质量只作软推荐，同时提供“优先匹配质量”和“优先完成发布”的明确取舍，不增加必填目标。

离线、暂停后恢复或创建时间已过时，显示逾期数量，提供“按剩余时段重排”；未选择补发策略时不要一次性集中补发。发布时间显示所用时区；“计划时间”和“实际时间”分开。

**验收：**同账号已有两条安排，新计划不会当成零占用；恢复后十条逾期任务不会同时提交；人工调换账号后重新检查该账号容量。

### R06 P0 重排会覆盖已经编辑的标题

**复现：**发布计划第三步，将“第1条发布标题”改为“评审验证：手工修改标题”，点击“重新生成排期”，标题恢复为“新版本入门：三分钟理清配装思路”。已在浏览器复现；`P.generateSchedule` 直接替换整份 `rows`。[P2]

**建议：**“重新生成排期”只调整未固定的时间；保留标题、账号、成片版本与后续动作的人工修改。被手工修改的字段显示轻量标记。确需按默认规则重置全部配置，提供单独操作并说明影响行数；返回第二步更换账号或内容，也只使受影响行重新计算。

**验收：**改标题后重排，标题保留；固定某条账号和时间后重新排其余行，该条保持；删除其账号时原行显示需重新分配，不偷偷换人。

### R07 P0 成功与可继续执行的边界要落到具体动作

**位置与现象：**最新设计已区分“提交”和“取得链接”，方向正确，但平台受理、作品可访问、后续互动可执行仍需细化；同时“只重试失败项”的叙述没有体现现有普通运营不可重试，以及 `execution_uncertain` 不可普通重试的规则。[D1 §7.4、§12；D2 §5.8；C1]

**建议：**提交后先显示实际阶段：待确认结果、平台处理中／审核中、已发布可访问等，以平台可观测事实选择表达；不因点击提交或得到 URL 就触发所有后续动作。引导与互动各自等待作品和权限可用，失败不改变发布成功。

生产重试继续使用原参数，改配置创建新任务。推荐另行确认是否向普通运营开放本人“明确失败”的重试；尚未调整权限前，原型必须给出可操作的管理人处理入口。结果不明确仍走核实流程，不通过“再做一遍”绕过。

**验收：**提交超时不重新点击发布；审核中不计为可访问作品；评论失败不重发视频；批量重试明确列出可重试、需核实、权限不足三种数量。

## 4 首轮闭环应补齐的体验

### R08 P1 聚合视图保留 但必须按操作明确选择单位

任务默认按本次生产、成片默认按素材，符合“看进度”和“找内容”的差异。需要补齐以下细节：[D1 §5.6、C2、C3]

- 分页单位写明“生产批次／素材组”，子列表显示“匹配 2／全部可见 8”，计数不泄露权限外数据。失败筛选后仍保留该批整体进度，避免把局部数量误当全部。
- 下载、质量标记按文件去重；去发布、转交按文件与平台用途计数。工具栏示例：“已选 4 个文件、6 项平台用途”。不能以同一勾选结果对所有动作使用同一种计数。
- 未选平台时，去发布先提供平台选择与有效用途摘要；已安排项给原因和查看入口。不要让组勾选隐含勾中多个平台。
- 单素材单成片可直接显示可用版本与主要动作；复杂分组再展开。保留“成片明细／任务明细”并记住用户选择。
- 从详情返回保留筛选、页码、滚动、展开项和选择；自动刷新不打断批量编辑。

“只是分组视图”不代表无需新增关联事实：当前人工任务有名称与逐项 request_key，但模型未见统一的人工提交批次标识；自动路径已有运行记录。应为新人工提交保存稳定分组关联，复用自动运行关联；历史无法可靠还原的任务保留单行，不能按相近时间或名称拼批。

### R09 P1 普通发布需要真正成为短路径

已走查的普通发布抽屉只有选择成片，没有上传外部视频和立即／定时选择；原型保存时间写死为演示时刻。作者引导和初始互动默认全开，长表单使单条发布承担了批量运营配置。[D1 §7.1、P1、P3]

建议首屏只保留视频来源、平台账号、标题及必填字段、发布时间；“使用已有成片／上传视频”并列。执行方式沿用已明确的个人或计划偏好并显示摘要，首次必须能辨认自动提交还是人工提交。发布后动作默认折叠且首次不勾选，允许使用运营主动保存的预设。多选时进入分配预览，而不是只显示首条标题、其他内容不可检查。

单条成片从详情进入应已带入文件和来源，账号无需重复搜索；发布成功后回到原素材组且可直接打开作品。

### R10 P1 片段选择要解决文件复用和批量边界

现有 `guide_insert`、`guide_pip` 使用一个引导 URL，当前 schema 没有独立片头与片尾，任务还禁止覆盖引导地址。因此“插入已剪好片段”虽在体验上简化，仍需要新增受支持的模板／参数能力，不能仅改表单名称。[C1、C6、D5]

建议在现有资源选择中增加片段用途筛选或轻量选择器：名称、缩略图、时长、预览、引导标识；无合适片段时可以上传／登记，不要求运营每次输入下载 URL。片段按文件版本引用，历史任务能追溯实际使用文件，避免同地址内容被替换后“按旧配置重做”结果变化。

提交前展示拼接顺序、预计时长和异常素材数量：主体不足 20 秒时广告放哪里；无音轨如何处理；不同分辨率如何拼接；最长时长是否会切掉广告或片尾。建议插入点超出主体时明确提示并采用已声明的尾部规则；影响广告完整性的截断必须可见。支持逐条排除异常，不让整批在运行后才失败。

### R11 P1 发布预览优先保障逐行核对空间

1366×900 下，第三步右侧概览常驻，而标题、账号、时间和后续动作挤在左侧表格；标题显示范围很短，后续动作需要横向查看。基础视觉体系可以继续复用，但第三步应把概览改为顶部紧凑摘要或可收起侧栏，让分配表占满工作区。[P2；前端规范 D7]

平台切换保留，默认显示有问题的行入口；逐行只放成片版本、引导、账号、时间、结果／问题，低频后续动作显示简短摘要并在抽屉编辑。完整标题在聚焦、详情或展开行可读。固定提交区直接写“保存并安排 18 条，2 条待补充”，减少需要用户自己计算的信息。

### R12 P1 五窗口是上限 不是每个平台各自的默认数量

设计写明切换平台保留已准备窗口，但未界定五窗口按设备、平台还是工作区计算；发布与互动还可能同时使用一个账号环境。原型 `workSlots` 在当前队列取五个不同账号，不能证明跨工作区总量受控。[D1 §7.3、P4]

建议以当前执行电脑为总准备上限，用户可在 1–5 内选择，恢复上次偏好。同账号／同 Profile 的发布与互动共用串行占用，等待原因显示“正在发布另一作品”等具体事实。工作区持续显示账号、当前视频和下一步，支持完成后打开下一项。

区分“返回列表”“暂停后续准备”“结束本轮并释放未提交窗口”。已准备窗口是否保留、稍后处理是否保留填写内容需明确；当前原型“稍后处理”会把任务退回 ready 并清空阶段。恢复时先检查现有窗口，不应默认重新上传一遍。API 使用队列视图，避免“人工连续＋API”的混合表达。

### R13 P1 互动结果必须细到动作

互动 8102 的结果抽屉已区分成功、未完成、待确认，值得保留；但每个账号仍只有一个结果单元格。选择点赞和评论时，看不出点赞是否已完成。[P5]

建议账号行下展示“点赞：成功／评论：失败／收藏：未选择”，主操作改为“重试评论”等实际动作。待确认评论先核实，不能与明确失败一起批量重发；“再发一批”改成“追加互动”，带出已参与账号和已完成动作，避免被理解为整批再来一次。

最新设计支持多链接按平台分组，当前创建抽屉只有单链接输入；可新增多行粘贴，解析后显示去重、有效、需修正数量，有效目标可以继续。浏览行为是否接入与评论回复一样需登记为新增能力，不用虚构播放增长证明执行成功。

评论回复保留现有账号身份、会话上下文、失败草稿和发送并下一条；补平台／管理账号筛选、实际同步时间与失败原因。发送请求结果未知时不直接标已处理；“无需回复”可撤销，新的追问继续回待处理。

### R14 P1 作品运营先补可观察性 再做增长推荐

赞成作品独立于发布任务，并复用现有 `tracked_object` 方向，避免另建平行的作品事实体系。现有发布任务记录回答“是否发出”，作品视图回答“发出后如何继续运营”。[D1 §9、D3 §6.7、D4]

第一阶段提供真实链接、平台／账号、累计数据、采集时间、关注和跟进入口；第二阶段在确有多次观测后增加日内增量。区分累计值、最近观测区间和数据延迟，不将外链关注计为我方发布量，不用自有互动执行数代替平台自然表现。

“30 分钟”暂作为采集目标，先验证重点平台与关注规模下的可达性。排序应能看出内容已发布多久、数据采集距今多久；只有两个样本时不声称已经形成稳定趋势。跟进保留原作品与生成批次，比较相近发布时长；原参数缺失时明确重新选择，不能伪造恢复。

## 6 建议采用的完整用户路径

### 日常单条生产和发布

1. 在我的素材选一条，点击“按策略制作”，素材已带入。
2. 选择可用策略，看到片段摘要、一个版本和产出归属；需要时展开本次调整。
3. 提交后直接进入本次生产，等待素材准备和合成阶段分别可见；成功后出现真实成片。
4. 从成片预览点“去发布”，带入文件、用途与来源；选择平台和可操作账号，核对引导及必填发布字段。
5. 选择立即／定时和执行方式，提交有效安排；系统处理云端文件到执行电脑的准备，必要时显示等待设备。
6. 人工提交或自动执行后核实结果；作品可访问后进入作品管理，可选的引导／互动单独推进。

每一步均可结束，未选择后续动作不影响前一步成功。

### 十条素材八版的批量路径

1. 选十条素材与八套明确配置，预览 80 条任务；同时标出相同配置和不适用素材。
2. 任务列表显示一个生产组，组内按素材查看版本。76 成功、3 执行中、1 失败时，可先使用 76 个成片；失败按权限和错误性质处理。
3. 成片按素材聚合。筛选“小红书＋未安排”后只显示匹配文件；勾选摘要分别说明文件数和平台用途数。
4. 发布计划先确定平台和账号范围，展示引导匹配、既有占用、预计完成日期；未匹配行保留待补充。
5. 第三步核对具体成片—账号—时间；重排不抹掉人工修改，启动只创建有效行。

### A 发布百家号后转交小红书

F 仍是一份文件，生产负责人始终为 A。百家号用途保持 A 已发布；转交仅将小红书未安排用途改为 B 负责安排。B 在“待我安排”找到 F 并预览，创建小红书任务后占用该用途。转交与保存同时发生时，只接受一个基于当前有效状态的操作，另一方得到就近说明。后续作品分别记录实际发布账号、发布操作者和来源，不把 B 的工作计成 A 的发布工作量。

### 发现增长后跟进

作品页显示真实观测区间 → 运营选择跟进 → 原素材与当时参数带入 → 明确修改片段形成新版本 → 在增长平台分配其他可用账号 → 保留来源作品与本轮作品关系。原文件尚未使用的其他平台可以直接复用；同平台重复发布仍遵循统一规则。

## 8 增量交付顺序建议

这是依赖建议，不创建或启动 CHG，也不预估未经验证的工期。

| 顺序 | 可独立验证的结果 | 继承的能力 | 本段不捆绑的内容 |
| --- | --- | --- | --- |
| 1 | 一条素材按两套明确配置生成两个可识别成片；普通单版路径保持 | 现有策略、任务、快照、Worker、预览下载 | 发布计划、转交、增长采集 |
| 2 | 一份现有成片完成一个平台的真实发布并得到可核对作品 | 现有资产和本机执行边界；按已确认方式交付 | 全平台 API、多平台复杂分配、评论采集 |
| 3 | 同文件跨平台使用互不影响；两人不能重复安排；剩余用途能转交 | 正式发布事实、文件访问和角色范围 | 自动抢单与复杂协作流程 |
| 4 | 一个多平台计划正确利用账号容量，重排保留编辑，局部失败可继续 | 普通发布和用途安排规则 | 全自动增长推荐 |
| 5 | 一个真实作品完成可用互动动作并处理局部失败；评论回复按能力单独闭环 | 作品链接、账号身份和执行事实 | 以互动动作数推算作品效果 |
| 6 | 关注作品保留多次有效观测，显示真实区间增量并能带入跟进制作 | 作品与生产来源关系 | 自动判爆后批量发起任务 |

独立链接互动与平台数据能力核对可以作为独立交付候选，不必等待全部生产改造；实施时仍按仓库依赖与执行规则选定一个 CHG。

旧策略默认映射为一条版本方案、数量 1，保留原参数和额度含义；旧成片用途未知显示待补充，不自动标通用；新归属规则只作用于新任务。无需为了界面统一而迁移、重做全部历史成片。

## 9 下一轮原型的验收清单

| 场景 | 必须可观察的结果 |
| --- | --- |
| 单素材单版 | 不选账号即可制作；成功后能预览下载，原短路径没有额外必填项 |
| 同配置数量 5 | 文件份数与不同配置数明确区分，无“自动差异化”承诺 |
| 三个文件供四平台 | 三次合成、四项平台用途，跨平台只复制安排不复制文件 |
| 人工使用共享策略 | 策略可找到，人工与自动各归正确负责人，历史不漂移 |
| 80 条任务局部失败 | 批次总量准确，可定位失败版本，可先使用成功成片 |
| 聚合筛选与选择 | 匹配数、可见总数、文件数、用途数清楚；下载不按用途重复下载 |
| 转交未安排用途 | 接收人可预览和发布；原负责人可追踪但不重复安排；无关资产不可见 |
| 同平台并发安排 | 只有一个有效安排，另一方输入保留并看到占用来源 |
| 普通发布外部视频 | 上传／准备可见，无素材策略任务前置；支持立即与定时 |
| 重新排期 | 人工标题、账号和后续动作保留；仅重算指定范围 |
| 跨计划账号容量 | 普通发布与多个计划一起计入容量；已执行事实不被重排覆盖 |
| 离线与逾期恢复 | 显示等待设备和逾期队列；按声明策略继续，无集中补发 |
| 五窗口跨平台 | 总数按设备限制，同 Profile 不重入，切平台保留上下文 |
| 已提交结果未知 | 不释放用途、不重复发布，核实后继续 |
| 点赞成功评论失败 | 明确两项结果，只重试失败评论，已完成点赞不重复执行 |
| 多链接互动 | 平台分组、重复目标合并、错误链接可单独修正 |
| 评论发送失败／追问 | 草稿保留；结果未知不标完成；新追问重新待处理 |
| 作品采集缺失 | 显示缺失或旧时间，不显示假 0；增量依据实际观测间隔 |
| 跟进制作 | 带入当时参数和来源，产生新记录，不改原作品与旧任务 |
| 历史数据兼容 | 旧模板可用、用途待补充、无法还原的批次保留明细 |

运营效果建议在小范围试用中记录：一次普通发布需要重新选择多少已知信息；批量任务的人工修正行数；可用成片生成到首次安排的耗时；同平台重复安排拦截；失败后恢复所需操作；未安排用途的闲置时间。先采集现状，再比较改版，不预设未经测量的效率提升比例。
