# M2 模块业务流程与当前实现现状

> 日期：2026-07-21  
> 基线：产品 PRD 第三章、工程架构、Cloud/Web/Agent 当前代码  
> 口径：只有用户从页面发起操作后，预期业务效果真实落库或写入 BitBrowser，并可看到结果，才算完成。

## 1. 总体业务链路

产品要求的主链路是：

```text
导入代理并检测
→ 同步或创建 Browser Profile
→ 将代理写入 Profile 并读回验证
→ 导入 CK 创建待识别社媒账号
→ 将账号绑定 Profile
→ 将 CK 写入 Profile
→ 打开 Profile 执行账号检查
→ 回填账号 ID、名称、登录状态和 active_cookie
→ 账号具备发布/互动执行条件
```

当前系统实际只能完成：

```text
代理记录入库及基础检测
账号记录入库
Profile 云端镜像、局部任务创建
少量 Agent executor 和结果投影
```

四个业务页面之间没有形成可操作的纵向闭环。

## 2. 社媒账号

### 2.1 产品应有功能

- 按当前用户、游戏、平台创建账号；
- 保存 original_cookie 和 active_cookie；
- 绑定一个 Browser Profile；
- 同一 Profile 可绑定多个不同平台账号，同平台最多一个；
- 标签批量添加、移除和筛选；
- 写入 CK、读取真实 CK、分别导出原始/真实 CK；
- 单个或批量账号检查；
- 检查后自动回填平台账号 ID、名称、头像、登录状态；
- 账号去重、重复标记、业务状态管理。

### 2.2 用户应有操作流程及效果

```text
新建/导入账号
→ 选择游戏与平台
→ 选择已有 Profile 或创建新 Profile
→ 选择代理
→ 写入 CK
→ 执行账号检查
→ 页面显示真实账号资料和登录状态
```

最终效果：`media_account` 与用户、游戏、Profile 建立关系，original_cookie 被保留，BitBrowser 中实际 Cookie 被读回为 active_cookie，账号状态可用于后续业务任务。

### 2.3 当前已完成

- 账号列表、平台筛选、标签筛选和统计卡片；
- 单条创建账号，保存用户、游戏、平台和原始 CK；
- 业务状态修改；
- 标签批量添加和移除；
- 手工填写账号 ID 和名称完成“识别”；
- original_cookie 与 active_cookie 数据字段和导出接口；
- 绑定 Profile、账号检查、Cookie 读取的后端接口和任务类型；
- Agent 已有 Cookie 读写和账号检查 executor 基础。

### 2.4 当前断点

- 页面没有 Profile 选择和绑定操作，后端 `bindProfile` 客户端方法没有被页面使用；
- 页面没有“账号检查”按钮，已有检查 API 没有进入用户流程；
- 页面“导入 CK”实际只把登录状态改成 `unknown`，没有保存用户输入的 CK，也没有创建 Cookie 写入任务；
- 页面没有“从 Profile 读取真实 CK”操作；
- 登录成功后的账号 ID、名称、头像和 active_cookie 自动回填没有闭环；
- 没有批量检查入口和逐项执行结果；
- 手工识别绕开了真实浏览器账号校验，只能算数据补录。

### 2.5 当前判断

数据管理部分可用；与 BitBrowser、Profile、Cookie、账号检查相关的执行链路未完成。不能作为“可执行社媒账号管理”验收。

## 3. 账号开户

### 3.1 产品应有功能

- 批量 CK、接码链接、人工验证码三种独立开户模式；
- 创建待识别账号；
- 创建或选择 Profile；
- 按平台配额自动分配代理，并允许预览调整；
- 逐条创建 Profile、绑定代理、写入 CK；
- 执行账号检查并回填真实账号资料；
- 回写 active_cookie；
- 支持部分成功、失败原因和失败项精确重试。

### 3.2 用户应有操作流程及效果

```text
选择开户模式、平台和游戏
→ 导入 CK/接码链接
→ 系统生成 Profile 与代理分配预览
→ 用户调整并确认
→ 系统逐条执行开户
→ 每条展示 Profile、代理、CK、账号检查结果
→ 成功账号进入社媒账号列表且可立即使用
```

### 3.3 当前已完成

- 批量粘贴 Cookie；
- 选择平台、填写游戏 ID；
- 拉取 active 代理并在前端进行轮询式“分配预览”；
- 代理数量少于 Cookie 数量时弹出提示；
- 逐条创建 `media_account` 记录并保存 original_cookie；
- 单条失败不影响其他条目；
- 失败条目可重新调用创建账号接口。

### 3.4 当前断点

- 预览中的代理只是前端字段，没有写入账号、Profile 或 BitBrowser；
- 没有检查平台配额、到期状态和检测结果；
- 没有创建 Browser Profile；
- 没有把代理写入 Profile；
- 没有把 CK 写入 Profile；
- 没有打开浏览器或执行账号检查；
- 没有回填账号 ID、名称、登录状态和 active_cookie；
- 没有接码链接模式和人工验证码模式；
- 页面步骤显示“执行开户”，实际效果只是批量创建数据库账号记录。

### 3.5 当前判断

当前页面应准确命名为“批量创建待识别账号记录”，不能称为“账号开户”。完整度最低，是主业务链路最大的断点。

## 4. 代理管理

### 4.1 产品应有功能

- 文本、TXT、CSV、Excel 导入和解析预览；
- 代理 CRUD、状态、供应商、地区、到期时间和备注；
- Agent 侧连通性检测；
- 平台默认配额和单代理覆盖配额；
- 分配给 Profile 前校验状态、到期、检测结果和配额；
- 自动分配预览；
- 将代理写入 BitBrowser Profile，随后读回验证；
- 外部代理变化通过 Profile Diff 确认后更新关系。

### 4.2 用户应有操作流程及效果

```text
导入并预览代理
→ 确认入库
→ 检测代理
→ 设置平台配额
→ 选择 Profile 分配代理
→ Agent 调用 BitBrowser 修改
→ 读回 Profile 验证
→ 页面展示正式绑定关系
```

### 4.3 当前已完成

- 代理列表、搜索和状态筛选；
- 文本、TXT、CSV 内容读取和常见格式解析；
- 代理记录创建、更新、状态、删除等 API；
- 代理详情和平台配额设置；
- 同步 Agent TCP 连通性检测；
- 同步失败时可显式创建后台检测任务；
- Cloud 有 `proxy/:id/assign` 接口，Agent 有代理变更 executor 基础。

### 4.4 当前断点

- “预览解析”调用的就是导入接口，数据已经入库；“确认导入”只刷新列表，页面语义与实际效果相反；
- 没有真正的 Excel 结构解析，只是浏览器按文本读取文件；
- 页面没有新增和编辑代理的完整表单；
- 页面没有选择 Profile 并分配代理的入口；
- 账号开户页面展示的代理分配没有调用 assign 接口；
- assign 前没有完整执行平台配额与实际占用校验；
- 代理写入 BitBrowser 后缺少强制读回验证；
- 没有在页面展示代理已绑定的 Profile；
- 没有自动分配预览和人工调整；
- 到期提醒和外部变更 Diff 未形成用户流程。

### 4.5 当前判断

代理资源台账和基础检测可用；“代理分配到浏览器环境”没有用户闭环，不能支撑开户流程。

## 5. 浏览器用户（Browser Profile）

### 5.1 产品应有功能

- 首次绑定当前系统用户与 BitBrowser 主账号树；
- 所有本地操作前校验 main_user_id 和 profile_user_id；
- 扫描完整 Profile 列表、生成 Diff、人工确认后应用；
- 展示新增、变更、代理变化和疑似删除；
- 创建、更新、分组、打开、关闭和检查 Profile；
- 绑定已有 Profile；
- 批量绑定代理；
- 本地删除后通过 Diff 将云端镜像标记失效；
- 外部修改后支持“接受本地变化”或“恢复系统配置”。

### 5.2 用户应有操作流程及效果

```text
启动 Desktop、Local Agent 和 BitBrowser
→ 检测并确认绑定 BitBrowser 主账号
→ 扫描全部 Profile
→ 查看 Diff
→ 接受本地变化或恢复系统配置
→ Cloud 更新 Profile 镜像
→ 对 Profile 分配代理、绑定账号和执行浏览器任务
```

### 5.3 当前已完成

- Cloud Profile 列表和详情；
- 创建、打开、关闭、更新 Profile 的任务接口；
- 本地 Agent 的 BitBrowser Profile 扫描、创建、开关、更新和删除适配器基础；
- 扫描快照提交 Cloud，生成 added/changed/missing Diff；
- Diff 确认后更新 Cloud Profile 镜像；
- main_user_id/profile_user_id 字段和部分身份错误阻断；
- 页面显示 Profile 当前代理信息；
- 页面删除仅删除/失效 Cloud 镜像，不直接删除 BitBrowser Profile。

### 5.4 当前断点

- Web 端扫描被直接限制为 Desktop；当前页面固定调用 Agent `8765`，而验收环境使用过 `18765`，运行配置不统一；
- 缺少首次绑定 BitBrowser 主账号的完整向导和用户确认；
- 页面没有 Profile 编辑、分组、代理分配和绑定账号入口；
- 创建/打开/关闭后只提示“已创建任务”，页面不自动追踪并回写最终结果；
- 扫描确认只支持接受本地变化，没有“恢复系统配置”；
- 页面没有扫描历史列表的完整加载入口；
- Diff 对代理变化、新发现代理和绑定账号影响展示不足；
- Profile 创建成功后没有自动进入代理分配、Cookie 写入和账号检查；
- 缺少 Profile 检查以及批量操作结果页面。

### 5.5 当前判断

Cloud 镜像和任务骨架已存在；用户无法通过该页面完成 Profile 生命周期和与账号、代理的关系管理。

## 6. 执行任务（四个模块的共同依赖）

### 6.1 产品应有功能

- 全局任务列表、筛选、详情、进度、错误和业务对象关联；
- pending/running/succeeded/failed/cancelled/result_uncertain 状态；
- 失败项重试、取消和恢复；
- 从业务页面跳转并回写业务结果；
- Agent 在线状态、租约和敏感 Profile 串行保护。

### 6.2 当前已完成

- Cloud 任务创建、领取、上报、详情、取消和重试接口；
- Agent 领取、执行、检查点和结果上报基础；
- Profile、代理、Cookie、账号检查等任务类型；
- 任务详情页可通过 `task_id` 查询单个任务；
- 代理检测失败可跳转查看一个后台任务。

### 6.3 当前断点

- 页面没有全局任务列表 API 和业务任务列表；
- 默认页面主要用于创建 noop 测试任务；
- 只有携带 task_id 才能看到任务；
- 多数业务页面创建任务后不跳转、不轮询、不展示最终结果；
- 业务对象与任务状态没有统一关联视图；
- 批次进度、逐项错误和精确重试没有统一模型。

## 7. 当前用户实际可用流程

### 7.1 可用：数据台账流程

```text
导入代理记录
→ 检测 TCP 连通性
→ 创建待识别社媒账号记录
→ 手工填写账号 ID/名称
→ 添加标签和修改业务状态
```

该流程只完成 Cloud 数据管理，不代表 BitBrowser 已配置，也不代表账号已登录。

### 7.2 局部可用：Profile 镜像流程

```text
在 Desktop 环境扫描 BitBrowser
→ 提交扫描快照
→ 查看部分 Diff
→ 确认后更新 Cloud Profile 镜像
```

该流程受 Agent 端口、Desktop 环境和 BitBrowser 身份前置条件影响，且不能继续完成代理、账号和 Cookie 绑定。

### 7.3 当前不存在：真实开户闭环

以下纵向流程当前无法由用户连续完成：

```text
代理 → Profile → CK → 账号识别 → 状态回填
```

## 8. 模块完成判断

| 模块 | 可用部分 | 半成品部分 | 未形成的关键效果 | 当前结论 |
|---|---|---|---|---|
| 社媒账号 | 台账、筛选、标签、状态、手工识别、Cookie 导出 | Profile绑定/检查/Cookie任务后端 | CK写入、真实检查、自动回填 | 数据台账可用，执行闭环未完成 |
| 账号开户 | 批量解析、创建账号记录、失败重试 | 前端代理预览 | Profile创建、代理绑定、CK写入、检查回填、接码/人工模式 | 页面名称与实际能力严重不符 |
| 代理管理 | 台账、文本导入、检测、配额记录 | assign API/Agent executor | UI分配、配额校验、BitBrowser读回 | 资源管理可用，分配闭环未完成 |
| 浏览器用户 | Profile镜像、扫描/Diff基础、任务接口 | 创建/开关任务、身份校验 | 绑定向导、编辑、代理/账号绑定、任务结果回写 | 骨架存在，生命周期未完成 |
| 执行任务 | 任务基础设施和单任务详情 | 取消/重试 | 全局列表、批次、业务关联与状态回写 | 基础设施可用，产品化未完成 |

## 9. 修复优先顺序

1. 先修正页面语义和假动作：账号导入 CK、代理导入预览、账号开户的代理预览必须与实际副作用一致。
2. 完成 Profile 关系操作：账号绑定 Profile、代理分配 Profile、任务状态与读回验证。
3. 完成 Cookie 与账号检查：写入、读取、识别、状态和 active_cookie 回填。
4. 将账号开户改造成真实批次编排：逐项任务、部分成功、明确失败、精确重试。
5. 补齐任务中心：全局列表、批次详情、业务对象关联和结果回写。
6. 最后用真实 MySQL、BitBrowser、代理和 Cookie 跑通整条纵向链路，才进入 M2 验收。
