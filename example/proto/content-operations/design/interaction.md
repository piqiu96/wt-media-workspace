# 互动管理产品与交互设计

更新日期：2026-11-04。当前为原型基线与评审范围梳理，完整优化方案尚待讨论；本次仅建立工作稿，未修改业务原型。

## 1. 本稿用途与边界

按用户要求，与[发布管理](publishing.md)、[作品管理](works.md)分别维护。共同工作方式见[设计索引](README.md)。

本轮以当前可执行原型和用户明确反馈为设计基线，[第七章 PRD](../../../../docs/product/prd/详细文档/第七章_互动管理.md)作为输入。方案建议、用户确认、原型实施和人工体验验收分别表达；稳定结论在原型通过后回写原有产品文档，不另建正式 PRD。

互动管理覆盖主动互动的目标、账号、动作、评论分配、执行与结果，以及收到／发出评论的查看、回复和连续处理。评论模板作为相关能力一并讨论。发布后的互动配置需与发布稿核对，作品来源及复刻关系需与作品稿核对。

## 2. 当前原型基线

以下是源码和现有说明中的做法，不自动代表产品规则已批准或体验已通过。

| 范围 | 当前做法与证据 | 后续评审关注 |
| --- | --- | --- |
| 主动互动列表 | [互动模块](../publishing/interaction.js)提供任务列表与独立发起入口，也接收作品传入的目标 | 独立创建、作品发起、发布后动作与复刻来源是否可辨认 |
| 发起互动 | 当前为一个目标作品、多个同平台账号，可选点赞、收藏与评论，逐账号分配评论 | 明确目标数、账号数、动作数与最终文案，核对默认选中是否合适；多作品批量不视为已有范围 |
| 评论模板 | 创建互动及评论回复可从关联模板抽屉带入内容 | 主动评论与回复的用途、适用范围及带入后的人工修改是否清楚 |
| 互动结果 | [当前结果覆盖实现](../interaction-results.js)按账号和动作显示结果；失败可单动作重试，待核对先确认，成功动作保留 | 单动作、单账号与整任务结果是否容易理解；暂停、跳过及恢复是否保留已有结果 |
| 评论管理 | [评论模块](../comments.js)合并收到与发出评论，支持账号标签、平台、状态，以及账号、作品、收发、类型、情绪等筛选 | 收件处理与发送记录是否清晰，评论者、作品发布账号和实际回复账号是否可辨 |
| 连续处理 | 评论详情提供下一条、标记并继续、发送回复、回复并继续；回复草稿按评论保存 | 切换不丢草稿，未处理不被自动标成完成；发送失败及结果不明需有明确恢复路径 |
| 弹幕 | 当前可查看与标记处理，不提供评论回复表单 | 与普通评论的能力差异是否清楚，不能从评论能力推断弹幕也可回复 |

当前入口：[主动互动](../index.html#interact/tasks)、[评论管理](../index.html#interact/replies)、[互动逐页评审](../review.html#page-interaction-tasks)、[评论逐页评审](../review.html#page-replies)。评审中的历史问题须核对最终生效实现，不能把已替换的旧实现当作当前事实。

## 3. 继续沿用的已有记录

- [原型说明的既有确认记录](../README.md#2026-11-03-已确认方向)记载：运营峰值管理 300 多个账号，评论按账号标签筛选后按需处理。后续评审需使用这一工作规模，而非只看少量样例是否能点击。
- [已有发布设计](publishing.md#7-发布结果与异常下一步必须清楚)提出发布成功后衔接可选后续动作、互动失败不要求重新发布；这是待评审的发布方案输入，本次不将其升级为已确认规则。
- 单作品多账号、逐动作结果与评论草稿是当前原型做法；跨平台真实能力、权限与执行结果仍须在相应阶段核实。

## 4. 本轮评审重点

以下为 AI 建议的评审重点，尚未形成完整优化方案：

1. **主动互动与评论处理目的清楚。** 一条路径主动对目标作品执行动作，另一条路径围绕收到的评论继续对话；两者可以相互回链，默认工作范围和操作文案应能区分。
2. **创建前看懂范围。** 目标、平台、账号标签、实际账号、动作和评论分配形成可检查清单；改变目标或账号后保留仍有效的人工输入，明确失配项。
3. **执行结果精确到动作。** 点赞成功、评论失败可以同时表达；重试沿用原任务中的未成功动作，新增互动与恢复旧任务分别说明，结果不明先核对。
4. **连续处理符合日常节奏。** 重点检查筛选后的处理队列、当前回复身份、草稿保留、下一条、发送反馈与失败恢复；标记处理与真实发送分别表达。
5. **模板与后续动作复用。** 模板按实际场景带入，配置、授权时机与目标关联结合发布和复刻流程集中 review，不从“保存配置”推断已经执行。

常规字段、布局和反馈由 AI 结合现有规范收敛；涉及账号权限、动作支持、自动执行授权、重复互动判定或跨模块核心流程变化的事项集中提交用户评审。

## 5. 跨模块衔接与体验验证

- 从[作品管理](works.md)进入时带入准确目标与来源关系；互动结束后可查看原作品。观察外部作品不自动等于拥有其评论收件权限。
- 发布及复刻中的后续互动，需在目标作品明确后沿用原关联；发布结果、每个互动动作结果和评论处理状态分别表达。具体方案与[发布设计](publishing.md)共同收敛。
- 评论与结果界面展示的演示数据和模拟发送不能作为真实平台操作证据；后续核实能力按平台、账号和动作区分。
- 后续原型检查覆盖单目标多账号、文案覆盖、部分成功、结果待核对、暂停恢复、评论连续处理、草稿与跨模块返回。检查标准随方案收敛补齐；本次未执行浏览器体验验证。
