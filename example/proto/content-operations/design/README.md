本轮按内容生产 → 发布管理 → 作品管理 → 互动管理推进。按用户要求，发布、作品、互动分别维护以上三份设计工作稿，内容生产原文件收敛为正式文档与原型导航；其他模块每轮更新当前有效结论。当前工作稿中的 AI 建议不代表用户已确认或原型已实施。用户要求评审拆成重点问题：按列表、状态与动作、新建组织、进度等单元给出具体做法，逐项讨论；已确认内容直接沿用，背景分析缩为依据，不把文档合并作为评审结果。

跨模块约定由负责该能力的工作稿维护，其他模块引用，不重复保存整套方案：发布稿维护安排、执行与发布结果确认；作品稿维护发布后的作品观察与复刻流程；互动稿维护主动互动、评论处理与执行结果。三稿都需检查入口带入、结果回链及返回上下文，不能因拆文件割断完整运营路径。

用户明确：重点问题只是评审组织方式，不是穷尽的设计范围。AI 负责主动发现用户未提及但业务闭环所需的场景、边界与连锁影响，将其纳入对应问题并检查整体完整性；精简呈现不能缩减必要覆盖。常规设计细节自主补齐，关键业务取舍集中说明，不将完整性检查转嫁给用户，也不借此增加无实际依据的功能。

## 维护规则

1. 本目录只保存每个业务模块一份当前工作稿，不按页面/轮次无限拆文件。
2. 每项结论标记为正式事实、用户确认、AI 建议或待确认；确认状态不得靠推测升级。
3. 产品逻辑先于交互细化；交互细化先于视觉实施。
4. 每个页面或有意义的讨论里程碑结束时，合并重复决策、清理已淘汰方案和无效过程说明。
5. 原型已实施不等于设计已验收；人工验收前不得标记 ACCEPTED。
6. 只有原型通过人工评审后，才把稳定业务规则回写现有 PRD；决策确认阶段仅更新本目录工作稿。正式规范与交付记录按原有归属承接，不创建平行正式文档。
7. 完成沉淀后移除重复规则与中间结论；若保留文件，仅作当前入口导航。Git 历史承担追溯，不额外归档逐轮稿。

本目录不是第二套 PRD、设计系统、评审系统或任务看板。
