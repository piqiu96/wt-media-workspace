# 视觉一致性与复用参考

目标是让产品整体一致，同时允许页面根据业务任务形成合理差异。

## 先看项目，再做设计

优先查看项目的设计规范、真实组件/主题实现、common 参考和相邻页面。文档与代码不一致时，指出差异并判断影响，不要静默覆盖。

## 复用与抽象

- 已有基础组件和设计 Token 优先复用。
- 跨页面反复出现的模式优先统一。
- Common 是参考还是运行时组件库，以项目实际架构为准；不要把展示 Demo 误当成生产依赖。
- 新页面可先采用局部实现；当多个场景出现同类需求，或明显需要统一体验时，再抽取/扩展公共模式。
- 如果当前已有公共模式明显不合适，可以提出改进，不要为了“复用”保留糟糕体验。

## 保持一致但不过度统一

统一组件行为、状态语义、排版秩序、间距体系和反馈习惯；不同业务页面可以采用不同的信息组织方式。

不要无理由新增装饰卡片、指标、标签页、徽标、筛选或设置。也不要把后台运营页面设计成营销型 C 端页面。

## 检查重点

根据修改范围检查标题与操作、筛选区、表格密度、状态文案、行操作、Drawer/Dialog、反馈、字体间距和响应式表现。只检查本次相关的部分即可。
