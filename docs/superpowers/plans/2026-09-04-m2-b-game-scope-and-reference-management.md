# M2-B 游戏范围与关联管理实施计划

> **执行方式：** 在当前工作区按顺序实施；每个运行时任务先补充失败测试，再完成最小修复并运行对应测试。

## 目标

以 `user_game_scopes` 限制非管理员媒体账号可选、可保存与可执行的游戏；游戏管理提供用户与媒体账号关联摘要、详情和安全禁用/删除；清理测试游戏 `game1` 的关系与游戏记录。

## 实施步骤

1. 治理记录：新增 Decision 0012，修订 Decision 0011、M2 里程碑、PRD 和 CHG-032，使用户确认的范围规则成为当前基线。
2. Identity：为游戏列表补充关联摘要，新增只读关联详情接口；将引用校验从已删除的 `media_accounts.game_id` 改为 `media_account_games`；补充用户缩小范围时的账号关系保护。
3. Media Account：对创建、更新、筛选与执行前的游戏集校验增加用户范围限制，管理员和归属管理员账号维持全量游戏权限。
4. Web：游戏管理显示关联摘要，存在任一关联时禁用停用/删除并提供详情抽屉；账号表单和展示标记沿用后端返回的受限游戏范围。
5. 数据与验收：先检查账号组筛选器是否引用 `game1`，无引用时仅删除其六条 `media_account_games` 关系和 `operation_games` 记录；构建 Cloud 与 Desktop，强制重启 M2-B 本地环境并记录 CHG 检查点。

## 验收标准

- 非管理员无法以 API 写入其 `user_game_scopes` 外的游戏，历史越界关联也不能被其继续保存或执行。
- 游戏列表展示用户数和媒体账号数；任一数值非零时停用、删除均不可操作，详情返回关联用户与账号。
- 删除 `game1` 后保留所有媒体账号，账号不再绑定该游戏，游戏列表不再出现该测试项。
- 现有 M2-B 多游戏 API 兼容字段和管理员全量游戏能力保持可用。
