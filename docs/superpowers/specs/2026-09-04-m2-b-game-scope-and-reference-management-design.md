# M2-B 用户游戏范围与游戏引用治理设计

日期：2026-09-04

状态：用户已确认设计，待书面规格复核
范围：CHG-20260805-032 的媒体账号游戏授权、游戏引用摘要/详情、停用与删除保护；不包含 M2-C 和检查项 7/8。

## 1. 已确认问题

媒体账号多游戏关系已经由 `media_account_games` 保存，但当前媒体账号服务只验证游戏存在且启用，不再校验账号归属用户的 `user_game_scopes`。这与用户管理中已配置的游戏范围不一致。

游戏管理页面只根据用户授权数控制停用/删除按钮，没有统计媒体账号引用。后端 `GameHasReferences` 仍查询已由迁移 025 删除的 `media_accounts.game_id`，因此引用检查产生 SQL 错误并返回“系统内部错误”。

当前真实数据用于验收：`game1` 没有用户授权引用，但有 6 个媒体账号引用；`operator01` 的授权范围是 `hy`、`sjz`，其既有账号仍关联 `game1`，属于新规则下需要管理员处理的历史不一致。

## 2. 用户可见目标

用户在媒体账号页面只能选择其在用户管理中被授予的启用游戏。管理员在游戏管理中可以先看到每个游戏的引用摘要，再查看“谁在什么环节引用”，并据此解除引用。只要存在用户授权或媒体账号引用，停用和删除按钮都不可点击；绕过页面直接调用 API 也必须得到明确的业务冲突，而不是 500。

## 3. 授权与一致性规则

- `user_game_scopes` 是非管理员可使用游戏范围的事实源；`media_account_games` 仍是媒体账号—游戏关系的事实源。
- `operator` 和 `senior_operator` 在媒体账号创建、编辑和筛选中，只能使用本人 `user_game_scopes` 内且状态为 `enabled` 的游戏。
- `admin` 在管理视角可看到所有游戏。管理员为非管理员用户创建或修改媒体账号时，选定游戏必须是目标用户授权范围的子集；管理员自己的账号不受空 `user_game_scopes` 限制，但只能关联启用游戏。
- Cloud 服务端必须执行范围校验，前端候选项过滤不能替代服务端授权。
- 缩减非管理员用户的游戏范围时，如果该用户的媒体账号仍引用将被移除的游戏，则阻止保存，并提示先调整媒体账号；不得自动删除关系。
- 已存在但超出当前用户范围的历史账号关系不静默清理。管理员仍可看到并处理；账号归属用户可看到现状，但在修正前不能以原越权集合保存或执行。

本设计以新的 Decision 取代 Decision 0011 中“媒体账号域全部启用游戏公开可用”的规则；多游戏关系、空关系和 `game_ids` 正式契约继续有效。

## 4. 游戏列表摘要与详情接口

Cloud 继续拥有游戏、用户授权和媒体账号引用的聚合查询。游戏管理采用“列表摘要 + 按需详情”，避免列表携带全部明细或由前端拼接多个业务接口。

管理员的 `GET /api/v1/games` 每项增加：

```json
{
  "reference_summary": {
    "user_scope_count": 1,
    "media_account_count": 6,
    "total_count": 7
  }
}
```

摘要由批量 SQL 一次读取所有游戏的两类引用数，禁止逐游戏 N+1 查询。非管理员使用同一路由获取媒体账号候选游戏时，只返回本人授权范围内的启用游戏，引用摘要可以省略。

新增管理员专用 `GET /api/v1/games/:game_id/references`：

```json
{
  "game_id": "game1",
  "users": [
    {"user_id": 3, "username": "operator01", "role": "operator", "team_id": 1, "team_name": "运营组"}
  ],
  "media_accounts": [
    {"account_id": "1", "name": "账号名称", "platform": "bilibili", "user_id": 3, "username": "operator01"}
  ]
}
```

详情只返回处理引用所需的安全字段，不返回 Cookie、会话、密码或本地浏览器敏感数据。不存在的游戏返回参数/资源错误；非管理员请求返回 403。

## 5. 停用、删除和并发保护

- 后端引用判断同时查询 `user_game_scopes.game_id` 和 `media_account_games.game_id`。
- 任一引用存在时，停用和删除返回 HTTP 409、业务错误 `20005`，文案说明存在用户授权或媒体账号引用，要求先查看关联详情并解除引用。
- 删除语句仍把外键冲突映射为同一业务错误，覆盖引用检查后到删除前出现新引用的竞态。
- 无引用的启用游戏可停用；无引用游戏可删除。启用操作不受引用限制。

## 6. Cloud Web 交互

游戏管理列表新增“关联情况”列，显示“用户 N / 账号 M”。总引用数大于 0 时显示可点击的“查看关联”，打开只读抽屉并分为：

- 用户授权：UID、用户名、角色、运营组；
- 媒体账号：账号 ID、账号名称、平台、归属用户。

任一引用存在时，“停用”和“删除”按钮均禁用，并通过提示说明需先处理关联；前端状态只用于操作引导，后端仍是最终保护。

媒体账号页的游戏候选由当前用户的授权范围提供。历史越权关联继续显示现有名称或 ID，并明确标记“超出用户游戏范围”；编辑保存时必须将集合修正为合法范围。

## 7. 数据和模块边界

- 不新增数据库表、不修改关系表结构。
- Cloud identity 模块拥有游戏目录、用户授权以及游戏引用管理投影；mediaaccount 模块继续拥有账号关系写入和账号业务行为。
- Cloud Web 只消费 Cloud API；Agent 不参与游戏授权或引用查询；Desktop 只刷新 Cloud Web 生成资产。
- 真实库不自动删除 `user_game_scopes` 或 `media_account_games` 数据。验收时由管理员根据关联详情显式调整。

## 8. 验证标准

自动化与真实环境必须同时证明：

1. 普通/高级运营只获得本人授权且启用的游戏候选；提交范围外游戏被服务端拒绝。
2. 管理员代管非管理员账号时按目标用户范围校验；管理员管理视角仍可查看完整游戏目录。
3. 用户范围缩减若会留下账号越权关系则返回可理解的冲突，不删除关系。
4. `game1` 的摘要显示 0 个用户授权和 6 个媒体账号引用，详情列出对应账号与归属用户。
5. `game1` 的停用/删除按钮禁用，直接 API 调用返回 409/20005，不再返回 500。
6. 一个无引用测试游戏可以完成停用、启用和删除。
7. Cloud Go 测试、Web Vitest、Cloud/Web 构建、真实 MySQL 查询及 `m2b-local-acceptance.sh all --force-restart` 全部通过；最新 Cloud Web 和 Desktop 环境重新启动供人工验收。
