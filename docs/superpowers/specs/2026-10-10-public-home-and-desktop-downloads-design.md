# 起飞公开首页、登录视觉与桌面版下载设计

## 已确认目标

Cloud Web 提供公开的 `/home` 官网入口，按用户提供的三张参考图实现蓝白色品牌视觉；Cloud Web 和 Desktop 共享登录页按第二张图重排，但保留现有用户名密码、会话替换、角色限制及版本显示逻辑。官网提供 Windows x64、macOS Intel、macOS Apple 芯片三个安装包入口。正式版更新时，脚本从 GitHub Release 读取真实资产 URL，更新官网使用的下载清单。用户确认下载方式为直接跳转公开 GitHub Release 资产。

## 方案比较

| 方案 | 收益 | 局限 |
| --- | --- | --- |
| 页面写死每个平台 URL | 实现少 | 每次升级必须改源码和重建页面 |
| 页面读取独立下载清单，脚本按版本更新 | 页面与版本分离，可核对目标资产，推荐 | 每次部署后需执行一次清单更新 |
| 页面运行时查询 GitHub API | 无发布后的清单操作 | 公共访问受 GitHub 可用性及匿名限流影响 |

## 页面与资产

- Cloud 路由新增无需会话的 `/home`；现有 `/` 业务首页继续要求登录。Desktop 不加入 `/home`。
- 官网顶部为品牌和四项导航，不展示登录入口、头像或登录引导；导航滚动时悬浮，四个目标区域沿页面纵向排列，点击与上下滚动均能到达并标识当前区域。独立 `/login` 页面继续可直接访问。主视觉用可响应的真实文字、CSS 背景和品牌图，不将带字参考图整张铺作页面。功能卡与下载区域在窄屏纵向排列。无真实价格或管理员联系地址时不制造失效导航。
- 共享登录页保留现有行为和错误提示，仅重排为左侧品牌主视觉、右侧表单卡；窄屏改为单列。用户名、密码保持可访问标签；密码显示切换和提交禁用按现有状态处理。
- 用户第三张图作为品牌图来源。官网与登录页用同一份资产；现有 Desktop 图标本次不改。

## 官网单页视觉收敛（2026-10-10）

- 用户提供完整视觉图和详细实现规格，按该规格收敛现有 /home，不调整 /login、业务路由、下载清单/API 或 Desktop 构建。页面顺序固定为 Header → #hero → #product → #download → #pricing → #contact → Footer；移除官网帮助中心区域。
- Header 使用已有 BrandLogo，右侧仅有「产品、下载、定价、联系」，初始高亮产品。IntersectionObserver 驱动上下滚动高亮；点击导航和 Hero CTA 平滑滚动，点击 Logo 平滑回顶部。临近页尾的定价区使用独立滚动位置，避免与联系区都被浏览器夹到同一个最大滚动位置。各区域设置 110px 顶部滚动留白。
- 保留「让流量跑起来」及固定副标题和现有品牌渐变表达。右侧从用户新提供的设计图中展示插画区域，不重新绘制 Logo 或生成新插画；页面其他内容保持真实文字与真实组件，不把整张设计图铺成首页。
- 产品功能只展示原有四项及固定副标题；下载卡沿用 loadDownloadManifest、三平台顺序和真实 Release URL，卡片等高，版本继续来自清单。定价与联系管理员只展示用户给定文案，保持紧凑，不虚构价格或联系方式。
- 页面使用现有 Vue/TDesign Icon、共享品牌组件和 --td-brand-color；统一浅蓝白背景、轻边框与弱阴影。桌面主内容最大 1280px，窄屏卡片重排且导航可用，不增加 UI 或动画依赖。

## 下载清单与更新脚本

- Cloud Web 在同源静态路径读取 `desktop-downloads.json`，内容含正式版版本号与三个平台的文件名、下载 URL。页面只在清单结构和 URL 合法时显示下载按钮；加载失败时明确提示暂不可下载。
- Workspace 发布脚本接收明确的产品 Tag 和 `--output` 清单路径。它读取 `piqiu96/wt-media-workspace` 的 GitHub Release，要求 Tag 与请求一致、`draft=false`、`prerelease=false`，并且三种资产名称均精确符合产品版本。URL 必须是该仓库该 Tag 的 HTTPS Release 下载地址；不接受缺失、重复或外部地址。
- 校验全部通过后，脚本将 JSON 写到目标目录的临时文件，原子替换输出文件。校验或写入失败时，旧清单保持可用。首次交付生成当前 `v0.1.0` 清单。升级时在新 Cloud Web 部署后，把同一脚本的 `--output` 指向新版本的 `current/web/desktop-downloads.json`；页面不依赖 Workspace 运行时代码。
- 只处理已公开正式版，不展示 RC、Draft 或 `latest` 浮动版本。脚本不推 Tag、不发布 Release、不下载大文件。部署目录权限和外网连通性由执行环境提供。

## 验证与边界

- 前端单元验证公开路由、登录行为不变、三个目标按清单生成；Cloud Web 和 Desktop Web 均构建通过。
- 脚本用模拟 Release 回包验证正常、Draft、RC、缺少平台资产、异常 URL、写入失败等情况；对 `v0.1.0` 实际 Release 回读资产清单。
- Cloud 静态服务验证 `/home` 和 JSON 路径可访问，API 404 不被前端路由吞掉。真实浏览器视觉、三平台完整安装和终端用户网络可达性须在部署环境验收；本地直连 GitHub 资产的 HEAD 请求曾超时，不将 GitHub API 回读等同于终端下载成功。
