# 前端视觉-AdminUI规范

> 目标：建立统一的企业级中后台视觉与交互规范。
> 本规范定义列表、筛选、表单、弹窗、抽屉、详情、关联信息、按钮、状态、反馈等通用设计规则。
> 适用于自媒体运营平台 Cloud Web / Desktop Vue 页面开发。

本文件是通用视觉与信息组织规范。具体字段、状态、权限和页面能力以对应产品文档为准；[前端交互规范](前端交互规范.md)负责操作语义，[用户反馈交互规范](feedback-system.md)负责反馈方式，[前端架构与视觉规范](前端架构与视觉规范.md)负责组件与样式实现。

以下图片用于理解布局和信息层级。图中的按钮数量、业务状态和字段是示意；与正文或产品文档不一致时，以正文和产品文档为准。

# 1. 设计原则
## 1.1 信息层级原则
所有后台页面必须遵循：当前对象 > 关联对象 > 产出对象
禁止所有信息平均展示。

### 当前对象
页面核心管理对象，拥有最高视觉权重。
例如：
-   合成策略：策略配置
-   合成任务：任务状态、执行过程、结果
-   我的成片：视频资产

设计要求：
-   占据主要页面区域
-   优先展示核心状态和操作
-   详情页必须围绕当前对象展开

### 关联对象
用于解释来源和关系。
例如：
-   素材
-   策略
-   任务
-   游戏
-   模板

设计要求：
-   使用摘要信息展示
-   支持点击查看详情
-   不抢占主体空间

### 产出对象

当前对象产生的下一阶段结果。
例如：
-   合成任务 → 我的成片
-   我的成片 → 发布

设计要求：
-   提供明确下一步动作
-   不反向成为当前页面主体

## 1.2 一致性

所有页面统一：
-   布局结构
-   组件样式
-   按钮语义
-   状态表达
-   关闭方式
-   反馈方式

## 1.3 清晰性

信息展示与操作行为分离：
-   列表负责快速管理
-   详情负责完整理解
-   编辑负责修改配置
-   确认负责风险控制

## 1.4 高密度运营

后台页面不是展示页面。
要求：
-   减少无意义留白
-   提高单位区域信息量
-   优先展示运营决策需要的信息

# 2. 页面通用结构

标准后台页面：
    页面标题
    ↓
    页面主操作
    ↓
    筛选区域
    ↓
    选中操作（有选中项时）
    ↓
    数据列表
    ↓
    分页区域

详情页面：

    当前对象核心信息
    ↓
    状态 / 操作 / 关键数据
    ↓
    关联对象
    ↓
    历史记录

# 3. 列表与筛选规范

## 3.1 页面结构

列表统一包含：
1.  页面标题
2.  页面说明
3.  页面主操作
4.  筛选区域
5.  选中操作（有选中项时）
6.  数据表格
7.  分页

## 3.2 筛选区域
规则：
-   高频条件默认展示
-   低频条件进入高级筛选
-   查询、重置固定顺序

按钮：
  类型     文案
  -------- ------
  主按钮   查询
  次按钮   重置


# 4. 表格设计规范
## 4.1 字段优先级

表格字段按照：
    核心对象信息
    >
    状态信息
    >
    关联对象摘要
    >
    时间信息
    >
    操作

排序。

## 4.2 关联对象展示

禁止：直接展示大量关联字段。
错误：
    素材名称
    素材ID
    平台
    作者
    创建时间
    状态
    ...

正确：
摘要卡：
    [缩略图]

    素材名称
    ID: xxx
    时长: xx秒

需要完整信息时，提供详情入口；详情容器按内容选择 Dialog 或 Drawer。

## 4.3 操作列

规则：

-   同一行的业务操作不超过 5 个时全部平铺，不显示「更多」
-   超过 5 个时保留高频操作，把低频操作收进「更多」
-   同一区域只突出一个主操作；按钮显隐由业务状态、权限和执行条件决定

# 5. 按钮规范

## 5.1 类型

  类型       用途
  ---------- --------------
  主按钮     核心业务动作
  次按钮     普通辅助操作
  线框按钮   低优先级操作
  危险按钮   风险操作
  更多按钮   收纳操作

## 5.2 命名规范

使用明确业务动作：

  场景   推荐
  ------ ---------------------
  新增   新增
  创建任务   创建任务
  查看   详情
  修改   编辑
  提交   保存
  执行   执行
  重试   重试
  发布   去发布
  停止   停用
  下载   下载

禁止：

-   打开
-   处理一下
-   操作
-   确认一下

已有统一文案以[前端交互规范](前端交互规范.md)为准；「创建任务」等明确的业务动作保留业务名称。

# 6. 表单、新增、编辑规范

![表单、弹窗与抽屉参考图](../../assets/images/ui/admin-ui/form-dialog-drawer-reference.png)

## 6.1 容器选择
  场景         组件
  ------------ ---------------
  简单配置     Dialog
  复杂配置     Drawer
  多模块配置   Drawer + 分区

## 6.2 信息分区

新增/编辑页面统一：
    基础信息
    ↓
    业务配置
    ↓
    高级参数

当前业务确有高级参数时才展示该分区；参数较多时默认折叠。字段集合由产品定义或模板 schema 决定，不按设计图增加尚未支持的参数。

## 6.3 内容选择组件

涉及大量素材、账号、策略等候选项的选择：不要在主表单中直接展开大列表。候选项很少时可以使用普通下拉选择。
使用：
    输入框
    ↓
    点击选择
    ↓
    弹出选择区域
    ↓
    勾选
    ↓
    确认
    ↓
    回填摘要
支持：
- 单选
- 多选
- 批量选择

# 7. 详情视图规范

![详情视图参考图](../../assets/images/ui/admin-ui/detail-view-reference.png)

## 7.1 详情定位

详情用于理解当前对象。

不是信息堆积页面。

## 7.2 信息结构

推荐：

    当前对象
    ↓
    状态与关键数据
    ↓
    关联对象
    ↓
    历史记录

## 7.3 Tab规范

当详情包含多个独立信息维度、连续滚动难以定位时，使用 Tab，例如「基本信息 / 关联信息 / 执行记录」。内容较少时直接分组展示。Tab 只展示当前产品确有的数据，不为了凑满版式加入尚未交付的记录。


# 8. 状态规范

状态用于表达业务结果。

## 8.1 状态颜色

  状态     颜色
  -------- ------
  成功     绿色
  处理中   蓝色
  等待     黄色
  失败     红色
  禁用     灰色

## 8.2 业务状态统一

同一业务对象在列表与详情中使用同一状态名称。状态取值由对应产品文档定义；设计稿中的示意状态不能直接进入页面。执行阶段可在详情辅助说明，但不能代替业务主状态，也不能直接把内部状态码展示给运营人员。


# 9. 反馈规范

反馈只回答：

1.  发生了什么
2.  是否需要处理
3.  什么时候消失

## 9.1 类型

字段错误、风险确认、一次性操作结果与持续页面状态，分别按[用户反馈交互规范](feedback-system.md)选用字段提示、Dialog、Toast 与页面状态组件。这里不维护第二份反馈类型或颜色规则。

## 9.2 原则

-   不重复提示同一事件
-   不用Toast表达长期状态
-   不用Alert表达一次性结果
-   不遮挡主要操作


# 10. 关闭与提交规范

## X关闭

表示：

关闭当前容器。

适用于：

-   Drawer
-   Dialog
-   详情

## 取消

表示：

放弃当前编辑。

## 保存

表示：提交当前修改。

禁止统一使用：确定。


# 11. 只读、编辑、确认规范

![读写与关闭方式参考图](../../assets/images/ui/admin-ui/read-edit-confirm-reference.png)

## 只读详情

字段不可编辑，不显示没有实际提交内容的「保存」「确定」。允许展示当前状态和权限下可执行的业务动作，例如下载、归档或查看关联对象；右上角 X 始终可关闭详情。

## 编辑

必须：
-   X关闭
-   取消
-   明确的提交动作，例如保存

存在未保存内容：
关闭需要提醒。

## 确认

用于有明确风险、需要用户选择是否继续的操作，例如：
- 删除
- 停用
- 覆盖
- 不可逆操作

格式：

取消 \| 明确业务动作

# 12. 前端实现要求

所有页面：
1.  优先复用已有组件
2.  不自行设计按钮
3.  不自行定义颜色
4.  不自行改变关闭规则
5.  不自行实现反馈组件
6.  新页面必须符合 Admin UI 规范

组件、色彩和间距复用现有[前端架构与视觉规范](前端架构与视觉规范.md)，不得在业务页面重复实现反馈组件。页面具体字段和操作仍以产品文档为准。

最终目标：让产品、设计、前端、AI协作共同遵循统一后台设计语言。
