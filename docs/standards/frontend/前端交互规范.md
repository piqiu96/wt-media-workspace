# 前端交互规范 V1

## 1. 规范定位

本文是 Web / Desktop 共享业务页面用户操作与系统反馈行为的唯一事实源：点击、权限显隐、打开与关闭、提交、确认、异步结果和反馈。页面区域、字段顺序与操作位置由[AdminUI 页面规范](AdminUI页面规范.md)定义；组件、Token 与样式实现由[前端架构与视觉规范](前端架构与视觉规范.md)定义。跨规范优先关系见 [AdminUI 页面规范](AdminUI页面规范.md) §0；三份规范按职责分工，不重复定义同一问题。

本文不定义具体业务状态机。具体状态、权限和业务动作以对应 PRD 为准。

---

## 2. 基本原则

### 2.1 操作结果明确

用户触发操作后，界面应区分已提交、进行中、已完成、失败与结果待确认；不能把请求发出当作最终成功。

### 2.2 状态驱动操作

操作必须由 `业务状态 + 当前用户权限 + 当前执行条件` 共同决定。

禁止为了页面统一而展示实际不可执行的业务操作。

### 2.3 操作显隐

当前可执行动作由状态、权限和执行条件共同决定；操作区域、主次位置及「更多」门槛见[AdminUI 页面规范](AdminUI页面规范.md) §4.3。

### 2.4 进入详情

打开详情不得改变原列表的筛选、分页与选择上下文；详情关闭后的返回行为见 §9.1 和 §9.4。列表与详情各展示哪些信息由[AdminUI 页面规范](AdminUI页面规范.md)定义。

## 3. 统一操作语言

全系统相同行为必须使用相同名称。

| 行为 | 统一文案 |
|---|---|
| 创建普通对象 | 新增 |
| 修改对象 | 编辑 |
| 查看当前对象 | 详情 |
| 保存修改 | 保存 |
| 放弃编辑 | 取消 |
| 真实删除 | 删除 |
| 启用 | 启用 |
| 停止继续使用 | 停用 |
| 为未配置的对象做首次设置 | 配置 |
| 临时停止一个可随时恢复的配置 | 暂停 |
| 失败后再次执行 | 重试 |
| 恢复业务状态 | 恢复 |
| 上传文件 | 上传 |
| 下载文件 | 下载 |
| 再次下载 | 重新下载 |
| 查询条件 | 查询 |
| 清空条件 | 重置 |
| 低频操作集合 | 更多 |

禁止同义词混用，例如：`新建 / 创建`、`修改`、`查看 / 查看详情`、`再次执行 / 重新执行`、`下载到本机`。

明确的业务动作不强行改名，例如：`转素材`、`加入我的素材`、`去我的素材`、`上传素材`、`加入合成`、`放弃使用`、`补充文件`、`打开原视频`。

## 4. 页面控件交互

页面区域的组成、位置及 SummaryMetrics 是否展示，见[AdminUI 页面规范](AdminUI页面规范.md) §2–§3。本节只规定这些区域存在时的交互。

- PageHeader / PageActions 的业务动作按权限和当前执行条件触发，不因位置不同改变同一动作的语义。
- 可交互 SummaryMetrics 点击后应用与其含义一致的快捷筛选；选中态反映当前筛选条件，清除筛选后同步取消选中。没有可执行筛选的指标不伪装成可点击控件。
- FilterPanel 的「查询」应用当前输入条件并回到有效页码；「重置」清除该区筛选条件并刷新列表。高频 / 低频条件的展示由 [AdminUI 页面规范](AdminUI页面规范.md) 决定。
- SelectionToolbar 根据选择状态提供可执行批量动作；取消选择或列表上下文改变后同步清除失效选择。
- Pagination 切页和修改每页数量后保持已应用的筛选条件，且总数、页码与实际查询结果一致。

## 5. 列表交互

### 5.1 字段与 ID

字段顺序、ID 独立列及展示格式仅由[AdminUI 页面规范](AdminUI页面规范.md) §4 定义；本节不另立列表信息架构。

### 5.2 行内触发

行内控件应有明确可触发范围和可访问名称，不把不可执行内容渲染成可点击入口。行内可执行动作的显隐规则见 §13；单元格内联配置开关的执行流程见 §7.5。

### 5.3 详情

存在详情能力且用户可查看时，点击「详情」进入当前对象详情；实体名称也可作为辅助入口，但不能替代明确的详情操作。文案统一使用 §3 定义的「详情」。

### 5.4 编辑

对象允许编辑且用户有权限时统一显示 `编辑`。不允许编辑时不展示。

禁止仅为了保持按钮位置而长期展示无意义 Disabled 按钮。

### 5.5 业务动作

点击前依据当前业务状态、用户权限和执行条件确认动作可执行；异步结果按 §10、§14 反馈，不把入口是否出现当作实际执行成功。

### 5.6 更多菜单

「更多」何时出现由[AdminUI 页面规范](AdminUI页面规范.md) §4.3 定义。菜单内动作与行内动作执行同一权限检查和结果反馈；危险操作仍经 §12 的确认 Dialog，不能把收纳当作安全措施。

### 5.7 自动刷新

列表页不设「刷新」按钮。列表默认每 10 秒自动重读一次，定时器由公共实现 `useAutoRefresh` 统一提供，页面不各自建 timer。

- 抽屉、弹窗、表单打开，或有选中行、正在提交 / 批量执行时跳过这一拍；页面不可见时同样跳过。
- 定时读取是静默的：不显示整页 Loading、不重置页码与筛选、失败保留上一次读数；用户主动查询仍显式显示 Loading 与错误。
- 需要跟踪单条执行状态的详情可以另设更短间隔的轮询，但只在详情打开时运行，不与列表刷新叠加。
- 本机执行面（账号、开户、浏览器窗口、代理、本地日志）不受此约束：那里的「刷新」是重新读取本机事实的动作，不是列表数据过期。

## 6. 新增、编辑与详情

### 6.1 新增

页面名称统一为 `新增账号`、`新增策略`、`新增模板` 等。

按钮统一：`保存`、`取消`。

“上传素材”等文件型业务入口保留业务名称，不改成“新增素材”。

### 6.2 编辑

标题统一为 `编辑账号`、`编辑策略` 等。

按钮统一：`保存`、`取消`。

### 6.3 详情

标题统一为 `账号详情`、`素材详情`、`任务详情` 等。

详情默认只读，不出现没有提交含义的「确认 / 取消」。独立页面使用返回入口，Drawer 使用 §9.1 的关闭行为；业务动作依据状态与权限决定是否可执行，位置见[AdminUI 页面规范](AdminUI页面规范.md) §7.4。

详情的信息分区、Tab 与业务操作位置见[AdminUI 页面规范](AdminUI页面规范.md) §7。

## 7. 状态与操作

### 7.1 状态和操作分离

状态用于描述“现在是什么”，按钮用于表达“下一步做什么”。业务结果状态、任务状态、健康状态和只读生命周期状态不得用可点击控件表达；列表单元格中内联可编辑的布尔配置值是唯一例外，适用条件见[AdminUI 页面规范](AdminUI页面规范.md) §4.4，执行流程见 §7.5。

状态颜色和按钮视觉层级由[前端架构与视觉规范](前端架构与视觉规范.md)定义；状态在页面中的信息位置由[AdminUI 页面规范](AdminUI页面规范.md)定义。

### 7.2 多状态维度分离

不同语义的状态分别解释，不为减少字段而造出混合状态。各状态的取值与文案由业务 PRD / 契约决定；页面收到多个状态时，应保持各自含义，并按其共同决定可执行动作。

### 7.3 不可执行操作

业务明确禁止的操作默认隐藏。

仅当用户需要理解“为什么当前不能执行”时，才使用 Disabled，并提供原因。

### 7.4 状态异常

异常状态优先给出 `状态 + 下一步恢复动作`，例如：

```text
下载失败 → 重试
文件异常 → 重新下载
```

不要一次展示所有可能处理方式。

### 7.5 内联配置开关

本节只用于[AdminUI 页面规范](AdminUI页面规范.md) §4.4 允许的**列表单元格内**联布尔配置值；被排除的状态类型不适用本节。编辑表单、配置 Drawer 内的开关按 §8 处理：它随表单保存统一提交，不逐次确认，也不走本节流程。

```text
点击开关
→ 打开确认 Dialog
→ 确认后开关进入 Loading，本行开关置为不可点击
→ 调用真实接口
→ 成功：按接口结果更新为新的配置值，按 §14.3 给出成功提示
→ 失败：保持原值，给出失败提示，不显示成功
```

确认 Dialog 必须让用户看懂三件事：**改哪一项、改成什么、对谁生效**。例如「暂停「运营号素材合成」的自动执行？暂停后该策略不再按计划自动执行。」确认按钮使用 §3 定义的实际动作词（`启用` / `暂停`），不使用「确定」；弹窗文案与关闭时机按[用户反馈规范](用户反馈规范.md)执行。

该确认是配置变更确认，不是 §12 的危险操作确认——不套用 §12 的影响说明结构。危险操作仍按 §12 确认，不因本节放宽；确认按钮视觉见[前端架构与视觉规范](前端架构与视觉规范.md) §4.4.3。

请求期间开关保持当前值并禁用，不接受重复点击；失败后由用户再次点击重试，不自动重试。禁止：先改界面再补失败处理；失败后停留在错误状态；连点造成重复请求；请求未结束就允许再次提交。

例如「自动执行」：开启成功提示「自动执行已启用」，暂停成功提示「自动执行已暂停」，失败提示「自动执行设置失败，请重试」；具体对象名称与文案由页面正式规格确定。

单元格中「配置」按钮点击后打开配置 Drawer：打开、关闭与返回按 §9.1，Drawer 内的保存、Loading、失败保留输入与重复提交防护按 §8。

## 8. 表单交互

新增 / 编辑表单的字段分区见[AdminUI 页面规范](AdminUI页面规范.md) §6.2；本节只规定填写过程中的行为。

必填项必须明确。

保存过程中：

- 防止重复提交；
- 按钮进入 Loading；
- 成功后更新真实业务状态；
- 失败保留用户已填写内容。

字段校验尽量贴近字段展示，不使用与字段无关的全局错误提示。字段布局、单双列与分区只引用[AdminUI 页面规范](AdminUI页面规范.md) §6.2、§7.2；改变布局不能丢失输入、重置校验状态或隐藏错误。

### 8.1 卡片式互斥选择

操作方式、来源或策略等少量互斥选项使用卡片时，仍复用真实Radio的语义与状态：整卡可选，焦点可见，支持Tab进入和原组件的方向键/空格选择；选中、禁用、Loading和错误由实际状态驱动，不能只改背景模拟选择。禁用项不可鼠标或键盘激活，需要知道的不可用原因可读取。

标题和一行差异说明需同时可读，选择后原表单的依赖字段与校验按业务规则更新；不因视觉组件变化自行增加提交、外部写入或权限。普通二值开关、无解释成本的选项不强制卡片化，适用条件见AdminUI §6.3。

## 9. Drawer、Dialog 与页面跳转

### 9.1 Drawer

用于长表单、多区配置和需要关联上下文的详情，不离开当前列表。容器选择由 [AdminUI 页面规范](AdminUI页面规范.md) §6.1 唯一定义；采用 Drawer 后，再按 §7.5 选择详情宽度。简短新建与编辑不再默认使用 Drawer。

只读Drawer的常规关闭入口是标题栏右上角的 `×`，不再在Footer放重复“关闭”。编辑表单可提供明确的“取消”，与保存分别处理；提交中X、Esc、遮罩与取消均不能丢弃正在处理的上下文。容器内正确管理焦点和滚动锁，多层弹层返回前一层，不因采用轻遮罩而允许点击穿透或错误关闭。

关闭后恢复打开前的页面筛选、分页、滚动位置和所在Drawer，详情字段自适应重排不得重置这些上下文。业务动作的 Footer 位置、有无 Footer 由[AdminUI 页面规范](AdminUI页面规范.md) §7.4 定义；TDesign 的 Footer 实现约束见[前端架构与视觉规范](前端架构与视觉规范.md) §4.4.2。

### 9.2 Dialog

适用于简短新建 / 编辑、二次确认、单次资源选择与简短摘要，居中且高度随内容。复杂配置不塞入小弹窗，具体条件见 [AdminUI 页面规范](AdminUI页面规范.md) §6.1。

短表单采用Dialog并保留目标视觉的字段组合和卡片选择；容器宽度与信息量判断见AdminUI §6.1，不能以改成Dialog为由压平所有布局。

表单Dialog使用明确的取消与保存动作，不靠遮罩误关。提交中关闭、取消与重复提交均阻断，失败保留输入；只读摘要没有提交含义时不渲染默认确认 / 取消。关闭后保留原列表筛选、分页与滚动，不因更换容器丢失上下文。

### 9.3 独立页面

适用于信息较多、存在多个子区域、需要连续操作或需要稳定 URL 的场景。

### 9.4 EntityLink 与跨对象详情

点击 EntityLink 一律在当前页面或当前 Drawer 上方打开关联实体的无路由、只读详情 Drawer，不因打开而改变页面路由。关闭关联 Drawer 后返回原页面 / 原 Drawer，并保留原筛选、分页、滚动和未提交输入状态。

关联 Drawer 内可以提供名称明确的「前往该实体页面」链接；只有用户点击该链接时才进行路由跳转。跨对象入口应写明对象名称，不能只写「详情」。如打开关联详情的权限不存在，入口不应可点击；需复用该实体已有详情能力，不复制第二套业务详情。哪些信息应渲染成 EntityLink 由[AdminUI 页面规范](AdminUI页面规范.md) §7.6 定义。

## 10. 异步操作

### 10.1 请求不等于成功

涉及 Agent、浏览器、平台、文件和外部服务时，`请求已发送 ≠ 操作成功`。

只有真实执行和必要读回成立后才能显示成功。

### 10.2 列表与详情边界

列表展示结果性状态，例如：`下载中`、`执行中`、`失败`、`已完成`。

详情展示过程，例如：进度、百分比、速度、剩余时间、错误原因、执行记录。

### 10.3 单项失败

采用：`Toast / Message + 当前行状态更新 + 详情入口`。

不把单条记录失败长期显示成页面级红色 Alert。

---

## 11. 批量操作

未选择数据时隐藏批量工具栏。

选择后展示 `已选 N 项 + 可执行批量操作`。

有限批量现场处理先展示进度，结束后自动进入结果，保留同一上下文和逐项原因。总数与六类互斥项目状态对应：

`总数 = 成功 + 失败 + 跳过 + 处理中 + 未处理 + 待确认`

已处理数量与进度从真实项目状态计算，不作为第七种项目状态重复计数。成功、失败、部分完成、中断、待确认分别表达，不能将未处理或待确认归入成功。原本可恢复的长任务仍使用其正式任务模型，本规则不新增任务历史或任务中心。

处理中阻断普通关闭、取消与重复执行；强制离开不能宣称撤销已生效项目，停止/恢复行为遵循真实业务定义。失败项仅在明确失败范围内重试，待确认项先读取并核实，不盲目重复写入；结果提供实际可执行的完成/重试/核实入口。视觉中心与内容顺序见AdminUI §7.7，呈现实现见架构视觉规范§4.5。批量操作不得改变单项业务规则。

---

## 12. 危险操作

以下操作根据实际影响进行确认：删除、强制中断、放弃使用、释放、覆盖。

确认内容必须说明：

```text
即将执行什么
会影响什么
不会影响什么
是否可以恢复
```

危险操作最终确认的按钮样式由[前端架构与视觉规范](前端架构与视觉规范.md) §3.7.5 定义。可恢复操作与不可恢复操作必须明确区分。

---

## 13. 权限交互

用户无操作权限时：

- 不展示可执行入口；
- 不先展示按钮再在点击后提示“无权限”。

用户可以查看但不能修改时：允许详情，隐藏编辑和业务操作。

权限变化后页面应刷新真实可执行状态，包括行内动作与入口显隐。

## 14. 状态反馈

本节是反馈的事实源：反馈的触发时机与在页面、列表和即时操作中的位置。组件入口、Toast / Dialog / Alert 的选型与生命周期按[用户反馈规范](用户反馈规范.md)执行；反馈组件的实现见[前端架构与视觉规范](前端架构与视觉规范.md) §4.5。

### 14.1 页面级

仅用于列表加载失败、权限不足、核心依赖不可用。

### 14.2 行级

用于单项失败、异常状态、待处理状态。

### 14.3 即时反馈

Toast / Message 用于保存成功、操作失败、恢复成功、提交完成。

不要重复同时出现页面 Alert、Toast 和行内错误。

### 14.4 空状态

必须区分四种情况，不能共用一句「暂无数据」：无数据、筛选无结果、加载失败、无权限。空状态不与行内错误或页面级 Alert 重复表达同一件事；筛选无结果给出清除筛选入口，加载失败给出重试。

---

## 15. 文案规范

按钮优先使用动词，推荐 2～4 个字，例如：`新增`、`编辑`、`详情`、`保存`、`下载`、`重试`、`恢复`、`停用`。

文案必须描述用户动作，而不是技术过程。

例如 `补充文件` 优于 `重新绑定本地视频文件`，但不能为了缩短造成歧义。

---

## 16. 应用示例边界

本规范中的业务动作名称只用于解释交互，不定义某模块的状态矩阵、当前代码能力或页面字段。具体业务状态、按钮可用条件与路由目标应从对应业务 PRD / 页面正式规格读取；已确认的模块特例须留在其正式规格中，不在交互规范维护第二份实现快照。

---

## 17. 规范边界与维护

本规范只收录跨多个页面稳定复用的交互模式。

以下内容不得直接写成全局规则：

- 单一页面特殊字段；
- 某个模块独有状态；
- 临时业务按钮；
- 某次需求的例外逻辑。

具体业务按钮和状态矩阵放在对应 Product 文档中。

只有当一种模式已经在多个模块稳定复用后，才升级到本文。

---

## 18. 开发验收

每次 UI 开发完成后至少检查：

- 相同行为是否使用相同文案；
- 列表是否有稳定的详情入口（对照 [AdminUI 页面规范](AdminUI页面规范.md) §4）；
- 每行是否只有一个主要业务操作（对照 [AdminUI 页面规范](AdminUI页面规范.md) §4.3）；
- 不可执行操作是否正确隐藏；
- 状态是否与操作分离（业务结果、任务、健康与只读生命周期状态未做成按钮或开关）；
- 内联开关是否只出现在允许的布尔配置列，并经过确认、Loading、真实接口与失败处理（见 §7.5、[AdminUI 页面规范](AdminUI页面规范.md) §4.4）；
- 配置变更确认是否与危险操作确认区分（未套用危险操作的影响说明结构与危险样式）；
- 多种状态维度是否被错误合并；
- 列表是否只保留决策信息、未塞入默认不进入列表的派生字段（对照 [AdminUI 页面规范](AdminUI页面规范.md) §4.1）；
- 链接是否只用于需要追溯的关联实体，归属与分类未使用链接视觉（对照 [AdminUI 页面规范](AdminUI页面规范.md) §7.6）；
- 过程信息是否进入详情（对照 [AdminUI 页面规范](AdminUI页面规范.md) §7）；
- 异步成功是否经过真实结果确认；
- 危险操作是否说明影响范围；
- 批量操作是否有完整结果反馈；
- 页面是否复用了已有公共组件和交互模式。
