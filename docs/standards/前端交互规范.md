# 前端交互规范 V1

## 1. 规范定位

本文定义 Web / Desktop 共享业务页面的统一交互规则，包括：页面与列表操作、新增/编辑/详情、状态与操作关系、表单/弹窗/抽屉、异步反馈、批量操作和操作文案。

本文不定义具体业务状态机。具体状态、权限和业务动作以对应 PRD 为准。

---

## 2. 基本原则

### 2.1 任务优先

页面首先回答：

1. 当前是什么状态；
2. 哪些内容需要处理；
3. 下一步可以做什么；
4. 操作后的真实结果是什么。

### 2.2 状态驱动操作

操作必须由 `业务状态 + 当前用户权限 + 当前执行条件` 共同决定。

禁止为了页面统一而展示实际不可执行的业务操作。

### 2.3 一个主要操作

同一区域只突出一个当前最重要的操作。

列表行默认：

```text
详情 | 主操作 | 更多
```

没有主操作时：

```text
详情 | 更多
```

无其他操作时：

```text
详情
```

### 2.4 列表用于决策，详情用于解释

列表只保留帮助用户查找、比较、判断和执行下一步的信息。

过程数据、技术信息、完整历史放入详情。

---

## 3. 统一操作语言

全系统相同行为必须使用相同名称。

| 行为 | 统一文案 |
|---|---|
| 创建普通对象 | 新增 |
| 修改对象 | 编辑 |
| 查看当前对象 | 详情 |
| 保存修改 | 保存 |
| 放弃编辑 | 取消 |
| 真实删除 | 删除 |
| 启用 | 启用 |
| 停止继续使用 | 停用 |
| 失败后再次执行 | 重试 |
| 恢复业务状态 | 恢复 |
| 上传文件 | 上传 |
| 下载文件 | 下载 |
| 再次下载 | 重新下载 |
| 查询条件 | 查询 |
| 清空条件 | 重置 |
| 低频操作集合 | 更多 |

禁止同义词混用，例如：`新建 / 创建`、`修改`、`查看 / 查看详情`、`再次执行 / 重新执行`、`下载到本机`。

明确的业务动作不强行改名，例如：`转素材`、`加入我的素材`、`去我的素材`、`上传素材`、`加入合成`、`放弃使用`、`补充文件`、`打开原视频`。

## 4. 页面结构

管理列表页面默认顺序：

```text
PageHeader
→ PageAlert
→ SummaryMetrics
→ PageActions
→ FilterPanel
→ SelectionToolbar
→ DataTable
→ Pagination
```

SelectionToolbar 只在存在选中项时出现。

### 4.1 PageHeader

包含页面名称、一行用途说明和必要的页面级操作。

页面说明解释“这里做什么”，不解释技术实现。

### 4.2 PageActions

页面级“新增、上传”等操作放在列表上方。同一区域最多一个 Primary。

### 4.3 FilterPanel

高频筛选优先，低频条件避免长期占据页面空间。

统一使用：`查询`、`重置`。

---

## 5. 列表交互

### 5.1 ID

有业务 ID 的列表：

- ID 独立成列；
- 除选择框外，为第一业务列；
- 直接显示数字，例如 `153`；
- 不增加 `#` 等装饰。

### 5.2 信息职责

每列只承担一个主要语义。禁止把多个独立状态合并为一个状态列。

### 5.3 详情

存在详情能力的对象，`详情` 为列表常驻操作。

标题可以同时支持点击进入详情，但不能作为唯一入口。

统一使用 `详情`，不要混用 `查看`、`查看详情`、`查看信息`。

### 5.4 编辑

对象允许编辑且用户有权限时统一显示 `编辑`。不允许编辑时不展示。

禁止仅为了保持按钮位置而长期展示无意义 Disabled 按钮。

### 5.5 主操作

根据当前状态只展示一个最重要的下一步，例如：

```text
详情 | 下载
详情 | 重试
详情 | 加入合成
```

### 5.6 更多

行内按钮总数不超过 5 个时全部平铺，不使用 `更多`。

超过 5 个时，把多余的低频操作收敛进 `更多`，保留高频与主操作平铺。`更多` 的候选是低频、辅助、危险操作，例如：重新下载、重新定位、放弃使用、打开原视频。

---

## 6. 新增、编辑与详情

### 6.1 新增

页面名称统一为 `新增账号`、`新增策略`、`新增模板` 等。

按钮统一：`保存`、`取消`。

“上传素材”等文件型业务入口保留业务名称，不改成“新增素材”。

### 6.2 编辑

新增和编辑尽量复用同一表单结构。

标题统一为 `编辑账号`、`编辑策略` 等。

按钮统一：`保存`、`取消`。

### 6.3 详情

详情默认只读。

标题统一为 `账号详情`、`素材详情`、`任务详情` 等。

详情页面或 Drawer：

- 不出现无意义的“确认 / 取消”；
- 关闭使用 `×` 或返回；
- 当前状态允许的业务动作可以保留。

详情建议按 `基本信息 / 状态 / 关联资源 / 操作记录` 组织。

---

## 7. 状态与操作

### 7.1 状态和操作分离

状态用于描述“现在是什么”，按钮用于表达“下一步做什么”。

状态颜色不得替代按钮层级。

### 7.2 多状态维度分离

不同语义的状态不得强行合并，例如：

```text
素材状态：可用 / 已暂停 / 已下架
文件状态：未准备 / 准备中 / 可下载 / 准备失败
使用状态：使用中 / 已放弃 / 已中断
```

用词说明（2026-09-30 用户走查，设计图「文案优化」）：文件状态这一档用「准备」而不是
「下载」——它描述的是**云端这条素材的源文件准备好了没有**，是素材库侧的属性；本机的
下载进度从来不是它的含义（下载由「我的素材」与文件传输任务承载）。

`video_status` 的契约取值不变（`not_downloaded / downloading / ready / failed`），
变的只是这四个取值的中文文案。素材库页面自 CHG-20260930-069 起渲染的正是这一套。

可以同时存在 `使用中 + 下载失败`，不应为了页面简单重新制造混合状态。

### 7.3 不可执行操作

业务明确禁止的操作默认隐藏。

仅当用户需要理解“为什么当前不能执行”时，才使用 Disabled，并提供原因。

### 7.4 状态异常

异常状态优先给出 `状态 + 下一步恢复动作`，例如：

```text
下载失败 → 重试
文件异常 → 重新下载
```

不要一次展示所有可能处理方式。

---

## 8. 表单交互

表单按业务含义分组，例如：`基本信息 / 业务配置 / 关联资源 / 备注`。

必填项必须明确。

保存过程中：

- 防止重复提交；
- 按钮进入 Loading；
- 成功后更新真实业务状态；
- 失败保留用户已填写内容。

字段校验尽量贴近字段展示，不使用与字段无关的全局错误提示。

---

## 9. Drawer、Dialog 与页面跳转

### 9.1 Drawer

适用于快速查看详情、不需要离开当前列表、信息量中等的场景。

### 9.2 Dialog

适用于简短输入、二次确认、小型选择。复杂配置不塞入小弹窗。

### 9.3 独立页面

适用于信息较多、存在多个子区域、需要连续操作或需要稳定 URL 的场景。

### 9.4 跨对象跳转

跨业务对象时必须明确对象名称，例如：`素材详情`、`任务详情`、`成片详情`。

不能只写“详情”，导致用户不知道跳到了哪个对象。

---

## 10. 异步操作

### 10.1 请求不等于成功

涉及 Agent、浏览器、平台、文件和外部服务时，`请求已发送 ≠ 操作成功`。

只有真实执行和必要读回成立后才能显示成功。

### 10.2 列表与详情边界

列表展示结果性状态，例如：`下载中`、`执行中`、`失败`、`已完成`。

详情展示过程，例如：进度、百分比、速度、剩余时间、错误原因、执行记录。

### 10.3 单项失败

采用：`Toast / Message + 当前行状态更新 + 详情入口`。

不把单条记录失败长期显示成页面级红色 Alert。

---

## 11. 批量操作

未选择数据时隐藏批量工具栏。

选择后展示 `已选 N 项 + 可执行批量操作`。

批量执行必须明确：总数、已完成、成功、失败、跳过。

失败项应支持单独重试。批量操作不得改变单项业务规则。

---

## 12. 危险操作

以下操作根据实际影响进行确认：删除、强制中断、放弃使用、释放、覆盖。

确认内容必须说明：

```text
即将执行什么
会影响什么
不会影响什么
是否可以恢复
```

危险操作最终确认使用危险按钮样式。可恢复操作与不可恢复操作必须明确区分。

---

## 13. 权限交互

用户无操作权限时：

- 不展示可执行入口；
- 不先展示按钮再在点击后提示“无权限”。

用户可以查看但不能修改时：允许详情，隐藏编辑和业务操作。

权限变化后页面应刷新真实可执行状态。

---

## 14. 状态反馈

### 14.1 页面级

仅用于列表加载失败、权限不足、核心依赖不可用。

### 14.2 行级

用于单项失败、异常状态、待处理状态。

### 14.3 即时反馈

Toast / Message 用于保存成功、操作失败、恢复成功、提交完成。

不要重复同时出现页面 Alert、Toast 和行内错误。

---

## 15. 文案规范

按钮优先使用动词，推荐 2～4 个字，例如：`新增`、`编辑`、`详情`、`保存`、`下载`、`重试`、`恢复`、`停用`。

文案必须描述用户动作，而不是技术过程。

例如 `补充文件` 优于 `重新绑定本地视频文件`，但不能为了缩短造成歧义。

---

## 16. 当前模块应用示例

以下仅用于说明本规范如何应用，具体状态仍以业务 PRD 为准。

### 16.1 内容池

正式状态：

```text
待筛选
已转素材
已忽略
```

自动转素材失败仍保持“待筛选”，以失败原因区分。

典型操作：

```text
待筛选
详情 | 转素材 | 更多：忽略

已转素材
详情 | 素材详情

已忽略
详情 | 恢复
```

### 16.2 素材库

素材生命周期：

```text
可用
已暂停
已下架
```

暂停和下架禁止新增领取，但历史关系和结果继续保留。

用词说明（2026-09-30 用户裁定）：这一档状态叫「已下架」，不叫「已退役」——它描述的是
素材被撤下、不再提供给运营选用，而不是某条记录被归档。

典型操作：

```text
可用 + 未领取
详情 | 加入我的素材

可用 + 已领取
详情 | 去我的素材

已暂停 / 已下架 + 未领取
详情

已暂停 / 已下架 + 已领取
详情 | 去我的素材
```

最后一行（2026-09-30 补记）：禁止下架素材**新增**领取，不等于把已有关系一并藏起来。
已领取的行任何状态下都保留「去我的素材」——那句话的后半截就是「历史关系和结果继续
保留」，藏掉入口等于让运营找不到自己已经领过的东西。

素材状态这一档的数据已落地（第五章「素材状态和生命周期」）：`materials.status` 是素材库
自有字段，取值 `available / paused / delisted`，本表的操作分支按真值生效。但**写路径尚未
存在**——没有任何接口能把一行改成 `paused` / `delisted`，所以今天每一行读到的都是「可用」，
本表后两行暂时只在被暂停过的数据上才看得见。

### 16.3 我的素材

素材领取后支持下载；下载失败允许重试，本地文件异常允许重新下载或重新定位；主动放弃后可以恢复。

典型操作：

```text
使用中 + 未下载
详情 | 下载

使用中 + 已下载
详情 | 加入合成

使用中 + 下载失败
详情 | 重试

已放弃
详情 | 恢复使用
```

## 17. 规范边界与维护

本规范只收录跨多个页面稳定复用的交互模式。

以下内容不得直接写成全局规则：

- 单一页面特殊字段；
- 某个模块独有状态；
- 临时业务按钮；
- 某次需求的例外逻辑。

具体业务按钮和状态矩阵放在对应 Product 文档中。

只有当一种模式已经在多个模块稳定复用后，才升级到本文。

---

## 18. 开发验收

每次 UI 开发完成后至少检查：

- 相同行为是否使用相同文案；
- 列表是否有稳定的详情入口；
- 每行是否只有一个主要业务操作；
- 不可执行操作是否正确隐藏；
- 状态是否与操作分离；
- 多种状态维度是否被错误合并；
- 列表是否只保留决策信息；
- 过程信息是否进入详情；
- 异步成功是否经过真实结果确认；
- 危险操作是否说明影响范围；
- 批量操作是否有完整结果反馈；
- 页面是否复用了已有公共组件和交互模式。
