# ADR-0026：托管代理绑定以比特成功响应为准

## Status

Accepted，局部替代 ADR-0025 第 7 条中对托管代理绑定的事后读回要求。

## Context

用户确认，正常绑定无需在比特更新成功后再读取配置逐字段核验。比特响应与代理连接检测是不同事实；超时或断开不能推断失败，也不能自动重复写入。

## Decision

- 绑定或重新应用托管代理时，先校验权限、团队、代理可用性与配额。比特更新接口明确成功后才能确认 Cloud 关系；正常路径不做事后字段读取。
- 明确拒绝则失败并保留原关系；响应未能确定时保留原关系、标记待确认，先读实际配置，不能直接重复写入或把协议/地址/端口相同推导为认证相同。
- 用户可看到系统检测结果，但不得把比特接口成功解释为代理连通或目标平台可访问。详情不得宣称未经观察的认证一致。
- 变更通过 Agent 新增可兼容的能力表达成功响应，旧 Agent/Cloud 路径保持原合同。新 Cloud 遇到不支持的旧 Agent 不得猜测成功，须提示升级。凭据不能出现在响应、日志或通用快照。
- 浏览器身份保护所需的写入前读取保持不变；直接解绑为直连以及窗口普通字段编辑的既有读回约束不变。

## Consequences

- Positive：正常绑定减少事后比特读取，降低延迟与额外失败点。
- Negative：比特成功响应后，字段未实际保存或认证后来被改动时，系统可能无法立即发现；不声称认证已核实。
- Follow-up：覆盖明确成功、拒绝、不确定、旧版本兼容、用户核对及配额并发；真实验收不能用模拟成功替代。
