# ADR-0023：M3–M5 团队公共资源与成片负责人边界

- Status: Accepted
- Date: 2026-10-26
- Scope: M3 内容池／挖掘策略／挖掘任务，M4–M5 素材与内容生产
- Supersedes: [ADR-0014](0014-m3-team-content-scope.md) 中“同团队运营均可修改、执行挖掘策略”的角色结论；其团队业务隔离、游戏归属与筛选、来源唯一键继续有效。

## Context

内容池和素材库是团队公共资源，个人“我的素材”是工作集。合成策略、任务和成片则需要明确最终运营负责人。把负责游戏直接当作公共资源的强授权边界，会妨碍同团队协作；把团队公共素材当作个人工作集，又会让自动执行依赖策略创建者。

## Decision

1. **Cloud 业务范围与 Desktop 入口。** 管理员可跨团队查看和管理 M3–M5 Cloud 业务数据；高级运营只在所属团队内，可覆盖该团队所有游戏。两者可以登录 Desktop 并进入 M3–M5 共用 Cloud 业务页面，Cloud Web 与 Desktop 页面遵循同一服务端授权。M2 本机浏览器操作仍受原有角色准入和当前用户身份约束；Local Agent、BitBrowser、Cookie、Profile 和本机文件不得因 Cloud 管理权限而开放给他人。
2. **公共资源。** `source_content` 内容池和 `material` 素材库按团队隔离，普通运营可查看、处理本团队所有游戏的公共内容。游戏是多选筛选，普通运营和高级运营初次默认选中本人负责的游戏；管理员先选目标团队，默认该团队全部游戏。调整筛选不改变团队授权。
3. **个人工作集。** `material_usage` 只表示当前用户的“我的素材”，高级运营和管理员也不能把他人的工作集作为自己的人工选材来源。本机下载原素材要求当前用户有有效工作集关系。
4. **策略与负责人。** 挖掘策略及任务异常由高级运营管理本团队、管理员跨团队管理，普通运营处理内容池。合成策略按团队、一个游戏、一个有效运营负责人限定适用性；高级运营创建时自动归本团队，管理员创建时选目标团队。普通运营只使用指定给自己的合成策略。
5. **生产归属。** `compose_strategy` 指定负责人；`compose_task` 创建时保存实际负责人和创建人；`composite_output` 继承任务负责人。修改策略或人员归属不改写历史。不能从 `created_by` 猜测历史成片负责人。人工任务只选创建者当前有效的“我的素材”；高级运营和管理员可在权限内代创建，但所选负责人必须匹配策略。自动和主动执行策略从策略团队、游戏匹配的 `material` 中取材，不依赖策略创建者的 `material_usage`。
6. **不同判据。** 素材库“我的使用”和“使用情况”只以成功成片为使用事实；“加入状态”单独来自当前用户的 `material_usage`。同一 `(策略, 素材)` 是否可新建任务继续按既有任务记录防重；失败任务不算素材已使用，却仍须回到原任务重试。
7. **跨团队同作品。** `source_content` 和 `material` 的业务状态继续按团队独立。后续可按外部作品身份或文件 Hash 复用昂贵抓取、封面、媒体和对象存储资源；共享层不得承载团队游戏、审核或处理状态。

## Consequences

- 普通运营、管理角色的筛选范围与服务端授权须分别验证，不能靠隐藏控件实现权限。
- 新负责人字段和接口变更须由 Cloud 正式 migration／合同承载；历史未知负责人保持未知或可核实后回填，不制造虚假归属。
- M6 发布、互动、统计的权限与业务流程不在本决策内；发布次数等口径可定义，页面需等真实 `publication` 查询能力交付。
- 实施范围和验收分别由 M3、M4、M5 的后续闭环承载，旧里程碑已通过的验收记录不改写。
