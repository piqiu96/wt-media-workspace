# ADR-0023：M3–M5 团队公共资源与成片负责人边界

- Status: Accepted；游戏术语、字段和标识由 [ADR-0028](0028-flat-business-categories.md) 收敛为扁平类目，团队范围与负责人边界不变
- Date: 2026-10-26
- Scope: M3 内容池／挖掘策略／挖掘任务，M4–M5 素材与内容生产
- Supersedes: [ADR-0014](0014-m3-team-content-scope.md) 中“同团队运营均可修改、执行挖掘策略”的角色结论；其团队业务隔离、游戏归属与筛选、来源唯一键继续有效。

## Context

内容池和素材库是团队公共资源，个人“我的素材”是工作集。合成策略、任务和成片则需要明确最终运营负责人。把负责类目直接当作公共资源的强授权边界，会妨碍同团队协作；把团队公共素材当作个人工作集，又会让自动执行依赖策略创建者。

## Decision

1. **Cloud 业务范围与 Desktop 入口。** 管理员可跨团队查看和管理 M3–M5 Cloud 业务数据；高级运营只在所属团队内，可覆盖该团队所有类目。两者可以登录 Desktop 并进入 M3–M5 共用 Cloud 业务页面，Cloud Web 与 Desktop 页面遵循同一服务端授权。M2 本机浏览器操作仍受原有角色准入和当前用户身份约束；Local Agent、BitBrowser、Cookie、Profile 和本机文件不得因 Cloud 管理权限而开放给他人。
2. **公共资源。** `source_content` 内容池和 `material` 素材库按团队隔离，普通运营可查看、处理本团队所有类目的公共内容。游戏是多选筛选，普通运营和高级运营初次默认选中本人负责的游戏；管理员先选目标团队，默认该团队全部游戏。调整筛选不改变团队授权。
3. **个人工作集。** `material_usage` 只表示当前用户的“我的素材”，高级运营和管理员也不能把他人的工作集作为自己的人工选材来源。本机下载原素材要求当前用户有有效工作集关系。
4. **策略与负责人。** 挖掘策略及任务异常由高级运营管理本团队、管理员跨团队管理，普通运营处理内容池。合成策略按团队、一个游戏、一个有效运营负责人限定适用性；高级运营创建时自动归本团队，管理员创建时选目标团队。普通运营只使用指定给自己的合成策略。
5. **生产归属。** `compose_strategy` 指定负责人；`compose_task` 创建时保存实际负责人和创建人；`composite_output` 继承任务负责人。修改策略或人员归属不改写历史。不能从 `created_by` 猜测历史成片负责人。人工任务只选创建者当前有效的“我的素材”；高级运营和管理员可在权限内代创建，但所选负责人必须匹配策略。自动和主动执行策略从策略团队、游戏匹配的 `material` 中取材，不依赖策略创建者的 `material_usage`。
6. **不同判据。** 素材库“我的使用”和“使用情况”只以成功成片为使用事实；“加入状态”单独来自当前用户的 `material_usage`。同一 `(策略, 素材)` 是否可新建任务继续按既有任务记录防重；失败任务不算素材已使用，却仍须回到原任务重试。
7. **跨团队同作品。** `source_content` 和 `material` 的业务状态继续按团队独立。后续可按外部作品身份或文件 Hash 复用昂贵抓取、封面、媒体和对象存储资源；共享层不得承载团队游戏、审核或处理状态。

## 2026-10-27 追加决议（CHG-20261026-104）

1. **使用情况可见性。** 素材库“使用情况”只对高级运营和管理员渲染；普通运营不显示该列、筛选和详情段，服务端也不返回使用人姓名。高级运营/管理员的列表只给一行可点摘要：无成功成片 `—`，有成片无已知负责人 `成片 N`，有已知负责人 `成片 N · 使用 M 人`；点击后用弹窗展示已知使用人与各自成片数，多人可滚动。不使用“暂无成功成片”“负责人未记录”“姓名不可见”等占位文案。
2. **类目筛选口径。** 素材库与成片的类目选项只列类目管理当前启用的游戏，默认选中本人负责且已启用的游戏（管理员默认所选团队全部）；类目选择只作筛选。成片列表新增 `category_id`，普通运营指定非本人负责类目时服务端返回 403，不静默放宽；高级运营/管理员仍按团队裁决。
3. **执行结果不明确的核对。** 由 M5-C6 的“仅管理员”放宽为管理员或同团队高级运营。普通运营即使能看到任务也不能提交核对；跨团队高级运营按不可见处理；两项确认（旧进程已停止、无已提交成片）和至少 20 字可核对依据不变，核对人与审计可读回。CHG-097 的已完成证据保留为当时事实，不回写。
4. **历史无负责人数据。** 负责人链路补齐前的无负责人任务、成片和策略按用户 2026-10-27 决定物理清理，不备份、不回填 `created_by`；审计日志保留，对象存储对象不在数据库清理范围内。清理不改变“历史归属无可靠依据时保持未知”的原则。

## 2026-10-27 追加决议（CHG-20261026-105）

1. **团队素材候选。** 定时与“立即执行”的系统候选只按策略团队取正式 `material`；游戏不匹配的素材不入选并记录 `other_game`，不再依赖策略创建者的 `material_usage`。人工“我的素材”入口不变，仍只从创建者当前有效的关系取材。策略创建者被禁用不再阻断执行；负责人失效仍是唯一的人员门禁。
2. **个人关系可空。** 自动任务与成片不替创建者或负责人写 `material_usage`，`compose_task.material_usage_id` 与 `composite_output.material_usage_id` 允许为空并保留外键。人工记录保留原值，不回填。`created_by` 保持策略创建者（系统代其调度），只是审计来源；任务与成片归属只看 `operator_id`。
3. **高级运营策略范围。** 高级运营管理本团队所有类目的策略、启停、主动执行与运行记录，不再按本人负责类目收窄；普通运营只使用指定给自己的策略，管理员跨团队。负责人“须负责该游戏”的硬匹配不变。
4. **运行任务列表。** 策略运行记录的任务列表由 `GET /compose-strategies/{strategy_id}/runs/tasks` 提供；无对应 run 返回 404，页面不渲染零值 run。

## 2026-10-27 追加决议（CHG-20261015-098）

1. **使用情况可见性（覆盖 CHG-20261026-104 第 1 条）。** 素材库“使用情况”的列、筛选与详情段对所有角色渲染；普通运营只看到成功成片数与使用人数，服务端仍不返回使用人姓名。高级运营/管理员的摘要与弹窗口径不变。
2. **类目选择口径（扩展 CHG-20261026-104 第 2 条）。** 所有页面的类目筛选、表单与人工导入选项只列启用类目：合成策略列表筛选与新建策略、创建合成任务的素材筛选、内容池筛选与人工导入、挖掘策略表单、用户列表筛选。默认负责类目与启用集合取交集，交集为空时不带类目条件。历史行名称解析仍读全量目录；类目管理页仍展示全部状态。编辑挂在停用游戏上的历史挖掘策略时，当前类目作为禁用选项显示并标注已停用。
3. **触发方式文案。** 合成策略运行记录、合成任务、成片管理统一为“策略自动 / 人工创建”，由前端公共常量提供。挖掘任务页的“重试 / 定时 / 手动”是挖掘任务的触发口径，不并入。

## 2026-10-27 追加决议（CHG-20261015-098，系统管理与桌面角色）

1. **系统管理可见性。** 用户管理只对管理员可见且可写；运营团队与类目管理对高级运营与管理员可见，高级运营只读。桌面端与 Cloud Web 使用同一张路径表与同一判据；桌面端复用 Cloud 的页面组件文件，不另写一套。团队人数由服务端随团队列表返回（`OperationTeam.user_count`），页面不再读用户列表——那条接口对高级运营是 403，会让整列显示 0。
2. **类目管理只读视图。** 高级运营的 `scope=management` 返回全部状态的游戏，但不返回关联摘要；关联详情仍只对管理员开放。普通运营访问 `management` 返回 403。
3. **桌面环境。** 本地日志与本机设置对运营与高级运营可见，管理员不可见；路由守卫与菜单使用同一判据。Desktop 仍只接受三种角色登录。
4. **账号本地操作按归属。** 社媒账号页对三种角色可见；本地检查、读 Cookie、窗口绑定只由账号本人在 Desktop 执行——普通运营与高级运营都可操作自己创建的账号，高级运营对同团队他人账号只读，管理员对所有账号只读。开户、浏览器窗口、代理仍是普通运营专属的本机执行面。
5. **导航不是授权。** 菜单隐藏只减少误入；每一处写入口与本地动作仍分别由服务端与页面内判定把关。
6. **本机执行凭证。** Agent Token 对运营与高级运营签发，管理员可登录 Desktop 使用共用页面但不取得凭证；登录或切换角色后 sidecar 按角色启动或停止。取得凭证不等于能操作他人账号：每个本地动作仍过账号归属门禁，异步 Cookie 读取与同步检查、同步读取同一套判定。

## Consequences

- 普通运营、管理角色的筛选范围与服务端授权须分别验证，不能靠隐藏控件实现权限。
- 新负责人字段和接口变更须由 Cloud 正式 migration／合同承载；历史未知负责人保持未知或可核实后回填，不制造虚假归属。
- M6 发布、互动、统计的权限与业务流程不在本决策内；发布次数等口径可定义，页面需等真实 `publication` 查询能力交付。
- 实施范围和验收分别由 M3、M4、M5 的后续闭环承载，旧里程碑已通过的验收记录不改写。
