# ADR-0025：代理团队范围与服务端健康检测

- Status: Accepted
- Date: 2026-10-28
- Scope: 代理管理、浏览器窗口的代理关系、代理导入与检测
- Related: CHG-20261028-099、ADR-0008、ADR-0023

## Context

代理原为全局资源池：列表不区分团队，检测由运营工作站上的 Local Agent 代理执行。V3 要求代理按团队共享、普通运营只能看到本人团队的资源，并把检测从本机迁到 Cloud。若检测仍依赖 Agent，运营电脑离线或比特浏览器未启动时，代理健康状态就无法更新；若团队归属只靠页面过滤，跨团队读写仍可能从接口进入。

存量代理没有团队事实，无法可靠回填。用户裁定：迁移时整体清理存量代理，后续新增必须带团队。

## Decision

1. **代理归属团队。** `proxy_configs.team_id` 必填。普通运营和高级运营固定本人团队；管理员可跨团队读写。服务端按角色与团队校验，列表与详情使用同一范围，页面筛选只是视图。
2. **存量整体清理。** 迁移 `20261028_077` 删除全部存量代理，并依靠 `browser_profiles.proxy_id -> proxy_configs` 的 `ON DELETE SET NULL` 把窗口上的正式关系置空；窗口、账号关系与备注保留。
3. **检测归 Cloud。** 连通性探测由 Cloud 进程直接对已保存的协议、主机和端口发起，返回 `ok`、`conn_failed`、`auth_failed`、`timeout`、`invalid_params`。它不依赖本机 Agent、比特窗口或某台工作站在线。只有 `ok` 且未停用、未到期、有剩余配额的资源可分配。
4. **结果绑定连接版本。** 检测结果只在代理仍保持被探测的连接时写入。地址编辑后，迟到的旧结果被丢弃，不能把新连接标成正常或失败。
5. **角色分工。** 普通运营维护名称、地区、供应商、标签和备注；高级运营与管理员额外管理连接信息、到期、配额、启停和删除。凭据只在详情返回，列表与窗口页不返回密码；动态提取 URL 只写不回显。
6. **配额与删除在服务端收口。** 配额不得低于正式占用；分配前的检查与写入使用代理级命名锁串行化。资源被窗口正式引用时拒绝物理删除，只能停用。
7. **代理关系仍由窗口侧写入。** 代理管理页不直接改写比特窗口；窗口页通过 Agent 写入并读回后才更新 Cloud 关系。动态地址提取仍在本机执行，因为要使用运营可用的网络。

## Consequences

- Positive：代理检测不再受工作站在线状态影响，健康事实只有一个来源。
- Positive：团队范围与角色在服务端收口，跨团队读写有明确拒绝路径。
- Negative：Cloud 需要具备访问外网代理端点的能力；受限网络下会出现统一的连接失败或超时结果。
- Negative：迁移清理是不可逆的数据删除。已部署环境若仍需旧代理数据，只能从迁移前备份恢复。
- Negative：BitBrowser 标签尚未接入 Agent 与 Cloud 合同，本期只在 Cloud 维护代理标签；比特侧标签同步需另立 CHG。
- Follow-up：动态提取、代理自有标签同步与检测并发上限若成为瓶颈，再单独评估，不把本机执行重新引入健康检测。
