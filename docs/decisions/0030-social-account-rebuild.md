# ADR-0030：未上线社媒账号整体重构

- Status: Accepted
- Date: 2026-10-30
- Scope: 社媒账号、Cookie 接入与检查，Cloud / Desktop / Agent
- Supersedes: 未上线账号旧方案（原 ADR-0010，历史保留在 Git）；ADR-0027 对原社媒账号表集合的限定。ADR-0027 的其他资源与职责边界继续有效。

## Context

原社媒账号没有投入使用。需求方已确认 V7 及矩阵运营场景，并授权直接重构需求、设计、数据和接口，清理废弃实现。旧文档的三种上号、V3 页面冻结和未分类阻止检查与确认目标不一致。继续兼容会扩大实现和运营成本。

## Decision

1. 只有一套社媒账号流程，按当前 PRD 与原型实施；不保留旧开户入口、旧接口兼容层和旧业务数据迁移项目。正确的公共窗口、代理、类目和本机执行能力继续复用。
2. 启停使用 enabled 布尔值，与平台登录结论分离。资料编辑不能写平台身份或登录状态。检查保留“本次执行结果”和“最近有效结论”，同 UID 刷新资料，不同 UID 只展示对照，不自动接管。
3. 人工完成浏览器登录后可手动识别，不以 Cookie 已入库或已分类为前置条件。只读检查不写浏览器 Cookie。
4. 账号领域保留 media_accounts、media_account_categories、media_account_tags，新增一张 media_account_import_batches。批次 content_json 顶层保存可变批次信息，items 数组保存单项，固定行号与批次 ID 定位，不生成逐项 UUID。不建立 Cookie 版本表、接入明细表、通用 operation、任务、敏感许可、审计或历史中心；Agent 不保存第二套业务库。
5. CK 明细直接存账号表：保留 original_cookie/active_cookie，补 before_cookie 与当前 cookie_update JSON；批次接入尚未形成账号时，必要输入/写前值保存在单项，成功后事务转存并移除重复凭证。只保留最初输入、当前确认、最近写前值与当前未收敛处理，不建设版本链或凭证历史。写前保护失败不执行，目标平台隔离，未知先核实，数据库事务不冒充跨 BitBrowser 原子性。
6. 批次以 user_id+request_key 防重复创建，以 revision 和步骤/尝试次数校验防止旧 JSON 覆盖和迟到结果；窗口写入以现有窗口表上的当前 Cookie 操作占用防冲突，短事务取得/结算，不跨浏览器调用持锁。单项短操作沿用 Vue → Tauri → Agent → BitBrowser；Cloud 校验并结算业务结果。Cookie 接入逐项执行，批次事实在 Cloud；关闭页面可暂停，重新进入先查看和核实，不承诺后台无人值守。窗口优先新建，不能确认创建结果时不重复创建；复用需要确认目标平台无占用或残留登录。
7. 删除没有业务消费者的独立账号组 API/表及自动创建账号即成功的旧开户流程。后续任务按筛选结果固化账号 ID，不以本次重构预建账号组产品。
8. 当前未上线业务不要求迁移兼容，不等于可删除外部真实窗口或清空会话。迁移不包含 BitBrowser 删除、清 Cookie 或自动登录动作；共享数据库变更用新的顺序迁移，旧迁移作为建库链保留。

9. 同一用户的同平台 UID 可在不同窗口各自保留运营记录，登录结论与 Cookie 按窗口独立；不新增账号主表/窗口关系表。移除用户+平台+UID 的唯一约束、重复异常状态和 duplicate_of 依赖，同窗口同平台仍唯一。详情顶部按读取投影提示同 UID 其他窗口，可选查看，列表不设专门跳转主操作。已验证的批次同 UID 新窗口正常结算，不当失败或要求跳过。Cloud 契约与共用页面协调更新，Agent 本机执行接口不变。

## Consequences

- 当前 PRD 与 Engineering 直接替换冲突正文；旧历史理由不悄悄改写，引用迁移后清理无独立价值的重复内容。
- Cloud 与 Agent 提供方契约先更新，再同步 Vue、Desktop DTO 和契约锁；破坏性改动不做双写和长期兼容。
- 数据模型、接口目录、清理边界与验证规则见[社媒账号设计](../engineering/specs/social-accounts.md)。
