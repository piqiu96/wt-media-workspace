# M3 内容挖掘：有效产品基线 V2

> 更新：2026-09-23。依据：用户明确提供的 M3 Milestone；决策见 ADR-0013（第 3 条已按 2026-09-23 确认结果增补）。
> 本文替代旧第四章“内容发现”的 M3 业务范围。已确认要求与待决细节严格区分；未列入的旧功能不自动成为新版本交付承诺。
> 落点：`docs/product/`。交付拆分见 `delivery/milestones/M3-content-discovery-v2.md`，本文不记录实施进度。团队范围决策见 ADR-0014，执行边界见 ADR-0015。

## 1. 目标与产品结构

建设外部内容进入 WT Media 的统一自动化入口，持续获得可供后续生产使用的内容来源。

内容挖掘包含且仅包含三个核心子模块：

- 内容池：人工主动发现入口及所有正式来源内容的统一处理页面。
- 挖掘策略：定义自动发现的业务规则。
- 挖掘任务：查看一次自动执行的记录、统计、状态和错误。

流程：外部来源 → 人工导入/搜索或自动挖掘 → source_content → 人工筛选或按策略规则自动转素材 → material → 后续内容生产。

当前仅实现抖音；未来渠道预留抽象，不承诺本期支持。素材创建仅代表元数据已提交，不能显示视频已下载或可用于合成。

## 2. 内容池的三个主动入口

| 入口 | 用户操作与正式写入时点 | 不允许的副作用 |
| --- | --- | --- |
| 分享链接 | 输入单/批量分享链接 → 点击解析并入池 → 识别平台、解析、补齐有效信息 → 创建或更新 source_content | 不自动建 material；失败链接不建残缺来源 |
| 关键词搜索 | 输入关键词 → 搜索/加载结果 → 选择加入内容池 | 未选择结果不写正式来源或素材 |
| 博主搜索 | 输入名称/账号/主页 → 定位博主 → 获取作品 → 选择加入内容池 | 不按模糊昵称静默认定唯一作者；未选择作品不入池 |

主动入口可用短期技术查询任务，但不创建代表自动挖掘的 crawl_task。界面保留失败条目与已加载结果，批量独立处理，已成功条目不因其他失败而回滚。链接入池意图在提交时已经给出，不强加第二次“选择导入素材”确认。

作者名称有歧义时应展示候选身份供选择；若供应接口不支持名称查找，不能用只能输入 ID 的实现宣称博主搜索完整通过。

单批数量、分页和限流根据接口实测确定；参考图中的样例数量不代表已测试容量。

## 3. 内容池管理与素材转换

列表至少展示封面、标题、平台、作者、来源方式、发布时间、处理状态与操作。来源方式应区分链接、关键词搜索、博主搜索和策略发现，技术枚举由提供方合同细化。

状态：

| 状态 | 说明 |
| --- | --- |
| pending | 待处理 |
| material_created | 已转素材 |
| ignored | 已忽略 |

支持列表/详情、条件检索、单条/批量转素材、忽略与恢复。恢复不删除历史处理事实；不能借恢复生成重复素材。外部可访问性独立于处理状态，外部作品下架不自动改变人工处理状态。

转素材：

1. 校验当前用户对来源的处理权限。
2. 在单条事务中锁定来源、检查已有 material、创建或关联 material、更新来源状态并记录处理人/时间。
3. 创建失败不把来源标为 material_created；允许重试。
4. 批量逐条独立提交，返回每条真实结果。
5. 素材库最小只读列表/详情能读回来源关联及精简不可变快照。

数据库规则：`source_content.team_id` 必填；同一团队内 unique(team_id, platform, platform_content_id)；unique(material.source_content_id)。source_content 不反向保存 material_id。跨团队同作品允许独立业务记录。

重复发现只更新允许变化的最新来源信息，不覆盖素材业务字段、不可变来源快照、人工忽略状态和首次来源。自动发现不会恢复 ignored；人工恢复/转素材必须显式操作。跨运营范围的忽略语义仍需确认。

## 4. 挖掘策略

统一对象 discovery_strategy：

- strategy_type：当前 keyword / author；
- channel_type：引用 content_channel，当前仅抖音；
- 名称、对应关键词列表或稳定作者身份、启停状态；
- 页面可配置关联的执行周期，并展示最近执行时间、执行记录；
- 关键词与博主策略共用生命周期，不分别建 keyword_strategy / author_strategy。

策略配置与执行分离：

- 策略定义“找什么”；执行周期描述“何时触发”。
- Cloud Scheduler 负责时间计算与触发，任务承担一次执行记录，Cloud Crawler 执行外部请求；M3 不创建 Agent 任务，也不由 Desktop 参与。
- 页面显示“每天 09:00”或“每若干小时”等业务配置，不提供 Cron 编辑器、节点编排或可视化调度器。
- 具体支持的周期集合、时区、启用是否立即执行、作者首次处理范围是实施前待决项。
- 编辑只影响后续创建任务；历史任务保留当次配置快照。
- 停用后不创建新周期任务，在途任务按已记录快照完成；历史策略/任务/来源保留。

策略可配置自动转素材。规则字段：

| 字段 | 含义 |
| --- | --- |
| `auto_material` | 是否自动转素材；关闭时策略结果全部进入内容池 |
| `material_rule` | `AND` 或 `OR` |
| 阈值 | 例如点赞、收藏；大于 0 参与规则，小于等于 0 忽略 |

`auto_material` 为真时至少需要一个正阈值；`AND` 要求全部正阈值通过，`OR` 要求任一通过。命中的发现结果入池后按规则自动转为 material，未命中的留在内容池等待人工处理。任务统计须分别显示发现、新增、自动转素材与待审核数量；自动入池不等于已完成生产。

> 2026-09-23 更新：本版原写“不提供自动转素材开关”，与实施结果冲突。用户已确认自动转素材为 M3 范围内的正式能力，本节按确认结果改写；ADR-0013 第 3 条随之增补。PRD 融合按 `delivery/milestones/README.md` 的 Milestone-first 规则留待 M3 完整验收后处理。

旧版高级筛选、两种作者首次模式、立即执行/人工任务重试按钮不因旧文档存在而自动加入新页面，是否保留须明确决策。

## 5. 挖掘任务

crawl_task 记录一次脚本或后台调度触发的自动挖掘执行，不承担业务配置或工作流定义。必须能追溯策略、当次配置、渠道、触发来源及计划时间。

业务状态五种：

| 状态 | 含义 |
| --- | --- |
| pending | 已创建，待执行 |
| running | 执行中 |
| success | 成功 |
| failed | 失败 |
| partial_success | 部分成功：至少一项失败且至少一项成功入池 |

多关键词或批量作品部分失败时，不丢弃已成功入池结果；应显示成功事实、失败数量及原因。这类部分失败由 `partial_success` 表达，界面显示为“部分成功”，可仅对失败项重新执行；不让技术 task 成功直接决定业务 success。

> 2026-09-23 更新：本版原写“不新增 partial 第五态”。该状态已端到端落地并有真实证据（任务状态、失败项重试），本节按实施事实改写。

任务列表/详情包含：

- 任务 ID、策略名称、渠道、任务类型、开始/结束时间、状态；
- 扫描数量、发现数量、新增数量、重复数量、失败数量；
- 错误原因、执行日志和必要的阶段摘要。

统计须区分单位：接口失败不等同于“1 条作品失败”；关键词级、作品级数量不可混加。明确计数口径、未扫描范围、重试去重和并发新增归属后再定正式合同，不能仅让界面数字相加好看。

同策略已有 pending/running 任务时不重复排队；同策略同计划周期幂等防重；跨策略发现同作品由全局唯一约束兜底。重启恢复不重复入池、不篡改终态统计，不批量补跑全部历史周期。有限网络重试属于运行保障，不等于建设用户自定义流程。

不建设 crawl_result、全量任务作品历史、多版本 raw_json、执行中人工取消或新工作流状态机。

## 6. 渠道扩展与运行视图

content_channel 是受控渠道能力抽象；不要求本期增加渠道后台或独立数据库表。channel_type 与 strategy_type 分别表达来源渠道和发现方式；不得把二者混成 douyin_keyword 一类组合业务类型。

至少能描述：链接解析、内容详情、关键词搜索、作者查找/作品列表是否受支持。未来接入新渠道允许新增适配实现和合同，但不重复建设内容池、策略和任务业务模型；不承诺未来零代码修改。

业务流转视图只读展示策略 → 定时触发 → 任务 → 内容池 → 素材，状态必须来自真实业务记录，不创建新的工作流实例。素材未生成时展示未转素材，不将自动入池画成已完成生产。

参考图用于页面结构、层级和 WT 视觉规范；B站、快手等预留内容不可点击执行，图片中的数据不作为真实证据。

## 7. 边界与权限

不做视频下载、文件存储/校验、剪辑、AI 评分、自动生产、发布、互动和数据分析；不建设通用工作流引擎、任意脚本执行、渠道插件市场或其他平台的真实采集。

权限沿用三角色框架。按 ADR-0014，M3 内容仅按业务团队隔离：同团队运营全量可见，管理员跨团队可见；不做游戏维度和跨团队共享。服务端必须执行授权，不能由客户端过滤替代。

凭据留在服务端；内容详情和日志不得泄露供应方凭据；原始数据与技术错误按权限脱敏。正式合同归 Cloud 提供方，Desktop 只复用 Web，不复制业务规则。

## 8. 最终验收

- 链接、关键词搜索、博主搜索均能通过真实接口入池；未选搜索结果零正式写入。
- 两种策略均能通过真实周期触发、生成 crawl_task、执行并自动入池；只创建配置或任务列表不算完成。
- 各入口汇入同一来源身份；重复与并发不重复建素材，来源/素材可追踪。
- 自动转素材关闭时入池后无 material、人工转换后素材库可读回；开启时命中规则的结果自动生成 material 且可从任务统计读回；错误时不出现假成功。
- 自动转素材规则（`auto_material`、`material_rule`、各阈值）的命中与未命中均有真实证据；阈值全为非正数时不得静默视为全部命中。
- 任务统计、失败原因、受控故障恢复有真实证据，五态边界（含 `partial_success` 与失败项重试）已确认。
- 三页面及只读流转视图沿用 WT UI，权限拒绝、M2 回归、Cloud Web/Desktop 走查通过。
- 用户最终验收前不得标记 M3 DONE。
