# 第四章：内容挖掘 V2 正式需求文档（M3）

> 本文档为第四章「内容挖掘」的正式产品需求基线。
> 依据：ADR-0013（第 3、7 条已增补）、ADR-0014（团队范围）、ADR-0015（执行边界）、ADR-0023（2026-10-26 后续角色与公共资源裁定）。
> 博主搜索与作者策略已于 2026-09-23 暂停，本期不交付、不计入验收。
> 本文替代 V1“内容发现”的 M3 业务范围；未列入的旧功能不自动成为新版本交付承诺。
> 实施状态、验收证据与缺陷跟踪见 `delivery/milestones/M3-content-discovery-v2.md`，本文只定义需求。

## 4.1 模块概述

### 4.1.1 模块定位

内容挖掘建设外部内容进入 WT Media 的统一自动化入口，持续获得可供后续生产使用的内容来源。

内容挖掘包含三个核心子模块：

- 内容池：人工主动发现入口及所有正式来源内容的统一处理页面。
- 挖掘策略：定义自动发现的业务规则。
- 挖掘任务：查看一次自动执行的记录、统计、状态和错误。

内容挖掘的输出是 `material`，进入第五章「素材生产」。素材创建仅代表元数据已提交，不能显示视频已下载或可用于合成。

### 4.1.2 建设目标

1. **统一来源入口**：人工发现与自动挖掘都沉淀为同一来源对象 `source_content`，不按入口维护两套内容记录。
2. **自动化获取内容**：策略按确认的周期真实触发，经 `crawl_task` 执行并回报结果，不把配置保存或任务列表当作自动化已完成。
3. **保留人工筛选**：自动发现结果进入内容池；只有命中策略规则时才自动转素材，其余由运营显式处理。
4. **边界清晰**：内容挖掘只负责获取与筛选来源；素材下载、合成、发布、互动与数据分析不在本章范围。

### 4.1.3 核心能力

| 子模块 | 核心能力 |
| --- | --- |
| 内容池 | 两个主动入口、列表与详情、条件检索、单条/批量转素材、忽略与恢复、审核模式 |
| 挖掘策略 | 统一 `discovery_strategy`、关键词配置、执行周期、自动转素材规则、启停与快照 |
| 挖掘任务 | 五态任务记录、任务项六态、统计口径、失败项重试、调度与防重、恢复 |

### 4.1.4 模块边界

- 当前仅实现抖音；未来渠道预留抽象，不承诺本期支持。
- 博主搜索与作者策略本期暂停：不交付、不计入验收；接口、字段与枚举保留，后续版本再评估。
- 不交付独立的只读业务流转视图；不建设通用工作流引擎、任意脚本执行、渠道插件市场或其他平台的真实采集。
- 不做视频下载、文件存储/校验、剪辑、AI 评分、自动生产、发布、互动和数据分析。
- 素材创建仅代表元数据已提交，不能表示视频已下载或可用于合成。
- 旧版高级筛选、两种作者首次模式、立即执行/人工任务重试按钮不因旧文档存在而自动加入新页面；是否保留须明确决策。

## 4.2 内容挖掘流程

### 4.2.1 人工发现流程

```text
外部来源
→ ID/链接发现 或 关键词发现
→ source_content
→ 人工筛选
→ material
→ 第五章：素材生产
```

运营在内容池通过两个主动入口提交入池意图；未选择搜索结果不写正式来源或素材。入池后由运营逐条或批量转为 `material`，第五章素材库从正式 `material` 查看来源关联。

### 4.2.2 自动挖掘流程

```text
discovery_strategy
→ 周期触发
→ crawl_task
→ Cloud Crawler / Worker 执行
→ source_content
→ 命中 auto_material 规则时自动转 material
→ 第五章：素材生产
```

策略定义“找什么”，执行周期描述“何时触发”。自动发现的未命中项留在内容池等待人工处理；自动入池不等于已完成生产。

### 4.2.3 人工与自动发现的统一和差异

- 两类发现都写入同一 `source_content` 身份，受同一团队唯一约束与全局去重规则约束。
- 人工关键词任务走 `import-results`，各条目要么成功要么整体失败，无法达到 `partial_success`。
- 自动按 ID/链接逐目标抓取的路径可以出现部分成功；`partial_success` 主要来自该路径。
- 自动策略可按 `auto_material` 规则自动转素材；人工路径必须显式提交转素材操作。
- 无论人工还是自动，重复发现都不覆盖素材业务字段、不可变来源快照、人工忽略状态和首次来源。

### 4.2.4 核心对象关系

```text
discovery_strategy（channel_type → content_channel）
→ crawl_task
→ source_content
→ material
→ 第五章：素材生产
```

- `discovery_strategy` 引用 `content_channel`；`strategy_type` 表达发现方式，`channel_type` 表达来源渠道，不合并成组合业务类型。
- `crawl_task` 记录一次自动执行，必须可追溯策略、当次配置、渠道、触发来源及计划时间。
- `source_content` 是统一来源身份；`material` 只通过显式转素材或策略规则创建。

## 4.3 内容池（source_content）

### 4.3.1 功能定位

内容池是人工主动发现入口及所有正式来源内容的统一处理页面。它承担来源入池、筛选、忽略/恢复和转素材。

### 4.3.2 主动入口

界面「发现内容」下拉提供两个入口：

| 入口 | 用户操作与正式写入时点 | 不允许的副作用 |
| --- | --- | --- |
| ID/链接发现 | 输入视频 ID 或分享链接（纯 ID、`douyin.com/video/<id>`、`v.douyin.com` 短链）→ 搜索 → 选择加入内容池 | 未选择结果不写正式来源或素材；失败目标不建残缺来源 |
| 关键词发现 | 输入关键词 → 搜索/加载结果 → 选择加入内容池 | 未选择结果不写正式来源或素材 |

两个入口都走 `POST /content-pool/search`：`ID/链接发现` 用 `query` 模式，`关键词发现` 用 `keyword` 模式；选择结果后由 `POST /content-pool/import-results` 提交入池。

不设置独立的“分享链接”入口；所谓“解析即入池”的意图在 `import-results` 提交时给出。遗留接口 `POST /content-pool/import-url` 在界面侧零调用，仅作兼容保留。

**博主搜索**（2026-09-23 暂停）：入口设计为输入名称/账号/主页 → 定位博主 → 获取作品 → 选择加入内容池；不按模糊昵称静默认定唯一作者，未选择作品不入池。该入口本期不交付、不计入验收，接口、字段与枚举保留，后续版本再评估。暂停期间不得以作者 ID 输入或占位数据宣称该入口可用。

主动入口可使用短期技术查询任务，但不创建代表自动挖掘的 `crawl_task`。界面保留失败条目与已加载结果，批量独立处理，已成功条目不因其他失败而回滚。链接入池意图在提交时已经给出，不强加第二次“选择导入素材”确认。

数量口径：ID/链接发现单批不超过 100 个目标、按 10 个分批；关键词搜索默认返回 20 条、上限 30 条，有分页。

### 4.3.3 来源方式

列表展示来源方式。来源方式四枚举与界面标签：

| 枚举 | 界面标签 |
| --- | --- |
| `link` | ID/链接发现 |
| `search` | 关键词发现 |
| `author` | 博主发现（暂停期间不产出） |
| `strategy` | 挖掘策略 |

列表另有「来源」列，按来源实体而非来源方式区分，把原先的「来源策略」「来源任务」两列合并为一列：

- 有 `strategy_id` 的来源显示可点击的策略名称，打开只读的「来源详情」抽屉，合并展示策略（名称、类型、关键词 / 作者、执行周期）与任务（任务 ID、触发方式、状态、创建时间、完成时间、结果概况）的关键信息；任务快照读取失败时保留策略事实并给出错误与重试，不伪造字段。
- 抽屉页脚在对应 id 存在时提供「前往策略页面」「前往任务页面」；跳转前关闭抽屉，原列表的筛选与分页保持不变。
- 人工来源显示固定文案「人工」，不可点击，也不提供任务跳转。只有 `crawl_task_id`、没有 `strategy_id` 的历史来源行同样显示「人工」。

### 4.3.4 处理状态

内容池处理状态三值：

| 状态 | 说明 |
| --- | --- |
| `pending` | 待处理 |
| `material_created` | 已转素材 |
| `ignored` | 已忽略 |

任务项处理状态另有六值，属于任务范畴而非内容池状态，见 §4.5.4。

### 4.3.5 列表、检索与详情

列表至少展示封面、标题、平台、游戏、作者、互动（浏览/赞/藏）、来源方式、来源、发布时间、入库时间、处理状态与操作。「来源」列按 §4.3.3 的规则合并策略与任务；详情抽屉保留完整的来源追溯链接。「平台」列与详情显示平台中文名（当前为抖音），不直接渲染 `douyin` 一类存储代码；筛选与人工导入的「平台」选项只列当前已接入的平台，不显示“待接入”的不可选占位。

入库时间即来源进入内容池的时间（`created_at`），列表列名与详情字段统一称「入库时间」，不使用「发现时间」：发现是策略与任务的执行事实，入池时间不等于发现时间，混用会让用户以为该列记录的是抓取时刻。

操作列按处理状态收敛到统一按钮名：待处理为「转素材 / 忽略 / 详情」，已忽略为「恢复 / 详情」，已转素材只留「详情」。不设「素材详情」一类按状态分叉的第二详情按钮；查看已生成素材的入口在详情抽屉的「关联素材」。

内容池支持列表/详情、条件检索、单条/批量转素材、忽略与恢复。恢复不删除历史处理事实；不能借恢复生成重复素材。外部可访问性独立于处理状态，外部作品下架不自动改变人工处理状态。

内容挖掘的三个列表页（内容池、挖掘策略、挖掘任务）都不设刷新按钮，默认每 10 秒自动重读。详情、来源、人工导入、策略编辑等抽屉/弹窗/表单打开，或有选中行、审核模式、批量操作进行中时暂停这一拍；页面不可见时同样暂停。定时读取不显示整页 Loading、不重置页码与筛选，失败保留上一次读数；用户主动查询仍显式报错。

### 4.3.6 审核模式

内容池提供逐条审核队列，按待处理队列依次处理；每条可「转素材并下一条」「忽略并下一条」或「跳过」，用于替代批量勾选的高效流转场景。

### 4.3.7 与素材库的边界

内容池的正式对象是 `source_content`；“素材库”的正式对象是第五章的 `material`，展示来源、准备状态、加入状态和使用事实。不得再把 `/material-library` 定义为内容池 `status=material_created` 的只读别名，也不另建第二个素材对象。历史页面或路由若仍沿用只读模式，后续交付须收敛到 `material` 查询与详情。

### 4.3.8 转素材规则

转素材流程：

1. 校验当前用户对来源的处理权限。
2. 在单条事务中锁定来源、检查已有 `material`、创建或关联 `material`、更新来源状态并记录处理人/时间。
3. 创建失败不把来源标为 `material_created`；允许重试。
4. 批量逐条独立提交，返回每条真实结果；批量上限 500 条。
5. 第五章素材库的 `material` 列表/详情能读回来源关联及精简不可变快照。
6. 目标团队恒为来源内容所在的 `team_id`，转换时不提供团队选择，管理员也一样。转换成功后页面必须告知素材去向：单条转换展示素材编号、名称与目标团队；批量转换按目标团队聚合展示条数；审核模式不打断「转素材并下一条」，用非阻塞提示带出目标团队。运营与高级运营原本就能看到自己团队，保留原有轻提示即可。

自动转素材失败不得记为成功：来源留在待处理并记录失败原因，可重试。

### 4.3.9 数据与唯一性规则

- `source_content.team_id` 必填。
- 同一团队内 unique(`team_id`, `platform`, `platform_content_id`)。
- `material.source_content_id` 唯一；`source_content` 不反向保存 `material_id`。
- 跨团队同作品允许独立业务记录。
- 跨团队同作品的处理状态、游戏、忽略和转素材事实互不影响；昂贵的外部抓取结果、封面、源视频与对象存储文件可按外部身份和文件 Hash 安全复用，但共享资源不得保存团队业务状态。资源复用属后续 P1，不改变本章已完成的 M3 验收。
- 重复发现只更新允许变化的最新来源信息，不覆盖素材业务字段、不可变来源快照、人工忽略状态和首次来源。
- 自动发现不会恢复 `ignored`；人工恢复/转素材必须显式操作。

## 4.4 挖掘策略（discovery_strategy）

### 4.4.1 功能定位

挖掘策略统一保存自动发现需求，定义“找什么”；执行周期描述“何时触发”。策略配置与执行分离，策略本身不直接发起外部请求。

关键词策略与博主策略共用生命周期，不分别建 `keyword_strategy` / `author_strategy`。本期只有关键词策略在使用；`author` 取值保留，随博主搜索暂停延后。

### 4.4.2 策略结构

统一对象 `discovery_strategy`：

- `strategy_type`：本期为 `keyword`；`author` 已暂停（取值保留，后续版本再评估）。
- `channel_type`：引用 `content_channel`，当前仅抖音。
- 配置字段：`keywords`（列表）/ `keyword`（单关键词，二者取其一）、`author` 与 `author_id`（随 `author` 暂停延后）、`game_id`（必填，默认 `other`）、`platform`（本期仅 `douyin`）。
- 名称、启停状态（稳定作者身份随 `author` 暂停延后）。
- 页面可配置关联的执行周期，并展示最近执行时间、执行记录。

### 4.4.3 执行周期

- 策略的 `schedule` 配置使用三种确定语法：`manual`（手动执行）、`interval:<N>`（每 N 分钟）、`daily HH:MM`（每天固定时刻）；界面分别显示为「手动执行」「每 N 分钟」「每天 HH:MM」。时区默认 `Asia/Shanghai`。
- 页面显示业务配置，不提供 Cron 编辑器、节点编排或可视化调度器。
- 非法周期取值必须被拒绝，不得接受后原样入库。

### 4.4.4 策略配置与执行分离

- 策略定义“找什么”；执行周期描述“何时触发”。
- Cloud Scheduler 负责时间计算与触发，`crawl_task` 承担一次执行记录，Cloud Crawler 执行外部请求。
- M3 不创建 Agent 任务，也不由 Desktop 参与。
- 启用策略不触发立即执行：首次触发等下一个计划窗口。
- 编辑只影响后续创建任务；历史任务保留当次配置快照。
- 停用后不创建新周期任务，在途任务按已记录快照完成；历史策略/任务/来源保留。

### 4.4.5 自动转素材规则

策略可配置自动转素材。规则字段：

| 字段 | 含义 |
| --- | --- |
| `auto_material` | 是否自动转素材；关闭时策略结果全部进入内容池 |
| `material_rule` | `AND` 或 `OR`；其他取值必须拒绝，不得猜测或降级 |
| 阈值 | `like_threshold`、`favorite_threshold`；大于 0 参与规则，小于等于 0 忽略 |

`auto_material` 为真时至少需要一个正阈值；`AND` 要求全部正阈值通过，`OR` 要求任一通过。命中的发现结果入池后按规则自动转为 `material`，未命中的留在内容池等待人工处理。

任务统计须分别显示发现、新增、自动转素材与待审核数量；自动入池不等于已完成生产。

自动转素材失败不得记为成功：来源留在待处理并记录失败原因，可重试（见 §4.3.8）。

条件集合本期就是上表四项——开关、连接方式与点赞/收藏两个阈值。发布时间、时长、作者、是否带货等其他条件不属本期范围；新增条件须先有明确产品决策，不得按渠道或策略类型私自扩展，也不得把「未配置阈值」解释为「全部命中」。

### 4.4.6 自动转素材发布时间过滤（2026-10-13 确认，待实施）

新增一层独立的自动转素材过滤，首版只支持发布时间范围：不限、最近 1 天、最近 3 天、最近 7 天。它不改变挖掘关键词和来源入池条件，也不加入点赞／收藏的 `AND`、`OR` 表达式。

自动转素材开启时，来源先进入内容池，再按以下顺序判断：

1. 发布时间过滤：选择了时间范围而来源发布时间缺失或超出范围时，跳过自动转素材，来源留在内容池；
2. 点赞／收藏阈值：只有通过过滤的来源才按现有 `material_rule` 判断是否自动转素材。

“最近 N 天”以当次任务处理时间和策略时区计算，过滤配置随任务快照保存；未设置过滤相当于“不限”。跳过过滤不记作自动转素材失败。该增量已确认但尚未实施，实施与验收由后续独立 CHG 承载。

### 4.4.7 策略页面与旧功能边界

策略页面提供关键词/博主策略的配置、编辑、启停与执行记录入口；页面显示“每天 09:00”或“每若干小时”等业务配置，不提供 Cron 编辑器、节点编排或可视化调度器。

策略列表的检索入口统一称「综合搜索」，一次输入同时匹配策略 ID 与策略名称，不按字段拆成多个搜索框，也不在标签上只写其中一个字段。

旧版高级筛选、两种作者首次模式、立即执行/人工任务重试按钮不因旧文档存在而自动加入新页面；是否保留须明确决策。

## 4.5 挖掘任务（crawl_task）

### 4.5.1 功能定位

`crawl_task` 记录一次脚本或后台调度触发的自动挖掘执行，不承担业务配置或工作流定义。必须能追溯策略、当次配置、渠道、触发来源及计划时间。

### 4.5.2 业务状态

业务状态五种：

| 状态 | 含义 | 界面标签 |
| --- | --- | --- |
| `pending` | 已创建，待执行 | 待执行 |
| `running` | 执行中 | 执行中 |
| `success` | 成功 | 成功 |
| `failed` | 失败 | 失败 |
| `partial_success` | 部分成功：至少一项失败且至少一项成功入池 | 部分成功 |

### 4.5.3 partial_success 判定

记 `processed = added + duplicate + pending + auto_materialized`：

- 若 `failed > 0`，则 `processed > 0` 时为 `partial_success`、`processed == 0` 时为 `failed`；
- 否则为 `success`。

人工关键词任务走 `import-results`，各条目要么成功要么整体失败，无法达到 `partial_success`；该状态主要来自按 ID/链接逐目标抓取的路径。

多关键词或批量作品部分失败时，不丢弃已成功入池结果；应显示成功事实、失败数量及原因。这类部分失败由 `partial_success` 表达，界面显示为“部分成功”，可仅对失败项重新执行；不让技术 task 成功直接决定业务 success。

### 4.5.4 任务项处理状态

任务项处理状态六值：

| 状态 | 界面标签 |
| --- | --- |
| `unprocessed` | 未入池 |
| `pending` | 待审核 |
| `auto_materialized` | 自动转素材 |
| `material_failed` | 转素材失败 |
| `duplicate` | 重复 |
| `failed` | 失败 |

### 4.5.5 列表与统计口径

任务列表/详情包含：

- 任务 ID、策略名称、渠道、任务类型、开始/结束时间、状态；
- 统计数字、错误原因、执行日志和必要的阶段摘要。

任务列表的检索入口统一称「综合搜索」，一次输入同时匹配任务 ID、任务名称与来源策略名称；标签不再只写「任务名称 / 来源策略」，避免用户误以为任务 ID 不可搜。

统计口径分两层：

- 落库 `stats_json` 七项：`scanned`（扫描）、`found`（发现）、`added`（新增）、`duplicate`（重复）、`failed`（失败）、`auto_materialized`（自动转素材）、`pending`（待审核）。
- 界面列表只展示其中五项：`发现 N · 新增 N · 自动素材 N · 待审核 N · 失败 N`；`scanned` 与 `duplicate` 保留在数据层与详情中。

统计须区分单位：接口失败不等同于“1 条作品失败”；关键词级、作品级数量不可混加。明确计数口径、未扫描范围、重试去重和并发新增归属后再定正式合同，不能仅让界面数字相加好看。

### 4.5.6 失败项重试

- 仅 `failed` 与 `partial_success` 终态的任务可重试。
- 重试创建新任务，新任务的 `parent_task_id` 指向原任务，`snapshot.retry_items` 只包含失败项。
- 原任务不可变，其终态与统计不被重试改写。
- 非失败任务、或没有失败项时重试返回 `400 / 14008`。

### 4.5.7 调度与防重

- 同策略已有 `pending` / `running` 任务时不重复排队。
- 同策略同计划周期幂等防重。
- 跨策略发现同作品由全局唯一约束兜底。
- 防重有两层：服务端比较计划窗口键，加数据库唯一键 `uq_crawl_tasks_strategy_schedule (strategy_id, schedule_key)`。
- 手工触发路径同样必须遵守“不重复排队”，不得以空计划键绕过唯一约束。

### 4.5.8 恢复与任务边界

- 重启恢复不重复入池、不篡改终态统计，不批量补跑全部历史周期。
- 有限网络重试属于运行保障，不等于建设用户自定义流程。
- 不建设 `crawl_result`、全量任务作品历史、多版本 `raw_json`、执行中人工取消或新工作流状态机。

## 4.6 渠道扩展与运行链路

### 4.6.1 渠道抽象

`content_channel` 是受控渠道能力抽象；不要求本期增加渠道后台或独立数据库表。

- `channel_type` 与 `strategy_type` 分别表达来源渠道和发现方式；不得把二者混成 `douyin_keyword` 一类组合业务类型。
- 至少能描述：链接解析、内容详情、关键词搜索、作者查找/作品列表是否受支持。
- 作者查找/作品列表本期为暂停能力：能力描述保留，但不作为 M3 验收项。
- 未来接入新渠道允许新增适配实现和合同，但不重复建设内容池、策略和任务业务模型；不承诺未来零代码修改。
- B站、快手等预留内容不可点击执行。

### 4.6.2 运行链路

本期交付的是功能链路，不是独立视图：策略执行 → 生成 `crawl_task` → Worker 领取执行 → 结果写入内容池（含按规则自动转素材）。

该链路以真实业务记录为准，各段都有真实数据库读回。素材未生成时展示未转素材，不将自动入池画成已完成生产。

### 4.6.3 视图与预留内容边界

本期不交付独立的只读业务流转视图，后续版本再评估；上述功能链路是数据流事实，不是视图交付。

ADR-0013 第 8 条中「不允许编排、拖拽、条件分支或任意脚本」的禁止性约束保持不变。

## 4.7 权限与验收要求

### 4.7.1 角色与团队范围

权限沿用三角色框架。团队隔离沿用 ADR-0014；策略管理角色按 ADR-0023 的后续裁定。管理员可跨团队，高级运营固定所属团队，普通运营可处理本团队公共内容池。

- `source_content` 与 `discovery_strategy` 均按 `team_id` 隔离。
- 普通运营可查看、入池、忽略/恢复和转素材本团队的 `source_content`；不能修改、启停或执行挖掘策略，也不处理挖掘任务异常。
- 高级运营可处理本团队内容池，并管理本团队所有游戏的挖掘策略、自动发现与挖掘任务异常。
- 管理员可选择目标团队并跨团队查看、处理和管理；转素材是唯一例外，目标团队由来源内容决定，管理员不选团队，转换结果必须告知素材进入的团队。
- 服务端必须执行授权，不能由客户端过滤替代。

### 4.7.2 游戏维度

游戏维度已纳入本期（ADR-0014）：

- `discovery_strategies` 与 `source_contents` 均带 `game_id`。
- `game_id` 必填，默认 `other`；策略与内容池界面均有「游戏」列。
- 内容池的游戏筛选支持多选：普通运营和高级运营初次默认选中本人负责且已启用的游戏，可改选本团队其他游戏；管理员先确定目标团队，默认该团队全部游戏。负责游戏不构成内容池的强可见性或处理授权边界。筛选与人工导入的「所属游戏」选项只列启用游戏；默认负责游戏与启用集合取交集，交集为空时不带游戏条件（按团队范围查看）。
- 挖掘策略仍记录所属游戏；高级运营可管理本团队各游戏策略，管理员可跨团队管理。游戏筛选不得突破团队边界。挖掘策略表单的「所属游戏」只列启用游戏；编辑挂在停用游戏上的历史策略时，当前游戏作为禁用选项展示并标注「已停用」，保证原值可见但不能重新选中停用游戏。
- 停用游戏仅用于历史行名称解析：列表与详情仍显示游戏名称，名称解析读全量游戏目录；游戏管理页仍展示全部状态。

### 4.7.3 凭据与安全

- 凭据留在服务端；内容详情和日志不得泄露供应方凭据；原始数据与技术错误按权限脱敏。
- 凭据读取方式为 TOML 配置（`config/credentials/douyin.toml`），Cloud 运行时全仓零 `os.Getenv`；`WT_MEDIA_DOUYIN_*` 环境变量与 `.env.local` 对运行时无效。
- 正式合同归 Cloud 提供方，Desktop 只复用 Web，不复制业务规则。

### 4.7.4 验收要求

- 链接、关键词搜索均能通过真实接口入池；未选搜索结果零正式写入。博主搜索已暂停，不在本期验收范围。
- 关键词策略能通过真实周期触发、生成 `crawl_task`、执行并自动入池；只创建配置或任务列表不算完成。作者策略已暂停，不在本期验收范围。
- 各入口汇入同一来源身份；重复与并发不重复建素材，来源/素材可追踪。
- 自动转素材关闭时入池后无 `material`、人工转换后素材库可读回；开启时命中规则的结果自动生成 `material` 且可从任务统计读回；错误时不出现假成功。
- 自动转素材规则（`auto_material`、`material_rule`、各阈值）的命中与未命中均有真实证据；阈值全为非正数时不得静默视为全部命中。
- 任务统计、失败原因、受控故障恢复有真实证据，五态边界（含 `partial_success` 与失败项重试）必须可验证。
- 三页面沿用 WT UI；权限拒绝、M2 回归、Cloud Web/Desktop 走查通过。
