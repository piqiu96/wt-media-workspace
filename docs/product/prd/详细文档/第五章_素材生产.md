# 第五章：素材生产 V2 正式需求文档（M4-M5 Cloud 生产版）

> 本文档为第五章「素材生产」的正式产品需求基线。
> 2026-09-24 M4-M5 调整：视频合成统一迁移到 Cloud；自动规则归入 `compose_strategy`；生产任务统一为 `compose_task`；新增横向文件任务 `file_transfer_task`；Desktop / Agent 不再执行视频合成。
> 工程实现依据：ADR-0017 与 `docs/engineering/specs/2026-09-24-m4-m5-cloud-content-production.md`。
> 2026-10-26 产品增量：M3–M5 团队公共资源、负责人和素材使用口径按 [ADR-0023](../../../decisions/0023-m3-m5-team-resources-and-production-operator.md) 收敛；本章描述目标需求，既有 M4/M5 验收状态以 Milestone 为准。

## 5.1 模块概述

### 5.1.1 模块定位

素材生产负责把内容挖掘阶段沉淀的正式素材转化为可发布成片，是 M3 内容挖掘（[PRD 第四章](第四章_内容挖掘.md)）与第六章「发布管理」之间的生产环节。

```text
source_content → material
人工：当前用户的 material_usage + 指定负责人的 compose_strategy → compose_task
自动：团队 material + 指定负责人的 compose_strategy → compose_task
compose_task → composite_output → publication（M6）
```

所有视频合成都由 Cloud Worker 执行。运营可以在 Cloud Web 或 Desktop WebView 发起生产和查看进度，但 Desktop / Local Agent 不执行 FFmpeg。

素材生产分为两个里程碑：

1. **M4 内容生产闭环**：运营从素材库加入“我的素材”，人工创建合成任务，由 Cloud 生成成片并支持下载。
2. **M5 自动生产**：在 M4 底座上，由 `compose_strategy.schedule` 触发 Scheduler 自动创建任务，Worker Pool 批量生产。

### 5.1.2 建设目标

1. **建立清晰的生产入口**
   素材库、我的素材、合成策略、合成任务、成片管理和下载中心各自承担单一职责。

2. **统一人工和自动生产**
   人工与自动生产都使用 `compose_strategy`、`compose_task` 和 `composite_output`，不维护两套对象。

3. **让生产与运营电脑解耦**
   合成不依赖 Desktop 是否在线，长耗时执行由 Cloud Worker 异步完成。

4. **控制文件与计算成本**
   原素材采用懒加载，不在进入素材库时批量下载；Worker 有并发、超时和重试上限。

5. **保证可追溯和真实成功**
   每个成片可追溯来源素材、策略快照、生产任务与最终运营负责人；人工任务还可追溯创建者的个人选材关系。失败任务不生成成片。

### 5.1.3 核心能力

| 产品能力 | 定位 | 核心对象 |
| --- | --- | --- |
| 素材库 | 管理进入生产体系的公共素材和源视频准备状态 | `material` |
| 我的素材 | 管理用户准备投入生产的素材集合 | `material_usage` |
| 合成策略 | 定义模板、视频参数与可选自动执行规则 | `compose_strategy` |
| 合成任务 | 管理一次具体的视频生产行为 | `compose_task` |
| 成片管理 | 管理成功生成的视频资产及其运营负责人 | `composite_output` |
| 下载中心 | 统一管理原素材和成片下载 | `file_transfer_task` |

禁止以其他名字复制这些职责，特别是：

- 不新增 `material_user_relation`、`user_material`、`favorite_material`；
- 不新增 `production_rule`；
- 不新增 `compose_pool_item` 或重复生产任务表；
- 不新增独立的成片下载任务表。

### 5.1.4 模块边界

#### 本章负责

- 正式素材进入生产体系；
- “我的素材”关系；
- 合成模板与策略配置；
- 人工和自动合成任务；
- Cloud 视频合成进度与结果；
- 成片生成和管理；
- 原素材与成片下载；
- 进入发布管理的入口。

#### 本章不负责

- 内容搜索、抓取和线索发现；
- 浏览器 Profile、Cookie 和账号登录态；
- 平台发布字段配置与浏览器发布执行；
- 发布结果采集与互动执行；
- 可视化工作流、任意脚本和动态插件；
- 微服务或 MQ 等技术选型。

发布任务、发布记录和平台结果回收属于第六章。第五章的“去发布”只是把 `composite_output` 带入发布流程，不代表已经发布。

## 5.2 素材生产流程

### 5.2.1 M4 人工内容生产流程

```text
material
→ material_usage
→ 选择 compose_strategy
→ compose_task(pending)
→ 原素材按需准备
→ Cloud Compose Worker + FFmpeg
→ composite_output
→ 成片管理
→ 下载 / 去发布
```

#### 流程说明

1. 运营在素材库点击“加入我的素材”，系统创建或恢复 `material_usage`。
2. 运营在“合成任务”页新建任务，从“我的素材”里选择素材和 `compose_strategy`。
3. 如果 `material.video_status != ready`，系统先创建 Cloud 执行的 `file_transfer_task` 准备原素材。
4. 原素材准备成功后，Cloud Worker 领取任务并执行 FFmpeg。
5. 输出文件完成媒体校验并写入对象存储后，系统创建 `composite_output`。
6. 运营在“成片管理”按负责人权限预览、下载并查看来源；发布入口由 M6 交付。

HTTP 请求只负责创建任务并返回，不同步等待视频生成。

### 5.2.2 M5 自动内容生产流程

```text
compose_strategy.schedule
→ Cloud Scheduler
→ 筛选 material
→ 幂等创建 compose_task
→ Worker Pool
→ composite_output
```

#### 流程说明

1. 高级运营为 `compose_strategy` 选择定时执行、配置计划和条件，并启用策略。
2. Scheduler 扫描到期策略，从策略所属团队、游戏匹配的 `material` 素材库筛选候选素材，不要求策略创建者先加入“我的素材”。
3. 同策略、同计划周期、同素材只能创建一个自动任务。
4. Scheduler 只创建 `pending compose_task`，不下载文件、不执行 FFmpeg。
5. Worker Pool 按并发上限领取任务，必要时先准备原素材，再执行合成。
6. 每个任务独立成功、失败或取消，不因一条失败阻塞整批策略。

自动生产不会创建新的 `production_rule`，也不会跳过 `compose_task` 直接生成成片。

### 5.2.3 人工与自动生产的统一和差异

| 对比项 | M4 人工生产 | M5 自动生产 |
| --- | --- | --- |
| 触发者 | 运营 | Scheduler |
| 策略来源 | 人工选择 | 到期 `compose_strategy` |
| 选材来源 | 创建者当前有效的“我的素材” | 策略团队与游戏匹配的 `material` |
| `material_usage` | 必须关联创建者 | 不要求个人使用关系 |
| 负责人 | 必须匹配策略指定的运营；普通运营固定本人，管理角色可代创建 | 继承策略指定的运营 |
| 生产任务 | `compose_task` | `compose_task` |
| 执行者 | Cloud Compose Worker | Cloud Compose Worker |
| 成片 | `composite_output` | `composite_output` |
| 文件下载 | 用户按需发起 | 用户按需发起 |

### 5.2.4 核心对象关系

```text
source_content
    ↓
material
    ├── material_usage ── user
    ├── file_transfer_task（原素材准备/下载）
    └── compose_task ── compose_strategy + strategy_snapshot
                           ↓
                    composite_output
                           ├── file_transfer_task（成片下载）
                           └── publication（第六章）
```

| 对象 | 职责 |
| --- | --- |
| `material` | 正式素材与源视频准备状态 |
| `material_usage` | 用户的“我的素材”关系 |
| `compose_strategy` | 视频如何生产、团队／游戏适用范围、指定运营及是否自动执行 |
| `compose_task` | 一次生产行为、创建人、运营负责人快照、执行状态和恢复事实 |
| `composite_output` | 已成功生成的唯一成片资产，继承任务运营负责人 |
| `file_transfer_task` | 原素材或成片的一次文件传输 |
| `publication` | 第六章管理的真实发布记录 |

## 5.3 素材库（material）

### 5.3.1 功能定位

素材库管理正式进入生产体系的公共素材。`material` 是生产输入，不等于源视频文件已经下载。

页面支持：

- 查看素材列表和详情；
- 查看来源内容、平台、游戏、作者和发布时间；平台一律显示中文名（抖音／B站／百度），不渲染存储代码；
- 在详情查看视频准备状态（列表不再展示文件状态，也不提供文件状态筛选）；
- 加入我的素材；
- 查看“加入状态”“我的使用”；
- 查看团队范围的“使用情况”及成功成片数；使用人明细仅高级运营和管理员可见，普通运营只看到使用人数。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/01-material-library.png`。

### 5.3.2 素材来源

M4-M5 默认来源是 M3 内容池的 `source_content` 转换：

```text
source_content
→ material
```

转换时保存源链接和不可变来源快照，不要求立即下载源视频。后续若支持用户自有素材，必须沿用 `material`，不得另建平行素材实体。

### 5.3.3 素材可见范围

素材库展示当前团队所有游戏的正式素材；管理员可先选择目标团队，高级运营固定本团队。游戏多选筛选的选项来自游戏管理当前启用的全部游戏，停用游戏不在选项中；普通运营和高级运营初次默认选中本人负责且已启用的游戏，可切换到本团队其他游戏；管理员默认所选团队全部游戏。负责游戏不作为公共素材的强授权边界。服务端仍须按团队隔离列表、详情与操作。

`material_usage` 只负责当前用户的个人工作集关系，不在 `material` 上增加“收藏人”或“领取人”字段。

同一 `material` 可被多个有权限用户加入“我的素材”，每个用户形成自己的有效 `material_usage`。

### 5.3.4 视频准备状态

```text
not_downloaded
→ downloading
→ ready

downloading
→ failed
→ downloading

ready
→ downloading        （确认云端对象已丢失，重新准备）
```

运营侧展示：

| 内部状态 | 页面文案 | 可创建合成任务 |
| --- | --- | --- |
| `not_downloaded` | 未下载 | 是，系统先准备文件 |
| `downloading` | 下载中 | 是，任务等待文件就绪 |
| `ready` | 已就绪 | 是，消费前确认文件仍在 |
| `failed` | 下载失败 | 是，系统自动重试准备一次 |

“已就绪”只表示数据库记录的状态，不保证云端文件一定还在。合成开始前、用户下载或预览前，系统都会先确认云端对象存在：不存在且素材有源页地址时自动重新准备，没有源页地址时明确拒绝。从 `ready` 回退到 `downloading` 只回退“确认丢失的那个文件”，不会把并发准备刚生成的新文件误标为待准备。

用户下载原视频只能从当前用户有效的“我的素材”发起，素材库列表、详情与 API 不提供绕过该关系的本机下载。“合成前准备”仍由 Cloud 执行，可直接服务团队素材库的自动任务；两种用途都沿用 `file_transfer_task`，不能把前者的个人门槛套到 Cloud Worker。

### 5.3.5 懒加载下载规则

禁止在素材进入素材库时批量下载全部视频。

创建文件任务的情况：

1. 用户在“我的素材”主动点击“下载原视频”；
2. 用户创建合成任务且源视频未就绪；
3. 系统恢复失败或长期未完成的文件任务；
4. 合成或用户下载前确认“已就绪”的文件已不在云端，且素材有源页地址，系统重新准备一次。

后台定期扫描只处理异常、失败、租约过期或长期未完成任务，不预下载所有素材。

### 5.3.6 加入状态、我的使用与使用情况

素材库列表直接展示三个相互独立的维度，不给 `material` 新增一套人工维护状态：

| 维度 | 筛选与列表口径 | 事实来源 |
| --- | --- | --- |
| 加入状态 | 全部／已加入／未加入；移出后为未加入 | 当前用户有效的 `material_usage` |
| 我的使用 | 全部／未使用／已合成；失败、取消、排队中均为未使用 | 负责人为当前用户的成功 `composite_output` |
| 使用情况 | 全部角色可见：全部／无人使用／有人使用；不按“本人／他人”拆成两个筛选 | 该团队内至少一位负责人拥有成功 `composite_output` |

首次进入时“我的使用”默认未使用；游戏多选按 §5.3.3 的角色规则设默认值。用户调整后可沿用既有页面筛选记忆。加入或移出只改变加入状态，不改变成功成片事实；失败任务保留历史，是否可重试仍按原任务资格判断，却不算“使用”。这里的“使用情况”指成功结果，与合成任务创建抽屉按 `(策略, 素材)` 检查**任何任务记录**的防重口径不同。

“使用情况”的列、筛选与详情段对所有角色渲染。高级运营可在本团队、管理员可按目标团队查看成功成片数、不同运营负责人人数及使用人明细；普通运营只能看到成功成片数与使用人数，服务端不返回姓名。列表只显示一行可点击摘要，无成功成片或没有关联数据显示 `—`，有成片但没有已知负责人显示 `成片 N`，有已知负责人显示 `成片 N · 使用 M 人`；点击摘要打开弹窗，高级运营与管理员看到已知使用人及各人成片数（多人时列表可滚动），普通运营只看到 `成片 N` 与 `使用人数 M`，不出现任何姓名。不输出“暂无成功成片”“负责人未记录”“姓名不可见”等占位文案。跨团队相同外部作品分别统计，不合并业务记录。未来“我的使用＝已发布”指当前负责人基于该素材的成片至少有一次成功 `publication`，优先于“已合成”；发布次数统计同一素材的成功发布事实。但 M6 尚未交付可查询事实，本轮不展示该筛选、状态或次数；待真实查询可用后再接入，不能用下载或 `composite_output.status` 冒充发布。

进行中任务、最近生产时间、源视频准备异常可作为独立辅助信息，不能混进“使用情况”。所有统计从正式任务和成片事实派生，不回写冗余生产状态。

### 5.3.7 素材列表和详情验收

- 来源链接存在即可创建 `material`；
- “未下载”不能被展示成“已就绪”；
- 重复点击“加入我的素材”不创建第二个有效关系；
- 素材库无本机下载入口，直接请求下载 API 无当前用户有效 `material_usage` 时失败关闭；“我的素材”下载失败显示错误并允许重试；
- 加入状态、我的使用和使用情况在加入／移出、失败／重试／成功场景下分别与正式事实一致；普通运营能看到使用情况列、筛选与计数，服务端不向其返回使用人姓名；
- 素材库列表不展示文件状态，也没有文件状态筛选；详情仍可查看文件状态；
- 无权限用户不能查看或操作超出业务范围的素材。

## 5.4 我的素材（material_usage）

### 5.4.1 功能定位

`material_usage` 表示某个用户把 `material` 加入自己的生产集合。页面名称固定为“我的素材”。

能力：

- 查看个人素材；
- 查看最近生产状态；
- 下载原视频；
- 移出我的素材；
- 恢复已移出的关系；
- 查看详情和来源。

创建合成任务的入口不在本页：本页只管“这条素材能不能用、文件在不在”，创建在“合成任务”页完成（见 5.4.4）。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/02-my-materials.png`。

### 5.4.2 与 material 的关系

```text
material
    ├── user A → material_usage A
    ├── user B → material_usage B
    └── user C → material_usage C
```

同一用户对同一 `material` 默认只能有一个有效关系。禁止创建 `user_material` 等替代表。

### 5.4.3 加入规则

- 素材可用且用户有权限：创建 `material_usage`；
- 已存在有效关系：返回“已加入”，不重复创建；
- 关系已移出：恢复原关系并记录操作时间；
- 素材已禁止生产：不允许新加入，并说明原因。

### 5.4.4 创建合成任务

入口在“合成任务”页（人工新建），素材在创建抽屉里从“我的素材”中选：候选只列使用中的关系，已放弃的须先恢复；下载状态不作为候选条件，因为准备原素材是任务自己的工作。

普通运营创建任务时负责人固定本人，只能选指定给自己的合成策略。高级运营可为本团队指定运营代创建，管理员可在目标团队内代创建：先选负责人，再选同团队、同游戏且指定该负责人的已启用策略；候选素材始终来自**创建者自己**当前有效的“我的素材”，不得读取负责人的个人工作集。服务端同时校验创建者的管理范围、负责人有效状态及其负责游戏、策略适用范围和素材团队／游戏。任务分别保存创建人和负责人快照，成片归负责人；代创建后创建者可直达所建任务；列表默认团队全部，刚创建的结果不会因负责人不是创建者而失联。

用户选择一个或多个合格素材、策略和可覆盖参数后创建任务。系统逐素材创建独立 `compose_task`，每个任务独立执行、记录状态和产出；批量操作只是创建命令，不形成新的核心批次表。以后需要把同次创建的任务归并展示时，可用任务名称或分组 code 作为查询与展示标识，不改变逐素材执行和失败处理的事实。标识字段、生成规则和页面交互在实施该展示需求时确定。

去重以 **(策略, 素材)** 为单位，且这一对**只跑一次**：只要该策略在这条素材上有过任何任务记录（`pending` / `running` / `success` / `failed` / `cancelled` 任一），创建就按条拒绝并给出中文原因（客户端整行只读，判定在服务端）；要再跑一次，走那条任务的重试（见 §5.8.5）。同一次提交重放的 `request_key` 仍返回既有任务，不算冲突。自动调度沿用 §5.7.5 的跳过规则，两条路由同一判据。

源视频未就绪时，任务保持 `pending` 并等待 Cloud 文件准备完成；页面不得显示为“处理中”或“成功”。

### 5.4.5 移出与恢复

移出后：

- 不允许基于该关系新建人工任务；
- 不删除历史 `compose_task`；
- 不删除历史 `composite_output`；
- 不影响已进入发布流程的成片；
- 支持恢复原关系。

### 5.4.6 生产状态投影

“我的素材”可展示最近状态：待合成、处理中、已生成、失败。该状态来自最近 `compose_task`，不是 `material_usage` 自身状态机。

列表还展示素材自身的**点赞量与收藏量**（来源采集字段，与素材详情的四项指标同一量法与同一千分位格式），因为运营挑素材时先看的就是这两个数。

### 5.4.7 权限边界

“我的素材”页面和人工选材接口对三种角色都只返回当前用户的有效 `material_usage`。高级运营和管理员可按业务权限处理正式任务和异常，但不能把他人的素材关系冒充为自己的工作集；本机文件仍只能由当前用户身份下载。

## 5.5 合成策略（compose_strategy）

### 5.5.1 功能定位

`compose_template` 定义可执行的生产方式和参数；`compose_strategy` 为业务范围选择一个固定模板版本并填写参数。M5 的自动执行规则继续归策略管理。

它包含：

- 固定模板版本；
- 该版本允许的视频参数；
- 执行方式、定时计划、按优先级执行的素材条件及数量上限。

不创建独立 `production_rule`。

### 5.5.2 策略结构

示例：

```json
{
  "template_code": "basic_cut",
  "template_version": 1,
  "config": {"start_seconds": 5, "end_seconds": 12}
}
```

### 5.5.3 视频模板

模板按 `(code, version)` 发布，记录参数 schema 和对应执行器；新版本新增记录，旧版本保留。模板由技术维护，不允许上传脚本。`basic_cut` v1 只开放已验证的切段起止时间。

运营在引导视频模板的策略中填写一个可下载的视频地址。转链接由独立运营工具完成，不属于合成策略。`guide_insert` 在原视频指定位置插入引导片段，支持截取引导片段和限制最终时长；`guide_pip` 在原视频上叠加引导视频画面，保留原视频前后段。两种生产方式分别发布固定模板版本，策略选择其中一种并填写该模板允许的参数。任务保存创建时的地址和参数快照，后续策略修改不改变既有任务。

地址必须是可公开下载的 HTTPS 视频地址。Worker 下载时限制目标地址、跳转、文件大小并探测实际媒体；无法访问、过期或视频内容无效时任务失败，不产生成功成片。链接内容由运营维护；任务快照固定地址，但外部链接的可用性和内容仍取决于链接提供方。首版不引入自动去重、随机贴纸、尾部动画、水印或用户自定义 FFmpeg 命令。

### 5.5.4 业务策略

高级运营基于已启用的模板版本为本团队创建策略；团队自动取其所属团队，无须重复选择。管理员创建时选择目标团队。每条策略必须指定该团队的**一个游戏和一个最终运营负责人**；负责人须在职有效、属于该团队并负责该游戏。策略的团队、游戏、负责人是创建任务的硬匹配条件，与公共素材库的游戏筛选不同。若现有引导配置有稳定的运营绑定，选择后自动带出并校验负责人；否则直接在策略保存负责人，不另建引导钩子管理实体。负责人失效或转出团队时策略不得再产生新任务，历史快照保留。

按模板 schema 填写参数（策略不携带模板之外的内容类型字段；例如 `basic_cut` v1 的切段起止时间）。策略修改直接覆盖当前配置，变更走审计日志，不保存策略版本。普通运营仅可选择指定给自己的已启用策略，并只能修改模板版本允许覆盖的任务参数；引导视频地址由策略维护，不能在单次任务里覆盖。停用模板版本后不能新建绑定或创建新任务。

### 5.5.5 策略快照

每个 `compose_task` 保存不可变快照，至少包含策略 ID、团队、游戏、实际运营负责人、创建人、模板代码与版本、引导配置、实际参数和执行所需的随机种子。`composite_output` 继承任务负责人。策略后续修改负责人或模板版本停用，不改变已创建任务的执行依据与历史成片。历史任务、成片若无可靠负责人依据，应标为未知／待核实，不得用创建人冒充。

### 5.5.6 多策略生产

同一 `material_usage` 可以创建多个独立任务：

```text
material_usage A
→ compose_task 1：16:9 高光集锦
→ compose_task 2：9:16 快节奏版本
→ compose_task 3：剧情解说版本
```

每个任务独立状态、快照和成片。

### 5.5.7 执行设置与执行条件

策略状态为 `enabled | disabled`，控制该策略能否创建新的人工或定时任务。`execution_mode` 为 `manual | scheduled`：手动模式不被 Scheduler 触发；定时模式保存当前支持的间隔或每天定时计划及时区。两者是独立事实，不设置第二个“自动执行”业务开关。计划只在定时模式参与调度；策略停用不取消已有任务，也不影响历史成片。

执行条件属于 `compose_strategy`：按持久化的优先级顺序排列规则组，每组指定 `match | filter`、`all | any` 及由服务端白名单定义的字段、运算符和值。先求整组谓词；`match` 在谓词成立时选中素材并占用额度，`filter` 对整组谓词取反，仅缩小后续候选池，不占额度。高优先级已选素材不再参与低优先级选择。同一次执行的单次和每日上限由服务端执行，候选按确定顺序处理。

Scheduler 到期执行与运营主动“执行”调用同一套候选选择及任务创建逻辑，分别创建独立 `compose_task`；定时策略被主动执行时不改变 `next_run_at`。M4 从“我的素材”人工选择素材创建任务的链路继续存在，该链路的任务不计入策略执行的每日额度。创建任务只表示执行已提交，成片完成仍由任务成功及 `composite_output` 证明。

M4 交付策略创建、编辑、复制和人工选择；M5 才启用 Scheduler 自动触发。

### 5.5.8 页面与权限

页面能力：新建、编辑、复制、启停策略、主动执行、查看执行任务。

界面参考：[合成策略参考图](../../../../assets/images/ui/content-production/compose-strategies-reference.png)。图片仅约束布局和信息层级；策略版本、草稿态、片头片尾、BGM 等图中示意能力不属于当前已交付范围。

策略列表展示 ID、策略名称、合成模板、所属游戏、所属团队、指定运营负责人、执行计划、状态及操作；不列下次执行时间，也不设独立“自动执行”状态列。状态列以 Switch 展示并操作整条策略，变更前先确认。详情以「概览 / 运行记录」两个 Tab 分隔当前配置与历史执行：概览按主体信息、合成配置、执行设置、执行条件展示，下次执行时间只在定时设置中显示后端真实值；运行记录提供触发方式与时间筛选、真实总数和分页；触发方式与合成任务页共用同一组文案：策略自动 / 人工创建。业务操作置于固定 Footer，遵循 [AdminUI 页面规范](../../../standards/frontend/AdminUI页面规范.md)。

新建和编辑共用基础信息、合成配置、执行设置、执行条件四个业务区域。创建后不可变的团队、游戏及模板在编辑时只读展示；模板参数按当前 schema 回显与校验。执行方式选择手动或定时，仅定时模式展示计划字段。详情主体信息展示策略 ID、绑定模板版本、创建与修改时间，以及团队、游戏、模板；不展示不存在的策略版本历史。合成配置按绑定模板 schema 展示实际参数，执行条件按真实优先级逐组展示。关联对象仅在有现成详情能力且有查看权限时提供点击入口；团队和游戏作为归属与分类显示普通文本。

策略状态决定能否执行；执行方式决定是否由 Scheduler 按计划触发。页面只提供策略状态 Switch 与执行方式选择，不暴露 `schedule.enabled` 作为独立操作。

- 普通运营：只查看、使用指定给自己的策略，不修改或启停；
- 高级运营：创建和维护本团队全部游戏策略、启停及主动执行；
- 管理员：跨团队管理策略，创建时明确目标团队；模板、版本和底层能力由具备技术职责的人员维护。

## 5.6 合成任务（compose_task）

### 5.6.1 功能定位

`compose_task` 表示一次具体的视频生产行为，也是 Cloud Worker 领取、执行和恢复的正式业务任务。

每条任务保存 `created_by`（人工请求发起人；自动任务记录策略创建者，系统代其调度）与 `operator_user_id`（最终运营负责人）两个不同事实。`created_by` 只是审计来源，不决定任务与成片的业务归属；归属只看负责人。自动任务负责人继承策略；人工任务负责人必须匹配所选策略。任务负责人在创建时固定，不随策略、用户团队或负责游戏之后的调整而漂移。

新任务在创建时保存稳定的任务名称：创建时可填写任务名称，一次选多条素材时按填写值加序号（`名称-1`、`名称-2`）；留空则按素材标题与策略名称生成。历史任务无法可靠还原创建时名称时按任务 ID 显示。策略或素材后续改名不改变已保存名称。

它同时回答：

- 使用哪个素材；
- 使用哪个策略快照；
- 由人工还是 Scheduler 触发；
- 当前执行到哪里；
- 是否成功生成成片。

不再设置 `compose_pool_item` 或额外通用 Agent task。

### 5.6.2 创建方式

1. 在“合成任务”页人工新建（素材从“我的素材”里选）；
2. 在已有成片或任务上复制配置重新创建；
3. M5 由 Scheduler 根据到期 `compose_strategy` 自动创建；
4. 失败后重试当前任务，或修改策略后创建新任务。

### 5.6.3 任务状态

```text
pending
→ running
→ success

pending / running
→ failed

pending / running
→ cancelled
```

页面文案：排队中、处理中、成功、失败、已取消。

等待源视频准备的任务保持 `running`，阶段为 `waiting_input`，页面文案显示“等待素材准备”，不显示“处理中”，也不改回“排队中”。合成任务发现素材文件丢失或未就绪时，本次领取内最多自动请求一次重新准备；准备结束仍不可用则以“素材准备失败”类错误明确结束，不循环重试。人工重试后，新一次领取重新获得一次自动准备的机会。

### 5.6.4 进度和阶段

详情可展示：

- 等待素材准备；
- 下载/校验输入；
- 合成处理中；
- 校验输出；
- 上传成片；
- 完成或失败。

列表百分比是执行进度投影，不替代主状态，也不得在失败时保留误导性的“100% 成功”视觉。

### 5.6.5 批量操作

P0 支持：

- 多素材创建任务；
- 批量选择策略；
- 批量取消尚未完成的任务；
- 对可重试技术失败批量重试。

每条素材仍生成独立任务，部分失败不回滚其他任务。创建抽屉的素材游戏筛选只列当前启用的游戏；候选素材本身不因停用游戏收窄，命中停用游戏的历史素材仍按策略匹配规则显示。

### 5.6.6 取消规则

- `pending`：可直接取消；
- `running`：发出取消请求，Worker 停止 FFmpeg 并清理本次临时文件后确认取消；
- `success`：不能取消，可归档成片；
- `failed`：可重试，`execution_uncertain`（结果不明确）除外——它走 §5.8.6 的人工核对通道，由同团队高级运营或管理员处理；
- `cancelled`：可重试，与失败同一入口、同一名称。

只修改数据库状态而不终止真实进程不算取消成功。

### 5.6.7 页面能力

合成任务页可按负责人、策略、触发方式、状态和时间筛选；有负责人筛选时展示顺序为**运营 → 合成策略 → 触发方式 → 状态 → 创建时间**。普通运营不显示运营筛选，服务端固定 `operator_user_id = current_user`；高级运营不选负责人时查看本团队全部，负责人下拉只列本团队启用成员（含本人），选中成员按 `operator_id` 收窄；管理员先选目标团队，可查看该团队全部或指定运营。管理角色代创建后的结果应提供直达链接。查看详情、日志摘要、取消、重试和查看成片均受相同服务端范围约束。

任务列表在创建时间之后展示完成时间（终态写入；排队中、处理中为空时显示 `-`）。触发方式在筛选项、列表与详情使用同一组文案：策略自动 / 人工创建。日期按用户所选本地自然日查询，结束日包含在内。服务端先在权限范围内筛选，再返回结果。逐次执行记录、是否可人工重试和重试操作须等服务端有对应事实与接口后开放，不能用当前任务摘要冒充执行日志。

界面参考：[合成任务参考图](../../../../assets/images/ui/content-production/compose-tasks-reference.png)。图片仅约束列表、详情和选择素材的交互；一条任务仍只对应一条素材，多素材提交创建多条任务，计划执行归策略管理。

任务详情先展示状态、阶段和关联素材，再展示策略快照、执行记录、失败原因与生成结果。批量创建后的部分成功或失败按各任务呈现，不把整体请求伪装成一条多素材任务。

列表把任务负责人、状态、进度与下一步操作放在易比较的位置；素材和策略只给摘要与详情入口。管理角色代创建时先选负责人，再选与其匹配的策略，然后确认创建者自己的候选素材和模板参数；普通运营负责人固定本人，直接从策略开始。提交后逐素材展示结果（素材是否已经用过是按策略算的，见 §5.6.7）。详情按「当前任务及状态 → 素材与策略快照 → 执行记录 → 成片结果」组织；信息维度足够多时再用 Tab，不能因参考图出现 Tab 就展示不存在的日志或结果。

创建抽屉的取材与参数按以下规则：

- 管理角色第 1 段先选负责人，随后只列匹配该负责人、团队和游戏的策略；普通运营负责人固定本人。选定策略后再判断素材是否对该策略有任务记录。
- 候选始终来自**当前创建者**“我的素材”中使用中的关系，是一张**内联候选列表**，只列与策略团队和游戏匹配的素材；可按游戏与**本策略任务记录**（一个下拉字段：未使用过 / 已使用过，带各自条数）筛选，也可按素材名称或素材编号搜索；默认按发布时间倒序，可切换为点赞倒序。切换筛选或排序只缩小或重排候选，不取消已选素材。
- 使用情况按 **(策略, 素材)** 判定：该策略在这条素材上有过**任何任务记录**（排队中 / 成功 / 失败 / 已取消）都算「已使用过」，从未有过任务记录才算「未使用过」；「已使用过」整行**只读且不给按钮**——一条素材在一条策略下只跑一次，要再跑走那条任务的「重试」；行内标出该行当前的状态标签（排队中 / 上次失败 / 已取消），并在成功过的行上说明已生成的版数。
- 候选行给出该素材的**点赞量与收藏量**，与素材详情、我的素材列表同一口径（千分位）。
- 同一条素材在同一个策略下**已有任何任务记录**时，创建按条拒绝并给出中文原因，指向那条任务的「重试」。
- 可覆盖参数按人在策略里看到的字段顺序展示，打开时**预填策略里保存的值**；清空某一项即回落到策略值，只把与策略不同的键随请求提交。
- 参数不合法（例如「开始秒数」不小于「结束秒数」）在提交前就地拦截并给出中文说明，**不发请求**；服务端校验失败同样只给可执行的下一步，不把英文原文交给运营。
- 任务名称可填可不填，确认区按上面 §5.6.1 的规则复述最终名称。

详情的信息归属固定为：

- 「关联信息」只放关联素材与合成策略，**不重复出现成片**；成片只在「生成结果」出现一次。
- 「生成结果」把**生成成片**与**生成时间**并列为两条独立事实，不拼成一句话；未成功时沿用既有三句空态。
- 任务失败时，「任务信息」在状态之后直接给出**失败原因**并高亮；列表不为此加列。
- 失败的任务**没有重试按钮时要说清为什么**：错误类型不可重试（如素材缺失，须修正后新建）与「可重试但当前账号无此权限」是两回事，各自给一句中文解释；同一句话不在两处并存两种说法，「执行记录」也用同一句。列表行不为此加列。
- 「执行记录」按每次执行列出关键过程，见 §5.6.8。

### 5.6.8 执行过程记录

每次执行（`compose_task_attempts` 的一次 attempt）记录一条关键过程日志，用于回答「它走到哪一步、每步花了多久、卡在哪一步失败」。日志随执行进展逐条追加，重试后每次执行各记各的，互不污染。

记录的步骤从固定集合中按实际走过的取：校验任务参数、准备源素材、（引导类模板）下载引导视频、视频合成、上传并校验成片、保存成片记录。每条步骤只记四类事实：

1. 步骤名（服务端给出的中文）；
2. 开始/结束时间与这一步的耗时；
3. 这一步的成果读数，且只允许白名单内的量：文件体积、成片时长、成片编号、文件摘要（sha256）；
4. 失败时中文的原因类别。

日志**不得**出现素材地址、对象存储地址、本机路径或 FFmpeg 原始报错；这些只留在服务端供运维排查。步骤名与原因类别一律由服务端生成，请求与数据库都不接受自由文本。没有日志的历史执行明确显示“该次执行没有步骤记录”，不用任务摘要冒充。

页面按同一形状渲染每一步（名称、时间、耗时、读数、失败原因）；失败步骤与详情里的失败原因使用同一处红色，指同一次事实。

## 5.7 自动生产（归属 compose_strategy）

### 5.7.1 功能定位

自动生产不是独立产品对象，而是 `compose_strategy.execution_mode=scheduled` 的执行方式：

```text
compose_strategy.execution_mode + schedule + 执行条件
→ Scheduler
→ compose_task
→ Worker Pool
→ composite_output
```

### 5.7.2 创建和维护角色

高级运营决定本团队策略的游戏、最终运营负责人、素材条件、执行方式、周期和数量上限；管理员可跨团队设置。技术人员维护 Worker 资源和模板能力。普通运营不能启停策略。

### 5.7.3 配置内容

策略执行配置至少包括：

- 游戏与业务范围；
- 一个有效的最终运营负责人；
- 可生产素材条件；
- 策略启停状态和手动 / 定时执行方式；
- 执行时间/周期与时区；
- 单次上限；
- 每日上限；
- 使用的模板和视频参数。

执行方式为手动或定时；定时计划使用每 N 分钟或每天 HH:MM，并明确时区。服务端验证周期格式、条件白名单和数量上限；页面仅在定时设置与详情中显示真实的下一次计划时间。这里借用交互形式，不让合成策略依赖挖掘策略数据。

策略列表的游戏筛选与新建策略的「所属游戏」只列启用游戏；服务端拒绝在停用游戏上创建策略。历史策略挂在停用游戏上时，列表与详情仍显示游戏名称（名称解析用全量目录），筛选不再提供该游戏。

### 5.7.4 自动调度

支持：

1. 定时执行；
2. 周期执行；
3. 高级运营“立即执行”。

“立即执行”也只创建 `compose_task`，不在 HTTP 请求中同步合成。

定时与“立即执行”都从该策略所属团队、指定游戏的正式 `material` 素材库取候选，按现有执行条件、额度、防重和可用性规则筛选；不要求素材属于策略创建人或负责人的“我的素材”。任务和成片归策略指定负责人。自动任务与成片不为创建者或负责人写入个人 `material_usage` 关系，因此其 `material_usage_id` 允许为空；`created_by` 仍记策略创建者作为审计来源，不参与归属判断。策略创建者账户被禁用不阻断定时执行，负责人失效才停止创建新任务。

启用或编辑计划不立即创建任务；首次自动触发等待下一计划窗口。历史任务保留创建时快照，不随策略修改而变。

### 5.7.5 防重与数量控制

- 同一 (策略, 素材) 只创建一次：候选上有过**任何任务记录**（排队中 / 成功 / 失败 / 已取消）即跳过，跳过原因记为 `previously_run`；要再跑一次走那条任务的重试，自动调度不替运营做这个决定；
- 同一策略已达单次或每日上限时跳过剩余候选；
- 禁用策略不再创建任务；
- 已创建任务不因策略随后停用而静默变成成功或删除。

### 5.7.6 素材可生产校验

自动创建任务前至少检查：

- 素材仍可见且可用；
- 素材的团队与游戏等于策略团队与指定游戏，策略负责人仍有效且属于该团队并负责该游戏；
- 来源链接存在；
- 没有明确禁止生产标记；
- 未超过策略配置的重复与数量限制；
- 相同调度键不存在。

源视频未就绪不是直接跳过理由，可先创建文件准备任务。

### 5.7.7 批量结果

一次策略触发中，每个候选素材独立创建或跳过。运行记录需展示：候选数、创建数、防重数、超限数、不可用数和失败数。部分创建成功不得显示成全部失败或全部成功。

### 5.7.8 自动生产信号

自动生产成功只通过 `compose_task` 与 `composite_output` 形成事实。发布成功由第六章 `publication` 形成事实。不得新增 `production_signal` 或以领取/下载冒充发布。

## 5.8 Cloud 执行、失败与恢复

### 5.8.1 功能定位

Cloud Worker 异步执行 `compose_task`。产品需要看到稳定的任务状态、进度、错误和恢复结果，不直接暴露租约、进程号或命令行等底层细节。

### 5.8.2 领取与并发

- Worker 从数据库原子领取 `pending` 任务；
- 同一任务同时只能有一个 Worker；
- 系统按配置限制总并发；
- 无可用资源时任务继续排队，不返回假失败。

### 5.8.3 Heartbeat 与超时

运行中任务持续 heartbeat。长时间无 heartbeat 或超过任务超时后，系统进入恢复判断：确认原执行已经停止后才能重排或失败，不能同时启动第二个 FFmpeg。

### 5.8.4 自动重试

允许自动重试：

- 临时网络错误；
- 对象存储短暂失败；
- Worker 崩溃且结果可确认未提交；
- 素材准备时平台临时播放地址解析或下载失败：同一准备任务内重新解析地址并再下载一次（只一次）；
- 其他已标记为可重试的技术错误。

不自动重试：

- 源文件永久不存在（包括平台地址不存在、重新解析后仍拿不到可用文件）；
- 素材准备中的租约丢失、探测/上传/写状态失败、进程被取消；
- 模板或参数非法；
- FFmpeg 能力不兼容；
- 输出内容无法通过校验；
- 外部结果不明确。

### 5.8.5 重试与重新生产

- 技术重试：保留同一 `compose_task` 的策略快照，增加尝试次数；
- 人工重试（高级运营或管理员）：把同一条 `compose_task` 重新排队，接受**已取消**与**失败**两类（`execution_uncertain` 除外）；清掉上一次的错误码与错误摘要，并**重新获得完整的自动容错配额**——`max_attempts = attempt_count + 3`，效果上是「重跑后又是满额 3 次容错」；**执行编号不回退**（新一次尝试接着往下编号），历史尝试记录原样保留；同时获得一次新的“自动重新准备素材”机会（每次领取最多一次）；
- 修改策略/参数：创建新的 `compose_task`；
- 复制成片配置：创建新的 `compose_task`，成功后生成新的 `composite_output`。

### 5.8.6 异常任务处理

任务详情展示：失败阶段、可理解的错误、是否可重试、已尝试次数和最后更新时间。技术可查看脱敏日志；普通运营不能看到凭据、内部命令或对象存储签名。

租约过期后结果不明确的任务保留失败和原尝试记录，普通重试入口不可用。同团队高级运营或管理员核实旧 FFmpeg 已停止且没有已提交成片后，在任务详情分别确认两项条件并填写可核对依据，才可将同一任务重新排队；核对记录、核对人与新人工尝试可读回。普通运营仍只能看到失败事实和联系提示，不能提交核对；跨团队高级运营不可见。无法核实时继续显示待处置。页面将其标为人工核对，不宣称系统已自动证明旧进程退出；错误摘要只呈现阶段、时间和固定错误类别。

### 5.8.7 卡死恢复

系统定期扫描租约过期、长期无 heartbeat 或超时任务。恢复必须以真实执行已结束为前提；仅把状态从 `running` 改回 `pending` 而不处理遗留进程属于假恢复。

## 5.9 成片管理与下载中心

### 5.9.1 成片管理定位

运营入口显示为「成片管理」，以成片资产、真实下载状态和来源追溯为主。列表与详情不提供「去发布」或「归档」；列表也不提供「打开文件 / 打开文件夹」，这两个本机动作只在 Desktop 确认文件存在后的详情底部出现。发布次数、发布记录须由 M6 `publication` 查询能力提供，数据就绪后再接入；本轮不显示虚构计数。

“成片管理”展示已经成功生成且当前用户有权查看的 `composite_output`。普通运营服务端固定只看本人负责游戏内负责人为本人的成片，不显示运营筛选；“游戏”筛选只列本人负责且已启用的游戏，并提供游戏列。高级运营不选负责人时查看本团队全部成片，负责人下拉只列本团队启用成员（含本人），选中成员按 `operator_id` 收窄；管理员先选目标团队，再看该团队全部或指定运营。游戏筛选选项来自游戏管理当前启用的游戏，选中只收窄结果、不接管授权；普通运营指定非本人负责游戏时服务端拒绝，不静默放宽。页面及详情使用相同授权；创建人、下载人不因此成为成片负责人。

能力：

- 视频预览；
- 查看来源素材；
- 查看生成策略和任务；
- 下载成片；
- 在本机文件存在时打开文件 / 打开文件夹（仅详情底部）。

界面参考：[成片页面参考图](../../../../assets/images/ui/content-production/my-outputs-reference.png)。图片仅约束列表与详情的信息层级；批量发布、发布记录和“发布中/发布失败”属于第六章发布能力，不作为 M4/M5 成片状态。

列表支持按运营负责人、游戏、已确定的成片状态、来源与时间查找，并展示游戏列；游戏筛选放在来源素材列之后展示。列表的「生成方式」列、筛选项与详情（含任务抽屉）统一使用 策略自动 / 人工创建 这组文案。详情先给可播放预览和文件信息，再展示负责人、来源素材、策略与任务追溯。下载与打开本机文件按当前用户身份及本机文件状态提供，管理角色不能下载到或打开他人电脑上的副本；不提供「去发布」与「归档」入口。

来源首版按素材 ID 精确匹配或素材名称包含匹配；时间按生成日期的本地自然日范围查询。预览地址暂时获取失败时保留成片详情和来源追踪，并给出可理解的错误反馈。

列表以成片预览、名称或 ID、状态、游戏、文件大小和生成时间为主要信息，来源素材与策略用摘要表示。详情先展示视频和文件信息，再展示来源追踪；不同信息维度较多时可分 Tab。下载与打开本机文件按当前状态与权限显示，行内不超过 5 个操作时全部平铺。发布记录只有第六章真实发布能力交付后才出现。

### 5.9.2 composite_output 定义

`composite_output` 是唯一成片资产，不是任务、下载记录或发布记录。成片文件位于对象存储；运营电脑上的副本仍属于同一成片。

成功创建时从 `compose_task.operator_user_id` 继承负责人快照；同一 `material` 可以经不同策略分别产出归不同负责人的多个成片，不增加素材“一对一成片”约束。历史成片无法可靠推断负责人时标明“历史未分配”，只允许管理角色按原有范围核查，不把创建人或下载人自动回填为负责人。

### 5.9.3 成片生成条件

必须同时满足：

- `compose_task` 的 FFmpeg 进程成功结束；
- 输出文件存在且媒体可读；
- 文件大小、时长和必要 Hash 校验通过；
- 对象存储写入和校验完成；
- 来源、策略快照和任务可追溯。

任一条件失败都不创建 `composite_output`。

### 5.9.4 来源追踪

成片详情必须可追溯：

- `material`；
- 人工生产时的 `material_usage`；
- `compose_strategy` 与快照；
- `compose_task`；
- 最终运营负责人及人工任务的创建人；
- 文件信息和生成时间；
- 后续 `publication`。

### 5.9.5 成片状态

数据状态字段：

```text
pending_publish
published
archived
```

这些字段保留在数据库与 API 中；本轮页面不以「待发布 / 已发布」作为主状态文案，页面以成片资产、真实下载状态和来源追溯为主。下载状态单独来自 `file_transfer_task`，不混入成片主状态。

### 5.9.6 下载中心定位

下载中心是横向文件能力，入口位于顶部导航“下载”，点击后打开右侧 Drawer，不属于素材库子菜单。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/06-download-center.png`。

### 5.9.7 file_transfer_task 定义

支持两类用户下载：

```text
material
→ file_transfer_task
→ 运营电脑本地文件
```

```text
composite_output
→ file_transfer_task
→ 运营电脑本地文件
```

同一张任务表也可表达 Cloud 合成前原素材准备，通过用途和执行位置区分，不新增其他下载任务表。

用户下载原素材前，服务端先验证**当前下载人**的有效 `material_usage`，再确认云端对象存在：存在才签发下载；不存在且素材有源页地址时，先创建一次云端准备并把文件信息挂到这条下载任务上，准备完成后运营电脑再直接下载（Cloud 不中转文件字节）；不存在且没有源页地址时明确提示暂不可下载。素材预览同理：对象不存在时提示暂不可用，不打开 404 页面。成片是已验收资产，本轮不做同样的自动重做；成片对象丢失会明确报错，规则另定。

### 5.9.8 下载任务状态

```text
pending
running
success
failed
cancelled
```

Drawer 展示：文件名、资产类型、文件大小、进度、当前速度、预计剩余时间、错误和完成时间。

### 5.9.9 下载操作

- 进行中任务：暂停/继续能力只有在执行器真实支持断点续传时才展示；必须支持取消；
- 失败任务：重新下载；
- 成功任务：打开文件或所在目录；
- 最近完成：可清理显示记录，但不得删除素材、成片或用户本地文件；
- 批量暂停等按钮不能只改前端状态。

### 5.9.10 本地文件边界

Cloud 保存任务事实、请求用户、领取审计和完成结果，不保存运营电脑绝对路径。Desktop / Local Agent 管理本地保存目录、临时文件、断点信息和最终路径。

### 5.9.11 下载完整性

成功前必须验证：

- 实际字节数与预期一致；
- 必要 Hash 一致；
- 临时文件已原子移动为最终文件；
- 取消或失败不留下被误认为完整文件的目标文件。

### 5.9.12 发布入口

本轮成片列表与详情不提供「去发布」入口；发布能力与发布记录由 M6 `publication` 查询能力提供，数据就绪后再接入。下载成片不创建 `publication`；只有真实发布或补录成功才创建发布事实。

### 5.9.13 重复风险

发布前仍可按成片、文件 Hash、素材 + 平台 + 账号范围提示重复风险。风险判断属于发布前校验，不通过成片池或领取关系实现。

### 5.9.14 文件生命周期

- 对象存储中的正式成片按存储策略保留；
- 对象存储中的正式素材按存储策略保留；素材准备的临时对象在确认转为正式对象后删除；
- 本地副本删除不删除 `composite_output`；
- 临时合成文件与成片临时对象在成功、失败或取消后按恢复规则清理；
- 清理不得删除仍被正式成片引用的对象。

## 5.10 权限与验收要求

### 5.10.1 角色模型

继续使用：

```text
普通运营
高级运营
管理员
```

权限采用角色 + 业务范围 + 资源归属，不新增复杂 RBAC。

### 5.10.2 普通运营

可以：

- 查看和处理本团队所有游戏的公共素材，游戏默认多选本人负责项；
- 加入和管理自己的素材；
- 选择可用策略并创建人工任务；
- 查看自己的任务与成片；
- 从自己的“我的素材”下载原素材，从有权查看的成片发起本人本机下载；
- M6 交付后进入发布流程。

不能：

- 修改公共策略模板；
- 启停自动生产；
- 查看其他人的任务、成片或本机下载；
- 绕过 Cloud 直接请求 Worker 执行。

### 5.10.3 高级运营

可以：

- 管理本团队所有游戏的 `compose_strategy`，为本团队有效运营指定负责人；
- 配置和启停 M5 自动执行；
- 默认查看本团队全部任务与成片，负责人下拉只列本团队启用成员（含本人），可按成员筛选；
- 从自己的“我的素材”代创建负责人匹配策略的人工任务；
- 取消、重试符合规则的任务；
- 查看自动调度统计和异常素材。

### 5.10.4 管理员

可以：

- 跨团队管理 M3–M5 Cloud 业务数据与策略，创建策略时选择目标团队；
- 在目标团队内指定有效运营，使用自己的“我的素材”代创建匹配策略的人工任务；
- 维护或授权技术人员维护模板、FFmpeg 能力和 Worker 配置；
- 查看全局执行状态、脱敏日志和资源指标；
- 处理租约、超时、对象存储和文件异常；
- 在审计下执行全局任务处置。

管理员和高级运营的 Cloud 权限不能绕过业务对象、对象存储安全、本机文件和 Local Agent 下载合同；Cloud Web 与 Desktop 共用业务页面的授权一致，本地能力仍按本人绑定。

### 5.10.5 P0 验收链路

#### M4 人工生产链路

```text
素材库加入我的素材
→ 选择策略创建 compose_task
→ 原素材懒加载准备
→ Cloud Worker 真实 FFmpeg 合成
→ 对象存储产生可播放文件
→ composite_output
→ 成片管理下载到本地
```

必须验证：

- `material_usage` 不重复；
- HTTP 不同步等待；
- 源文件未准备时任务不提前执行；
- 失败不创建成片；
- 下载进度和最终 Hash 真实；
- Desktop 退出不影响 Cloud 合成。

#### M5 自动生产链路

```text
启用 compose_strategy.schedule
→ Scheduler 到期扫描
→ 幂等创建 compose_task
→ Worker Pool 按并发上限执行
→ 自动生成 composite_output
```

必须验证：

- 禁用策略不创建任务；
- 同周期不重复；
- 单次和每日上限生效；
- Worker 并发不越界；
- heartbeat、超时、重试和重启恢复真实有效；
- HTTP Server 单独运行不启动 Scheduler / Worker。

#### 异常恢复链路

必须覆盖：

- 原素材下载失败；
- 输入损坏；
- FFmpeg 非零退出；
- Worker 崩溃；
- heartbeat 中断和租约过期；
- 对象存储上传失败；
- 任务取消；
- 本地下载失败和重试。

所有异常都不得生成假成片、假下载成功或两个并行执行者。

#### 发布衔接链路

M6 接入后：成片页面提供去发布入口，进入第六章发布流程。

```text
成片管理
→ 去发布
→ publication（第六章）
```

下载、预览和归档均不等于发布。

### 5.10.6 第五章最终设计原则

1. **一个成片，一个资产**：Cloud 与本地文件是同一 `composite_output` 的不同位置。
2. **一种合成执行边界**：人工和自动生产都由 Cloud Compose Worker 执行。
3. **一种生产任务**：使用 `compose_task`，不再叠加生产意图表或 Agent task。
4. **自动规则归策略**：`compose_strategy.schedule` 是自动生产唯一规则来源。
5. **我的素材语义不变**：`material_usage` 是唯一个人素材关系。
6. **下载是横向能力**：原素材和成片统一使用 `file_transfer_task`，入口为全局 Drawer。
7. **源视频懒加载**：进入素材库不等于下载视频。
8. **真实成功优先**：任务成功、文件校验和对象存储落盘同时成立才创建成片。
9. **生产和发布解耦**：成片生成不创建发布记录。
10. **保持简单**：不引入微服务、MQ、工作流引擎或复杂 Agent 架构。
