# 第五章：素材生产 V2 正式需求文档（M4-M5 Cloud 生产版）

> 本文档为第五章「素材生产」的正式产品需求基线。
> 2026-09-24 M4-M5 调整：视频合成统一迁移到 Cloud；自动规则归入 `compose_strategy`；生产任务统一为 `compose_task`；新增横向文件任务 `file_transfer_task`；Desktop / Agent 不再执行视频合成。
> 工程实现依据：ADR-0017 与 `docs/engineering/specs/2026-09-24-m4-m5-cloud-content-production.md`。

---

## 5.1 模块概述

### 5.1.1 模块定位

素材生产负责把内容发现阶段沉淀的正式素材转化为可发布成片，是第四章「内容发现」与第六章「发布管理」之间的生产环节。

```text
source_content
→ material
→ material_usage
→ compose_strategy
→ compose_task
→ composite_output
→ publication
```

所有视频合成都由 Cloud Worker 执行。运营可以在 Cloud Web 或 Desktop WebView 发起生产和查看进度，但 Desktop / Local Agent 不执行 FFmpeg。

素材生产分为两个里程碑：

1. **M4 内容生产闭环**：运营从素材库加入“我的素材”，人工创建合成任务，由 Cloud 生成成片并支持下载。
2. **M5 自动生产**：在 M4 底座上，由 `compose_strategy.schedule` 触发 Scheduler 自动创建任务，Worker Pool 批量生产。

### 5.1.2 建设目标

1. **建立清晰的生产入口**
   素材库、我的素材、合成策略、合成任务、我的成片和下载中心各自承担单一职责。

2. **统一人工和自动生产**
   人工与自动生产都使用 `compose_strategy`、`compose_task` 和 `composite_output`，不维护两套对象。

3. **让生产与运营电脑解耦**
   合成不依赖 Desktop 是否在线，长耗时执行由 Cloud Worker 异步完成。

4. **控制文件与计算成本**
   原素材采用懒加载，不在进入素材库时批量下载；Worker 有并发、超时和重试上限。

5. **保证可追溯和真实成功**
   每个成片可追溯来源素材、个人使用关系、策略快照和生产任务；失败任务不生成成片。

### 5.1.3 核心能力

| 产品能力 | 定位 | 核心对象 |
| --- | --- | --- |
| 素材库 | 管理进入生产体系的公共素材和源视频准备状态 | `material` |
| 我的素材 | 管理用户准备投入生产的素材集合 | `material_usage` |
| 合成策略 | 定义模板、视频参数与可选自动执行规则 | `compose_strategy` |
| 合成任务 | 管理一次具体的视频生产行为 | `compose_task` |
| 我的成片 | 管理成功生成的视频资产 | `composite_output` |
| 下载中心 | 统一管理原素材和成片下载 | `file_transfer_task` |

禁止以其他名字复制这些职责，特别是：

- 不新增 `material_user_relation`、`user_material`、`favorite_material`；
- 不新增 `production_rule`；
- 不新增 `compose_pool_item` 或重复生产任务表；
- 不新增独立的成片下载任务表。

### 5.1.4 模块边界

#### 本章负责

- 正式素材进入生产体系；
- “我的素材”关系；
- 合成模板与策略配置；
- 人工和自动合成任务；
- Cloud 视频合成进度与结果；
- 成片生成和管理；
- 原素材与成片下载；
- 进入发布管理的入口。

#### 本章不负责

- 内容搜索、抓取和线索发现；
- 浏览器 Profile、Cookie 和账号登录态；
- 平台发布字段配置与浏览器发布执行；
- 发布结果采集与互动执行；
- 可视化工作流、任意脚本和动态插件；
- 微服务或 MQ 等技术选型。

发布任务、发布记录和平台结果回收属于第六章。第五章的“去发布”只是把 `composite_output` 带入发布流程，不代表已经发布。

## 5.2 素材生产流程

### 5.2.1 M4 人工内容生产流程

```text
material
→ material_usage
→ 选择 compose_strategy
→ compose_task(pending)
→ 原素材按需准备
→ Cloud Compose Worker + FFmpeg
→ composite_output
→ 我的成片
→ 下载 / 去发布
```

#### 流程说明

1. 运营在素材库点击“加入我的素材”，系统创建或恢复 `material_usage`。
2. 运营在“我的素材”选择素材和 `compose_strategy`，创建 `compose_task`。
3. 如果 `material.video_status != ready`，系统先创建 Cloud 执行的 `file_transfer_task` 准备原素材。
4. 原素材准备成功后，Cloud Worker 领取任务并执行 FFmpeg。
5. 输出文件完成媒体校验并写入对象存储后，系统创建 `composite_output`。
6. 运营在“我的成片”预览、下载、查看来源或进入发布管理。

HTTP 请求只负责创建任务并返回，不同步等待视频生成。

### 5.2.2 M5 自动内容生产流程

```text
compose_strategy.schedule
→ Cloud Scheduler
→ 筛选 material
→ 幂等创建 compose_task
→ Worker Pool
→ composite_output
```

#### 流程说明

1. 高级运营为 `compose_strategy` 配置自动执行计划并启用。
2. Scheduler 扫描到期策略，根据业务范围、素材状态与数量上限筛选候选素材。
3. 同策略、同计划周期、同素材只能创建一个自动任务。
4. Scheduler 只创建 `pending compose_task`，不下载文件、不执行 FFmpeg。
5. Worker Pool 按并发上限领取任务，必要时先准备原素材，再执行合成。
6. 每个任务独立成功、失败或取消，不因一条失败阻塞整批策略。

自动生产不会创建新的 `production_rule`，也不会跳过 `compose_task` 直接生成成片。

### 5.2.3 人工与自动生产的统一和差异

| 对比项 | M4 人工生产 | M5 自动生产 |
| --- | --- | --- |
| 触发者 | 运营 | Scheduler |
| 策略来源 | 人工选择 | 到期 `compose_strategy` |
| `material_usage` | 必须关联 | 可不关联个人使用关系 |
| 生产任务 | `compose_task` | `compose_task` |
| 执行者 | Cloud Compose Worker | Cloud Compose Worker |
| 成片 | `composite_output` | `composite_output` |
| 文件下载 | 用户按需发起 | 用户按需发起 |

### 5.2.4 核心对象关系

```text
source_content
    ↓
material
    ├── material_usage ── user
    ├── file_transfer_task（原素材准备/下载）
    └── compose_task ── compose_strategy + strategy_snapshot
                           ↓
                    composite_output
                           ├── file_transfer_task（成片下载）
                           └── publication（第六章）
```

| 对象 | 职责 |
| --- | --- |
| `material` | 正式素材与源视频准备状态 |
| `material_usage` | 用户的“我的素材”关系 |
| `compose_strategy` | 视频如何生产以及是否自动执行 |
| `compose_task` | 一次生产行为、执行状态和恢复事实 |
| `composite_output` | 已成功生成的唯一成片资产 |
| `file_transfer_task` | 原素材或成片的一次文件传输 |
| `publication` | 第六章管理的真实发布记录 |

## 5.3 素材库（material）

### 5.3.1 功能定位

素材库管理正式进入生产体系的公共素材。`material` 是生产输入，不等于源视频文件已经下载。

页面支持：

- 查看素材列表和详情；
- 查看来源内容、平台、游戏、作者和发布时间；
- 查看视频准备状态；
- 加入我的素材；
- 下载原视频；
- 查看生产次数。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/01-material-library.png`。

### 5.3.2 素材来源

M4-M5 默认来源是第四章 `source_content` 转换：

```text
source_content
→ material
```

转换时保存源链接和不可变来源快照，不要求立即下载源视频。后续若支持用户自有素材，必须沿用 `material`，不得另建平行素材实体。

### 5.3.3 素材可见范围

素材库展示授权团队与游戏范围内的正式素材。`material_usage` 负责个人使用关系，不在 `material` 上增加“收藏人”或“领取人”字段。

同一 `material` 可被多个有权限用户加入“我的素材”，每个用户形成自己的有效 `material_usage`。

### 5.3.4 视频准备状态

```text
not_downloaded
→ downloading
→ ready

downloading
→ failed
→ downloading
```

运营侧展示：

| 内部状态 | 页面文案 | 可创建合成任务 |
| --- | --- | --- |
| `not_downloaded` | 未下载 | 是，系统先准备文件 |
| `downloading` | 下载中 | 是，任务等待文件就绪 |
| `ready` | 已就绪 | 是 |
| `failed` | 下载失败 | 是，但必须先重试成功 |

“下载原视频”可能是下载到运营电脑；“合成前准备”是下载到 Cloud 生产环境。两者都创建 `file_transfer_task`，但执行位置与用途不同。

### 5.3.5 懒加载下载规则

禁止在素材进入素材库时批量下载全部视频。

创建文件任务的情况：

1. 用户主动点击“下载原视频”；
2. 用户创建合成任务且源视频未就绪；
3. 系统恢复失败或长期未完成的文件任务。

后台定期扫描只处理异常、失败、租约过期或长期未完成任务，不预下载所有素材。

### 5.3.6 素材生产统计

素材列表可展示：

- 成功成片数量；
- 进行中任务数量；
- 最近生产时间；
- 最近发布时间；
- 是否存在源视频准备异常。

统计必须从正式任务、成片和发布事实派生，不通过冗余“生产规则”对象回写。

### 5.3.7 素材列表和详情验收

- 来源链接存在即可创建 `material`；
- “未下载”不能被展示成“已就绪”；
- 重复点击“加入我的素材”不创建第二个有效关系；
- 下载失败显示错误并允许重试；
- 无权限用户不能查看或操作超出业务范围的素材。

## 5.4 我的素材（material_usage）

### 5.4.1 功能定位

`material_usage` 表示某个用户把 `material` 加入自己的生产集合。页面名称固定为“我的素材”。

能力：

- 查看个人素材；
- 创建合成任务；
- 查看最近生产状态；
- 下载原视频；
- 移出我的素材；
- 查看详情和来源。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/02-my-materials.png`。

### 5.4.2 与 material 的关系

```text
material
    ├── user A → material_usage A
    ├── user B → material_usage B
    └── user C → material_usage C
```

同一用户对同一 `material` 默认只能有一个有效关系。禁止创建 `user_material` 等替代表。

### 5.4.3 加入规则

- 素材可用且用户有权限：创建 `material_usage`；
- 已存在有效关系：返回“已加入”，不重复创建；
- 关系已移出：恢复原关系并记录操作时间；
- 素材已禁止生产：不允许新加入，并说明原因。

### 5.4.4 创建合成任务

用户选择一个或多个“我的素材”、合成策略和可覆盖参数后创建任务。系统逐素材创建独立 `compose_task`，批量操作只是创建命令，不形成新的核心批次表。

源视频未就绪时，任务保持 `pending` 并等待 Cloud 文件准备完成；页面不得显示为“处理中”或“成功”。

### 5.4.5 移出与恢复

移出后：

- 不允许基于该关系新建人工任务；
- 不删除历史 `compose_task`；
- 不删除历史 `composite_output`；
- 不影响已进入发布流程的成片；
- 支持恢复原关系。

### 5.4.6 生产状态投影

“我的素材”可展示最近状态：待合成、处理中、已生成、失败。该状态来自最近 `compose_task`，不是 `material_usage` 自身状态机。

### 5.4.7 权限边界

普通运营只能管理自己的 `material_usage`。高级运营可在负责业务范围内查看异常关系，但不能把其他人的素材关系冒充为自己所有。技术处理全局异常时必须留下审计。

## 5.5 合成策略（compose_strategy）

### 5.5.1 功能定位

`compose_strategy` 定义“视频如何生产”，同时承载 M5 自动执行规则。

它包含：

- 视频模板与版本；
- 视频比例、字幕、BGM、片尾等参数；
- 参数校验规则；
- 可选自动执行计划；
- 单次和每日数量上限。

不创建独立 `production_rule`。

### 5.5.2 策略结构

示例：

```json
{
  "template": "high_light",
  "template_version": "1.2",
  "video_ratio": "16:9",
  "subtitle": true,
  "bgm": true,
  "outro": true,
  "schedule": {
    "enabled": true,
    "cron": "0 9 * * *",
    "timezone": "Asia/Shanghai",
    "limit": 10,
    "daily_limit": 50
  }
}
```

### 5.5.3 视频模板

模板描述技术能够执行的生产方式、参数结构、资源引用和版本。模板由技术维护，但模板不是动态代码插件，不允许上传脚本。

### 5.5.4 业务策略

高级运营基于模板创建策略，设置适用游戏、内容类型、视频参数和默认值。普通运营在创建人工任务时选择可用策略，并只能修改允许覆盖的参数。

### 5.5.5 策略快照

每个 `compose_task` 保存不可变策略快照，至少包含模板、模板版本、策略版本、实际参数和必要随机种子。策略后续修改不改变历史任务和成片。

### 5.5.6 多策略生产

同一 `material_usage` 可以创建多个独立任务：

```text
material_usage A
→ compose_task 1：16:9 高光集锦
→ compose_task 2：9:16 快节奏版本
→ compose_task 3：剧情解说版本
```

每个任务独立状态、快照和成片。

### 5.5.7 自动执行规则

自动执行规则直接属于 `compose_strategy.schedule`：

- `enabled`：是否自动执行；
- 执行时间或周期；
- 时区；
- 单次任务上限；
- 每日任务上限；
- 素材筛选范围。

M4 交付策略创建、编辑、复制和人工选择；M5 才启用 Scheduler 自动触发。

### 5.5.8 页面与权限

页面能力：新建、编辑、复制、启停自动执行、查看执行任务。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/03-compose-strategies.png`。

- 普通运营：选择可用策略；
- 高级运营：创建和维护业务策略、启停自动执行；
- 技术：维护模板、版本和底层能力。

## 5.6 合成任务（compose_task）

### 5.6.1 功能定位

`compose_task` 表示一次具体的视频生产行为，也是 Cloud Worker 领取、执行和恢复的正式业务任务。

它同时回答：

- 使用哪个素材；
- 使用哪个策略快照；
- 由人工还是 Scheduler 触发；
- 当前执行到哪里；
- 是否成功生成成片。

不再设置 `compose_pool_item` 或额外通用 Agent task。

### 5.6.2 创建方式

1. 在“我的素材”人工创建；
2. 在已有成片或任务上复制配置重新创建；
3. M5 由 Scheduler 根据到期 `compose_strategy` 自动创建；
4. 失败后重试当前任务，或修改策略后创建新任务。

### 5.6.3 任务状态

```text
pending
→ running
→ success

pending / running
→ failed

pending / running
→ cancelled
```

页面文案：排队中、处理中、成功、失败、已取消。

等待源视频准备的任务仍是 `pending`，可在详情显示当前阶段，不新增主状态。

### 5.6.4 进度和阶段

详情可展示：

- 等待原素材；
- 下载/校验输入；
- 合成处理中；
- 校验输出；
- 上传成片；
- 完成或失败。

列表百分比是执行进度投影，不替代主状态，也不得在失败时保留误导性的“100% 成功”视觉。

### 5.6.5 批量操作

P0 支持：

- 多素材创建任务；
- 批量选择策略；
- 批量取消尚未完成的任务；
- 对可重试技术失败批量重试。

每条素材仍生成独立任务，部分失败不回滚其他任务。

### 5.6.6 取消规则

- `pending`：可直接取消；
- `running`：发出取消请求，Worker 停止 FFmpeg 并清理本次临时文件后确认取消；
- `success`：不能取消，可归档成片；
- `failed`：可按错误类型重试。

只修改数据库状态而不终止真实进程不算取消成功。

### 5.6.7 页面能力

合成任务页支持按状态、触发方式、策略和时间筛选；查看详情、日志摘要、取消、重试和查看成片。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/04-compose-tasks.png`。

## 5.7 自动生产（归属 compose_strategy）

### 5.7.1 功能定位

自动生产不是独立产品对象，而是 `compose_strategy` 的一种启用方式：

```text
compose_strategy.schedule
→ Scheduler
→ compose_task
→ Worker Pool
→ composite_output
```

### 5.7.2 创建和维护角色

高级运营决定业务范围、素材条件、执行周期和数量上限；技术维护 Worker 资源和模板能力。普通运营不能启停全局自动执行。

### 5.7.3 配置内容

策略自动配置至少包括：

- 游戏与业务范围；
- 可生产素材条件；
- 启停状态；
- 执行时间/周期与时区；
- 单次上限；
- 每日上限；
- 使用的模板和视频参数。

### 5.7.4 自动调度

支持：

1. 定时执行；
2. 周期执行；
3. 高级运营“立即执行”。

“立即执行”也只创建 `compose_task`，不在 HTTP 请求中同步合成。

### 5.7.5 防重与数量控制

- 同策略、同计划周期、同素材不重复创建；
- 同一策略已达单次或每日上限时跳过剩余候选；
- 禁用策略不再创建任务；
- 已创建任务不因策略随后停用而静默变成成功或删除。

### 5.7.6 素材可生产校验

自动创建任务前至少检查：

- 素材仍可见且可用；
- 来源链接存在；
- 没有明确禁止生产标记；
- 未超过策略配置的重复与数量限制；
- 相同调度键不存在。

源视频未就绪不是直接跳过理由，可先创建文件准备任务。

### 5.7.7 批量结果

一次策略触发中，每个候选素材独立创建或跳过。运行记录需展示：候选数、创建数、防重数、超限数、不可用数和失败数。部分创建成功不得显示成全部失败或全部成功。

### 5.7.8 自动生产信号

自动生产成功只通过 `compose_task` 与 `composite_output` 形成事实。发布成功由第六章 `publication` 形成事实。不得新增 `production_signal` 或以领取/下载冒充发布。

## 5.8 Cloud 执行、失败与恢复

### 5.8.1 功能定位

Cloud Worker 异步执行 `compose_task`。产品需要看到稳定的任务状态、进度、错误和恢复结果，不直接暴露租约、进程号或命令行等底层细节。

### 5.8.2 领取与并发

- Worker 从数据库原子领取 `pending` 任务；
- 同一任务同时只能有一个 Worker；
- 系统按配置限制总并发；
- 无可用资源时任务继续排队，不返回假失败。

### 5.8.3 Heartbeat 与超时

运行中任务持续 heartbeat。长时间无 heartbeat 或超过任务超时后，系统进入恢复判断：确认原执行已经停止后才能重排或失败，不能同时启动第二个 FFmpeg。

### 5.8.4 自动重试

允许自动重试：

- 临时网络错误；
- 对象存储短暂失败；
- Worker 崩溃且结果可确认未提交；
- 其他已标记为可重试的技术错误。

不自动重试：

- 源文件永久不存在；
- 模板或参数非法；
- FFmpeg 能力不兼容；
- 输出内容无法通过校验；
- 外部结果不明确。

### 5.8.5 重试与重新生产

- 技术重试：保留同一 `compose_task` 的策略快照，增加尝试次数；
- 修改策略/参数：创建新的 `compose_task`；
- 复制成片配置：创建新的 `compose_task`，成功后生成新的 `composite_output`。

### 5.8.6 异常任务处理

任务详情展示：失败阶段、可理解的错误、是否可重试、已尝试次数和最后更新时间。技术可查看脱敏日志；普通运营不能看到凭据、内部命令或对象存储签名。

### 5.8.7 卡死恢复

系统定期扫描租约过期、长期无 heartbeat 或超时任务。恢复必须以真实执行已结束为前提；仅把状态从 `running` 改回 `pending` 而不处理遗留进程属于假恢复。

## 5.9 我的成片与下载中心

### 5.9.1 我的成片定位

“我的成片”管理已经成功生成、当前用户有权查看的 `composite_output`。

能力：

- 视频预览；
- 查看来源素材；
- 查看生成策略和任务；
- 下载成片；
- 去发布；
- 归档。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/05-my-outputs.png`。

### 5.9.2 composite_output 定义

`composite_output` 是唯一成片资产，不是任务、下载记录或发布记录。成片文件位于对象存储；运营电脑上的副本仍属于同一成片。

### 5.9.3 成片生成条件

必须同时满足：

- `compose_task` 的 FFmpeg 进程成功结束；
- 输出文件存在且媒体可读；
- 文件大小、时长和必要 Hash 校验通过；
- 对象存储写入和校验完成；
- 来源、策略快照和任务可追溯。

任一条件失败都不创建 `composite_output`。

### 5.9.4 来源追踪

成片详情必须可追溯：

- `material`；
- 人工生产时的 `material_usage`；
- `compose_strategy` 与快照；
- `compose_task`；
- 文件信息和生成时间；
- 后续 `publication`。

### 5.9.5 成片状态

产品状态：

```text
pending_publish
published
archived
```

页面文案：待发布、已发布、已归档。下载状态单独来自 `file_transfer_task`，不混入成片主状态。

### 5.9.6 下载中心定位

下载中心是横向文件能力，入口位于顶部导航“下载”，点击后打开右侧 Drawer，不属于素材库子菜单。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/06-download-center.png`。

### 5.9.7 file_transfer_task 定义

支持两类用户下载：

```text
material
→ file_transfer_task
→ 运营电脑本地文件
```

```text
composite_output
→ file_transfer_task
→ 运营电脑本地文件
```

同一张任务表也可表达 Cloud 合成前原素材准备，通过用途和执行位置区分，不新增其他下载任务表。

### 5.9.8 下载任务状态

```text
pending
running
success
failed
cancelled
```

Drawer 展示：文件名、资产类型、文件大小、进度、当前速度、预计剩余时间、错误和完成时间。

### 5.9.9 下载操作

- 进行中任务：暂停/继续能力只有在执行器真实支持断点续传时才展示；必须支持取消；
- 失败任务：重新下载；
- 成功任务：打开文件或所在目录；
- 最近完成：可清理显示记录，但不得删除素材、成片或用户本地文件；
- 批量暂停等按钮不能只改前端状态。

### 5.9.10 本地文件边界

Cloud 保存任务事实、目标节点和完成结果，不保存运营电脑绝对路径。Desktop / Local Agent 管理本地保存目录、临时文件、断点信息和最终路径。

### 5.9.11 下载完整性

成功前必须验证：

- 实际字节数与预期一致；
- 必要 Hash 一致；
- 临时文件已原子移动为最终文件；
- 取消或失败不留下被误认为完整文件的目标文件。

### 5.9.12 发布入口

点击“去发布”进入第六章流程。下载成片不创建 `publication`；只有真实发布或补录成功才创建发布事实。

### 5.9.13 重复风险

发布前仍可按成片、文件 Hash、素材 + 平台 + 账号范围提示重复风险。风险判断属于发布前校验，不通过成片池或领取关系实现。

### 5.9.14 文件生命周期

- 对象存储中的正式成片按存储策略保留；
- 本地副本删除不删除 `composite_output`；
- 临时合成文件在成功、失败或取消后按恢复规则清理；
- 清理不得删除仍被正式成片引用的对象。

## 5.10 权限与验收要求

### 5.10.1 角色模型

继续使用：

```text
普通运营
高级运营
技术
```

权限采用角色 + 业务范围 + 资源归属，不新增复杂 RBAC。

### 5.10.2 普通运营

可以：

- 查看有权限的素材；
- 加入和管理自己的素材；
- 选择可用策略并创建人工任务；
- 查看自己的任务与成片；
- 下载原素材和成片；
- 进入发布流程。

不能：

- 修改公共策略模板；
- 启停自动生产；
- 查看其他业务范围的任务或下载；
- 绕过 Cloud 直接请求 Worker 执行。

### 5.10.3 高级运营

可以：

- 管理负责范围内的 `compose_strategy`；
- 配置和启停 M5 自动执行；
- 查看范围内任务和成片；
- 取消、重试符合规则的任务；
- 查看自动调度统计和异常素材。

### 5.10.4 技术

可以：

- 维护模板、FFmpeg 能力和 Worker 配置；
- 查看全局执行状态、脱敏日志和资源指标；
- 处理租约、超时、对象存储和文件异常；
- 在审计下执行全局任务处置。

技术权限不能绕过业务对象、对象存储安全、本机文件和 Local Agent 下载合同。

### 5.10.5 P0 验收链路

#### M4 人工生产链路

```text
素材库加入我的素材
→ 选择策略创建 compose_task
→ 原素材懒加载准备
→ Cloud Worker 真实 FFmpeg 合成
→ 对象存储产生可播放文件
→ composite_output
→ 我的成片下载到本地
```

必须验证：

- `material_usage` 不重复；
- HTTP 不同步等待；
- 源文件未准备时任务不提前执行；
- 失败不创建成片；
- 下载进度和最终 Hash 真实；
- Desktop 退出不影响 Cloud 合成。

#### M5 自动生产链路

```text
启用 compose_strategy.schedule
→ Scheduler 到期扫描
→ 幂等创建 compose_task
→ Worker Pool 按并发上限执行
→ 自动生成 composite_output
```

必须验证：

- 禁用策略不创建任务；
- 同周期不重复；
- 单次和每日上限生效；
- Worker 并发不越界；
- heartbeat、超时、重试和重启恢复真实有效；
- HTTP Server 单独运行不启动 Scheduler / Worker。

#### 异常恢复链路

必须覆盖：

- 原素材下载失败；
- 输入损坏；
- FFmpeg 非零退出；
- Worker 崩溃；
- heartbeat 中断和租约过期；
- 对象存储上传失败；
- 任务取消；
- 本地下载失败和重试。

所有异常都不得生成假成片、假下载成功或两个并行执行者。

#### 发布衔接链路

```text
我的成片
→ 去发布
→ publication（第六章）
```

下载、预览和归档均不等于发布。

### 5.10.6 第五章最终设计原则

1. **一个成片，一个资产**：Cloud 与本地文件是同一 `composite_output` 的不同位置。
2. **一种合成执行边界**：人工和自动生产都由 Cloud Compose Worker 执行。
3. **一种生产任务**：使用 `compose_task`，不再叠加生产意图表或 Agent task。
4. **自动规则归策略**：`compose_strategy.schedule` 是自动生产唯一规则来源。
5. **我的素材语义不变**：`material_usage` 是唯一个人素材关系。
6. **下载是横向能力**：原素材和成片统一使用 `file_transfer_task`，入口为全局 Drawer。
7. **源视频懒加载**：进入素材库不等于下载视频。
8. **真实成功优先**：任务成功、文件校验和对象存储落盘同时成立才创建成片。
9. **生产和发布解耦**：成片生成不创建发布记录。
10. **保持简单**：不引入微服务、MQ、工作流引擎或复杂 Agent 架构。
