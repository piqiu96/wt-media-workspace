# 第五章：素材生产 V2 正式需求文档（完整版）

> 本文档为第五章「素材生产」的正式需求文档版本，基于当前已确认的讨论结论整理。  
> 文档聚焦产品需求、业务规则、边界和验收口径，不展开数据库字段、接口、调度器实现、Agent 内部实现等技术设计内容。

---

## 5.1 模块概述

### 5.1.1 模块定位

素材生产模块负责将系统中的正式素材转化为可发布成片，是内容运营平台中承接「内容发现」与「发布管理」之间的核心生产环节。

整体链路为：

```text
content_lead
→ material
→ 素材生产
→ composite_output
→ publication
```

素材生产支持两种生产模式：

1. **本地人工生产**  
   由运营主动领取素材，在本地 Agent 环境中完成下载、合成、校验和成片生成。

2. **云端自动生产**  
   由系统根据 `production_rule` 自动筛选素材，在云端 Agent 批量生成成片，用于利用夜间、空闲时间提升生产效率。

---

### 5.1.2 建设目标

素材生产模块主要解决以下问题：

1. **提升生产效率**  
   通过批量任务、本地 Agent、云端自动生产，减少运营重复操作。

2. **支持规模化生产**  
   支持多游戏、多平台、多内容类型的持续生产，满足运营矩阵内容供给。

3. **统一生产链路**  
   本地生产和云端生产最终都汇聚到统一的 `composite_output` 成片管理体系。

4. **降低重复生产和重复发布风险**  
   通过 material 生产摘要、生产复核池、成片领取独占、发布前重复检测，降低同素材、同成片、同文件重复使用风险。

5. **保证生产过程可追溯**  
   每个成片需要能够追溯来源素材、生产任务、执行记录、合成策略和发布记录。

---

### 5.1.3 核心能力

素材生产模块包含以下能力：

| 能力 | 说明 | 核心对象 |
|---|---|---|
| 素材库 | 管理正式素材、私有素材、素材生命周期 | material |
| 我的素材 | 管理运营个人领取素材后的使用关系 | material_usage |
| 合成策略 | 管理模板、策略和策略快照 | composite_strategy_template / composite_strategy / composite_strategy_snapshot |
| 合成任务台 | 管理一次合成生产意图 | compose_pool_item |
| 自动生产规则 | 管理云端自动生产计划 | production_rule |
| 执行任务 | 记录一次真实执行过程 | task |
| 成片管理 | 管理成功生成的视频资产 | composite_output |
| 云端成片池 | 管理云端成片分发、可见和领取规则 | composite_output_pool |
| 成片领取 | 管理运营领取、下载和本地文件状态 | composite_output_claim |
| 发布补录入口 | 支持手机/外部发布后的结果回填 | publication |

---

### 5.1.4 模块边界

#### 本章负责

- 正式素材进入生产体系
- 运营领取素材
- 本地合成任务管理
- 云端自动生产规则
- 生产执行状态追踪
- 失败重试和异常处理
- 成片生成和成片管理
- 云端成片池、领取和下载
- 发布入口和发布补录入口
- 发布前重复风险提示

#### 本章不负责

- 内容搜索、抓取、线索发现
- 完整平台发布流程
- 平台账号发布字段配置
- 浏览器窗口发布执行
- 发布结果数据采集
- 调度器、队列、Agent 等底层技术实现

发布流程、发布任务、发布记录创建和发布结果回收归属第六章「发布管理」。第五章仅提供成片进入发布流程的入口，以及发布补录入口。

## 5.2 素材生产流程

素材生产包含两条主链路：

1. 本地人工生产链路
2. 云端自动生产链路

两条链路最终统一生成 `composite_output`。

---

### 5.2.1 本地人工生产流程

本地人工生产适用于运营主动选择素材进行生产。

流程：

```text
material
→ material_usage
→ compose_pool_item
→ task
→ composite_output
→ 发布入口 / 发布补录
```

#### 流程说明

1. **领取素材**  
   运营从素材库选择素材，系统创建 `material_usage`，表示该运营开始使用该素材。

2. **创建合成任务**  
   运营选择合成策略和参数，创建 `compose_pool_item`。

3. **执行生产**  
   系统创建 `task`，由本地 Agent 执行素材下载、文件校验、FFmpeg 合成、结果同步。

4. **生成成片**  
   task 执行成功且文件校验通过后，系统创建 `composite_output`。

5. **进入发布入口**  
   成片可进入系统内直接发布，也可在手机或外部发布后补录结果。

---

### 5.2.2 云端自动生产流程

云端自动生产适用于系统按规则定时筛选素材，在云端 Agent 批量生成成片。

流程：

```text
material
→ production_rule
→ compose_pool_item
→ task
→ composite_output
→ composite_output_pool
→ composite_output_claim
→ 本地文件
→ publication
```

#### 流程说明

1. **production_rule 触发**  
   系统根据定时、周期或手动触发规则启动自动生产。

2. **筛选 material**  
   系统根据游戏、平台、内容类型、素材状态、素材分类等条件筛选可生产素材。

3. **风险判断**  
   系统基于 material 的生产次数、发布次数、库存情况和风险状态进行判断。低风险直接生产，中风险降低优先级，高风险进入生产复核池。

4. **创建生产意图**  
   系统创建 `compose_pool_item`，表示本次自动生产的一次合成意图。

5. **创建执行任务**  
   系统创建 `task`，由云端 Agent 执行。

6. **生成成片**  
   task 成功后创建 `composite_output`。

7. **进入成片池**  
   根据 production_rule 指定的目标池，将成片归入 `composite_output_pool`。

8. **运营领取下载**  
   运营在有权限的成片池中领取成片，创建 `composite_output_claim`，下载到本地后进入本地成片管理。

9. **发布与补录**  
   运营可系统内直接发布，或手机/外部发布后补录 publication。

---

### 5.2.3 本地生产与云端生产的区别

| 对比项 | 本地人工生产 | 云端自动生产 |
|---|---|---|
| 触发方式 | 运营主动 | production_rule 自动触发 |
| 是否创建 material_usage | 是 | 否 |
| 是否创建 compose_pool_item | 是 | 是 |
| 执行方式 | 本地 Agent | 云端 Agent |
| 成片结果 | composite_output | composite_output |
| 文件位置 | 默认本地 | 默认云端临时存储，运营按需下载 |
| 适用场景 | 临时生产、人工判断、快速处理 | 批量生产、无人值守、夜间生产 |
| 权限控制 | 以个人素材为主 | 以成片池和领取关系为主 |

云端自动生产不创建 `material_usage`。  
`material_usage` 表示运营个人领取素材后的使用关系，而云端生产是系统规则驱动的生产行为。

---

### 5.2.4 核心对象关系

```text
content_lead
    ↓
material

======================
本地人工生产
======================

material_usage
    ↓
compose_pool_item
    ↓
task

======================
云端自动生产
======================

production_rule
    ↓
compose_pool_item
    ↓
task

======================

task
    ↓
composite_output
    ↓
composite_output_pool
    ↓
composite_output_claim
    ↓
local_file
    ↓
publication
```

| 对象 | 职责 |
|---|---|
| material | 正式素材，是生产体系中的基础输入 |
| material_usage | 运营个人领取和使用素材的关系 |
| compose_pool_item | 一次合成生产意图 |
| task | 一次真实执行过程 |
| production_rule | 云端自动生产规则 |
| composite_output | 唯一成片资产 |
| composite_output_pool | 云端成片分发池 |
| composite_output_claim | 运营领取和下载成片的关系 |
| publication | 真实发布记录 |

## 5.3 素材库（material）

### 5.3.1 功能定位

素材库负责管理进入生产体系的正式素材。  
`material` 是素材生产流程中的基础资产，所有本地生产和云端自动生产都应尽量关联 material，用于追踪来源、统计使用、判断重复风险。

---

### 5.3.2 素材来源

material 来源包括：

1. **content_lead 转换**  
   内容线索经过人工确认后转为正式素材。

2. **自动规则转换**  
   系统根据规则将符合条件的内容线索转为素材。

3. **运营创建私有素材**  
   运营手动创建个人素材，例如截图、自录视频、临时素材。

4. **私有素材转公共素材**  
   私有素材经过高级运营审核后，可转为公共素材。

Excel、链接批量导入属于内容发现阶段，不作为 material 的直接来源。

---

### 5.3.3 公共素材与私有素材

#### 公共素材

公共素材是授权业务范围内共享的正式素材。

特点：
- 多个运营可见和使用
- 可进入自动生产候选范围
- 可进入授权业务范围内生产流程

公共素材由高级运营负责审核和生命周期控制。

#### 私有素材

私有素材是运营个人创建的素材。

规则：
- 默认仅创建人可见
- 默认仅创建人使用
- 不进入公共素材库
- 不需要公共审核
- 如需转公共素材，需要高级运营审核

---

### 5.3.4 素材状态管理

material 包含生命周期状态：

```text
active
paused
retired
```

#### active

正常生产状态。

支持：
- 新领取
- 加入合成任务台
- 本地生产
- 自动生产
- 推荐展示

#### paused

暂停状态。

暂停：
- 新领取
- 新推荐
- 自动生产

默认不自动中断：
- 已存在 material_usage
- 已创建 compose_pool_item
- 已排队 task
- 执行中的 task
- 历史成片
- 历史发布记录

进入 paused 时，系统应提示高级运营：

> 当前素材可能已被运营领取或进入生产流程，是否需要强制中断后续生产？

如果高级运营选择强制中断，可中断：
- material_usage 后续生产
- 未执行 compose_pool_item
- 排队中的 task

执行中的 task 需要根据执行状态处理，可选择等待结束、请求停止或标记异常。

#### retired

退场状态。

禁止：
- 新领取
- 新推荐
- 自动生产

保留：
- 历史 material_usage
- 历史 compose_pool_item
- 历史 task
- 历史 composite_output
- 历史 publication

retired 表示停止新增使用，不等于删除。

---

### 5.3.5 素材生产统计

material 负责记录素材级生产摘要，用于自动生产判断、重复风险提示和运营决策。

material 需要保存的摘要包括：
- 已生产成片数量
- 已发布数量
- 最近生产时间
- 最近发布时间
- 生产额度
- 发布提醒阈值
- 重复风险状态

material 不记录：
- 谁领取过素材
- 谁下载过成片
- 某次任务失败原因
- 某个成片被谁领取

这些分别由 `material_usage`、`task`、`composite_output_claim` 等对象负责。

---

### 5.3.6 自动生产风险判断

自动生产前需要基于 material 判断风险。

风险来源包括：
- 同一素材生产次数过高
- 同一素材发布次数过高
- 同一素材在同平台短时间内出现多次
- 成片库存过高但无人领取
- 已下载未补录数量过高

风险处理方式：

| 风险等级 | 处理方式 |
|---|---|
| 低风险 | 正常生产 |
| 中风险 | 降低生产优先级 |
| 高风险 | 进入生产复核池 |
| 明确不可用 | 强制阻止生产 |

明确不可用包括：
- retired
- 人工禁用
- 违规标记
- production_rule 明确配置为超额跳过

---

### 5.3.7 生产复核池

生产复核池用于处理自动生产系统无法自动判断的问题。

复核对象是：

```text
material
```

不是：

```text
composite_output
```

原因是复核问题是：

> 这个素材是否还值得继续被机器生产？

而不是：

> 某一条成片是否合格？

高级运营在生产复核池中需要看到：
- 素材标题、封面、来源、游戏、内容类型
- 已生产成片数
- 已发布次数
- 最近生产时间
- 最近发布时间
- 未领取成片数量
- 已下载未补录数量
- 触发复核原因
- 系统建议动作

可执行操作：
- 继续生产
- 冷却一天
- 降低优先级
- 暂停自动生产
- 调整生产规则

生产复核只阻塞该 material 继续进入自动生产，不阻塞整个 production_rule。

---

## 5.4 我的素材（material_usage）

### 5.4.1 功能定位

`material_usage` 表示运营个人领取并使用素材的关系。

它用于记录：

> 某个运营已经领取某个 material，并准备基于该素材进行生产。

material_usage 仅用于本地人工生产。  
云端自动生产不创建 material_usage。

---

### 5.4.2 与 material 的关系

一个 material 可以被多个运营领取，每个运营形成自己的 material_usage。

```text
material
    ↓
运营A material_usage
运营B material_usage
运营C material_usage
```

同一个用户对同一个 material 默认只能存在一个有效 material_usage。

---

### 5.4.3 素材领取规则

运营从素材库领取素材后，系统创建 material_usage。

重复领取规则：
- 已存在正常使用记录：提示已领取，不重复创建
- 已放弃记录：支持恢复原 material_usage
- 素材 paused / retired：不允许重新领取

---

### 5.4.4 下载规则

素材领取后支持下载。

下载方式：
1. **手动下载**  
   运营主动下载素材。

2. **合成前自动补下载**  
   进入合成流程前，如果本地素材不存在，由 Agent 自动下载。

下载失败时支持：
- 查看失败原因
- 手动重试
- 自动重试

本地文件异常时支持：
- 重新下载
- 重新定位本地文件

---

### 5.4.5 放弃与恢复

运营可以主动放弃素材使用。

放弃后：
- 不允许继续新建合成任务
- 不删除历史合成任务
- 不删除历史成片
- 不删除历史发布记录

已放弃的 material_usage 可以恢复。恢复后可以继续加入合成任务台。

---

### 5.4.6 强制中断机制

当 material 进入 paused，默认不影响已有 material_usage。  
如果高级运营选择强制中断，可对关联生产链路执行中断。

中断范围：
- 禁止 material_usage 后续创建新任务
- 取消未执行 compose_pool_item
- 取消排队 task
- 执行中 task 根据状态停止或标记异常

强制中断需要提示风险，避免影响正在执行的本地文件和临时任务。

---

### 5.4.7 权限边界

普通运营可以：
- 查看自己的 material_usage
- 下载素材
- 创建合成任务
- 放弃和恢复使用

高级运营可以：
- 查看负责游戏范围内 material_usage
- 强制中断异常使用关系
- 处理素材风险

技术可基于当前职责参与素材使用异常处理，关键修改必须记录操作日志。

---

## 5.5 合成策略

### 5.5.1 功能定位

合成策略用于定义：

> 如何将素材加工成为成片。

合成策略负责：
- 选择生产模板
- 配置生成参数
- 控制生成效果
- 支持成片复刻

合成策略不负责：
- 选择素材
- 决定生产时间
- 执行生产任务

---

### 5.5.2 策略体系

策略采用三层结构：

```text
composite_strategy_template
→ composite_strategy
→ composite_strategy_snapshot
```

| 对象 | 说明 |
|---|---|
| composite_strategy_template | 技术模板能力 |
| composite_strategy | 业务生产策略 |
| composite_strategy_snapshot | 某次生产实际使用的策略快照 |

---

### 5.5.3 合成模板

模板由技术维护。

模板负责定义：
- 支持的生产方式
- 参数结构
- 资源位置
- 模板版本
- 底层执行能力

例如：
- 活动攻略模板
- 福利领取模板
- 角色介绍模板

---

### 5.5.4 合成策略

策略由运营使用和配置。

策略负责：
- 选择模板
- 配置业务参数
- 定义生成效果

同一模板可以有多个策略，例如：
- B站 60 秒攻略策略
- 抖音 30 秒快节奏策略
- 百家号说明型策略

---

### 5.5.5 策略快照

每次生产必须保存策略快照。

策略快照用于：
- 历史追溯
- 失败排查
- 爆款复刻
- 多版本对比

策略快照应保存：
- 使用的模板
- 使用的策略
- 模板版本
- 实际参数
- 随机种子
- 配置摘要

---

### 5.5.6 多策略生产

支持一个素材使用多个策略生成多个版本。

示例：

```text
material A
→ compose_pool_item 1：B站攻略视频
→ compose_pool_item 2：短视频快节奏版本
→ compose_pool_item 3：福利领取版本
```

每个 compose_pool_item 独立保存策略快照、参数、随机种子和执行结果。

---

### 5.5.7 production_rule 与策略关系

production_rule 不直接绑定单个策略。

自动生产通过 JSON 配置策略选择规则：

```text
production_rule
→ strategy_config(JSON)
→ composite_strategy
→ composite_strategy_snapshot
```

不单独建立 strategy_group。

---

### 5.5.8 策略权限

普通运营：
- 选择可用策略
- 修改当前任务参数

高级运营：
- 配置业务策略
- 设置默认策略
- 管理授权业务范围内常用策略

技术：
- 创建模板
- 修改模板版本
- 管理底层能力

---

## 5.6 合成任务台（compose_pool_item）

### 5.6.1 功能定位

`compose_pool_item` 表示一次明确的合成生产意图。

它描述：
- 使用哪个素材
- 使用什么策略
- 希望生成什么成片

它不是：
- 执行任务
- 最终成片

关系：

```text
compose_pool_item
→ task
→ composite_output
```

---

### 5.6.2 创建方式

支持以下方式创建：

1. **加入合成任务台**  
   创建 compose_pool_item，但不立即执行。

2. **直接合成**  
   创建 compose_pool_item 后立即进入执行队列。

3. **批量生产**  
   多个素材批量创建 compose_pool_item。

4. **复制生成**  
   基于已有成片或任务创建新的 compose_pool_item，用于复刻或多版本生产。

---

### 5.6.3 一个素材多个生产任务

一个 material_usage 可以创建多个 compose_pool_item。

适用于：
- 多策略生成
- 多平台版本
- A/B 测试
- 爆款复刻

---

### 5.6.4 合成任务状态

compose_pool_item 关注业务状态，建议展示为：

- 待配置
- 待执行
- 执行中
- 已完成
- 失败
- 已取消
- 异常

技术执行细节由 task 管理。

---

### 5.6.5 批量操作

P0 支持：
- 批量加入任务台
- 批量配置策略
- 批量开始执行
- 批量取消
- 批量技术重试

P1 再增强：
- 复杂批量参数编辑
- 批量复制生成
- 云端 Agent 调度优化

---

### 5.6.6 取消规则

允许取消：
- 未执行任务
- 排队任务

执行中任务需要请求执行 Agent 停止，根据结果标记为取消、失败或异常。

---

### 5.6.7 与云端自动生产的关系

云端自动生产同样需要创建 compose_pool_item。

流程：

```text
production_rule
→ 筛选 material
→ 创建 compose_pool_item
→ 创建 task
→ 生成 composite_output
```

这样本地生产和云端生产统一进入同一生产体系。

---

## 5.7 自动生产规则（production_rule）

### 5.7.1 功能定位

production_rule 是云端自动生产入口，用于定义系统在什么条件下自动生产什么类型的成片。

production_rule 负责：
- 生产范围
- 调度周期
- 生产数量
- 策略配置
- 目标成片池
- 风险控制

production_rule 不负责：
- 执行任务
- 生成视频
- 管理云端 Agent

---

### 5.7.2 创建角色

production_rule 由高级运营创建和维护。

原因：
- 生产什么由业务决定
- 什么时候生产由运营节奏决定
- 生产给谁使用由运营分配决定

技术负责模板能力、执行环境和云端 Agent 资源；同时可基于当前职责参与业务生产规划，关键业务修改必须记录操作日志。

---

### 5.7.3 配置内容

production_rule 需要配置：

#### 基础信息

- 规则名称
- 游戏
- 平台
- 内容类型

#### 素材筛选范围

- 游戏
- 平台
- 内容分类
- 素材状态
- 素材标签

#### 策略配置

通过 `strategy_config(JSON)` 配置：
- 使用哪些策略
- 策略匹配条件
- 策略优先级

#### 目标成片池

production_rule 必须绑定目标 `composite_output_pool`。

---

### 5.7.4 自动调度

支持三类触发方式：

1. **定时执行**  
   如每天 02:00 执行。

2. **周期执行**  
   如每 6 小时执行一次。

3. **手动执行**  
   高级运营点击立即执行，用于活动上线、临时热点、爆款复刻。

调度器属于技术实现，产品只定义执行频率、执行时间和启停状态。

---

### 5.7.5 生产数量控制

P0 支持：
- 单次生产数量
- 每日生产上限

P1 可扩展：
- 目标库存
- 按池子缺口自动补量
- 按运营消化速度动态调整

---

### 5.7.6 生产风险控制

production_rule 执行前需要检查 material 风险。

风险判断依据：
- 已生产数量
- 已发布数量
- 最近生产时间
- 最近发布时间
- 成片库存
- 已下载未补录数量

处理方式：

| 风险 | 处理 |
|---|---|
| 低风险 | 正常生产 |
| 中风险 | 降低生产优先级 |
| 高风险 | 进入生产复核池 |
| 明确不可用 | 阻止生产 |

---

### 5.7.7 生产复核池

生产复核池用于处理自动生产中的高风险素材。

复核对象是 material。

高级运营在复核池中查看：
- 素材信息
- 已生产数量
- 已发布数量
- 最近生产时间
- 最近发布时间
- 未领取成片数量
- 风险原因
- 系统建议动作

可执行操作：
- 继续生产
- 冷却一天
- 降低优先级
- 暂停自动生产
- 调整生产规则

复核只影响该 material，不阻塞整个 production_rule。

---

### 5.7.8 自动生产信号回写

自动生产只向 material 回写两个核心信号：

1. **生产成功信号**  
   更新已生产成片数量和最近生产时间。

2. **发布成功信号**  
   更新已发布数量和最近发布时间。

不回写领取成功信号。

领取属于 `composite_output_claim` 的职责，不直接构成重复发布风险。

---

## 5.8 执行任务与失败重试（task）

### 5.8.1 功能定位

task 表示一次真实执行过程。

它负责记录：
- 执行状态
- 执行结果
- 执行 Agent
- 异常情况

task 不负责定义生产目标，也不保存最终成片。

---

### 5.8.2 创建时机

#### 本地生产

```text
运营开始合成
→ compose_pool_item
→ task
→ Agent 执行
→ composite_output
```

#### 云端自动生产

```text
production_rule 触发
→ 筛选 material
→ compose_pool_item
→ task
→ 云端 Agent 执行
→ composite_output
```

---

### 5.8.3 执行 Agent

task 需要记录执行来源，包括：
- 本地 Agent
- 云端 Agent

用于：
- 定位异常
- 分析效率
- 后续调度优化

---

### 5.8.4 状态管理

内部状态：
- created
- queued
- running
- success
- failed
- cancelled
- timeout

运营展示状态：
- 等待执行
- 执行中
- 已完成
- 失败
- 已取消
- 异常

技术细节记录在 execution_log，不直接暴露给运营。

---

### 5.8.5 自动重试

#### 技术失败

例如：
- 网络异常
- 下载失败
- 节点异常
- 上传失败

处理：
- 复用 compose_pool_item
- 复用策略快照
- 重新创建 task

默认自动重试 3 次。

#### 策略失败

例如：
- 模板效果不好
- 参数错误
- 策略不适合

处理：
- 创建新的 compose_pool_item
- 生成新的策略快照

#### 复制生产

用于爆款复刻和多版本生产。

处理：
- 创建新的 compose_pool_item
- 可复用原策略
- 生成新的随机种子
- 输出新的 composite_output

---

### 5.8.6 异常任务处理

异常分为：

#### 技术异常

例如：
- 节点异常
- 环境异常
- 网络问题

由技术处理。

#### 业务异常

例如：
- 素材不可用
- 策略问题
- 模板问题

由高级运营或技术共同处理。

---

### 5.8.7 卡死任务处理

当 task 长时间无状态更新时，系统标记为异常。

支持：
- 查看日志
- 重新执行
- 取消任务

---

## 5.9 成片管理（composite_output）

### 5.9.1 功能定位

成片管理负责管理所有已经生产完成的视频成片。

无论来源是本地人工生产还是云端自动生产，最终统一进入 `composite_output`。

---

### 5.9.2 composite_output 定义

`composite_output` 表示一条已经完成生产的视频成片资产。

它不是：
- 下载记录
- 发布记录
- 领取记录

这些分别由：
- task
- composite_output_claim
- publication

负责。

---

### 5.9.3 成片生成条件

只有满足以下条件才创建 composite_output：
- task 执行成功
- 输出文件存在
- 文件基础校验通过
- 生产结果可追踪

失败、取消、文件损坏、上传失败不创建 composite_output，只保留 task 和日志。

---

### 5.9.4 来源追踪

每个成片必须能够追溯：
- 来源 material
- 来源 material_usage（如人工生产）
- compose_pool_item
- task
- production_rule（如云端自动生产）
- 策略快照

用于回答：
- 这个视频来自哪里？
- 为什么生成？
- 使用什么策略？
- 是否发布过？

---

### 5.9.5 云端成片池（composite_output_pool）

`composite_output_pool` 是云端成片分发池。

它用于：
- 管理云端生成成片
- 控制可见范围
- 控制领取权限
- 控制下载规则

它不是文件存储。

成片池应在 production_rule 启用前创建。

创建方式：
- 高级运营提前创建
- 创建 production_rule 时选择或新建

production_rule 必须绑定目标 composite_output_pool。

---

### 5.9.6 成片池权限规则

采用池级权限控制。

普通运营：
- 只能看到自己有权限领取的池

高级运营：
- 可查看负责游戏范围内业务池

技术：
- 可查看全局业务与执行相关数据

不为每条 composite_output 单独配置用户权限。

---

### 5.9.7 成片领取（composite_output_claim）

`composite_output_claim` 表示运营领取某个成片的使用关系。

领取不等于发布。

领取表示：
- 获得使用资格
- 可以下载
- 可以进入发布流程

领取流程：

```text
查看成片池
→ 选择成片
→ 点击领取
→ 权限检查
→ 创建 composite_output_claim
→ 允许下载
```

---

### 5.9.8 独占领取规则

同一个 composite_output 同一时间只能存在一个有效领取关系。

原因：
- 避免多个运营下载同一个视频
- 避免重复发布
- 避免账号风险

---

### 5.9.9 领取状态和释放

领取状态包括：
- 已领取
- 下载中
- 已下载
- 发布处理中
- 已发布
- 已释放

释放方式：
- 自动释放
- 运营主动释放
- 高级运营强制释放

已发布成片不再释放。

---

### 5.9.10 云端文件与本地文件

核心原则：

> 一个成片，一个资产，多份文件位置。

关系：

```text
composite_output
    ├── 云端文件
    └── 本地文件
```

云端文件用于下载来源。  
本地文件用于本地发布、手机上传或后续处理。

不会创建“云端成片”和“本地成片”两条成片记录。

---

### 5.9.11 本地成片管理

本地文件属于 composite_output 的本地状态。

管理内容：
- 是否已下载
- 文件是否有效
- 所属 Agent
- 本地文件状态

本地文件删除不会删除 composite_output。

---

### 5.9.12 发布入口和补录

下载不创建 publication。

publication 只在以下情况创建：
- 系统内发布成功
- 手机/外部发布后补录成功

补录信息包括：
- 发布平台
- 发布账号
- 发布时间
- 发布链接
- 发布方式
- 备注

补录成功后：
- 绑定 composite_output
- 绑定 material
- 绑定 operator
- 更新成片发布状态
- 回写 material 发布统计

---

### 5.9.13 重复风险检测

发布前进行三级检测。

#### 成片级

检测同一个 composite_output 是否已发布。

处理：强控制。

#### 文件级

检测 file_hash 是否已发布。

处理：高风险提示，必要时拦截。

#### 素材级

检测：

```text
material + 平台 + 账号组 + 时间窗口
```

处理：风险提示。

---

### 5.9.14 云端文件生命周期

未领取云端成片：
- 默认保留 7 天

已领取未下载：
- 提醒运营处理

已下载未发布：
- 进入已下载未回填列表

已发布：
- 保留业务记录和发布记录
- 文件按存储策略处理

已归档：
- 长期保留

---

## 5.10 权限与验收要求

### 5.10.1 角色模型

素材生产模块采用三类角色：

```text
普通运营
高级运营
技术
```

不设计复杂 RBAC。

权限控制采用：

```text
角色权限 + 业务范围 + 资源归属
```

---

### 5.10.2 普通运营

负责日常素材使用、成片处理和发布执行。

可以：
- 查看有权限素材
- 领取素材
- 创建 material_usage
- 创建 compose_pool_item
- 选择策略
- 查看自己的任务
- 领取成片
- 下载成片
- 发布或补录发布结果

不能：
- 修改公共素材状态
- 修改公共策略
- 修改 production_rule
- 删除成片记录

---

### 5.10.3 高级运营

负责业务规划、生产管理、素材审核和权限范围管理。

可以：
- 审核私有素材转公共素材
- 管理 material 生命周期
- 创建 production_rule
- 管理 composite_output_pool
- 处理生产复核池
- 释放异常领取
- 管理负责游戏范围内的生产规则和资源可见范围

---

### 5.10.4 技术

负责系统生产能力、执行环境维护，并基于当前职责承担全局业务管理。

可以：
- 维护合成模板
- 管理模板版本
- 维护 Agent
- 维护云端 Agent
- 查看执行日志
- 处理技术异常
- 处理全局业务规则、素材状态和生产异常

技术执行关键业务修改时必须记录操作日志；技术权限不能绕过本地 Agent、Browser Profile、Cookie 和本地文件访问边界。

---

### 5.10.5 P0 验收链路

#### 本地生产链路

```text
material
→ material_usage
→ compose_pool_item
→ task
→ composite_output
```

必须支持：
- 领取素材
- 创建任务
- 执行合成
- 查看成片

#### 云端自动生产链路

```text
production_rule
→ compose_pool_item
→ task
→ composite_output
→ composite_output_pool
→ composite_output_claim
→ 本地文件
```

必须支持：
- 创建生产规则
- 自动触发
- 自动筛选素材
- 自动生成成片
- 自动进入成片池
- 运营领取下载

#### 异常恢复链路

必须支持：
- 自动重试
- 异常池
- 卡死恢复
- 人工处理

#### 发布闭环链路

```text
领取成片
→ 下载
→ 发布 / 补录
→ publication
```

必须支持：
- 系统直接发布入口
- 手机发布补录
- publication 创建
- material 发布统计更新

---

### 5.10.6 第五章最终设计原则

1. **一个成片，一个资产**  
   云端文件和本地文件属于同一个 composite_output。

2. **本地生产和云端生产统一产出**  
   两种生产模式最终都进入 composite_output。

3. **自动生产不等于无限生产**  
   通过 material 风险统计、生产复核池和风险提示控制重复生产。

4. **领取控制使用权，不等于发布控制**  
   系统控制领取和下载，但外部发布需要通过 publication 补录回流。

5. **下载不创建 publication**  
   只有真实发布或补录成功才创建 publication。

6. **生产和发布解耦**  
   素材生产负责生成成片，发布管理负责完成平台发布。
