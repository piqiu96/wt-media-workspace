## 5.1 模块概述

### 5.1.1 模块定位

素材生产负责把内容挖掘阶段沉淀的正式素材转化为可发布成片，是 M3 内容挖掘（[PRD 第四章](第四章_内容挖掘.md)）与第六章「发布管理」之间的生产环节。

```text
source_content → material
人工：任务负责人的 material_usage + 匹配的 compose_strategy → 任务批次 → compose_task
策略执行：团队 material + 指定负责人的 compose_strategy → 任务批次 → compose_task
compose_task → composite_output → publication（M6）
```

所有视频合成都由 Cloud Worker 执行。运营可以在 Cloud Web 或 Desktop WebView 发起生产和查看进度，但 Desktop / Local Agent 不执行 FFmpeg。

素材生产分为两个里程碑：

1. **M4 内容生产闭环**：运营从素材库加入“我的素材”，人工创建合成任务，由 Cloud 生成成片并支持下载。
2. **M5 自动生产**：在 M4 底座上，由 `compose_strategy.schedule` 触发 Scheduler 自动创建任务，Worker Pool 批量生产。

### 5.1.2 建设目标

1. **建立清晰的生产入口**
   素材库、我的素材、合成策略、合成任务、成片管理和下载中心各自承担单一职责。

2. **统一人工和自动生产**
   人工与自动生产都使用 `compose_strategy`、`compose_task` 和 `composite_output`，不维护两套对象。

3. **让生产与运营电脑解耦**
   合成不依赖 Desktop 是否在线，长耗时执行由 Cloud Worker 异步完成。

4. **控制文件与计算成本**
   原素材采用懒加载，不在进入素材库时批量下载；Worker 有并发、超时和重试上限。

5. **保证可追溯和真实成功**
   每个成片可追溯来源素材、策略快照、生产任务与最终运营负责人；人工任务还可追溯任务负责人的个人选材关系。失败任务不生成成片。

### 5.1.3 核心能力

| 产品能力 | 定位 | 核心对象 |
| --- | --- | --- |
| 素材库 | 管理进入生产体系的公共素材和源视频准备状态 | `material` |
| 我的素材 | 管理用户准备投入生产的素材集合 | `material_usage` |
| 合成策略 | 定义模板、视频参数与可选自动执行规则 | `compose_strategy` |
| 合成任务 | 管理一次具体的视频生产行为 | `compose_task` |
| 成片管理 | 管理成功生成的视频资产及其运营负责人 | `composite_output` |
| 下载中心 | 统一管理原素材和成片下载 | `file_transfer_task` |

禁止以其他名字复制这些职责，特别是：

- 不新增 `material_user_relation`、`user_material`、`favorite_material`；
- 不新增 `production_rule`；
- 不新增 `compose_pool_item` 或重复生产任务表；
- 不新增独立的成片下载任务表。

### 5.1.4 模块边界

#### 本章负责

- 正式素材进入生产体系；
- “我的素材”关系；
- 合成模板与策略配置；
- 人工和自动合成任务；
- Cloud 视频合成进度与结果；
- 成片生成和管理；
- 原素材与成片下载；
- 进入发布管理的入口。

#### 本章不负责

- 内容搜索、抓取和线索发现；
- 浏览器 Profile、Cookie 和账号登录态；
- 平台发布字段配置与浏览器发布执行；
- 发布结果采集与互动执行；
- 可视化工作流、任意脚本和动态插件；
- 微服务或 MQ 等技术选型。

发布任务、发布记录和平台结果回收属于第六章。第五章的“去发布”只是把 `composite_output` 带入发布流程，不代表已经发布。

## 5.2 素材生产流程

### 5.2.1 M4 人工内容生产流程

1. 在“合成任务”点“新增任务”，首先填写任务名称，再确定类目、负责人和匹配的启用策略。
2. 从任务负责人的“我的素材”或同团队、同类目的素材库选材；选择器确认后，库中素材加入该负责人的个人工作集并按需准备视频。只在素材库点击“加入我的素材”不触发准备。
3. 带入策略的全部成片设置，仅允许调整模板明确开放的参数；显示预计任务数后提交。
4. 为本次受理的任务建立一个真实任务批次，按“素材 × 成片设置 × 份数”展开独立任务。没有实际创建任务时不生成空批次。
5. Cloud Worker 按需准备输入、执行 FFmpeg、校验并上传成片。只有成功任务产生 `composite_output`。
6. 在任务批次详情查看全批进度；在成片管理查找、下载或勾选成片去发布。

HTTP 提交不等待视频生成；确认选材与最终创建任务是两个动作。取消父级创建表单，不回滚已经确认的加入和视频准备。

### 5.2.2 M5 策略执行流程

```text
立即执行／定时触发 → 团队同类目候选 → 选材与数量限制
→ 执行记录 → 有任务时建立批次并展开 compose_task
→ Cloud Worker → composite_output
```

手动策略与定时策略都支持“立即执行”；定时策略另外由 Scheduler 到期触发。两者共用选材、展开和配额逻辑，不能直接生成成片或在调度请求里运行 FFmpeg。没有选中素材时保留执行记录，不伪造任务批次。已创建任务独立执行，一条失败不阻塞其他任务。

### 5.2.3 人工创建与策略执行

| 对比项 | 人工创建 | 立即执行 | 定时执行 |
| --- | --- | --- | --- |
| 选材 | 人工选择任务负责人的个人素材，或从库确认加入 | 策略团队、类目的公共素材库 | 同立即执行 |
| 负责人 | 必须匹配策略；普通运营固定本人，管理角色可受权代办 | 继承策略 | 继承策略 |
| 个人素材关系 | 关联任务负责人 | 不要求、不自动创建 | 不要求、不自动创建 |
| 重复制作 | 明确确认后可创建新任务 | 有本策略任务历史的素材跳过 | 同立即执行 |
| 数量限制 | 受理本次明确所选素材，不占策略规则执行额度 | 每次上限；定时策略另计每日额度 | 每次与每日上限 |
| 执行 | Cloud Worker | Cloud Worker | Cloud Worker |

执行来源统一显示“人工创建／立即执行／定时执行”；它与策略的“手动执行／定时执行”、同一任务的重试次数是不同维度。

### 5.2.4 核心对象关系

| 对象 | 职责 |
| --- | --- |
| `material` | 团队正式素材、来源与视频准备事实 |
| `material_usage` | 用户的个人素材工作集关系 |
| `compose_template` | 固定版本的执行能力、参数及可调整范围 |
| `compose_strategy` | 负责人、类目、模板、成片设置与选材／执行配置 |
| 任务批次 | 同次人工创建或策略执行中实际创建任务的集合，不是新的执行器 |
| `compose_task` | 一条素材、一组成片设置中的一份产出的执行及恢复事实 |
| `composite_output` | 该任务成功生成的成片资产，继承任务负责人 |
| 策略执行记录 | 一次策略选材／创建的结果，可没有任务批次 |
| 任务执行记录 | 同一任务每次尝试的实际过程，重试保留历史 |
| `file_transfer_task` | 原素材准备、原素材或成片的传输 |
| `publication` | 第六章管理的真实发布事实 |

“成片批次”是按素材 ID 汇总成功成片的展示视图，不能与任务批次混用。

## 5.3 素材库（material）

### 5.3.1 功能定位

素材库管理正式进入生产体系的公共素材。`material` 是生产输入，不等于源视频文件已经下载。

页面支持：

- 查看素材列表和详情；
- 查看来源内容、平台、类目、作者和发布时间；当前来源平台仅抖音，显示中文名，不渲染存储代码；
- 在详情查看视频准备状态（列表不再展示文件状态，也不提供文件状态筛选）；
- 加入我的素材；
- 查看“加入状态”“我的使用”；
- 查看团队范围的“团队使用”及成功成片数；使用人明细仅高级运营和管理员可见，普通运营只看到使用人数。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/01-material-library.png`。

### 5.3.2 素材来源

当前素材来源仅抖音；成片适用平台为 B站、百度、小红书。不提供抖音目标平台及抖音发布账号候选，来源与去向使用独立选项，不共享平台候选集合。平台候选不代表对应发布执行器已经交付。

M4-M5 默认来源是 M3 内容池的 `source_content` 转换：

```text
source_content
→ material
```

转换时保存源链接和不可变来源快照，不要求立即下载源视频。后续若支持用户自有素材，必须沿用 `material`，不得另建平行素材实体。

转素材生成的 `material` 属于来源内容所在的团队，不由转换人选择团队；管理员跨团队转换时也一样。转换成功后的去向提示（单条明细、批量按团队聚合）见第四章 §4.3.8。

### 5.3.3 素材可见范围

素材库展示当前团队所有类目的正式素材；管理员可先选择目标团队，高级运营固定本团队。类目多选筛选的选项来自类目管理当前启用的全部类目，停用类目不在选项中；普通运营和高级运营初次默认选中本人负责且已启用的类目，可切换到本团队其他类目；管理员默认所选团队全部类目。负责类目不作为公共素材的强授权边界。服务端仍须按团队隔离列表、详情与操作。

`material_usage` 只负责当前用户的个人工作集关系，不在 `material` 上增加“收藏人”或“领取人”字段。

同一 `material` 可被多个有权限用户加入“我的素材”，每个用户形成自己的有效 `material_usage`。

### 5.3.4 视频准备状态

```text
not_downloaded
→ downloading
→ ready

downloading
→ failed
→ downloading

ready
→ downloading        （确认云端对象已丢失，重新准备）
```

运营侧展示：

| 内部状态 | 页面文案 | 可创建合成任务 |
| --- | --- | --- |
| `not_downloaded` | 待准备 | 是，系统先准备文件 |
| `downloading` | 准备中 | 是，任务等待文件就绪 |
| `ready` | 可用 | 是，消费前确认文件仍在 |
| `failed` | 失败 | 是，系统自动重试准备一次 |

数据库 `ready` 只表示记录的准备状态，不保证云端文件一定还在。合成开始前、用户下载或预览前，系统都会先确认云端对象存在：不存在且素材有源页地址时自动重新准备，没有源页地址时明确拒绝。从 `ready` 回退到 `downloading` 只回退“确认丢失的那个文件”，不会把并发准备刚生成的新文件误标为待准备。

用户下载原视频只能从当前用户有效的“我的素材”发起，素材库列表、详情与 API 不提供绕过该关系的本机下载。“合成前准备”仍由 Cloud 执行，可直接服务团队素材库的自动任务；两种用途都沿用 `file_transfer_task`，不能把前者的个人门槛套到 Cloud Worker。

### 5.3.5 懒加载下载规则

禁止在素材进入素材库时批量下载全部视频。

创建文件任务的情况：

1. 用户在“我的素材”主动点击“下载原视频”；
2. 用户创建合成任务且源视频未就绪；
3. 在任务选择器确认“使用所选”，为任务负责人按需准备视频；
4. 系统恢复失败或长期未完成的文件任务；
5. 合成或用户下载前确认记录为 `ready` 的文件已不在云端，且素材有源页地址，系统重新准备一次。

后台定期扫描只处理异常、失败、租约过期或长期未完成任务，不预下载所有素材。

### 5.3.6 加入状态、我的使用与团队使用

素材库列表直接展示三个相互独立的维度，不给 `material` 新增一套人工维护状态：

| 维度 | 筛选与列表口径 | 事实来源 |
| --- | --- | --- |
| 加入状态 | 全部／已加入／未加入；移出后为未加入 | 当前用户有效的 `material_usage` |
| 我的使用 | 全部／未使用／已合成；失败、取消、排队中均为未使用 | 负责人为当前用户的成功 `composite_output` |
| 团队使用 | 全部角色可见：全部／无人使用／有人使用；不按“本人／他人”拆成两个筛选 | 该团队内至少一位负责人拥有成功 `composite_output` |

首次进入时“我的使用”默认未使用；类目多选按 §5.3.3 的角色规则设默认值。用户调整后可沿用既有页面筛选记忆。加入或移出只改变加入状态，不改变成功成片事实；失败任务保留历史，是否可重试仍按原任务资格判断，却不算“使用”。“团队使用”指成功成片，包含本人；与策略执行检查本策略任务历史的防重口径不同。人工再次制作仍须明确提示已有产出和进行中任务。

“团队使用”的列、筛选与详情段对所有角色渲染。高级运营可在本团队、管理员可按目标团队查看成功成片数、不同运营负责人人数及使用人明细；普通运营只能看到成功成片数与使用人数，服务端不返回姓名。列表只显示一行可点击摘要，无成功成片或没有关联数据显示 `—`，有成片但没有已知负责人显示 `成片 N`，有已知负责人显示 `成片 N · 使用 M 人`；点击摘要打开弹窗，高级运营与管理员看到已知使用人及各人成片数（多人时列表可滚动），普通运营只看到 `成片 N` 与 `使用人数 M`，不出现任何姓名。不输出“暂无成功成片”“负责人未记录”“姓名不可见”等占位文案。跨团队相同外部作品分别统计，不合并业务记录。未来“我的使用＝已发布”指当前负责人基于该素材的成片至少有一次成功 `publication`，优先于“已合成”；发布次数统计同一素材的成功发布事实。但 M6 尚未交付可查询事实，本轮不展示该筛选、状态或次数；待真实查询可用后再接入，不能用下载或 `composite_output.status` 冒充发布。

进行中任务、最近生产时间、源视频准备异常可作为独立辅助信息，不能混进“团队使用”。所有统计从正式任务和成片事实派生，不回写冗余生产状态。

### 5.3.6.1 操作人

素材库列表在「入库时间」后展示「操作人」，详情「基本信息」同步展示。操作人即素材创建人（`created_by`）：人工转素材时是执行转换的人，自动转素材时是任务创建人。

操作人是素材自身的事实，不是查看者投影，三种角色都读；「团队使用」按角色隐藏姓名（普通运营只拿计数）的规则不适用于它。服务端解析昵称、无昵称回退用户名；目录里已没有此人时留空，页面显示占位符，不伪造姓名，也不回填历史行。

### 5.3.7 素材列表和详情验收

列表包含素材 ID、来源平台、素材／作者、类目、发布时间、内容表现、加入状态、我的使用、团队使用、入库时间、操作人及操作。来源当前仅抖音，不据此混入成片目标平台。默认发布时间倒序，当前排序列只显示一个方向；切换字段默认降序，缺失值始终置后。内容表现只展示点赞／收藏／评论，紧凑并列，下方显示数据更新时间；缺失为“—”、真实零值正常显示。素材库与我的素材筛选区不提供浏览／点赞／收藏／评论等指标区间。数据更新时间取来源作品最近一次成功从抖音采集并保存的时间（`metrics_updated_at`）；数值未变也更新时间，失败、页面查询、加入素材及视频准备不改变它。重复采集刷新原来源的较新指标快照，不重建素材或使用关系；较旧结果不能覆盖新结果。历史无法确认的采集时间显示“—”，不以素材修改时间、下载时间、入库时间或迁移时间代替。详情额外展示原作品转发数，列表仍仅点赞／收藏／评论；缺失与真实零值保持区分。

素材库基础筛选按综合搜索、类目、平台、发布时间、我的使用、团队使用、加入状态排列；管理员另有团队筛选。平台仅为来源平台，当前候选只有抖音。使用公共多选栏批量“加入我的素材”，跨页保留，查询/重置清空；跳过已加入及不可加入项，反馈已加入、跳过、失败及原因，失败项保留选择供重试。行内仅详情和符合资格的加入/重新加入，不提供“去我的素材”。

详情按素材内容、基本信息、内容表现、使用情况、视频文件分区，只读不重复放加入／下载按钮。基本信息按素材 ID/平台、平台作品 ID/类目、作者/发布时间、入库时间/操作人两列配对，平台作品链接独占一行。平台作品 ID 是外部作品标识，不能用内部来源 ID 替代。“团队使用”摘要可打开沿用原权限的计数/使用人明细。运营详情隐藏“准备完成时间”，后台仍保留用于文件校验和并发保护。平台作品链接仅在基本信息出现；视频区给视频状态与实际文件访问入口，来源失效不推断已有视频丢失。文件访问仅在可核验、未过期时提供；本机位置按当前用户和设备核验，不能共享他人路径。

- 来源链接存在即可创建 `material`；
- 没有准备事实时不能显示视频可用；
- 重复点击“加入我的素材”不创建第二个有效关系；
- 素材库无本机下载入口，直接请求下载 API 无当前用户有效 `material_usage` 时失败关闭；“我的素材”下载失败显示错误并允许重试；
- 加入状态、我的使用和团队使用在加入／移出、失败／重试／成功场景下分别与正式事实一致；普通运营能看到团队使用列、筛选与计数，服务端不向其返回使用人姓名；
- 素材库列表不展示文件状态，也没有文件状态筛选；详情仍可查看文件状态；
- 素材库列表与详情显示操作人（素材创建人），普通运营也可见；创建人目录失效时显示占位而不是空白或他人姓名；
- 素材库、我的素材、合成策略、合成任务与成片管理的列表不设刷新按钮，默认每 10 秒自动重读；抽屉/弹窗/表单打开或有选中行、批量操作进行中时暂停，定时读取不重置页码与筛选、失败保留上一次读数；
- 无权限用户不能查看或操作超出业务范围的素材。

## 5.4 我的素材（material_usage）

### 5.4.1 功能定位

`material_usage` 表示某个用户把 `material` 加入自己的生产集合。页面名称固定为“我的素材”。

能力：

- 查看个人素材；
- 查看最近生产状态；
- 下载原视频；
- 移出我的素材；
- 恢复已移出的关系；
- 查看详情和来源。

创建合成任务的入口不在本页：本页只管“这条素材能不能用、文件在不在”，创建在“合成任务”页完成（见 5.4.4）。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/02-my-materials.png`。

### 5.4.2 与 material 的关系

```text
material
    ├── user A → material_usage A
    ├── user B → material_usage B
    └── user C → material_usage C
```

同一用户对同一 `material` 默认只能有一个有效关系。禁止创建 `user_material` 等替代表。

### 5.4.3 加入规则

- 素材可用且用户有权限：创建 `material_usage`；
- 已存在有效关系：返回“已加入”，不重复创建；
- 关系已移出：恢复原关系并记录操作时间；
- 素材已禁止生产：不允许新加入，并说明原因。

### 5.4.4 创建合成任务

入口统一在“合成任务”，不在“我的素材”重复增加创建入口。普通运营负责人固定本人；高级运营可为本团队有效运营代创建，管理员可在目标团队代创建。负责人必须属于策略团队、负责该类目并匹配策略。

选材上下文为**任务负责人**：“我的素材”列其有效关系，“素材库”列匹配团队和类目的公共素材；管理角色必须经受权代办入口访问，不将他人工作集冒充为登录人的工作集。选择器“使用所选”才创建／恢复负责人的关系并准备云端视频，取消选择器不产生这些写入。原素材下载仍只验证当前下载人的工作集和本机身份，代选材权限不扩展为代下载权限。

素材曾合成过可以再次选择，提交前提示已有产出与进行中任务，由运营确认本次新建；新制作产生新批次与新任务，旧任务和成片保留。重复点击同一次提交只返回原结果。失败或取消任务的“重试”则沿用原任务与配置，不能用重试修改参数。

### 5.4.5 移出与恢复

移出后：

- 不允许基于该关系新建人工任务；
- 不删除历史 `compose_task`；
- 不删除历史 `composite_output`；
- 不影响已进入发布流程的成片；
- 支持恢复原关系。

### 5.4.6 列表、使用与视频投影

列表包含素材 ID、来源平台、素材／作者、类目、发布时间、内容表现、视频状态、我的使用、团队使用、加入时间、入库时间、操作人及操作。默认有效关系、我的使用为未使用、发布时间倒序，重置恢复这些默认值；查询、排序和分页按用户保留上下文。表现指标及缺失值与素材库一致。

“我的素材”行操作为“放弃”，仅移出个人关系，不删除团队素材及历史成片；筛选名称为“视频状态”，并入基础筛选，不为单一字段保留高级筛选入口。

“我的使用／团队使用”只统计成功成片，不以最近任务状态代替；详情提供成功产出摘要，不堆完整任务历史。视频状态复用 §5.9.5 的展示口径，准备与下载分别取真实事实。可用且当前电脑已核验有文件时隐藏下载；准备中、下载中不重复提交，失败可按失败流程恢复，批量只处理有资格项并返回逐项结果。

详情按基本信息、内容表现、使用情况、视频文件分区；无重复下载按钮。有效云端视频可打开，当前用户和设备的文件位置可打开目录；没有文件或未核验不编造可用入口。

### 5.4.7 权限边界

独立“我的素材”页仍只属于当前登录用户；授权管理角色在创建任务时可为指定负责人代选材，服务端同时核验团队、类目、负责人、策略和个人关系。此例外不开放他人的本机文件、下载记录和 Agent 操作。

## 5.5 合成策略（compose_strategy）

### 5.5.1 功能定位

合成模板定义“怎么合成”，策略定义“为谁、用哪些素材、生成哪些成片、何时执行”。模板按代码和版本发布，策略无版本管理；历史任务读创建时快照。

### 5.5.2 策略结构

新增／编辑依次组织为基本信息、默认成片设置、执行设置、选材条件：

| 区域 | 内容与约束 |
| --- | --- |
| 基本信息 | 策略名称、所属类目、合成模板、负责人全部必填；管理员另选目标团队，高级运营团队自动带入 |
| 默认成片设置 | 至少一组；每组名称、适用平台、份数及模板参数 |
| 执行设置 | 执行方式必选：手动执行／定时执行；按方式显示数量及计划 |
| 选材条件 | 排除规则和按优先级排列的选入规则 |

基本信息中策略名称独占首行，随后按“所属类目／合成模板”“所属团队／负责人”配对，新增与编辑使用相同排列。管理员新建时选择团队，高级运营的团队自动带入且禁用。创建后团队、类目、模板引用使用禁用输入框展示，需更换时复制为新策略。负责人须有效、属该团队并负责该类目；负责人失效阻止新任务，历史归属不改写。

### 5.5.3 视频模板与参数

模板按 `(code, version)` 固定版本，提供名称、用途、执行步骤、输入要求、参数含义、默认值、范围、必填及任务内是否可调整。选择模板后可点“模板说明”查看业务说明，先呈现“将对视频做什么”，参数定义作为详细内容。查看历史绑定版本时不得拿最新版本替代。

参数随模板变化：`basic_cut` 显示截取范围；`guide_insert` 显示引导视频、插入位置、引导时长及成片时长上限；`guide_pip` 按该版本定义显示叠加参数。引导视频地址归入**模板参数**，不与名称／平台等通用字段混排。参数区域默认展开，不用“折叠这段话”等说明作为标题。

引导视频须为可公开下载的 HTTPS 视频地址，转链接由独立工具承担。Cloud 限制目标、跳转、大小并校验媒体；失效或不合法时明确失败。任务快照固定地址和参数，不能保证外部链接内容不变。运营不上传脚本、不自定义 FFmpeg 命令；新增模板须有真实执行能力。

模板区分任务内可调整与固定参数；未明确开放的参数按固定处理。固定参数在任务参数弹窗中禁用并提供简短原因，服务端拒绝越权覆盖。引导地址仍按固定参数保护，不能因通用参数表单而开放。涉及敏感地址的任务读取遵循原有脱敏规则。

### 5.5.4 默认成片设置

采用每组完整默认值的简单方案：新增组带入模板初始值，复制组显式沿用该组参数；不引入实时全局继承。组内顺序为：

1. 成片设置名称。
2. 适用平台，至少一项，紧接名称；当前可选 B站、百度、小红书，仅作用于本组。
3. 每条素材生成份数，默认 1，范围 1–20。
4. 该模板版本的参数。

策略可增删、复制、排序组，至少保留一组。组列表下方使用左对齐、内容宽度的描边按钮“添加成片设置”，不拉伸为整行。拖动、上移、下移、移除使用公共组件，与选材规则保持同一布局及边界状态。新增、复制、增删条件保留表单草稿和当前位置；校验失败才主动定位错误。

### 5.5.5 策略快照

每条任务保存策略／团队／类目／负责人、创建人、模板版本、成片设置标识与名称、适用平台、份序号、最终参数及必要随机种子。任务名称在创建任务时保存；成片名称在首次成功提交时由素材标题与任务组名生成并保存。各自创建后不能从已改名素材或当前策略重新推导。任务创建后策略变更不改写历史执行。

### 5.5.6 多组、多份与产量

一条素材按各组份数分别创建独立任务；每个任务成功时生成一份成片：

```text
预计任务数／预计成片数 = 选中素材数 × 各组成片份数之和
例：2 条素材 ×（通用版 1 份 + 竖版 2 份）= 6 条任务，预计 6 个成片
```

适用平台是成片适用范围，不乘以平台数量；预计数量不等于成功结果。不同组、任务与成片保留独立配置和状态。

### 5.5.7 执行设置与选材条件

| 执行方式 | 每次素材上限 | 每日素材上限 | 时间设置 |
| --- | --- | --- | --- |
| 手动执行 | 必填 | 不显示、不校验隐藏旧值 | 无自动计划 |
| 定时执行 | 必填 | 必填 | 当前支持的间隔或每日时间及时区 |

数量以实际受理的素材条数计，不按展开后的任务数计。定时触发与该策略的立即执行共用每日额度，立即执行不改变下一计划时间；人工新建不占策略规则额度。策略启停独立于执行方式，停用不取消旧任务。

选材先检查全部排除条件，再按优先级选入；规则组支持全部满足／任一满足及白名单指标、比较和值。已选素材不重复选入，未命中不选入。缺失指标保持未知，不能补零；只有已知条件足以确定结论时才可短路判断，否则不选入并给出缺失字段。候选限策略团队与类目，按发布时间倒序、稳定 ID 次序处理。

立即执行、定时执行均跳过本策略已有任何任务历史的素材，失败不等于可重新自动选入；人工明确再次制作不受此永久拦截。规则摘要、详情、预览和实际提交必须使用同一判定。

### 5.5.8 页面与权限

策略列表展示名称、模板、类目、负责人、执行计划摘要、状态和操作；不堆完整选材规则。基础筛选按“综合搜索、类目、合成模板、状态”排列。

详情分“策略信息／执行记录”。策略信息沿用公共分区、状态标签与只读信息组件：名称整行，ID／状态、类目／模板、团队／负责人、创建／修改时间配对；默认成片设置按组展示，参数顺序与编辑一致；执行方式、数量限制和计划集中在执行设置，选材条件表按优先级展示命中动作、条件关系和具体条件。窄容器按公共规则转为单列。

执行记录按触发与单一日期范围筛选，列顺序为“批次 ID、触发方式、候选数、跳过数、创建任务数、失败数、执行时间、操作”。有真实批次时“详情”进入批次，零任务时直接解释未创建原因，不补造批次 ID；缺失批次 ID 显示“—”。选材／创建结果不冒充任务最终成功率。

“立即执行”保留原名，手动及定时策略均可操作，按三种情况组织：

| 情况 | 内容 | 动作 |
| --- | --- | --- |
| 同策略尚有未完成任务或创建正在提交 | “该策略有任务执行中”，列真实批次、时间和简短进度；历史无批次则追到原任务 | 查看进度，不再提交 |
| 没有可选素材 | 明确无素材、已执行、条件不符、指标缺失、额度不足或不可用等实际原因 | 关闭 |
| 可创建任务 | 策略、选入素材数、预计成片数；各组产量；素材的选入／跳过依据 | 确认执行 |

预览是只读计算，不创建个人关系、准备文件、预占额度、批次或任务。确认时再次核验配置、资格、额度和未完成任务；有实质变化须更新预览再确认。此处防重复点击不扩展为未经确认的定时重叠规则。按钮处理中禁用并做请求幂等。

结果文案要具体，例如“点赞 3,622 ≥ 3,000”“缺少收藏数”“本策略已执行”；不合并成“条件不符或指标不足”。手动策略预览不显示每日剩余；定时额度、选材范围已由上下文明确时不重复堆说明。

普通运营只查看、使用指定给自己的策略；高级运营管理本团队策略并立即执行；管理员按目标团队管理。模板及底层能力由技术人员维护。字段短说明用悬浮帮助；模板说明等可点击入口有明确链接态。集中提示只保留必要规则，例如“调整仅对本次任务生效”。列表、筛选、日期、表单、弹窗、排序及操作数量遵循 [AdminUI 页面规范](../../../standards/frontend/AdminUI页面规范.md)，不另设本模块规范。

## 5.6 合成任务（compose_task）

### 5.6.1 功能定位

任务批次提供同次创建的整体视角；`compose_task` 是 Worker 领取的最小执行单位。每条任务对应“素材 × 成片设置 × 第几份”，成功后只有一个成片。批次不承担执行、重试或文件状态机。

任务保存创建人和负责人两个事实。人工创建人是请求人，定时由系统代策略创建者调度，立即执行保留实际发起人的审计；业务归属只看创建时固定的负责人，不随策略修改而漂移。

### 5.6.2 创建方式

人工新建、策略立即执行、策略定时执行，以及成片“再次制作”均进入同一创建链路；新制作建立新批次、新任务。重试沿用原任务 ID、批次、参数和已有成功产出，增加执行记录。

“再次制作”只在成片侧提供，任务页不再出现另一套“再生成一批”。它带入原素材及该成片对应的原组成片设置，按原模板版本和最终参数再生成一份，进入新建确认；只允许调整原模板开放参数，不能增加组、切换策略或修改负责人。不可用策略、负责人归属变化、模板版本不可执行或旧快照不完整须明确提示，不能悄悄换用当前配置。原成片文件缺失仍可使用可获取的原素材重新制作。原素材在确认提交时加入／恢复到负责人的“我的素材”并按需准备；界面明确说明此动作，打开或取消弹窗不写入。加入失败不继续创建任务，已确认加入的关系不随后续创建失败回滚。

### 5.6.3 任务状态与操作

| 状态／情形 | 展示与操作 |
| --- | --- |
| 排队中 `pending` | 详情；有操作权限可取消 |
| 等待素材准备 `running + waiting_input` | 详情；有操作权限可取消；不能重试 |
| 处理中 `running` | 详情；有操作权限可请求取消；等待执行器确认，不能提前显示已取消 |
| 成功 `success` | 详情；有实际成片时可进入成片详情，不能取消／重试 |
| 失败 `failed` | 详情；高级运营／管理员对可恢复任务重试；不可恢复原因或权限不足须区分 |
| 已取消 `cancelled` | 详情；高级运营／管理员可重试 |
| 失败且结果不明确 | 详情；普通重试关闭；仅受权角色可按 §5.8.6 核实后恢复 |

取消按可见范围及既有权限处理，批次不新增授权。源视频未就绪不等于不可选；等待准备保持运行态。每次领取最多自动重新准备一次，准备仍失败则明确结束。

### 5.6.4 进度和阶段

单条任务展示实际阶段：准备输入、视频合成、校验输出、上传、完成或失败。仅有阶段信息时展示阶段，不把固定阶段百分比包装成真实逐帧进度。

批次进度为全部有权查看任务的已结束数／总数，结束包括成功、失败、取消；另列各状态计数。成功率与结束率分开，0／1 不能填满进度条，零任务不显示 100%。进度使用只读统计及进度组件，不用输入框。局部筛选不改变全批分母。

### 5.6.5 批量操作

任务列表支持多选；批次详情可操作整批符合条件的任务。按钮使用“重试”“取消”，旁边或确认步骤交代范围与数量，不使用长说明作按钮名。

操作前列出实际可操作数量及跳过原因，提交时逐项重验权限与状态；只重试允许恢复的失败／取消任务，只取消未完成任务，保留成功产出。批次范围与明确所选任务范围不得混淆，部分受理不显示全部成功。批次内状态筛选不静默缩小整批命令。

### 5.6.6 取消规则

排队任务可直接取消；运行任务只先受理请求，确认旧进程退出并处置临时文件后才进入已取消。成功任务不能取消，失败、已取消任务不能重复取消。仅修改数据库状态而遗留执行进程不算成功。

### 5.6.7 页面能力

合成任务分“任务批次／任务列表”，默认批次。批次行仅“详情”，不看成片、不在外面堆重试／取消按钮。批次详情显示名称、ID、策略、负责人、触发来源、创建时间、全批进度和任务清单；具体操作集中于详情，符合公共行操作数量和固定 Footer 规范。

列表提供综合搜索、负责人／策略／触发／状态及创建日期范围；普通运营固定本人，管理角色在其团队范围查询。创建与完成时间分别显示；日期范围使用公共组件，结束日包含在内。分页、排序、选择与返回上下文保持一致。

新建任务：

1. 任务名称置于首项且必填，作为批次名称保存；单条任务保留可识别的稳定名称与设置／份序号。
2. 类目、负责人、策略联动，普通运营固定本人；管理角色按授权代办。切换导致已有选择失效时先提示。
3. 打开选择素材弹窗。“我的素材／素材库”为任务负责人上下文；“我的使用／团队使用”始终按当前登录人／授权团队的成功成片计算，代办时不得偷偷改成负责人的“我的使用”，如需展示须明确标注负责人使用。
4. 基础筛选优先搜索、发布时间范围；高级筛选放我的使用、团队使用及浏览／点赞／收藏区间，选择器使用情况默认全部。固定团队与类目约束可见但不重复让用户选择。默认发布时间倒序，指标可排序，缺失值为“—”。
5. 不用本机是否下载、云端准备状态作为合成筛选。可准备的素材允许选，明确无法获取输入的行禁选并解释；来源失效但已有有效输入仍可选。跨页、跨来源按素材 ID 去重，筛选与排序不丢已选项，支持只看已选和清空。
6. 成片设置以紧凑列表展示名称、平台、份数、预计任务，每组通过“参数”弹窗查看／调整模板开放参数；无可调整项时只读。固定参数禁用，组数、名称、平台、份数、顺序全部继承策略，任务中无新增、删除、复制和排序入口。
7. 参数预填策略默认值，修改只作用本次全部所选素材，不回写策略。非法范围就地拦截，提交时服务端再校验。显示预计任务／成片数与重复制作提示，提交返回真实批次和逐项受理结果。

任务详情分“任务信息／执行记录”。任务信息中的基本信息只放任务主体：ID、状态、任务名称、批次、负责人、触发、创建／完成时间。合成配置单独展示模板版本、设置名、适用平台和最终参数；关联信息展示素材、策略，成功产出单独进入生成结果。删除与状态重复的“当前说明”，仅失败／异常给有用原因。

### 5.6.8 执行过程记录

每次执行（`compose_task_attempts` 的一次 attempt）记录一条关键过程日志，用于回答「它走到哪一步、每步花了多久、卡在哪一步失败」。日志随执行进展逐条追加，重试后每次执行各记各的，互不污染。

记录的步骤从固定集合中按实际走过的取：校验任务参数、准备源素材、（引导类模板）下载引导视频、视频合成、上传并校验成片、保存成片记录。每条步骤只记四类事实：

1. 步骤名（服务端给出的中文）；
2. 开始/结束时间与这一步的耗时；
3. 这一步的成果读数，且只允许白名单内的量：文件体积、成片时长、成片编号、文件摘要（sha256）；
4. 失败时中文的原因类别。

日志**不得**出现素材地址、对象存储地址、本机路径或 FFmpeg 原始报错；这些只留在服务端供运维排查。步骤名与原因类别一律由服务端生成，请求与数据库都不接受自由文本。没有日志的历史执行明确显示“该次执行没有步骤记录”，不用任务摘要冒充。

页面按尝试分组，最近一次默认展开，历史可收起；每步用紧凑时间线呈现步骤、时间、耗时与真实结果。创建、重试、完成事件不重复拼成虚假执行步骤，缺失记录不推算。失败原因保持同一口径；人工核实作为原尝试的处置事件展示，依据仍只对原有受权角色返回，不新增独立核实记录查询页。

## 5.7 自动生产（归属 compose_strategy）

### 5.7.1 功能定位

自动生产归 `compose_strategy`，仅执行方式为定时的启用策略由 Scheduler 触发；其配置、选材、配额和立即执行见 §5.5。不另建自动规则产品。

### 5.7.2 创建和维护角色

高级运营维护本团队，管理员可跨团队；普通运营不能启停或立即执行策略。技术人员维护模板能力与 Worker 资源，不以技术配置替代业务负责人。

### 5.7.3 配置内容

沿用策略的团队、类目、有效负责人、模板版本、成片设置、每次／每日素材上限、执行时间／周期及时区和选材条件。计划格式及数量由服务端验证，下次计划时间只显示真实值，不在前端猜测。

### 5.7.4 自动调度

到期执行选材后按组和份数创建任务。启用、修改计划不立即触发，等待下一窗口；定时策略的立即执行不改变下次时间。创建者被禁用不阻断调度，负责人失效则不创建新任务。

策略执行不写个人素材关系；任务和成片的个人关系可空，归属只看负责人。调度周期须幂等，多个调度进程或提交重放不能重复建批次和任务。

### 5.7.5 防重与数量控制

本策略已有任何任务历史的素材不再自动选入；同次展开的各组与份数不是重复。额度按实际受理素材计；已选入但创建失败的结果与额度处理必须一致并可追溯。停用后不创建新任务，已有任务不删除或假成功。

### 5.7.6 素材可生产校验

候选须在策略团队与类目范围内、负责人有效、素材无明确禁止生产、输入可用或可按需准备，且通过规则、防重和额度校验。缺失视频准备不是直接跳过理由；缺失必要来源且没有有效输入才明确不可用。

### 5.7.7 执行结果

策略执行记录回答“有没有启动任务、为什么没有启动”，首层只区分有任务、无匹配素材、未启动任务并给出具体原因。详情可展开候选、选入、创建及跳过明细；不以长状态名和多套汇总增加理解成本。真实任务执行情况从批次读取。

### 5.7.8 自动生产信号

任务成功与实际成片证明生产完成；发布由真实发布记录证明。下载、加入个人素材、选材命中均不算成功产出，不建冗余信号对象。

## 5.8 Cloud 执行、失败与恢复

### 5.8.1 功能定位

Cloud Worker 异步执行 `compose_task`。产品需要看到稳定的任务状态、进度、错误和恢复结果，不直接暴露租约、进程号或命令行等底层细节。

### 5.8.2 领取与并发

- Worker 从数据库原子领取 `pending` 任务；
- 同一任务同时只能有一个 Worker；
- 系统按配置限制总并发；
- 无可用资源时任务继续排队，不返回假失败。

### 5.8.3 Heartbeat 与超时

运行中任务持续 heartbeat。长时间无 heartbeat 或超过任务超时后，系统进入恢复判断：确认原执行已经停止后才能重排或失败，不能同时启动第二个 FFmpeg。

### 5.8.4 自动重试

允许自动重试：

- 临时网络错误；
- 对象存储短暂失败；
- Worker 崩溃且结果可确认未提交；
- 素材准备时平台临时播放地址解析或下载失败：同一准备任务内重新解析地址并再下载一次（只一次）；
- 其他已标记为可重试的技术错误。

不自动重试：

- 源文件永久不存在（包括平台地址不存在、重新解析后仍拿不到可用文件）；
- 素材准备中的租约丢失、探测/上传/写状态失败、进程被取消；
- 模板或参数非法；
- FFmpeg 能力不兼容；
- 输出内容无法通过校验；
- 外部结果不明确。

### 5.8.5 重试与重新生产

- 技术重试：保留同一 `compose_task` 的策略快照，增加尝试次数；
- 人工重试（高级运营或管理员）：把同一条 `compose_task` 重新排队，接受**已取消**与**失败**两类（`execution_uncertain` 除外）；清掉上一次的错误码与错误摘要，并**重新获得完整的 3 次自动容错配额**；**执行编号不回退**（新一次尝试接着往下编号），历史尝试记录原样保留；同时获得一次新的“自动重新准备素材”机会（每次领取最多一次）；
- 修改策略/参数：创建新的 `compose_task`；
- 复制成片配置：创建新的 `compose_task`，成功后生成新的 `composite_output`。

### 5.8.6 异常任务处理

任务详情展示：失败阶段、可理解的错误、是否可重试、已尝试次数和最后更新时间。技术可查看脱敏日志；普通运营不能看到凭据、内部命令或对象存储签名。

租约过期后结果不明确的任务保留失败和原尝试记录，普通重试入口不可用。同团队高级运营或管理员核实旧 FFmpeg 已停止且没有已提交成片后，在任务详情分别确认两项条件并填写可核对依据，才可将同一任务重新排队；核对记录、核对人与新人工尝试可读回。普通运营仍只能看到失败事实和联系提示，不能提交核对；跨团队高级运营不可见。无法核实时继续显示待处置。页面将其标为人工核对，不宣称系统已自动证明旧进程退出；错误摘要只呈现阶段、时间和固定错误类别。

### 5.8.7 卡死恢复

系统定期扫描租约过期、长期无 heartbeat 或超时任务。恢复必须以真实执行已结束为前提；仅把状态从 `running` 改回 `pending` 而不处理遗留进程属于假恢复。

## 5.9 成片管理与下载中心

### 5.9.1 成片管理定位

仅展示成功生成的成片。页面分“成片批次／成片列表”：

| 视图 | 列表内容 | 主要操作 |
| --- | --- | --- |
| 成片批次 | 按素材 ID 汇总权限范围内跨策略、跨任务批次的实际成片；素材／作者、类目、策略摘要、成片数量、最近生成时间 | 详情 |
| 成片列表 | 成片 ID、名称／生成时间、来源素材、类目、负责人、适用平台、视频状态 | 详情、条件满足时下载、再次制作 |

成片批次不是任务批次，不按相似标题或时间猜测合并；详情围绕该素材产生的成片展示，只关心各成片视频状态，不增加下载进度列。成片列表不显示文件大小、格式等技术列，名称不重复拼 ID；视频状态旁不再写“可下载”。勾选后工具栏支持“下载”“去发布”，无单行“去发布”。

普通运营只看本人负责且在本人类目范围内的成片，不显示负责人筛选；高级运营看本团队，可按启用成员筛选；管理员先选目标团队。类目选项只列启用项，普通运营提交非负责类目不得扩大授权。聚合、计数、明细及下载使用同一范围，不能从跨权限汇总泄露明细。

成片详情无封面／播放器占位，分四区：

- 基本信息：成片 ID、名称、视频状态、负责人、生成时间；不使用“生产负责人”。
- 视频信息：直接展开。成片显示名称为“素材标题 · 成片设置名称”，视频文件名额外包含成片 ID 与扩展名以避免重名；正式名称与文件名在创建时固定。视频文件名为蓝色链接，可访问时打开；时长、分辨率、文件大小合并为一行。格式可由扩展名表达，不重复堆字段，未知值不补造。
- 制作来源：素材、策略、任务、任务批次、成片设置及创建时实际配置；有权限且有真实详情时提供链接。详情只读，编辑参数进入再次制作。
- 发布情况：按适用平台展示未安排／已安排／已发布及关联发布任务；适用平台不在基本信息重复出现，相同负责人不重复作使用人。

列表搜索支持名称、素材 ID、批次 ID；另有类目、负责人、平台、视频状态及生成日期范围。精确关联查询不得用混合文本搜索代替。返回保留筛选、排序、分页和选择；多选工具栏、窄选择列、日期范围和高级筛选遵循公共规范。

### 5.9.2 composite_output 定义

`composite_output` 是唯一成片资产，不是任务、下载记录或发布记录。成片文件位于对象存储；运营电脑上的副本仍属于同一成片。

成功创建时继承任务的负责人快照；同一 `material` 可以经不同策略分别产出归不同负责人的多个成片，同策略的人工再次制作也可保留多个成片，不增加素材“一对一成片”约束。历史成片无法可靠推断负责人时标明“—”并附未知原因，只允许管理角色按原有范围核查，不把创建人或下载人自动回填为负责人。

### 5.9.3 成片生成条件

必须同时满足：

- `compose_task` 的 FFmpeg 进程成功结束；
- 输出文件存在且媒体可读；
- 文件大小、时长和必要 Hash 校验通过；
- 对象存储写入和校验完成；
- 来源、策略快照和任务可追溯。

任一条件失败都不创建 `composite_output`。

### 5.9.4 来源追踪

成片详情必须可追溯：

- `material`；
- 人工生产时的 `material_usage`；
- `compose_strategy` 与快照；
- `compose_task`；
- 最终运营负责人及人工任务的创建人；
- 文件信息和生成时间；
- 后续 `publication`。

### 5.9.5 视频状态与发布情况

视频状态与任务结果、发布安排、本机副本分别取事实，不混成一套状态机：

| 视频状态 | 含义／操作 |
| --- | --- |
| 待准备 | 没有可用视频，需要准备；原素材可按流程准备，成片不得假装自动重做 |
| 准备中 | 正在准备视频，不重复发起 |
| 可用 | 已有可验证的视频；按权限与当前设备文件情况提供下载／打开 |
| 下载中 | 当前用户与设备正在下载，不重复下载 |
| 失败 | 准备／下载失败；明确原因，提供该失败流程支持的恢复动作 |
| — | 事实不足，悬浮说明未核验，不猜测可用 |

这是与“我的素材”一致的展示词汇，并非每类资产都会经过所有状态。成片记录只在合成成功后存在；对象丢失不能回写任务为合成失败，也不能凭历史下载成功认定当前设备文件仍在。列表不区分“云端可用”，不再追加“可下载／已下载”重复提示。下载能力由文件可访问性、权限和设备核验共同决定。

每个平台的发布情况仅三种：未安排（无有效发布任务）、已安排（存在有效任务，包括执行中、失败待处理）、已发布（有真实成功发布事实）。取消安排后重新计算，不以失败自动释放安排；没有“可使用／可安排”状态。发布情况不影响视频是否存在，不用一个全局发布字段代替逐平台事实。

### 5.9.6 下载中心定位

下载中心是横向文件能力，入口位于顶部导航“下载”，点击后打开右侧 Drawer，不属于素材库子菜单。

界面参考位于 `wt-media-cloud/docs/product/m4-m5-content-production/assets/06-download-center.png`。

### 5.9.7 file_transfer_task 定义

支持两类用户下载：

```text
material
→ file_transfer_task
→ 运营电脑本地文件
```

```text
composite_output
→ file_transfer_task
→ 运营电脑本地文件
```

同一张任务表也可表达 Cloud 合成前原素材准备，通过用途和执行位置区分，不新增其他下载任务表。

用户下载原素材前，服务端先验证**当前下载人**的有效 `material_usage`，再确认云端对象存在：存在才签发下载；不存在且素材有源页地址时，先创建一次云端准备并把文件信息挂到这条下载任务上，准备完成后运营电脑再直接下载（Cloud 不中转文件字节）；不存在且没有源页地址时明确提示暂不可下载。素材预览同理：对象不存在时提示暂不可用，不打开 404 页面。成片是已验收资产，本轮不做同样的自动重做；成片对象丢失会明确报错，规则另定。

### 5.9.8 下载任务状态

```text
pending
running
success
failed
cancelled
```

Drawer 展示：文件名、资产类型、文件大小、进度、当前速度、预计剩余时间、错误和完成时间。

### 5.9.9 下载操作

- 进行中任务：暂停/继续能力只有在执行器真实支持断点续传时才展示；必须支持取消；
- 失败任务：重新下载；
- 成功任务：本机核验文件存在时打开文件或所在目录；已确认丢失时可重新下载，不能用历史成功冒充文件仍在；
- 最近完成：可清理显示记录，但不得删除素材、成片或用户本地文件；
- 批量暂停等按钮不能只改前端状态。

同一用户、同一资产仍有排队／执行中下载时复用该任务，防止连续点击重复下载。上次已结束后，显式重新下载创建新传输并保留历史，不改写原成功记录。

### 5.9.10 本地文件边界

Cloud 保存任务事实、请求用户、领取审计和完成结果，不保存运营电脑绝对路径。Desktop / Local Agent 管理本地保存目录、临时文件、断点信息和最终路径。

### 5.9.11 下载完整性

成功前必须验证：

- 实际字节数与预期一致；
- 必要 Hash 一致；
- 临时文件已原子移动为最终文件；
- 取消或失败不留下被误认为完整文件的目标文件。

### 5.9.12 发布入口

成片列表勾选一项或多项后点“去发布”，打开与“发布任务”页右上角“新建发布任务”**同一个新建弹窗**；前者带入已选成片，后者从空选择开始。两者都在弹窗内配置并确认，不先跳到一个没有安排的任务列表。创建完成后定位实际发布任务。

“发布计划”的“新建发布计划”服务多日、规则化的发布编排，与一次明确所选文件的新建任务场景区分。成片管理不重复提供另一套发布安排表单。发布执行、账号校验和结果仍归第六章；此处仅确定入口和数据带入，不能宣称尚未实施的发布能力已交付。下载、打开视频或提交安排均不等于已发布。

### 5.9.13 重复风险

发布前仍可按成片、文件 Hash、素材 + 平台 + 账号范围提示重复风险。风险判断属于发布前校验，不通过成片池或领取关系实现。

### 5.9.14 文件生命周期

- 对象存储中的正式成片按存储策略保留；
- 对象存储中的正式素材按存储策略保留；素材准备的临时对象在确认转为正式对象后删除；
- 本地副本删除不删除 `composite_output`；
- 临时合成文件与成片临时对象在成功、失败或取消后按恢复规则清理；
- 清理不得删除仍被正式成片引用的对象。

## 5.10 权限与验收要求

### 5.10.1 角色模型

继续使用：

```text
普通运营
高级运营
管理员
```

权限采用角色 + 业务范围 + 资源归属，不新增复杂 RBAC。

### 5.10.2 普通运营

可以：

- 查看和处理本团队所有类目的公共素材，类目默认多选本人负责项；
- 加入和管理自己的素材；
- 选择可用策略并创建人工任务；
- 查看自己的任务与成片；
- 从自己的“我的素材”下载原素材，从有权查看的成片发起本人本机下载；
- M6 交付后进入发布流程。

不能：

- 修改公共策略模板；
- 启停自动生产；
- 查看其他人的任务、成片或本机下载；
- 绕过 Cloud 直接请求 Worker 执行。

### 5.10.3 高级运营

可以：

- 管理本团队所有类目的 `compose_strategy`，为本团队有效运营指定负责人；
- 配置和启停 M5 自动执行；
- 默认查看本团队全部任务与成片，负责人下拉只列本团队启用成员（含本人），可按成员筛选；
- 按授权代办入口从任务负责人的“我的素材”或同类目素材库代创建匹配策略的任务；
- 取消、重试符合规则的任务；
- 查看自动调度统计和异常素材。

### 5.10.4 管理员

可以：

- 跨团队管理 M3–M5 Cloud 业务数据与策略，创建策略时选择目标团队；
- 在目标团队内指定有效运营，按其工作集或同类目素材库代创建匹配策略的人工任务；
- 维护或授权技术人员维护模板、FFmpeg 能力和 Worker 配置；
- 查看全局执行状态、脱敏日志和资源指标；
- 处理租约、超时、对象存储和文件异常；
- 在审计下执行全局任务处置。

管理员和高级运营的 Cloud 权限不能绕过业务对象、对象存储安全、本机文件和 Local Agent 下载合同。Local Agent 本机执行仅支持运营与高级运营，管理员可查看业务成片但不能新建本机下载；管理员仍可取消本人已有下载，不能操作他人传输。Cloud Web 与 Desktop 共用业务页面的授权一致，本地能力仍按本人绑定。

### 5.10.5 P0 验收链路

#### M4 人工生产链路

```text
素材库加入我的素材
→ 选择策略创建 compose_task
→ 原素材懒加载准备
→ Cloud Worker 真实 FFmpeg 合成
→ 对象存储产生可播放文件
→ composite_output
→ 成片管理下载到本地
```

必须验证：

- `material_usage` 不重复；
- HTTP 不同步等待；
- 源文件未准备时任务不提前执行；
- 失败不创建成片；
- 下载进度和最终 Hash 真实；
- Desktop 退出不影响 Cloud 合成。

#### M5 自动生产链路

```text
启用 compose_strategy.schedule
→ Scheduler 到期扫描
→ 幂等创建 compose_task
→ Worker Pool 按并发上限执行
→ 自动生成 composite_output
```

必须验证：

- 禁用策略不创建任务；
- 同周期不重复；
- 单次和每日上限生效；
- Worker 并发不越界；
- heartbeat、超时、重试和重启恢复真实有效；
- HTTP Server 单独运行不启动 Scheduler / Worker。

#### 异常恢复链路

必须覆盖：

- 原素材下载失败；
- 输入损坏；
- FFmpeg 非零退出；
- Worker 崩溃；
- heartbeat 中断和租约过期；
- 对象存储上传失败；
- 任务取消；
- 本地下载失败和重试。

所有异常都不得生成假成片、假下载成功或两个并行执行者。

#### 发布衔接链路

M6 接入后：成片页面提供去发布入口，进入第六章发布流程。

```text
成片管理
→ 去发布
→ publication（第六章）
```

下载、打开视频及创建发布安排均不等于发布。

#### 本次原型落地补充验收

- 多组多份展开、平台不乘份数；组 key 稳定、各任务执行快照隔离，任务内固定参数不可越权修改。
- 人工再次制作与同次提交重放、策略历史防重分开验证；立即执行预览只读，重复点击及确认时状态变化不重复创建。
- 人工、立即、定时均有真实批次；零任务执行有记录无伪批次；结束率与成功率分开，局部筛选不改全批统计。
- 代选材关系属于任务负责人，我的使用属于登录人；普通角色不泄露他人使用姓名；本机权限不因管理权限扩大。
- 成片按素材 ID 聚合且先授权后统计；历史名称、平台和参数不随当前策略漂移；状态与视频操作由实际事实决定。
- 任务状态、批量受理、部分失败、人工核实权限及执行历史保留；取消请求不提前显示取消成功。
- 来源仅抖音、目标无抖音，来源／目标候选隔离；新增表单项不跳顶、草稿不丢；公共筛选、日期、多选、操作数量在 Web／Desktop 一致。
- 去发布与新建发布任务共用表单、分别带入／选择成片，创建后可追到实际安排。

### 5.10.6 第五章最终设计原则

1. **一个成片，一个资产**：Cloud 与本地文件是同一 `composite_output` 的不同位置。
2. **一种合成执行边界**：人工和自动生产都由 Cloud Compose Worker 执行。
3. **一种生产任务**：使用 `compose_task`，不再叠加生产意图表或 Agent task。
4. **自动规则归策略**：`compose_strategy.schedule` 是自动生产唯一规则来源。
5. **我的素材语义不变**：`material_usage` 是唯一个人素材关系。
6. **下载是横向能力**：原素材和成片统一使用 `file_transfer_task`，入口为全局 Drawer。
7. **源视频懒加载**：进入素材库不等于下载视频。
8. **真实成功优先**：任务成功、文件校验和对象存储落盘同时成立才创建成片。
9. **生产和发布解耦**：成片生成不创建发布记录。
10. **保持简单**：不引入微服务、MQ、工作流引擎或复杂 Agent 架构。
