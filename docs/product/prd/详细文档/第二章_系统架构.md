# 第二章：系统架构

## 2.1 架构目标与设计原则

### 2.1.1 架构目标

本系统面向多平台自媒体的持续运营，支撑以下完整业务闭环：

```text
内容发现
→ 素材生产
→ 成片生成
→ 发布
→ 互动
→ 数据统计
```

系统架构应满足以下目标：

1. **支持本地与云端并行执行**
   - 依赖比特浏览器、本地文件和本地登录环境的任务，由本地 Agent 执行；
   - 不依赖运营电脑的自动生产、云端合成、定时抓取和统计任务，由云端 Agent 执行；
   - 本地 Agent 与云端 Agent 使用统一的 Python 执行框架；
   - 任务执行位置由任务类型在代码中固定，不建设动态执行位置配置。

2. **降低运营重复劳动**
   - 支持批量账号接入、Profile 创建、代理绑定、账号检查、素材生产、辅助发布和互动；
   - 支持任务进度、失败原因、部分成功、失败项重试和结果回填。

3. **保证本地资源和业务数据正确**
   - 比特浏览器相关操作必须先校验当前 `main_user_id`；
   - 本地 Agent 离线或异常时，不得产生错误业务结果；
   - 云端不能绕过本地 Agent 直接访问运营电脑资源；
   - 本地与云端数据冲突时，不允许静默覆盖。

4. **保证任务和结果可追溯**
   - 核心业务结果应能够追溯到任务、执行 Agent、执行用户、执行时间、结果和失败原因；
   - 不要求所有业务任务共用一张万能任务表，但执行状态和日志口径应统一。

5. **支持长期持续运营**
   - 系统不是一次性脚本或临时工具；
   - 应具备稳定性、可维护性、可升级性、故障恢复、可观测和基础备份能力。

### 2.1.2 设计原则

#### 1. 简单优先

首版只建设解决当前运营问题所必需的能力，不提前建设：

- 复杂微服务；
- 通用工作流编排器；
- 动态 Agent 路由；
- 复杂消息队列体系；
- 通用插件市场；
- 高度灵活的配置中心；
- 自研指纹浏览器。

#### 2. 模块化单体

云端采用 Go + CloudWeGo Hertz 的模块化单体架构，模块包括：

- 用户与账号；
- 内容发现；
- 素材生产；
- 发布管理；
- 互动管理；
- 数据统计；
- 任务调度；
- 配置、日志与可观测。

各模块代码和数据对象保持清晰边界，但首版统一部署，不拆分微服务，不使用 Kitex。

#### 3. 业务与执行分离

云端 Go 服务负责：

- 权限和业务规则；
- 正式业务数据；
- 任务创建和状态管理；
- 定时调度；
- 结果接收和业务回写；
- 配置、日志和统计。

Python Agent 负责：

- 比特浏览器调用；
- 文件处理；
- FFmpeg 和 Python 执行；
- 内容抓取；
- 合成；
- 发布和互动；
- 进度、日志和结果回传。

业务接口不能直接承担长时间运行的任务，Agent 不得直接修改云端业务数据库。

#### 4. 事实源明确

| 数据类型 | 事实来源 |
|---|---|
| 用户、权限、任务和业务记录 | 云端 MySQL |
| Browser Profile 实际状态 | 比特浏览器 |
| 浏览器当前 Cookie | 比特浏览器 Profile |
| 本地文件是否存在 | 本地文件系统 |
| 本地任务临时状态 | 本地 SQLite |
| 云端文件是否存在 | 云端对象存储 |

#### 5. 固定流程加必要配置

平台发布、互动和生产采用：

```text
代码固定流程
+
必要 JSON 配置
```

JSON 配置主要用于页面元素、少量平台参数和版本兼容，不建设拖拽式流程编排。

#### 6. 失败可见、结果可恢复

所有长任务应支持：

- 进度展示；
- 成功、失败、中断和取消状态；
- 明确失败原因；
- 安全重试；
- 部分成功；
- 已成功结果保留；
- 异常恢复或人工处理。

### 2.1.3 非功能目标

#### 1. 稳定性与数据正确性

系统优先保障：

- 用户、账号、Browser Profile 和代理关系不串乱；
- 外部接口失败时不写入错误结果；
- 批量任务单条失败不回滚其他已成功项；
- 高风险任务不会因超时自动重复执行；
- 本地离线不污染云端正式数据。

#### 2. 可观测性

系统应能够查看：

- 云端业务服务状态；
- 云端 Agent 和本地 Agent 状态；
- 比特浏览器、Python、FFmpeg 等依赖状态；
- 定时任务最近执行结果；
- 待执行、执行中、失败和中断任务数量；
- 外部服务最近状态；
- 本地和云端磁盘空间；
- 最近异常和影响范围。

可观测页面应重点回答：当前是否可用、哪里异常、影响什么、如何处理。

#### 3. 日志与追踪

关键操作和任务必须记录：

- 操作人或执行 Agent；
- 操作时间；
- 操作对象；
- 任务阶段；
- 执行结果；
- 重试次数；
- 错误类型和失败原因。

日志不得记录完整 CK、密码、代理密码、Token 和 API 密钥。

#### 4. 可维护和可升级

系统应支持：

- 客户端和 Agent 版本检测；
- 平台元素配置独立更新；
- 本地依赖安装、修复和升级；
- 配置版本记录和回退；
- 数据迁移和基础备份；
- 错误分类和统一命名。

#### 5. 简单易用和操作友好

产品应：

- 减少技术字段和复杂配置；
- 提供合理默认值；
- 支持批量操作；
- 清晰展示进度和结果；
- 失败时说明原因、影响范围和处理入口；
- 支持仅重试失败项；
- 使用运营可理解的页面名称和提示。

## 2.2 系统总体架构

### 2.2.1 技术选型

| 层级 | 技术选型 |
|---|---|
| 云端业务服务 | Go + CloudWeGo Hertz |
| 云端架构 | 模块化单体 |
| 内部 RPC | 首版不使用 Kitex |
| 前端运营后台 | Vue 3 + Vite |
| 本地桌面外壳 | Tauri 2 |
| 桌面支持范围 | Windows、macOS Intel（x86_64）、macOS Apple Silicon（arm64） |
| 本地 Agent | Python |
| 云端 Agent | Python |
| Agent 打包 | 按操作系统和CPU架构分别构建的PyInstaller独立可执行文件 |
| 云端数据库 | MySQL |
| 本地数据库 | SQLite |
| 云端文件 | 对象存储 |
| 本地文件 | 本地文件系统 |
| Agent 通信 | HTTPS JSON API |
| 本地通信 | `127.0.0.1` 本地 API |

### 2.2.2 总体组成

```text
云端管理与调度层
        │
        ├──────────────────┐
        ↓                  ↓
本地运营端             云端执行环境
        │                  │
        ↓                  ↓
本地 Agent             云端 Agent
        │                  │
        ↓                  ↓
比特浏览器、本地文件    对象存储、FFmpeg、Python
```

系统整体由以下部分组成：

1. 云端管理与调度层；
2. 统一 Agent 执行层；
3. 本地运营端；
4. 云端执行环境；
5. 数据和文件存储；
6. 外部服务与平台适配。

### 2.2.3 云端部署形态

首版云端运行在 Linux 服务器，组成包括：

```text
云端 Linux
├── Vue 运营后台
├── Go + Hertz 业务服务
├── 进程内定时调度
├── Python 云端 Agent
├── MySQL
├── Python / FFmpeg
└── 对象存储访问能力
```

云端 Agent 首版与 Go 服务同机部署，但保持独立进程和职责边界。

首版云端不建设桌面环境，也不执行依赖比特浏览器或可视化浏览器的发布、互动和账号操作。

### 2.2.4 本地部署形态

```text
运营电脑（Windows / macOS Intel / macOS Apple Silicon）
├── Tauri 桌面客户端
├── 内置 Vue 运营页面
├── Python 本地 Agent
├── SQLite
├── 比特浏览器
├── Python / FFmpeg
└── 本地素材与成片目录
```

桌面客户端负责窗口、Agent 生命周期、依赖状态、文件选择和升级；Python Agent 负责全部本地执行。

### 2.2.5 故障隔离

- 本地 Agent 离线，不影响云端自动生产和业务查询；
- 云端 Agent 异常，不影响用户登录和普通管理页面；
- 比特浏览器异常，只阻断依赖浏览器的本地任务；
- 单条批量任务失败，不回滚其他成功项；
- 某个第三方服务异常，不影响无关模块；
- 统计汇总异常，不修改原始业务数据。

## 2.3 系统逻辑分层与依赖关系

### 2.3.1 逻辑分层

```text
产品展示与交互层
        ↓
云端应用与业务层
        ↓
任务控制与调度层
        ↓
Agent 执行层
        ↓
平台适配与工具层
        ↓
数据、文件与外部依赖层
```

逻辑分层不代表首版必须拆成独立服务。

### 2.3.2 产品展示与交互层

包括 Vue 运营后台和 Tauri 桌面外壳。

负责：

- 页面展示和用户输入；
- 参数配置和筛选；
- 任务创建入口；
- 状态、进度和统计展示；
- 本地文件选择和桌面通知。

不得：

- 直接访问 MySQL 或 SQLite；
- 直接调用比特浏览器；
- 直接运行 FFmpeg；
- 绕过云端创建正式业务任务。

### 2.3.3 云端应用与业务层

Go + Hertz 负责：

- 用户认证、角色和数据权限；
- 业务参数和状态校验；
- 正式业务对象管理；
- 任务创建；
- Agent 结果接收；
- 业务状态更新；
- 查询、统计和审计。

各业务模块通过正式对象和服务接口协作，不直接跨模块修改数据。

### 2.3.4 任务控制与调度层

属于 Go 服务内部逻辑模块，负责：

- 任务创建和状态；
- 任务领取和防重复；
- Agent 心跳；
- 取消、中断和重试；
- 超时识别；
- 定时规则扫描。

不建设独立分布式调度平台。

### 2.3.5 Agent 执行层

本地和云端 Agent 统一使用 Python，负责：

- 领取任务；
- 参数和依赖校验；
- 调用适配器；
- 分阶段执行；
- 进度和心跳；
- 结果回传；
- 异常恢复。

Agent 不负责用户权限和正式业务状态口径。

### 2.3.6 平台适配与工具层

封装：

- 比特浏览器；
- 抖音内容获取；
- B站发布和互动；
- 百家号发布和互动；
- FFmpeg；
- Python 素材处理；
- DeepSeek；
- 代理检测；
- 接码链接；
- 对象存储。

适配层不得直接修改云端数据库。

### 2.3.7 依赖限制

禁止以下调用：

```text
Vue / Tauri → 数据库
Vue / Tauri → 比特浏览器正式操作
Go 业务层 → 运营电脑本地文件
Python Agent → 云端 MySQL
平台适配器 → 直接修改 publication 或 media_account
```

## 2.4 云端管理与调度层

### 2.4.1 模块定位

云端是系统的业务控制中心，负责“做什么、谁能做、什么时候做、结果如何保存”。

### 2.4.2 云端模块

```text
Go + Hertz
├── API 接口层
├── 用户与权限
├── 账号与资源
├── 内容发现
├── 素材生产
├── 发布管理
├── 互动管理
├── 数据统计
├── 任务控制
├── 定时调度
├── 配置管理
├── 日志与可观测
└── 数据访问
```

### 2.4.3 API 接口层

为 Vue、Tauri、本地 Agent 和云端 Agent 提供 HTTPS API，负责：

- 身份认证；
- 会话校验；
- 角色和数据权限；
- 参数校验；
- 基础限流；
- 请求日志；
- 链路标识；
- 统一错误格式。

### 2.4.4 任务控制

各业务模块可以保留自己的任务对象，但执行过程统一使用以下基础状态：

```text
pending
running
success
failed
cancelled
interrupted
```

任务领取时应原子记录：

- `agent_id`；
- 领取时间；
- 最近心跳；
- 锁定截止时间。

发布、互动等可能已经产生外部结果的任务，不得因心跳超时直接自动重复执行。

### 2.4.5 定时调度

首版使用 Go 进程内定时调度，负责扫描：

- `production_rule`；
- 抖音关键词和作者监控规则；
- 平台效果数据采集计划；
- 日级统计汇总；
- 代理到期提醒；
- 云端成片池 7 天清理；
- Agent 心跳和任务超时；
- 其他明确周期任务。

定时调度只创建任务，不直接执行抓取、合成和文件处理。

同一规则同一执行周期必须防止重复创建任务。服务恢复后只补执行最近一次必要周期，不批量补跑全部历史周期。

### 2.4.6 Agent 状态管理

本地 Agent 记录：

- 当前用户和会话；
- 设备；
- Agent 版本；
- 最近心跳；
- 本地依赖摘要；
- 当前任务。

云端 Agent 记录：

- 服务身份；
- Agent 版本；
- 最近心跳；
- 当前任务；
- Python、FFmpeg、磁盘等运行状态。

## 2.5 统一 Agent 执行架构

### 2.5.1 两种运行模式

```text
local  → 本地 Agent
cloud  → 云端 Agent
```

两者共用 Agent Core 和任务协议，但加载不同执行能力。

### 2.5.2 Agent Core

```text
Agent Core
├── 启动和配置
├── 身份注册与心跳
├── 任务领取
├── 参数校验
├── 执行器映射
├── 进度上报
├── 日志
├── 取消与中断
├── 重试和恢复
└── 结果回传
```

任务类型与执行器在代码中固定映射，不提供动态执行器配置页面。

### 2.5.3 本地 Agent 能力

- `main_user_id` 校验；
- Browser Profile 同步、创建和修改；
- 代理绑定；
- CK 读写；
- 账号检查；
- 本地文件处理；
- 本地合成；
- 辅助发布；
- 点赞、评论和收藏。

### 2.5.4 云端 Agent 能力

- 云端自动生产；
- 云端合成；
- 云端素材和文件处理；
- 对象存储上传下载；
- 云端成片生成和入池；
- 内容抓取和效果采集；
- 统计和清理任务。

### 2.5.5 本地运行方式

Python Agent 使用 PyInstaller 打包为 Tauri Sidecar：

```text
启动 Tauri
→ 检查 Agent 版本
→ 启动 Agent
→ 用户登录
→ Agent 绑定会话并注册
→ 开始领取任务
```

桌面客户端关闭后，本地 Agent 同步停止。首版不建设开机常驻、远程唤醒和无人值守本地执行。

### 2.5.6 本地通信

Agent 只监听：

```text
127.0.0.1
```

Tauri 可通过本地 API 获取状态、通知立即拉取任务、执行诊断和打开本地目录。

正式任务仍必须由云端创建，Tauri 的本地通知不包含可直接执行的完整正式任务。

### 2.5.7 任务生命周期

```text
领取任务
→ 参数和依赖校验
→ 准备资源
→ 分阶段执行
→ 上报进度和心跳
→ 验证结果
→ 回传成功、失败或中断
→ 清理临时资源
```

高风险任务在执行前还必须检查：

- 会话是否有效；
- Browser Profile 是否存在；
- `main_user_id` 是否匹配；
- 登录状态是否满足；
- 是否存在冲突任务；
- 云端连接是否正常。

### 2.5.8 异常恢复

可以安全恢复或重跑：

- 文件下载和上传；
- 本地或云端合成；
- 内容抓取；
- 统计汇总。

不得盲目恢复或自动重跑：

- 发布；
- 评论；
- 点赞；
- 收藏；
- CK 写入；
- Profile 和代理修改。

无法确认外部结果时，应标记为“结果待确认”或“执行中断”。

### 2.5.9 并发控制

- 同一 Browser Profile 同一时间只执行一个浏览器操作任务；
- 发布和互动默认串行；
- 批量发布一次只打开一个窗口；
- 文件和合成任务使用固定少量并发；
- 云端 Agent 根据 CPU、内存、磁盘设置固定并发。

并发参数由技术配置，不向普通运营开放。

### 2.5.10 版本与安全

- 云端维护最低兼容 Agent 版本；
- 版本不兼容时禁止领取相关任务；
- 平台配置可以独立更新；
- Agent 只能执行代码中注册的任务类型；
- 不允许用户上传脚本或任意命令；
- 敏感信息不得写入普通日志。

## 2.6 本地运营端与本地环境管理

### 2.6.1 模块组成

```text
本地运营端
├── Tauri 2 桌面客户端
├── 内置 Vue 运营页面
├── Python 本地 Agent
├── SQLite
├── JSON / TOML 配置
├── 比特浏览器
├── Python / FFmpeg
└── 本地工作目录
```

首版支持Windows与macOS。macOS需同时兼容Intel（x86_64）和Apple Silicon（arm64）。

### 2.6.2 跨平台兼容要求

桌面端的“兼容”不仅指页面能够打开，还包括桌面外壳、本地Agent、本地数据库、文件处理和主要执行依赖能够正常安装、升级和运行。

需要分别提供：

- Windows安装包；
- macOS Intel（x86_64）安装包；
- macOS Apple Silicon（arm64）安装包。

首版建议分别构建macOS Intel和Apple Silicon版本，不强制合并为Universal Binary。

不同平台需要分别处理：

- Tauri应用构建与升级包；
- Python本地Agent可执行文件；
- FFmpeg及相关二进制依赖；
- Python原生依赖和平台执行脚本；
- 文件路径、目录权限和进程管理差异；
- macOS应用签名、公证和升级校验；
- 比特浏览器及平台自动化能力的兼容检测。

本地配置、SQLite和工作目录使用操作系统标准应用数据目录，不在代码中写死Windows路径。

客户端启动时应识别：

```text
operating_system
cpu_architecture
desktop_version
agent_version
dependency_version
```

云端根据操作系统和CPU架构返回匹配的客户端、Agent及依赖升级信息。

某项外部依赖在当前操作系统或架构下不可用时，系统必须明确展示受影响功能和处理方式，不能在任务执行过程中才以未知错误失败。

### 2.6.3 Tauri 职责

负责：

- 应用窗口；
- 内置运营页面；
- Agent 启动、停止和升级；
- 本地依赖检测；
- 文件和目录选择；
- 桌面通知；
- 安装、修复和卸载本地组件。

不负责：

- 正式业务逻辑；
- 发布和互动执行；
- 直接写 SQLite；
- 直接修改云端业务数据。

### 2.6.4 本地环境检测

客户端启动后至少检测：

- 操作系统与CPU架构；
- 客户端和 Agent 版本；
- Agent 是否正常运行；
- 云端连接；
- 比特浏览器安装、启动和 API；
- 当前 `main_user_id`；
- Python 和 FFmpeg；
- 工作目录读写；
- SQLite；
- 磁盘空间。

状态统一展示为：

```text
正常
异常
未安装
需要升级
不可连接
需要用户处理
```

### 2.6.5 依赖管理

支持：

- 一键检测；
- 一键安装；
- 一键修复；
- 一键升级；
- 一键卸载；
- 重新检测。

可自动管理 Agent、FFmpeg、Python 运行依赖、合成和平台脚本。比特浏览器可提供检测、启动和安装指引，但不要求首版自动完成登录。

### 2.6.6 本地 SQLite

SQLite 只由 Python Agent 读写，用于保存：

- 本地任务快照；
- 待回传结果；
- 本地文件索引；
- 下载缓存；
- 同步游标；
- 最近依赖检测结果。

SQLite 不复制完整云端业务数据。

推荐启用：

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
```

### 2.6.7 本地工作目录

```text
workspace/
├── material/
├── output/
├── download/
├── cache/
├── temp/
├── log/
└── data/
```

SQLite 和执行中临时文件不放在网络共享盘。客户端和 Agent 升级不得删除工作目录。

### 2.6.8 离线处理

云端不可连接时：

- 已完整获取参数和文件的本地合成、文件处理可以继续；
- 完成结果写入 SQLite，网络恢复后回传；
- 发布、互动、CK、Profile 和代理修改等高风险任务原则上暂停。

## 2.7 任务分发与本地、云端协同机制

### 2.7.1 基本原则

1. 正式任务由云端创建；
2. Agent 主动领取任务；
3. 任务位置由任务类型代码固定；
4. 不建设 `execution_scope` 表；
5. 本地任务不自动转云端；
6. 云端任务不自动转本地；
7. 云端状态是任务正式状态；
8. 本地 SQLite 只保存临时状态。

### 2.7.2 执行位置

#### 本地 Agent

- Profile 同步、创建和修改；
- 代理和 CK 操作；
- 账号检查；
- 本地合成；
- 发布；
- 点赞、评论和收藏。

#### 云端 Agent

- 云端自动生产；
- 云端合成和文件处理；
- 云端成片入池；
- 抖音关键词和作者定时监控；
- 效果数据采集；
- 日级统计；
- 清理任务。

### 2.7.3 本地任务流程

```text
用户提交业务操作
→ Go 校验权限和业务条件
→ 创建业务对象及任务
→ Tauri 通知 Agent 立即拉取
→ Agent 从云端领取
→ 执行前二次校验
→ 执行并回传进度
→ 云端校验结果并更新业务状态
```

### 2.7.4 云端定时任务流程

```text
Go 定时扫描规则
→ 防止同周期重复创建
→ 创建云端任务
→ 云端 Agent 领取
→ 执行处理
→ 回传结果
→ Go 创建或更新正式业务对象
```

### 2.7.5 领取、心跳和锁定

领取时应原子更新任务，记录：

- `agent_id`；
- 领取时间；
- 最近心跳；
- 锁定截止时间。

Agent 长时间无心跳时，任务进入异常判断，不直接认定成功或自动重复执行。

### 2.7.6 结果回传和幂等

结果回传必须：

- 校验任务和 Agent 关系；
- 校验当前任务状态；
- 校验结果结构；
- 支持同一结果重复提交；
- 防止重复创建成片、发布记录和互动结果。

本地只有在收到云端明确确认后，才能清理待回传记录。

### 2.7.7 批量任务

批量任务拆分为可独立执行的单项任务：

- 单项独立成功或失败；
- 单项失败不回滚其他成功项；
- 支持仅重试失败项；
- 发布和互动默认串行。

### 2.7.8 用户会话失效

同一用户新登录后，旧会话立即失效。旧 Agent：

- 停止领取新任务；
- 尚未开始的任务不再执行；
- 执行中任务按风险安全停止；
- 已经产生的真实外部结果仍允许按受控方式上报。

## 2.8 数据与文件存储架构

### 2.8.1 存储组成

```text
云端
├── MySQL：正式业务数据
├── 对象存储：云端素材和成片
└── 云端日志

运营电脑
├── SQLite：Agent 本地运行状态
├── 本地文件系统：素材、成片、缓存和临时文件
├── 比特浏览器：Profile 和当前 Cookie
└── 本地 Agent 日志
```

### 2.8.2 云端 MySQL

保存：

- 用户、角色、会话和权限；
- `media_account`；
- `browser_profile` 云端镜像；
- `proxy_resource`；
- `crawl_task`、`source_content`；
- `material`、`material_usage`；
- 合成任务、`composite_output`；
- `composite_output_pool`、`composite_output_claim`；
- `publication`；
- `tracked_object`、`interaction_task`及执行结果；
- 平台效果和日级统计；
- 配置、操作日志和 Agent 状态。

### 2.8.3 对象存储

保存：

- 云端自动生产素材；
- 合成模板和资源；
- 云端成片；
- 云端成片池文件；
- 用户明确上传的本地文件；
- 需要多人共享或云端继续处理的文件。

文件通过系统文件标识和临时授权地址访问，不默认提供永久公开地址。

### 2.8.4 本地文件索引

本地完整路径只保存在 SQLite。云端只保存：

- 本地文件标识；
- 文件名；
- 文件大小；
- Hash；
- 所属设备或 Agent；
- 本地和云端副本状态。

云端不得依赖运营电脑绝对路径作为唯一定位。

### 2.8.5 成片规则

#### 本地生成

- 完整文件默认只保存在本地；
- 云端保存 `composite_output` 业务记录和元数据；
- 用户明确上传、进入云端成片池或云端后续任务需要时，才上传完整文件。

#### 云端生成

- 文件保存对象存储；
- 创建 `composite_output`；
- 按规则进入 `composite_output_pool`；
- 运营领取后由本地 Agent 下载并建立本地文件索引。

### 2.8.6 素材规则

`material` 是业务记录，不等同于完整文件。

- 云端自动生产和多人共享素材应上传对象存储；
- 仅供当前电脑本地合成的素材可以只保存本地；
- 云端任务需要本地素材时，必须先上传。

### 2.8.7 CK、代理和 Profile

- `original_cookie` 和 `active_cookie` 正式记录保存在云端 `media_account`；
- 当前真实 Cookie 以比特浏览器 Profile 为准；
- 本地 SQLite 不长期复制完整 CK；
- 代理正式记录和配额以云端为准；
- Profile 当前实际代理以比特浏览器为准；
- 差异通过第三章确认的 Diff 流程处理。

### 2.8.8 文件传输

上传和下载必须：

- 使用临时文件；
- 校验文件大小；
- 校验 Hash；
- 成功后再更新业务状态；
- 网络异常时保留可恢复状态。

Hash 用于完整性、缓存复用和重复风险辅助，不强制合并不同业务记录。

### 2.8.9 清理和备份

可自动清理：

- 临时文件；
- 失败任务中间文件；
- 过期下载缓存；
- 可重新生成的派生文件；
- 超期本地和云端日志。

不得自动清理：

- 正式本地成片；
- 用户明确保留素材；
- 执行中任务文件；
- 未回传结果对应文件。

云端成片池未领取文件按 7 天规则清理。MySQL 和对象存储应具备基础备份和恢复能力。

## 2.9 外部服务与平台适配架构

### 2.9.1 适配原则

所有外部能力通过适配层接入：

```text
Go 创建任务和提供配置
→ Python Agent
→ 平台或工具适配器
→ 外部平台、接口或本地工具
```

原则：

- 业务层不直接调用平台；
- Agent 通过适配器执行；
- 外部结果必须验证；
- 平台差异集中处理；
- 元素变化优先更新 JSON；
- 流程变化修改代码；
- 不建设插件市场和任意脚本执行。

### 2.9.2 比特浏览器适配

运行在本地 Agent，负责：

- 获取和校验 `main_user_id`，并记录 Profile 级 `profile_user_id`；
- Profile 获取、创建和修改；
- 代理绑定；
- Profile 开关；
- Cookie 读写；
- 发布、互动和账号检查所需浏览器环境。

`main_user_id` 不一致或无法确认时，阻止全部比特浏览器读写、同步和正式数据变更。

### 2.9.3 内容挖掘渠道适配（当前抖音）

支持：

- 多链接解析入池；
- 关键词主动搜索；
- 博主定位与作品主动搜索；
- 作者监控；
- 定时获取新增内容；
- 获取标题、封面、视频 ID、发布时间和互动数据。

（2026-09-23 注：上述「博主定位与作品主动搜索」「作者监控」已暂停且服务端硬禁用，本期不交付、不计入验收：Cloud `service/manual_search.go` 恒返回 `ErrDouyinAuthorUnavailable`，接口恒返回 400/14006「博主搜索接口维护中」，UI 无入口。`author` 枚举取值保留，能力合同与字段描述不变，仅当前不可用。用户 2026-09-23 裁定「现在不做，改成暂停，以后再做」。）

依据 ADR-0013，使用 `content_channel` / `channel_type` 预留渠道能力，当前仅实现抖音，不新增其他平台发现。关键词/博主主动搜索未选择前不保存正式数据；链接提交解析并入池后成功内容进入 `source_content`。主动操作不创建自动业务 `crawl_task`；调度/受控脚本触发策略才形成该记录。自动结果按策略的 `auto_material` 开关、`material_rule`（`AND`/`OR`，其他取值必须拒绝）、`like_threshold` 与 `favorite_threshold` 条件化自动转素材：命中项入池后自动生成 `material`，未命中项留在内容池由人工转换创建；阈值 >0 才参与判定、≤0 跳过，`auto_material` 为真时至少需要一个正阈值（2026-09-23 更正：原表述为「所有自动结果仅入内容池，`material` 由人工转换创建」）。业务和周期配置不在适配器中执行调度。

### 2.9.4 B站和百家号适配

B站和百家号均支持账号检查、辅助发布、点赞、评论、收藏和效果采集。

发布采用：

```text
固定平台代码流程
+
平台 JSON 配置
```

不同平台流程独立维护，可共用上传、元素查找、等待、截图和日志工具。

### 2.9.5 平台 JSON 配置

原 `platform_element_config` 与 `platform_publish_config` 合并为一份配置，包含：

- 平台标识；
- 配置版本；
- 页面地址；
- 页面元素和备用定位；
- 默认等待时间；
- 少量平台参数；
- 适用 Agent 版本；
- 启用状态。

配置由技术维护，必须校验格式、记录版本和操作日志。

### 2.9.6 结果验证

完成点击不能直接判定成功。

发布应验证成功提示、页面状态、发布记录或作品链接；互动应验证按钮状态、评论内容或平台提示。

无法确认时标记为“结果待确认”，不得自动重复执行。

### 2.9.7 FFmpeg 和 Python 工具

FFmpeg 适配器负责安全生成参数、执行、进度、超时、取消和输出验证。

Python Agent 只能执行代码中注册的处理模块，不允许页面输入任意 Python 代码或上传未知脚本。

### 2.9.8 DeepSeek

用于标题和评论文本生成。

- 密钥只保存在服务端；
- 不下发 Vue、Tauri 或本地 Agent；
- 失败时允许人工继续；
- 不建设多模型动态路由平台；
- 返回异常内容不得直接进入正式标题或评论。

### 2.9.9 统一错误分类

至少包括：

```text
DEPENDENCY_UNAVAILABLE
AUTH_INVALID
RATE_LIMITED
NETWORK_TIMEOUT
ELEMENT_NOT_FOUND
PAGE_CHANGED
INVALID_RESPONSE
FILE_TRANSFER_FAILED
TOOL_EXECUTION_FAILED
RESULT_UNCONFIRMED
CONFIG_INVALID
```

适配器返回技术错误，Agent 转换为任务错误，云端再转换为运营可理解的提示。

## 2.10 配置、日志、安全、可观测与架构验收

### 2.10.1 配置管理

配置分为：

- 业务配置；
- 平台适配配置；
- 系统运行配置；
- 本地配置。

原则：

- 只配置确实需要变化的内容；
- 固定流程写在代码中；
- 普通运营不接触技术配置；
- 关键配置保留版本和修改日志；
- 已领取任务继续使用领取时确定的配置版本；
- 配置不兼容时阻止高风险任务执行。

### 2.10.2 日志分类

包括：

- 操作日志；
- 任务执行日志；
- 系统运行日志；
- 外部依赖日志；
- 安全日志。

关键操作日志至少记录：

- 操作人；
- 时间；
- 对象；
- 操作类型；
- 必要的变更摘要；
- 结果和失败原因。

任务日志至少记录：

- 业务对象；
- `task_id`；
- `agent_id`；
- 用户；
- Agent、适配器和配置版本；
- 执行阶段；
- 开始和结束时间；
- 重试次数；
- 错误类型和摘要。

### 2.10.3 可观测与告警

云端状态页展示：

- Go 服务、云端 Agent、MySQL、对象存储；
- 定时调度；
- 任务积压和失败；
- 磁盘和最近异常。

本地状态页展示：

- Tauri 和 Agent 版本；
- 云端连接；
- 比特浏览器和 `main_user_id`；
- Python、FFmpeg、SQLite；
- 工作目录和磁盘；
- 当前任务和待回传结果。

建议三级告警：

- 提示；
- 警告；
- 严重。

首版告警通过系统页面、桌面通知和技术异常列表实现，后续可接入飞书等通知渠道。

### 2.10.4 身份和权限安全

- 系统采用普通运营、高级运营、技术三角色；
- 同一用户只能有一个有效会话；
- 新登录立即使旧会话失效；
- 本地 Agent 绑定当前有效会话；
- 前端隐藏按钮不能替代后端权限校验；
- 技术拥有云端全局业务与技术权限，但不能绕过本地 Agent 操作运营电脑资源。

### 2.10.5 Agent 和本地安全

- 本地 Agent 只监听 `127.0.0.1`；
- Agent 只能执行注册任务类型；
- 不提供任意命令接口；
- 不加载用户未知脚本；
- 不直接访问云端 MySQL；
- 比特浏览器操作前强制校验 `main_user_id`；
- 云端不得远程直接读取本地文件。

### 2.10.6 接口、文件和命令安全

云端 API 应具备：

- HTTPS；
- 认证和权限；
- 参数校验；
- 请求大小和上传限制；
- 基础限流；
- 防重复提交；
- 请求链路标识；
- 关键操作审计。

文件和命令执行应：

- 防止路径穿越；
- 使用独立临时目录；
- 限制可执行程序；
- 结构化传递参数；
- 禁止拼接未经校验的用户输入；
- 设置超时和资源限制；
- 校验最终文件。

### 2.10.7 持续运营要求

系统应支持：

- Agent 和依赖持续检查；
- 账号状态持续检查；
- 代理到期提醒；
- Profile Diff 持续处理；
- 自动生产和内容监控；
- 效果采集和日级统计；
- 失败任务集中处理；
- 平台配置和 Agent 持续升级；
- 日志清理；
- 数据和文件备份。

### 2.10.8 架构验收要求

#### 总体技术

1. 云端采用 Go + Hertz 模块化单体。
2. 首版不使用 Kitex，不拆微服务。
3. 本地和云端 Agent 统一使用 Python。
4. 云端 Agent 首版与 Go 服务同机部署。
5. 本地桌面采用 Tauri 2 + Vue 3/Vite。
6. 桌面端支持Windows、macOS Intel（x86_64）和macOS Apple Silicon（arm64）。
   - 三类目标环境分别提供可安装、可升级的客户端和本地Agent；
   - FFmpeg、Python原生依赖及平台执行脚本按目标环境完成兼容验证；
   - 本地路径、权限和进程管理不得依赖写死的Windows实现；
   - macOS安装包具备正式签名、公证和升级完整性校验能力。

#### 职责和任务

7. Go 负责业务、权限、调度和状态。
8. Python Agent 负责实际执行。
9. Agent 不得直接修改云端 MySQL。
10. Vue 和 Tauri 不得直接访问数据库。
11. 正式任务必须由云端创建。
12. 任务执行位置由任务类型代码固定。
13. 不建设 `execution_scope` 表。
14. 定时调度只扫描规则和创建任务。
15. 任务领取必须防止重复领取。
16. 结果回传必须幂等。
17. 高风险任务不得盲目自动重试。
18. 同一 Browser Profile 不得并行执行多个浏览器操作任务。

#### 本地和数据

19. 本地 Agent 只监听本机地址。
20. 桌面关闭后本地 Agent 同步停止。
21. 本地 SQLite 只由 Python Agent 读写。
22. SQLite 不复制完整云端业务数据。
23. 比特浏览器操作前必须校验 `main_user_id`。
24. 正式业务数据保存在云端 MySQL。
25. 云端文件保存在对象存储。
26. 本地成片默认不自动上传云端。
27. 文件上传和下载必须校验完整性。
28. 文件缺失不得直接删除业务记录。

#### 配置、日志和持续运营

29. 平台流程采用固定代码加 JSON 配置。
30. 平台配置具备版本和兼容校验。
31. Agent 不得执行未知脚本。
32. 敏感信息不得进入普通日志。
33. 云端和本地均具备基础状态页面。
34. 任务能够查看进度、结果和失败原因。
35. 关键操作、任务和配置修改必须有日志。
36. 错误提示必须说明影响范围和处理方式。
37. 系统具备基础备份和恢复能力。
38. 客户端、Agent 和平台配置支持持续升级。

### 2.10.9 首版明确不建设

- 微服务和 Kitex RPC；
- Kafka、RabbitMQ 和分布式调度平台；
- `execution_scope` 表和动态 Agent 路由；
- 本地任务与云端任务自动迁移；
- 云端可视化浏览器发布；
- 桌面关闭后的无人值守 Agent；
- 云端远程唤醒运营电脑；
- 本地完整业务数据库；
- 云端与本地数据库全量双向同步；
- 通用插件市场；
- 用户自定义执行脚本；
- 可视化工作流编排；
- 专业大型 APM 和复杂告警规则引擎；
- 多地域和多节点容灾集群。

首版重点建设一套结构清晰、运行稳定、问题可见、操作可追踪、简单易用且能够持续运营的系统。
