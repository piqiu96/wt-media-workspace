# 第七章：互动管理 V2 正式需求文档

> 本章为《模块化自媒体运营平台产品需求说明书 V2》中「第七章：互动管理」的正式需求文档版本。  
> 本章基于当前已确认的产品边界整理，聚焦互动对象、评论模板、互动任务、Agent 执行、基础风控、异常处理、结果管理、权限与验收要求。  
> 本章不展开数据库表结构、接口协议、Agent 代码实现、浏览器自动化脚本细节。

---

## 7.1 模块概述

### 7.1.1 模块定位

互动管理模块面向明确的社媒作品目标，组织媒体账号执行点赞、收藏和评论，并记录完整执行结果。

核心链路：

```text
tracked_object
→ interaction_task
→ task
```

其中：

| 对象 | 定位 |
|---|---|
| `tracked_object` | 被互动的作品目标 |
| `interaction_task` | 针对一个作品创建的互动业务任务 |
| `task` | 某个媒体账号对该作品的一次实际执行 |

互动管理不是内容发现工具、发布工具、账号管理工具或数据分析工具。

---

### 7.1.2 建设目标

互动管理主要解决以下问题：

1. **提升批量互动效率**  
   支持针对一个作品圈选多个媒体账号，一次配置点赞、收藏和评论。

2. **降低账号错配风险**  
   保证媒体账号、浏览器窗口和实际登录账号一致。

3. **控制基础互动风险**  
   对重复动作、评论重复、执行频率、验证码、账号掉登和窗口异常进行基础限制。

4. **保证执行可追溯**  
   能够追踪哪个账号对哪个作品执行了什么动作、使用了什么评论、何时执行以及最终结果。

---

### 7.1.3 系统支持范围

系统支持的作品级互动动作：

```text
点赞
收藏
评论
```

不同平台的实际可用动作由平台能力配置决定。

P0 互动平台范围为 B站和百家号，均支持点赞、收藏和评论。

系统明确不建设：

```text
关注
转发
私信
主动搜索互动作品
评论回复
评论点赞
自动养号
无人监管循环互动
```

互动目标只允许来自：

```text
我方已发布作品
运营手工录入的明确外部作品链接
```

---

### 7.1.4 模块边界

第三章负责：

```text
媒体账号
浏览器窗口
账号分类
账号筛选与使用规则
账号与窗口绑定
登录状态
```

第四章负责：

```text
内容搜索
内容抓取
内容发现
内容线索
```

第六章负责：

```text
我方作品发布
publication
发布成功后形成 tracked_object
```

第七章负责：

```text
对明确 tracked_object 创建互动任务
组织账号执行点赞、收藏和评论
记录互动结果
```

第八章负责：

```text
跨任务统计
账号互动统计
作品互动效果分析
互动前后数据变化
```

---

### 7.1.5 账号圈选原则

互动目标确定后，目标平台自动确定可选媒体账号的平台筛选条件。

账号圈选流程：

```text
互动目标确定社媒平台
→ 运营选择社媒账号分类
→ 系统展示分类下且符合使用规则的媒体账号
→ 系统过滤不可用账号
→ 运营确认具体执行账号
```

账号分类只用于快速筛选，不能作为独立账号授权模型。

点赞、收藏和评论统一使用同一套账号圈选逻辑。评论动作在账号圈选后额外配置评论内容。

账号分类由第三章维护，第七章只使用账号分类筛选结果。

---

### 7.1.6 产品原则

互动管理遵循以下原则：

1. 所有互动必须关联明确的 `tracked_object`。
2. 所有互动必须使用系统内的 `media_account`。
3. Agent 执行动作前必须校验账号、窗口和页面状态。
4. 点赞、收藏等开关型动作必须先判断当前状态，禁止盲目点击。
5. 账号安全优先于任务完成率。
6. 单账号异常只影响对应账号任务。
7. 作品失效或平台能力异常时，停止相应范围的执行。
8. 第七章只做基础风控，不建设复杂风控体系。

---

## 7.2 互动对象与业务流程

### 7.2.1 互动目标对象

互动管理不新增 `interaction_target`。

产品中的“互动目标”直接使用：

```text
tracked_object
```

“互动目标列表”只是 `tracked_object` 在互动场景中的产品视图。

对象关系：

```text
tracked_object
→ interaction_task
→ task
```

---

### 7.2.2 互动目标来源

互动目标只有两类来源：

| 来源类型 | 含义 | 创建方式 |
|---|---|---|
| `publication` | 我方已发布作品 | `publication.status = published` 后创建或关联 |
| `external_manual` | 运营手工录入的外部作品 | 运营粘贴明确作品链接后创建 |

我方作品：

```text
composite_output
→ publication
→ tracked_object
```

外部作品：

```text
运营粘贴作品链接
→ tracked_object
```

外部作品不创建虚假的 `publication`，也不关联虚假的 `composite_output` 或我方发布账号。

---

### 7.2.3 外部作品录入

外部作品支持两个入口：

```text
互动目标列表
→ 添加外部目标
```

或：

```text
创建互动任务
→ 添加外部作品链接
```

统一处理流程：

```text
粘贴链接
→ 识别社媒平台
→ 解析作品 ID
→ 标准化链接
→ 查询是否已存在
→ 抓取基础信息
→ 创建或复用 tracked_object
```

建议自动获取：

```text
平台
作品 ID
标准化链接
作品标题
作者昵称
作者主页
封面
发布时间
```

P0 创建外部目标的最低条件：

```text
平台能够识别
作品 ID 能够解析
作品链接有效
```

标题、封面或作者暂时无法获取时，可以先创建并标记信息待补全。

---

### 7.2.4 互动目标去重

主要去重依据：

```text
社媒平台 + 作品 ID
```

分享短链接、完整链接、移动端链接、桌面端链接及带追踪参数的链接，应先标准化后再解析作品 ID。

如果目标已存在：

```text
不重复创建 tracked_object
→ 展示该作品已存在
→ 直接复用已有目标
→ 允许继续创建新的 interaction_task
```

同一个目标允许多次创建互动任务。是否可以重复执行某个动作，由账号级风控判断。

---

### 7.2.5 互动目标状态

互动目标保留三种简单状态：

```text
available
unavailable
disabled
```

对应：

| 状态 | 中文展示 | 含义 | 是否允许新建任务 |
|---|---|---|---:|
| `available` | 可用 | 作品可以正常访问和互动 | 是 |
| `unavailable` | 不可用 | 作品删除、私密、链接失效或无法访问 | 否 |
| `disabled` | 已停用 | 高级运营主动停止继续互动 | 否 |

`unavailable` 可以由系统检测或 Agent 执行反馈。  
`disabled` 由高级运营主动设置。

历史互动任务、执行记录和数据记录全部保留。

---

### 7.2.6 删除与停用

未创建过互动任务、没有执行记录和数据记录的误录外部目标，可以由有权限人员删除。

只要已经存在以下任一记录：

```text
interaction_task
task
platform_metric_snapshot
```

就不允许物理删除，只能停用。

---

### 7.2.7 互动目标列表

建议提供以下筛选：

```text
全部目标
我方作品
外部作品
可用
不可用
已停用
社媒平台
```

列表主要展示：

```text
封面
作品标题
社媒平台
作者
来源类型
作品状态
作品链接
已创建互动任务数
最近互动时间
创建或录入时间
```

支持操作：

```text
创建互动任务
批量创建互动任务
打开作品链接
查看互动记录
停用
恢复
补全基础信息
```

互动目标列表不承担播放增长、互动效果等数据分析功能。

---

### 7.2.8 互动任务创建流程

单个目标：

```text
选择互动目标
→ 创建互动任务
→ 选择互动动作
→ 按平台和账号分类圈选账号
→ 配置评论内容
→ 系统预检查
→ 查看执行预览
→ 保存为待执行 / 立即执行
```

批量目标：

```text
多选多个互动目标
→ 批量创建互动任务
→ 统一选择动作和账号分类
→ 按作品配置或调整评论
→ 预览
→ 创建
```

后台规则：

```text
一个 tracked_object
→ 一条 interaction_task
```

一次选择多个作品时，系统为每个作品分别创建独立的 `interaction_task`。

---

### 7.2.9 批量操作边界

系统不建设独立的互动批次对象和互动批次管理页面。

批量创建完成后，只提供一次性的创建结果：

```text
本次成功创建任务数
创建失败目标数
失败原因
```

运营可以：

```text
查看本次创建结果
全部开始
返回互动任务列表
```

批量操作只负责提高创建效率，不形成另一套任务管理体系。

---

### 7.2.10 目标失效处理

创建任务前目标已经明确不可用：

```text
阻止创建互动任务
```

任务创建后、执行前发现目标失效：

```text
interaction_task 标记无法继续执行
→ 停止全部未开始 task
→ 保留已完成结果
```

Agent 执行某个账号时发现作品整体失效：

```text
当前 task 失败
→ 上报目标不可用
→ 停止该 interaction_task 下其他未执行 task
→ 更新 tracked_object 为 unavailable
```

如果只是某个互动动作不可用，例如评论区关闭，则只影响对应动作，其他可用动作可以继续。

---

### 7.2.11 外部作品后续关联我方发布

外部作品后续被补录为我方发布作品时，不重新创建 `tracked_object`。

处理方式：

```text
原 external_manual tracked_object
→ 补充关联 publication
→ 更新来源关联
```

系统应通过：

```text
平台 + 作品 ID
```

查找已有目标，避免同一作品重复存在。

---

### 7.2.12 与数据监控的关系

创建互动目标不等于自动启动长期数据监控。

第七章只负责创建可复用的 `tracked_object`。

是否进入长期数据抓取、抓取频率和快照保留规则，由第八章统一确定。

---

## 7.3 评论模板与评论内容

### 7.3.1 功能定位

评论模板用于维护可重复使用的一组评论话术。

关系：

```text
comment_template
→ 多条评论内容
→ 创建互动任务时选择和分配
→ 保存为本次实际评论快照
```

评论模板只负责复用。实际执行评论以账号级 `task` 中保存的评论快照为准。

---

### 7.3.2 模板范围

评论模板支持两种范围：

```text
personal
public
```

对应：

| 模板类型 | 创建人 | 可见范围 | 适用场景 |
|---|---|---|---|
| 个人模板 | 普通运营 | 仅本人 | 个人常用话术和个人运营风格 |
| 公共模板 | 高级运营 | 授权业务范围内可见 | 授权业务范围内通用话术和统一活动评论 |

创建任务时，模板列表分组展示：

```text
我的模板
公共模板
```

---

### 7.3.3 模板内容

一个评论模板支持维护多条完整评论内容。

例如：

```text
模板名称：火影活动互动评论

评论内容：
- 这个活动现在还能参加吗？
- 奖励是直接发到邮箱吗？
- S忍碎片箱怎么选？
- 金币领取入口在哪里？
```

不为每一句评论单独创建一个模板。

---

### 7.3.4 模板适用范围

模板建议包含：

```text
模板名称
社媒平台
账号分类
游戏
模板范围
模板状态
备注
```

规则：

- 社媒平台必填；
- 账号分类可选；
- 游戏可选；
- 未选择账号分类或游戏时，表示平台通用模板。

系统不支持评论变量替换。

不建设：

```text
{游戏名}
{活动名}
{奖励}
```

等变量能力。模板直接保存完整评论，通过模板名称、平台、游戏和账号分类标记用途。

---

### 7.3.5 模板权限

普通运营可以：

```text
创建个人模板
修改个人模板
停用个人模板
删除未使用的个人模板
使用公共模板
复制公共模板为个人模板
```

普通运营不能修改公共模板。

高级运营可以：

```text
创建公共模板
修改公共模板
停用公共模板
查看授权业务范围内公共模板
将合适的个人模板复制为公共模板
```

高级运营不直接修改普通运营的个人模板。

---

### 7.3.6 模板状态与删除

模板只保留：

```text
active
disabled
```

规则：

- 启用模板可以用于新任务；
- 停用模板不能用于新任务；
- 停用不影响历史任务；
- 已被使用过的模板不物理删除；
- 从未使用过的误建模板可以删除。

不建设模板审核流程。

---

### 7.3.7 评论内容录入

支持：

```text
逐条新增
批量粘贴
删除单条
调整顺序
```

批量粘贴时，系统按换行拆分为多条评论。

系统自动进行基础清洗：

```text
去除空行
去除首尾空格
识别完全重复内容
提示疑似重复内容
```

---

### 7.3.8 DeepSeek 生成评论

后端支持通过 DeepSeek 生成候选评论。

生成流程：

```text
作品信息 / 运营要求
→ DeepSeek 生成候选评论
→ 运营查看、删除和修改
→ 保存为模板或仅用于本次任务
→ 分配给账号
```

产品入口：

```text
评论模板页面
→ AI 生成评论
```

或：

```text
创建互动任务
→ 配置评论
→ AI 生成评论
```

运营生成后可以：

```text
仅用于本次任务
保存为个人模板
保存为公共模板（高级运营）
```

DeepSeek 生成的评论必须经过运营确认后才能执行。

Agent 执行阶段不调用 DeepSeek，只读取已经确认的评论快照。

DeepSeek 的 API 地址、API Key、模型名称、超时时间和生成参数直接由后端代码或部署环境维护，不建设产品配置页面。

---

### 7.3.9 评论分配方式

选择评论动作后，系统按账号生成评论分配预览。

支持：

```text
随机分配
顺序分配
手工指定
```

默认采用随机打散分配。

运营可以逐账号修改最终评论内容。

---

### 7.3.10 评论不足与重复提示

当评论数量少于账号数量时，允许重复使用评论，但系统需要提示：

```text
评论数量少于执行账号数，将存在重复评论
```

系统应尽量均匀打散，避免连续账号使用完全相同的评论。

评论重复比例过高时强提醒，但不强制阻断任务创建。

---

### 7.3.11 评论基础校验

评论内容需要进行基础检查：

```text
不能为空
长度符合平台要求
不能包含平台明确不支持的字符
完全重复比例提示
高度相似内容提示
基础敏感词检查
```

DeepSeek 生成评论和手工评论使用相同的校验规则。

P0 不建设复杂语义审核和智能评论审核平台。

---

### 7.3.12 评论修改规则

当 `interaction_task` 尚未开始执行时，可以修改每个账号分配的评论。

一旦存在任意 `task` 已开始执行：

```text
锁定原 interaction_task 评论配置
```

确实需要修改时，应取消对应未执行任务并重新创建新的互动任务。

---

### 7.3.13 评论快照

每条账号级 `task` 保存：

```text
计划评论内容
实际确认提交内容
评论执行结果
评论提交时间
平台返回提示
```

通常计划内容和实际内容一致。

如果运营人工接管后修改了平台页面中的评论，且系统无法识别最终文字，需要明确标记：

```text
人工修改，最终内容未确认
```

---

## 7.4 互动任务与执行

### 7.4.1 互动任务定位

`interaction_task` 表示：

> 针对一个明确作品，使用一批社媒账号执行一组互动动作的业务任务。

一个 `interaction_task` 只关联一个 `tracked_object`。

例如：

```text
互动目标：B站作品 A
互动动作：点赞、收藏、评论
账号分类：火影忍者手游
选择账号：10 个
```

系统创建：

```text
1 条 interaction_task
10 条账号级 task
```

---

### 7.4.2 创建入口

提供以下入口：

```text
互动目标列表
→ 创建互动任务
```

```text
我方作品详情
→ 去互动
```

```text
创建互动任务
→ 临时录入外部作品链接
```

批量选择多个目标时，系统为每个作品分别创建一条独立的 `interaction_task`。

---

### 7.4.3 配置顺序

创建互动任务按照以下顺序：

```text
确认互动目标
→ 选择互动动作
→ 按社媒平台和账号分类圈选账号
→ 配置评论内容
→ 系统预检查
→ 查看执行预览
→ 保存为待执行 / 立即执行
```

执行预览至少展示：

```text
目标作品
互动动作
计划账号数量
实际可执行账号数量
被排除账号及原因
每个账号的评论内容
重复评论风险
预计生成 task 数量
```

---

### 7.4.4 任务创建时机

只有运营点击以下按钮时才创建任务：

```text
保存为待执行
立即执行
```

仅进入配置页面或查看预览，不创建任务记录。

点击保存或立即执行后：

```text
创建 interaction_task
→ 为每个实际入选账号创建一条 task
→ 保存每个账号的互动动作和评论快照
```

区别：

| 操作 | 结果 |
|---|---|
| 保存为待执行 | 创建任务，不立即交给 Agent |
| 立即执行 | 创建任务并进入执行队列 |

---

### 7.4.5 interaction_task 状态

保留以下状态：

```text
pending
running
paused
completed
partially_completed
failed
cancelled
```

对应：

| 状态 | 中文展示 |
|---|---|
| `pending` | 待执行 |
| `running` | 执行中 |
| `paused` | 已暂停 |
| `completed` | 已完成 |
| `partially_completed` | 部分完成 |
| `failed` | 执行失败 |
| `cancelled` | 已取消 |

不建设任务草稿状态。点击保存之前不创建任务。

---

### 7.4.6 task 状态与动作结果

账号级 `task` 建议状态：

```text
pending
running
success
partial_success
failed
paused
cancelled
skipped
```

同时分别记录动作结果：

```text
点赞：成功 / 已完成过 / 失败 / 未执行
收藏：成功 / 已完成过 / 失败 / 未执行
评论：成功 / 失败 / 待确认 / 未执行
```

task 整体状态不能代替动作级真实结果。

---

### 7.4.7 任务进度

互动任务列表按账号展示整体处理进度：

```text
已处理账号数 / 计划账号数
```

例如：

```text
6 / 10
```

同时展示结果摘要：

```text
成功 6
部分成功 2
失败 1
跳过 1
```

任务详情展示动作级进度：

```text
点赞成功 8 / 10
收藏成功 7 / 10
评论成功 5 / 10
```

---

### 7.4.8 执行队列

P0 使用简单、受控的任务队列，不建设复杂账号调度和窗口复用机制。

默认按照任务创建时生成的账号顺序执行。

运营在任务完全未开始时可以调整账号顺序。

不承诺：

```text
所有账号同时执行
按账号价值自动排序
跨任务智能调度
为了节省窗口启动时间自动合并任务
```

---

### 7.4.9 窗口占用边界

`interaction_task` 负责：

```text
整体开始
暂停
继续
取消
进度汇总
结果汇总
```

账号级 `task` 负责：

```text
具体账号
具体 browser_profile
窗口占用
互动动作执行
动作结果
```

一个 `interaction_task` 可以包含多个账号级 `task`，每个账号可能绑定不同窗口，因此 `interaction_task` 不直接绑定唯一窗口。

窗口占用粒度：

```text
一个 task
= 一个账号
+ 一个作品
+ 一组互动动作
```

task 执行时：

```text
获取并锁定 browser_profile
→ 打开或激活窗口
→ 校验当前账号
→ 打开目标作品
→ 执行点赞、收藏和评论
→ 记录结果
→ 释放窗口占用
```

释放窗口占用不等于必须物理关闭浏览器进程。

浏览器是否继续保留，由 Agent 根据本地资源和运行状态自行处理，不作为产品强制要求。

同一 `browser_profile` 同一时间只能执行一个敏感任务。

敏感任务包括：

```text
发布辅助
互动执行
需要登录状态的账号检测
```

窗口被占用时，当前 task 等待，不直接失败。

---

### 7.4.10 Agent 单账号执行流程

固定执行流程：

```text
领取 task
→ 检查平台互动能力
→ 检查账号和窗口状态
→ 锁定窗口
→ 打开或激活浏览器
→ 校验当前登录账号
→ 打开目标作品
→ 校验作品有效性
→ 执行所选互动动作
→ 校验每个动作结果
→ 上报执行结果
→ 释放窗口占用
```

默认动作顺序：

```text
点赞
→ 收藏
→ 评论
```

点赞、收藏和评论在同一个账号级 `task` 内执行，不按单个动作重复打开窗口。

---

### 7.4.11 点赞与收藏执行

点赞、收藏属于开关型动作，必须先判断当前平台状态。

```text
尚未完成
→ 执行动作
→ 校验完成状态
```

```text
已经完成
→ 不再次点击
→ 记录为已完成过
```

```text
无法判断
→ 不冒险点击
→ 标记失败或待人工确认
```

禁止找到按钮后直接点击。

---

### 7.4.12 评论执行

评论执行流程：

```text
检查实际评论内容
→ 检查平台长度和格式限制
→ 定位评论输入框
→ 填写评论
→ 提交评论
→ 判断提交结果
```

评论成功判断不能只依据“已经点击提交按钮”，至少结合：

```text
成功提示
评论输入框状态
页面是否出现评论内容
是否出现审核、频率限制或风险提示
```

无法明确确认成功时：

```text
comment_result = pending_confirmation
```

系统不自动重复提交同一评论。

---

### 7.4.13 暂停与继续

运营可以暂停整个 `interaction_task`。

暂停后：

```text
不再领取新的待执行 task
正在执行的 task 完成当前安全步骤后停止
已完成结果保留
```

继续时：

```text
从剩余 pending / paused task 继续
```

已成功、已跳过和已取消任务不重新执行。

---

### 7.4.14 取消任务

允许对未完全结束的任务执行取消。

取消后：

```text
停止剩余未执行 task
→ 已完成动作保留
→ interaction_task.status = cancelled
```

取消不等于删除，也不撤销已经发生的点赞、收藏或评论。

系统不自动取消点赞、不自动取消收藏，也不自动删除评论。

---

### 7.4.15 任务修改

当所有账号级 `task` 都尚未开始时，可以修改：

```text
互动动作
选择账号
账号顺序
评论内容
```

修改后重新预检查，并更新、新增或取消对应 `task`。

一旦任意 `task` 已开始执行：

```text
锁定原 interaction_task 配置
```

新增账号或变更评论需要重新创建新的互动任务。

---

### 7.4.16 人工接管

验证码、掉登或页面异常时，运营可以：

```text
打开对应窗口
→ 人工完成必要处理
→ 回到系统点击继续检查
```

人工接管不代表可以直接将任务标记为成功。

继续后 Agent 必须重新校验：

```text
当前账号
目标作品
互动动作状态
```

再决定继续、标记已完成或保持失败。

---

## 7.5 互动风控与异常处理

### 7.5.1 基础风控原则

互动风控只建设基础能力，不设计复杂规则体系。

风控默认作用于账号级 `task`。

只有以下情况扩大影响范围：

```text
作品整体失效
平台整体能力异常
平台某项互动动作不可用
```

普通运营不能关闭或绕过风控。

---

### 7.5.2 风控配置入口

统一配置入口：

```text
系统设置
→ 互动设置
→ 基础风控配置
```

系统只保留一份全局默认配置，作用于所有平台和媒体账号。

由高级运营或技术维护。普通运营只能看到限制结果，不能修改配置。

---

### 7.5.3 全局风控配置

只保留以下基础配置：

| 配置项 | 作用 |
|---|---|
| 单账号互动最小间隔 | 控制同一账号两次互动任务之间的间隔 |
| 单账号每日点赞上限 | 达到后不再执行点赞 |
| 单账号每日收藏上限 | 达到后不再执行收藏 |
| 单账号每日评论上限 | 达到后不再执行评论 |
| 评论最小间隔 | 限制同一账号连续评论 |
| 连续失败暂停次数 | 连续失败达到阈值后暂停账号后续执行 |
| 重复评论提醒比例 | 评论内容重复过高时提示运营 |
| 临时技术异常自动重试次数 | 控制页面加载、网络异常等安全场景的有限重试 |

具体数值由系统提供默认值，并允许高级运营或技术修改。

不建设：

```text
平台级独立风控配置
账号级独立风控配置
账号分类级规则
游戏级规则
多套风控方案
规则优先级和继承
动态时间段规则
智能风控模型
```

---

### 7.5.4 风控检查时机

创建任务时进行预检查：

```text
账号是否正常
窗口是否正常
账号与平台是否匹配
是否已经执行过相同动作
是否达到明确的频率限制
评论是否存在明显重复风险
```

Agent 执行前再次实时检查：

```text
账号是否仍然登录
浏览器窗口是否正常
实际登录账号是否匹配
目标作品是否仍然可访问
当前动作是否已经完成
当前是否达到实时频率限制
是否出现验证码或平台风险提示
```

---

### 7.5.5 重复互动控制

同一账号、同一作品、同一种动作，不重复执行。

如果系统历史记录显示已成功：

```text
不再执行
→ 标记为已完成过
```

如果历史记录没有成功，但平台页面显示已经点赞或收藏：

```text
不点击
→ 标记为平台状态已完成
```

同一账号对同一作品已经评论成功后，默认禁止再次评论。

---

### 7.5.6 达到限制后的处理

间隔时间不足：

```text
task 暂缓执行
→ 显示预计可继续时间
```

当日动作上限已满：

```text
跳过对应动作
→ 记录达到当日限制
```

不作为技术失败，也不继续强制排队。

连续失败达到阈值：

```text
暂停该账号后续互动 task
```

评论重复比例过高：

```text
任务创建前强提醒
→ 运营确认后仍可继续
```

---

### 7.5.7 验证码、掉登与账号不匹配

验证码或风险验证：

```text
暂停当前 task
→ 保持或打开对应窗口
→ 提示运营人工处理
```

账号掉登：

```text
停止当前 task
→ 更新账号异常状态
→ 引导运营到账号管理处理登录
```

实际登录账号与绑定账号不一致：

```text
立即停止执行
→ 停止敏感操作
→ 标记账号或窗口疑似切换
```

该问题回到第三章处理。

---

### 7.5.8 作品和动作异常

作品整体不可访问：

```text
更新 tracked_object = unavailable
→ 停止该 interaction_task 下全部剩余 task
```

只有评论区关闭：

```text
评论动作失败或跳过
→ 点赞和收藏可以继续
```

只有某个互动动作能力不可用时，只影响对应动作。

---

### 7.5.9 页面适配异常

出现以下情况：

```text
找不到点赞按钮
找不到收藏按钮
找不到评论输入框
页面结构发生变化
动作结果状态无法识别
```

处理原则：

```text
停止可疑动作
→ 记录平台适配异常
→ 不盲目点击或重复提交
```

如果只有单个动作异常，其他可安全确认的动作可以继续。

如果页面整体无法识别，则停止当前 `task`。

---

### 7.5.10 自动重试边界

只对明确发生在互动动作之前的临时技术问题进行有限自动重试：

```text
页面首次加载超时
临时网络异常
浏览器启动失败
作品页面第一次打开失败
```

不自动重试：

```text
验证码
账号掉登
账号不匹配
平台风控提示
明确频率限制
点赞或收藏状态无法判断
评论已经提交但结果不确定
```

---

### 7.5.11 评论待确认

评论已经提交但无法确认最终结果时：

```text
comment_result = pending_confirmation
```

运营可以：

```text
打开窗口查看
重新检查
稍后重新检查
```

系统不允许直接将结果标记为成功，也不自动重复提交相同评论。

长期无法确认时，可以结束处理并保留为结果未知。

---

### 7.5.12 部分成功与精确重试

例如：

```text
点赞：成功
收藏：成功
评论：失败
```

账号级 `task` 状态：

```text
partial_success
```

已成功动作不回滚，也不重复执行。

重试时：

```text
创建新的重试 task
→ 关联原 task
→ 只包含允许重试的失败动作
```

例如：

```text
原 task：点赞成功、收藏成功、评论失败
重试 task：只执行评论
```

重试前重新检查：

```text
账号状态
窗口状态
目标状态
动作历史
全局风控限制
```

---

### 7.5.13 异常展示

运营侧只展示易理解的业务原因：

```text
账号掉登
窗口异常
账号不匹配
目标不可用
评论区关闭
达到互动限制
需要验证码
页面暂时异常
结果待确认
```

技术详情保存在：

```text
execution_log
```

仅技术查看。

---

## 7.6 互动记录与结果管理

### 7.6.1 记录对象

不新增独立的 `interaction_record`。

现有对象直接承担记录职责：

```text
interaction_task
→ task
```

其中：

- `interaction_task` 保存作品级任务和整体结果；
- `task` 保存账号级执行和动作结果；
- 重试 task 保留历史执行过程。

---

### 7.6.2 互动任务页面

不建设独立的“互动记录”页面。

统一使用“互动任务”页面覆盖任务创建后到历史完成的完整生命周期。

建议 Tab：

```text
全部
待执行
执行中
待处理
已完成
部分完成
已取消
```

“待处理”聚合：

```text
需要验证码
账号掉登
结果待确认
页面异常
```

---

### 7.6.3 任务列表

列表展示：

```text
目标作品
来源类型
互动动作
账号分类
计划账号数
执行进度
结果摘要
任务状态
创建人
创建时间
最近执行时间
```

支持筛选：

```text
社媒平台
账号分类
任务状态
创建人
创建时间
目标来源
```

列表只展示作品级任务、整体进度和结果摘要，不展示底层技术日志。

---

### 7.6.4 任务详情

任务详情分为三部分。

#### 任务概览

```text
目标作品
作品链接
互动动作
账号分类
计划账号数
任务状态
创建人
创建时间
```

#### 动作结果汇总

例如：

```text
点赞：成功 8 / 10
收藏：成功 7 / 10
评论：成功 6 / 10
待确认：1
失败：2
```

#### 账号执行明细

| 账号 | 窗口 | 点赞 | 收藏 | 评论 | 实际评论内容 | 状态 | 失败原因 |
|---|---|---|---|---|---|---|---|

支持：

```text
重试失败动作
重新检查
打开窗口
处理账号异常
取消未执行
查看执行详情
```

---

### 7.6.5 动作结果类型

动作结果区分：

```text
success
already_completed
failed
pending_confirmation
skipped
not_executed
```

对应：

| 结果 | 中文含义 |
|---|---|
| `success` | 本次执行成功 |
| `already_completed` | 执行前发现平台已完成 |
| `failed` | 执行失败 |
| `pending_confirmation` | 已操作但结果无法确认 |
| `skipped` | 因重复、限制或配置原因跳过 |
| `not_executed` | 尚未执行 |

`already_completed` 视为目标已满足，但不计入本次实际新增互动量。

---

### 7.6.6 评论展示

账号明细展示：

```text
计划评论内容
实际确认提交内容
评论结果
提交时间
```

普通列表不展示完整长评论。

详情中支持展开或复制。

人工接管后无法确认最终文字时，展示：

```text
最终内容未确认
```

---

### 7.6.7 重试历史

账号执行明细默认展示最终结果。

例如：

```text
账号 A
点赞：成功
收藏：成功
评论：重试后成功
重试次数：1
```

点击“查看执行详情”后，以时间线展示：

```text
首次执行：评论失败
→ 失败原因

第 1 次重试：评论成功
```

主列表不为每次重试重复展示账号行。

---

### 7.6.8 任务整体结果

状态汇总规则：

| 情况 | interaction_task 状态 |
|---|---|
| 所有计划动作成功或已完成过 | 已完成 |
| 部分动作成功，部分失败、跳过或未知 | 部分完成 |
| 所有动作均失败且没有有效完成 | 执行失败 |
| 尚有 task 正在执行 | 执行中 |
| 存在待人工处理且任务暂停 | 已暂停 / 待处理 |
| 运营取消剩余执行 | 已取消 |

结果统计需区分：

```text
本次执行成功
此前已完成
```

---

### 7.6.9 手工修改结果

运营不允许直接将失败或未知结果改为成功。

允许运营：

```text
重新检查平台状态
处理账号异常
结束待确认处理
补充备注
```

长期无法确认时，可以标记为结果未知，但不能伪造成功结果。

---

### 7.6.10 记录保留

已开始执行的 `interaction_task` 和 `task` 不允许物理删除。

原则上统一使用：

```text
取消
```

保留历史记录。

历史任务用于：

```text
重复互动判断
失败排查
账号执行追踪
后续数据统计
```

---

### 7.6.11 明细导出

支持基础 Excel 导出：

```text
导出当前筛选结果
导出单条互动任务账号明细
```

建议包含：

```text
平台
作品标题
作品链接
账号分类
媒体账号
互动动作
点赞结果
收藏结果
评论内容
评论结果
执行时间
失败原因
创建人
```

复杂趋势统计和效果分析归属第八章。

---

## 7.7 权限与验收要求

### 7.7.1 角色模型

系统只有三类角色：

```text
普通运营
高级运营
技术
```

不新增管理员、运营管理或其他角色。

权限由：

```text
角色权限
+
负责游戏范围
+
资源归属和 policy 规则
```

共同决定。

账号分类只用于筛选，不自动授予账号权限。

---

### 7.7.2 普通运营权限

普通运营可以：

```text
查看权限范围内的互动目标
录入明确的外部作品链接
创建、修改和停用个人评论模板
使用公共评论模板
使用 DeepSeek 生成候选评论
创建互动任务
使用符合规则的媒体账号
保存或立即执行任务
暂停、继续和取消自己的任务
处理验证码等人工接管事项
重试可安全重试的失败动作
查看和导出自己的互动明细
```

普通运营不能：

```text
修改公共评论模板
修改全局基础风控配置
修改 platform_interaction_config
使用不符合规则的媒体账号
绕过账号状态和风控限制
直接把失败或未知结果改成成功
查看无权限范围内的其他运营任务
```

---

### 7.7.3 高级运营权限

高级运营可以：

```text
拥有普通运营的业务能力
创建、修改和停用公共评论模板
查看负责游戏范围内互动目标和互动任务
暂停或取消负责游戏范围内异常任务
批量重试负责游戏范围内可安全重试的失败项
停用和恢复互动目标
查看负责游戏范围内互动明细
维护全局基础风控配置
管理负责游戏范围内媒体账号使用规则
将合适的个人模板复制为公共模板
```

高级运营不直接修改普通运营的个人模板。

---

### 7.7.4 技术权限

技术负责：

```text
维护 platform_interaction_config
维护平台互动适配器代码
维护页面 selector 和状态识别规则
查看 task、execution_log 和失败截图
处理 Agent、浏览器和页面适配异常
启用、降级或停用平台互动动作
维护 DeepSeek 后端调用代码
排查 DeepSeek 调用失败和超时
处理全局业务规则、互动任务和异常结果
```

技术执行以下业务操作时必须记录操作日志：

```text
创建日常互动任务
维护个人或公共评论模板
修改互动业务结果
```

技术权限不能绕过本地 Agent、Browser Profile、Cookie 和本地文件访问边界。

---

### 7.7.5 DeepSeek 权限边界

DeepSeek 作为固定后端能力，不建设产品配置页面。

产品只提供：

```text
AI 生成评论
→ 填写生成要求
→ 生成候选评论
→ 运营修改和确认
```

不提供：

```text
模型选择
API Key 配置
模型参数配置
Prompt 编排
运营切换模型
```

调用失败时，运营侧只展示生成失败或超时提示，技术原因写入日志。

---

### 7.7.6 审批边界

不建设：

```text
互动任务审批
个人模板审批
评论执行审批
```

运营完成配置后：

```text
系统预检查
→ 保存待执行 / 立即执行
```

通过账号授权、基础风控、评论预览、执行前实时检查、异常阻断和操作记录进行管理。

---

### 7.7.7 二次确认

以下高影响操作需要二次确认：

```text
批量立即执行多条互动任务
取消正在执行的互动任务
批量重试评论失败项
停用已有历史任务的互动目标
修改全局基础风控配置
停用某个平台的点赞、收藏或评论能力
```

普通保存、暂停、继续、单条安全重试和修改个人模板不需要二次确认。

---

### 7.7.8 数据查看范围

| 角色 | 默认查看范围 |
|---|---|
| 普通运营 | 自己创建的任务，以及有权限账号的执行记录 |
| 高级运营 | 负责游戏范围内互动目标、任务和记录 |
| 技术 | 全局互动目标、任务、执行日志和失败信息 |

第七章复用第三章的角色、负责游戏、资源归属和 policy 规则，不单独建设互动数据授权模型。

---

### 7.7.9 互动目标验收

必须满足：

```text
我方发布成功作品能够进入互动目标列表
运营能够录入明确外部作品链接
外部链接能够识别平台和作品 ID
相同平台、相同作品 ID 不重复创建 tracked_object
目标支持可用、不可用和已停用状态
不可用或已停用目标不能创建新任务
作品失效后能够停止该作品的剩余执行
```

---

### 7.7.10 评论模板验收

必须满足：

```text
普通运营可以创建和维护个人模板
高级运营可以创建和维护公共模板
一个模板可以维护多条完整评论
支持逐条录入和按换行批量粘贴
支持随机、顺序和手工分配评论
支持基础重复风险提示
模板停用不影响历史任务
支持 DeepSeek 生成候选评论
AI 评论必须经过运营确认
任务保存每个账号实际使用的评论快照
```

---

### 7.7.11 互动任务验收

必须满足：

```text
一个 interaction_task 只关联一个 tracked_object
批量选择多个作品时分别创建多条 interaction_task
目标平台自动确定可选媒体账号平台
账号可以按照社媒账号分类筛选
系统只能展示运营有权限的账号
系统过滤掉登、异常和窗口不可用账号
保存或立即执行时按账号创建 task
支持保存待执行和立即执行
支持暂停、继续和取消剩余执行
列表可以查看账号处理进度
详情可以查看账号级和动作级结果
```

---

### 7.7.12 Agent 执行验收

必须满足：

```text
task 能够关联正确 media_account 和 browser_profile
执行前能够校验当前登录账号
同一窗口同一时间只能执行一个敏感任务
窗口以账号级 task 为占用粒度
一个 task 内完成同一账号对同一作品的一组动作
点赞和收藏执行前能够判断当前状态
已完成过的点赞或收藏不会再次点击
评论提交后能够判断成功、失败或待确认
task 结束后能够释放窗口占用
```

浏览器是否物理关闭不作为产品验收条件。

---

### 7.7.13 异常与重试验收

必须满足：

```text
验证码可以暂停 task 并支持人工接管
账号掉登能够停止执行并反馈账号异常
登录账号与绑定账号不一致时立即停止
单账号异常不影响其他账号继续执行
作品失效能够停止整个 interaction_task 的剩余 task
点赞、收藏和评论结果能够独立记录
支持 partial_success
重试时只执行失败动作
评论结果待确认时不会自动重复提交
原 task 和重试 task 均可追溯
```

---

### 7.7.14 基础风控验收

必须满足：

```text
系统设置中存在一份全局基础风控配置
支持配置单账号互动最小间隔
支持配置每日点赞上限
支持配置每日收藏上限
支持配置每日评论上限
支持配置评论最小间隔
支持配置连续失败暂停阈值
支持配置重复评论提醒比例
支持配置临时技术异常自动重试次数
创建任务时进行预检查
Agent 执行前进行实时检查
普通运营不能关闭或绕过风控
```

不要求验收：

```text
平台级独立风控配置
账号级独立风控配置
账号分类规则覆盖
复杂规则优先级
智能风控模型
```

---

### 7.7.15 记录与审计验收

必须满足：

```text
互动任务页面覆盖待执行到历史完成的完整生命周期
可以查看每个账号的互动动作结果
可以查看每个账号实际使用的评论
可以查看失败原因和重试历史
不能手工将失败或未知结果修改为成功
已产生执行记录的任务不能物理删除
支持导出互动任务和账号执行明细
关键创建、执行、取消、重试和配置修改有操作记录
技术可以查看 execution_log
```
