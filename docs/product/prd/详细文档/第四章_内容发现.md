# 第四章：内容发现

## 4.1 模块概述与建设范围

### 4.1.1 模块定位

内容发现模块负责从抖音中发现、查询和抓取可用于后续生产的外部内容，并将正式进入系统处理链路的作品统一沉淀为 `source_content`，再根据人工选择或抓取策略转换为 `material`，进入第五章“素材生产”。

本章解决以下问题：

- 运营如何通过抖音链接或关键词即时查找内容；
- 系统如何通过关键词和作者监控定时发现内容；
- 外部作品如何统一去重和保存来源信息；
- 自动发现内容如何直接转素材或进入人工筛选；
- 抓取策略、抓取任务及异常如何管理；
- 如何与第五章素材生产保持清晰边界。

总体流程如下：

```text
抖音链接 / 手动关键词搜索 / 关键词监控 / 作者监控
                         ↓
                  source_content
                         ↓
              自动转素材 / 人工筛选
                         ↓
                      material
                         ↓
                 第五章：素材生产
```

### 4.1.2 首版建设范围

首版只支持抖音平台，不建设多平台统一发现能力。

支持的内容发现方式：

| 发现方式 | 首版范围 |
|---|---|
| 多链接即时查询 | 支持一次粘贴多条抖音作品链接 |
| 手动关键词搜索 | 支持输入关键词搜索并选择作品 |
| 关键词定时监控 | 支持一条策略配置多个关键词 |
| 作者定时监控 | 一条策略只配置一个作者 |
| 自动转素材 | 支持按策略配置 |
| 人工筛选 | 支持待选内容处理 |

抖音多链接即时查询和手动关键词搜索已确认可由业务方提供接口。关键词定时监控、作者定时监控、返回字段、限流和失败策略需要在接口接入阶段补充具体说明。

首版不建设：

- Excel 批量导入；
- B站及其他平台内容发现；
- 抖音推荐流自动刷取；
- 自动点赞、关注、转发、私信；
- 多级审核和候选内容领取；
- AI 内容评分和复杂规则引擎；
- 完整抓取结果明细表；
- 每次抓取的历史原始 JSON；
- 互动量历史趋势分析。

### 4.1.3 与第五章的边界

第四章负责：

- 外部作品发现；
- 作品信息解析；
- 原始接口数据保存；
- 外部作品去重；
- 人工筛选；
- 创建正式素材记录。

第五章负责：

- 正式视频文件下载；
- 文件校验与存储；
- 素材状态和生命周期；
- 素材领取与使用；
- 合成任务与成片管理。

第四章创建 `material` 成功，不代表视频文件已经下载完成。文件准备及下载失败重试统一由第五章处理。

## 4.2 即时内容发现与导入

### 4.2.1 功能定位

即时内容发现用于运营主动查询并选择抖音作品。

首版统一建设“内容搜索”页面，提供两种搜索方式：

```text
内容搜索
├── 链接查询
└── 关键词搜索
```

两种即时操作均不创建 `crawl_task`。

### 4.2.2 多链接查询

运营可一次粘贴多条抖音作品链接，建议单次最多 50 条。

支持：

- 一行一个链接；
- 兼容空格或逗号分隔；
- 标准抖音作品链接；
- 常见抖音分享短链接；
- 可解析出作品 ID 的链接。

暂不支持：

- 作者主页链接作为作品导入；
- 抖音合集链接；
- 搜索结果页链接；
- Excel 文件导入。

处理流程：

```text
粘贴多条链接
    ↓
链接清洗和输入去重
    ↓
解析作品 ID
    ↓
批量查询作品信息
    ↓
展示查询结果
    ↓
运营确认
    ↓
创建或更新 source_content
    ↓
创建 material
```

查询结果需要逐条展示：

- 查询成功；
- 输入重复；
- 链接无法识别；
- 短链接解析失败；
- 作品不存在；
- 作品不可访问；
- 接口查询失败；
- 已存在素材。

查询成功但运营未确认导入的作品，不创建 `source_content`。

有效且未存在的内容可默认勾选，由运营点击“批量导入素材”后正式入库。

### 4.2.3 手动关键词搜索

运营输入关键词后，系统即时调用抖音搜索接口并展示结果。

建议支持：

| 搜索条件 | 说明 |
|---|---|
| 关键词 | 必填 |
| 排序方式 | 综合、最新、热门 |
| 发布时间 | 最近 1 天、3 天、7 天、不限 |
| 继续加载 | 每次加载固定数量 |

默认建议：

- 排序方式：综合；
- 发布时间：最近 7 天；
- 首次获取 20 条；
- 每次继续加载 20 条；
- 单次搜索最多展示 100 条。

搜索结果展示：

- 封面；
- 标题；
- 作者；
- 发布时间；
- 点赞量；
- 收藏量；
- 作品 ID；
- 是否已存在素材。

支持：

- 单条选择；
- 批量选择；
- 查看原作品；
- 批量转素材。

未选择的搜索结果不保存。运营选中后，系统才创建或更新 `source_content` 并创建 `material`。

### 4.2.4 即时导入统一流程

链接查询和手动关键词搜索使用统一导入流程：

```text
运营确认导入
    ↓
按 platform + platform_content_id 查询 source_content
    ├─ 不存在：创建
    └─ 已存在：更新允许变化的来源字段
    ↓
检查 material 是否存在
    ├─ 已存在：返回已有素材
    └─ 不存在：创建 material
```

手动操作已经完成业务确认，因此不进入待筛选状态。

### 4.2.5 已忽略内容的手动导入

如果运营通过链接或关键词主动选择了一条此前已忽略的内容：

1. 提示该内容此前已忽略；
2. 运营确认继续；
3. 创建或关联 `material`；
4. 将 `source_content` 更新为已转素材。

人工主动选择优先于历史忽略状态；自动策略不得自动恢复已忽略内容。

### 4.2.6 即时操作异常

即时搜索和导入失败不进入抓取任务中心。

支持：

- 保留当前搜索条件；
- 保留已经成功加载的结果；
- 对失败链接单独重新查询；
- 对部分失败的批量导入单独重试；
- 已成功内容不因其他内容失败而回滚。

## 4.3 抓取策略配置

### 4.3.1 功能定位

抓取策略 `crawl_strategy` 定义系统需要定时抓取什么内容、多久抓取一次、使用什么过滤条件，以及抓到后自动转素材还是进入人工筛选。

首版支持两种策略：

| 策略类型 | 说明 |
|---|---|
| 关键词监控 | 定时搜索多个关键词 |
| 作者监控 | 定时获取单个作者的新增作品 |

### 4.3.2 通用配置

两类策略共用以下配置：

| 配置项 | 说明 |
|---|---|
| 策略名称 | 运营识别名称 |
| 策略类型 | 关键词监控或作者监控 |
| 执行频率 | 固定选项 |
| 单次处理上限 | 单次最多处理的唯一作品数 |
| 入库方式 | 自动转素材或人工筛选 |
| 启用状态 | 启用或停用 |
| 最近执行时间 | 系统记录 |
| 下次执行时间 | 系统计算 |
| 最近执行结果 | 系统记录 |
| 连续失败次数 | 系统记录 |
| 最近失败原因 | 系统记录 |

执行频率建议提供：

- 每 30 分钟；
- 每 1 小时；
- 每 3 小时；
- 每 6 小时；
- 每 12 小时；
- 每天一次。

页面不开放 Cron 表达式。

### 4.3.3 关键词监控策略

一条关键词策略支持配置多个关键词，建议最多 20 个。

多个关键词：

- 各自独立调用搜索接口；
- 共用排序方式；
- 共用发布时间范围；
- 共用点赞量和收藏量条件；
- 共用执行频率；
- 共用入库方式；
- 不是复杂的“且、或”组合表达式。

建议配置：

| 配置项 | 推荐值 |
|---|---|
| 关键词数量 | 最多 20 个 |
| 搜索排序 | 综合、最新、热门 |
| 发布时间范围 | 最近 1 天、3 天、7 天、不限 |
| 最低点赞量 | 可选 |
| 最低收藏量 | 可选 |
| 单关键词获取上限 | 默认 20 条 |
| 单次任务处理上限 | 默认 100 条 |
| 默认入库方式 | 人工筛选 |

精准词和泛化词不增加单独分类字段，由入库方式表达：

| 关键词情况 | 推荐入库方式 |
|---|---|
| 精准活动名、精准福利词 | 自动转素材 |
| 游戏名、宽泛品类词 | 人工筛选 |

首版不支持：

- 多关键词逻辑表达式；
- 排除关键词；
- 作者白名单和黑名单；
- AI 质量评分；
- 复杂规则组；
- 单关键词独立过滤配置。

如果关键词需要不同过滤条件或入库方式，应拆分为不同策略。

### 4.3.4 作者监控策略

一条作者策略只配置一个作者。

配置内容：

| 配置项 | 推荐值 |
|---|---|
| 作者主页链接或作者 ID | 必填 |
| 作者名称 | 系统解析，仅展示 |
| 首次处理方式 | 导入最近作品或只监控后续新增 |
| 首次抓取数量 | 默认 20 条 |
| 后续单次处理上限 | 默认 50 条 |
| 执行频率 | 默认每 1 小时 |
| 入库方式 | 默认自动转素材 |

作者唯一身份使用平台作者 ID，昵称只作为展示字段，可随抓取更新。

作者监控首版不配置点赞量和收藏量门槛，避免新作品因初始互动量低而永久遗漏。

### 4.3.5 首次执行规则

新建并启用策略后，默认立即执行一次。

关键词策略首次执行与后续一致。

作者策略提供：

- 导入最近作品：首次抓取最近指定数量作品；
- 只监控后续新增：首次建立当前作品基线，不创建 `source_content`。

作者初始化仍创建 `crawl_task`，用于保存初始化执行记录。

### 4.3.6 策略启停和编辑

新建策略：

- 可保存为启用或停用；
- 启用时立即执行一次。

编辑策略：

- 不立即执行；
- 只影响后续任务；
- 不追溯改变已有 `source_content` 和 `material`；
- 入库方式变更不自动处理历史待选内容。

停用策略：

- 不再生成后续定时任务；
- 当前执行中的任务继续完成；
- 历史任务和业务数据保留。

重新启用：

- 立即执行一次；
- 不补跑停用期间的所有历史周期。

策略已产生任务后不物理删除，只允许停用。

### 4.3.7 立即执行

策略页面支持“立即执行”。

点击后：

- 创建正式 `crawl_task`；
- 触发方式记为人工触发；
- 使用当前策略配置；
- 不改变下一次定时执行时间；
- 同一策略已有任务执行中时，不允许重复执行。

### 4.3.8 配置快照

每次创建 `crawl_task` 时，保存当次策略配置快照。

配置快照用于还原任务执行时实际使用的：

- 关键词列表或作者 ID；
- 排序方式；
- 发布时间范围；
- 点赞量和收藏量条件；
- 单关键词获取上限；
- 单任务处理上限；
- 入库方式；
- 作者首次处理方式。

首版不建设策略版本管理。

## 4.4 定时抓取任务

### 4.4.1 功能定位

抓取任务 `crawl_task` 记录抓取策略的一次具体执行。

任务负责：

- 保存当次策略配置快照；
- 调用关键词或作者接口；
- 汇总搜索结果；
- 执行任务内去重和过滤；
- 创建或更新 `source_content`；
- 自动转素材或进入待筛选；
- 记录执行统计和错误。

任务不长期保存完整作品主体数据，不建设独立 `crawl_result`。

### 4.4.2 任务创建范围

| 场景 | 是否创建任务 |
|---|---:|
| 多链接即时查询 | 否 |
| 手动关键词即时搜索 | 否 |
| 定时执行关键词策略 | 是 |
| 定时执行作者策略 | 是 |
| 点击策略立即执行 | 是 |
| 作者策略首次初始化 | 是 |
| 失败任务重新执行 | 是 |

### 4.4.3 任务触发方式

支持：

- 定时触发；
- 人工触发；
- 初始化触发；
- 重试触发。

任务记录 `trigger_type`。

人工立即执行不改变原有定时计划。

### 4.4.4 幂等与并发

同一策略不允许并行执行。

上一任务处于等待执行或执行中时：

- 定时触发跳过本轮；
- 人工触发提示当前任务正在执行；
- 不重复排队。

同一计划周期通过以下幂等标识防止重复创建：

```text
策略 ID + 计划执行时间
```

不同策略可以并行执行。

跨策略同时发现同一作品时，由数据库唯一约束兜底。

### 4.4.5 关键词任务执行流程

```text
创建 crawl_task
    ↓
读取任务配置快照
    ↓
依次或小并发执行多个关键词搜索
    ↓
汇总搜索结果
    ↓
按作品 ID 做任务内去重
    ↓
执行发布时间及互动量过滤
    ↓
获取作品详情
    ↓
创建或更新 source_content
    ↓
自动转素材或保持待筛选
    ↓
汇总任务结果
```

同一作品命中多个关键词时，本次任务只处理一次。

不为每个关键词创建子任务表，关键词执行情况保存在任务摘要 JSON 中。

### 4.4.6 作者任务执行流程

```text
创建 crawl_task
    ↓
读取作者 ID 和配置快照
    ↓
获取作者最新公开作品
    ↓
按作品 ID 与系统已有记录对比
    ↓
识别新增作品
    ↓
创建或更新 source_content
    ↓
自动转素材或保持待筛选
    ↓
汇总任务结果
```

作品是否新增最终以平台作品 ID 判断，时间游标只用于减少查询范围。

### 4.4.7 任务状态

首版状态：

| 状态 | 说明 |
|---|---|
| 等待执行 | 已创建，等待执行器处理 |
| 执行中 | 正在抓取和处理 |
| 执行成功 | 全部流程成功 |
| 部分失败 | 部分关键词或作品失败 |
| 执行失败 | 核心流程未完成 |

任务结束后状态不再修改。重新执行创建新任务，并通过 `retry_of_task_id` 关联原任务。

### 4.4.8 任务统计

任务记录：

- 接口返回数量；
- 唯一作品数量；
- 已存在数量；
- 过滤数量；
- 新增来源内容数量；
- 更新来源内容数量；
- 自动转素材数量；
- 待筛选数量；
- 已忽略数量；
- 失败数量；
- 开始时间；
- 结束时间；
- 执行耗时。

任务列表只展示主要指标，详细统计放在任务详情。

### 4.4.9 关键词执行摘要

一条多关键词策略只创建一个任务。

任务中保存关键词级摘要 JSON，包括：

- 关键词；
- 接口返回数量；
- 唯一作品数量；
- 新增数量；
- 过滤数量；
- 失败数量；
- 执行状态；
- 错误摘要。

某个关键词失败时：

- 其他关键词继续执行；
- 部分失败时任务状态为部分失败；
- 全部关键词失败时任务状态为执行失败。

### 4.4.10 任务与作品明细边界

首版不建设：

- `crawl_result`；
- 任务与作品完整历史多对多关系表；
- 每次任务返回的全部作品明细；
- 每次命中关键词的完整历史。

任务详情可以查看：

- 汇总统计；
- 关键词执行摘要；
- 失败作品 ID 和原因；
- 本次新创建的 `source_content`；
- 本次新创建的 `material`。

未来如有严格审计或关键词效果分析需求，再增加轻量任务内容关联表。

### 4.4.11 重试规则

接口级临时异常自动重试：

- 网络超时；
- 接口限流；
- 临时服务不可用。

建议最多自动重试 2 次，使用系统全局配置，不向运营开放单策略设置。

部分关键词失败：

- 只重试失败关键词；
- 不重新执行已成功关键词。

单条作品失败：

- 不阻断其他作品；
- 记录失败阶段和原因。

自动转素材失败：

- 保留 `source_content`；
- 只重试素材创建；
- 不重新执行搜索。

### 4.4.12 人工重新执行

任务详情支持重新执行。

规则：

- 创建新任务；
- 关联原任务；
- 使用当前策略配置；
- 默认只重试失败关键词；
- 原任务记录不修改。

### 4.4.13 超时与中断

任务使用系统全局超时配置。

任务超时后：

- 停止继续获取新结果；
- 已成功创建的数据不回滚；
- 任务标记为失败或部分失败；
- 保存已完成统计和失败原因；
- 支持人工重新执行。

首版不提供执行中人工取消。

### 4.4.14 任务保留

建议 `crawl_task` 默认保留 180 天。

首版可以先不启用自动清理，但预留统一保留期配置。

## 4.5 待选内容与素材入库

### 4.5.1 `source_content` 定位

`source_content` 是系统对外部抖音作品的统一来源主记录。

职责：

- 保存平台作品唯一身份；
- 保存来源关键字段；
- 保存最新接口原始 JSON；
- 承担跨入口和跨策略全局去重；
- 承担待人工筛选内容管理；
- 记录是否已经转为素材；
- 作为 `material` 的统一来源。

所有确认进入系统处理链路的作品都必须先进入 `source_content`。

临时搜索结果和未通过策略过滤的内容不创建 `source_content`。

### 4.5.2 创建范围

需要创建或更新 `source_content`：

- 多链接查询后确认导入；
- 手动关键词搜索后选择导入；
- 关键词策略命中并通过过滤；
- 作者监控发现新增公开作品；
- 已存在作品再次被发现。

不创建：

- 临时查询但未确认导入；
- 手动搜索未选择结果；
- 被策略过滤的内容；
- 无法解析作品 ID 的内容；
- 核心接口信息获取失败的内容。

### 4.5.3 状态设计

首版业务状态仅保留：

| 状态 | 说明 |
|---|---|
| 待筛选 | 等待运营判断 |
| 已转素材 | 已创建正式素材 |
| 已忽略 | 运营明确不使用 |

不增加复杂状态机。

自动转素材失败仍保持待筛选，通过 `pending_reason = materialize_failed` 区分。

### 4.5.4 待选内容页面

页面名称统一为“待选内容”。

默认只展示待筛选内容。

展示字段：

- 封面；
- 标题；
- 作者；
- 发布时间；
- 点赞量；
- 收藏量；
- 来源策略；
- 命中关键词；
- 首次发现时间；
- 最近发现时间；
- 发现次数；
- 当前状态。

操作：

- 单条转素材；
- 批量转素材；
- 单条忽略；
- 批量忽略；
- 恢复；
- 查看详情；
- 打开原作品；
- 查看失败原因；
- 重试自动入库失败内容。

首版不建设：

- 领取；
- 分配；
- 编辑锁；
- 多级审核；
- 内容评分；
- 复杂标签体系。

### 4.5.5 筛选与排序

支持：

- 来源策略；
- 命中关键词；
- 作者；
- 发布时间；
- 首次发现时间；
- 点赞量区间；
- 收藏量区间；
- 状态；
- 自动入库失败快捷筛选。

默认按首次发现时间倒序。

可切换发布时间、点赞量、收藏量排序。

### 4.5.6 转素材流程

```text
运营或自动策略触发转素材
    ↓
校验 source_content 当前状态
    ↓
检查 material 是否已存在
    ├─ 已存在：返回已有素材
    └─ 不存在：创建 material
    ↓
更新 source_content.status = 已转素材
```

自动和人工入库必须使用同一转换服务。

### 4.5.7 转换事务

单条转素材在同一数据库事务中完成：

1. 读取并锁定 `source_content`；
2. 检查已有素材；
3. 创建或关联 `material`；
4. 更新 `source_content` 状态；
5. 记录处理人和处理时间。

创建素材失败时：

- 事务回滚；
- 不写入错误关联；
- `source_content` 保持原状态；
- 记录失败原因；
- 允许重试。

批量转换逐条独立提交，不因部分失败整体回滚。

### 4.5.8 数据关联

`source_content` 与 `material` 使用单向外键：

```text
material.source_content_id
```

`source_content` 不保存 `material_id`。

数据库约束：

```text
unique(material.source_content_id)
```

关系：

```text
source_content 1 —— 0..1 material
```

### 4.5.9 Material 来源数据

`material` 保存：

- `source_content_id`；
- 来源平台；
- 平台作品 ID；
- 原始作品链接；
- 素材基础业务信息；
- 精简不可变来源快照。

来源快照至少包含：

- 平台；
- 平台作品 ID；
- 标题；
- 作者 ID；
- 作者名称；
- 发布时间；
- 原始链接；
- 转素材时间。

`material` 不重复完整保存：

- 最新点赞量；
- 最新收藏量；
- 最近发现时间；
- 抓取策略信息；
- 最新原始 JSON。

### 4.5.10 已忽略内容

运营可将待选内容标记为已忽略。

可选忽略原因：

- 内容不相关；
- 内容质量较低；
- 已有相似素材；
- 内容失效；
- 其他。

自动策略再次抓到已忽略内容时：

- 更新允许变化的来源数据；
- 保持已忽略；
- 不自动转素材。

人工主动选择时，可以确认后直接恢复并转素材。

已忽略内容支持恢复为待筛选。

### 4.5.11 已转素材后的更新

同一作品后续再次被发现时，`source_content` 可更新：

- 标题；
- 封面；
- 视频链接；
- 作者名称；
- 点赞量；
- 收藏量；
- 最新原始 JSON；
- 最近发现时间；
- 发现次数。

不得自动覆盖：

- `material` 素材名称；
- 素材标签；
- 素材状态；
- 素材文件；
- 来源快照。

### 4.5.12 外部作品可用状态

外部可访问状态使用独立技术字段：

```text
availability_status
```

建议值：

- `available`；
- `unavailable`；
- `unknown`。

同时记录：

```text
last_availability_checked_at
```

外部作品失效不改变待筛选、已转素材或已忽略业务状态。

### 4.5.13 原始数据

`source_content.raw_json` 保存最近一次成功获取的完整接口原始 JSON，可被后续抓取覆盖。

首版不保存：

- 历史原始 JSON；
- 点赞量历史；
- 收藏量历史；
- 外部数据趋势。

`material` 只保存精简不可变来源快照。

### 4.5.14 数据删除

`source_content` 不提供常规物理删除。

常规操作只包括：

- 转为素材；
- 标记忽略；
- 恢复待筛选。

技术可以通过维护工具清理测试或异常数据，但不作为正式产品能力。

## 4.6 去重、异常处理、权限与验收要求

### 4.6.1 全局去重

外部作品唯一标识：

```text
platform + platform_content_id
```

数据库约束：

```text
source_content:
unique(platform, platform_content_id)
```

素材唯一约束：

```text
material:
unique(source_content_id)
```

所有即时导入、定时抓取和自动入库必须使用统一去重服务。

### 4.6.2 去重层级

输入级去重：

- 清理重复链接；
- 相同作品 ID 只解析一次。

任务内去重：

- 多关键词结果汇总后按作品 ID 合并；
- 同一作品本次任务只处理一次。

全局去重：

- 不同策略、不同入口发现同一作品时，统一更新同一 `source_content`。

素材去重：

- 同一 `source_content` 最多创建一个 `material`；
- 并发创建通过数据库唯一约束兜底。

### 4.6.3 重复发现更新规则

允许更新：

- 标题；
- 封面；
- 视频链接；
- 作者名称；
- 点赞量；
- 收藏量；
- 最新原始 JSON；
- 最近发现时间；
- 最近来源；
- 最近策略；
- 最近任务；
- 最近关键词；
- 发现次数。

禁止覆盖：

- 首次发现时间；
- 首次来源信息；
- 当前业务状态；
- 忽略原因；
- 人工备注；
- 人工处理人和时间。

### 4.6.4 异常分类

异常按阶段记录：

| 阶段 | 示例 |
|---|---|
| 调度阶段 | 任务未创建 |
| 搜索阶段 | 关键词接口失败 |
| 作者获取阶段 | 无法获取作者作品 |
| 链接解析阶段 | 无法识别作品 ID |
| 详情获取阶段 | 作品详情获取失败 |
| 数据写入阶段 | `source_content` 写入失败 |
| 素材转换阶段 | `material` 创建失败 |
| 超时阶段 | 任务超过执行时限 |

记录：

- 失败阶段；
- 错误代码；
- 错误摘要；
- 失败关键词或作品 ID；
- 已重试次数；
- 最后失败时间。

### 4.6.5 自动重试

使用系统全局默认配置。

自动重试：

- 网络超时；
- 接口限流；
- 临时服务异常。

不自动重试：

- 链接格式错误；
- 作品不存在；
- 作品已删除；
- 作品无访问权限；
- 唯一标识缺失；
- 人工已忽略内容。

### 4.6.6 权限原则

沿用系统既定三个角色，不新增角色体系。

权限点包括：

- 内容搜索；
- 素材导入；
- 查看待选内容；
- 处理待选内容；
- 查看抓取策略；
- 管理抓取策略；
- 立即执行策略；
- 查看抓取任务；
- 重新执行任务；
- 查看原始数据。

推荐：

- 普通运营可搜索、导入和处理待选内容；
- 策略创建、编辑、启停限制给高级运营或技术；
- 任务列表可开放查看；
- 原始 JSON 和技术错误详情只向技术开放。

业务数据在授权业务范围内共享，不按导入人私有隔离。

### 4.6.7 并发处理

多个运营同时处理同一条待选内容时：

- 第一个成功创建素材的操作生效；
- 后续请求返回已有素材；
- 不重复创建；
- 页面刷新为最新状态。

首版不建设内容占用、领取和编辑锁。

### 4.6.8 操作日志

记录：

- 多链接批量导入；
- 手动关键词导入；
- 策略创建、编辑、启用和停用；
- 策略立即执行；
- 任务重新执行；
- 待选内容转素材；
- 批量转素材；
- 忽略和恢复；
- 自动入库；
- 自动入库失败；
- 关联已有素材。

不记录普通搜索、打开详情和列表浏览。

### 4.6.9 首版验收要求

#### 即时内容搜索

1. 支持一次粘贴多条抖音作品链接；
2. 支持标准链接和常见短链接；
3. 能逐条展示成功、重复、失败和已存在状态；
4. 支持批量确认导入；
5. 支持关键词搜索和继续加载；
6. 支持批量选择搜索结果导入；
7. 未选择结果不写入业务数据；
8. 即时操作不创建抓取任务。

#### 抓取策略

1. 支持关键词监控和作者监控；
2. 一条关键词策略支持多个关键词；
3. 一条作者策略只支持一个作者；
4. 支持执行频率、过滤条件和入库方式；
5. 支持自动转素材和人工筛选；
6. 支持启用、停用和立即执行；
7. 同一策略不并行执行；
8. 编辑策略只影响后续任务。

#### 抓取任务

1. 定时和人工触发均创建任务；
2. 任务保存策略配置快照；
3. 支持关键词执行摘要和汇总统计；
4. 部分关键词失败不影响其他关键词；
5. 失败任务支持重新执行；
6. 超时不回滚已成功数据；
7. 首版不依赖 `crawl_result`；
8. 首版不保存完整任务作品明细。

#### 来源内容

1. 所有正式进入处理链路的作品统一进入 `source_content`；
2. `source_content` 按平台和作品 ID 全局唯一；
3. 重复发现不重复创建；
4. 待选内容支持批量转素材、忽略和恢复；
5. 已忽略内容不能被自动策略转素材；
6. 人工主动选择可恢复并转素材；
7. 最新原始 JSON 和关键字段能够更新。

#### 素材入库

1. 所有 `material` 关联唯一 `source_content`；
2. 同一外部作品不能重复创建素材；
3. 自动和人工入库使用同一转换服务；
4. 创建素材和更新来源状态在同一事务中完成；
5. 素材保存不可变精简来源快照；
6. 文件下载由第五章负责；
7. 下载失败不影响第四章完成素材记录创建。

#### 异常与权限

1. 各阶段失败能够展示明确原因；
2. 临时接口异常支持自动重试；
3. 外部作品可用性与业务状态分离；
4. 关键操作保留日志；
5. 权限沿用既定三个角色；
6. 并发处理不会产生重复素材。

### 4.6.10 核心数据对象关系

```text
crawl_strategy
    1
    ↓
crawl_task
    多

source_content
    外部作品统一主记录
    unique(platform, platform_content_id)
    ↓ 0..1
material
    正式素材
    unique(source_content_id)
```

关键对象职责：

| 对象 | 职责 |
|---|---|
| `crawl_strategy` | 定义定时抓取规则 |
| `crawl_task` | 记录一次策略执行 |
| `source_content` | 保存外部作品、全局去重和待筛选状态 |
| `material` | 正式素材业务对象 |

第四章不建设独立 `crawl_result`，也不将临时搜索结果长期保存。
