# 内容挖掘：逐页逐场景 Review 与原型分镜稿

2026-11-05 · 当前合并设计工作稿 · 已实现离线视觉稿，待用户评审。

本稿合并前序只读 review 与本次获授权后的视觉设计实现。用户再次指出前次视觉不满足要求，本轮据此重做当前原型，前次稿不作为已认可的视觉基线。下文保留原稿问题与逐场景设计依据；新版已在同一入口实现 38 个可操作场景。正式 PRD、common 和运行仓本轮未修改；视觉实现不代表业务变更已获批准，也不代表用户已验收。

## 1. 结论与评审边界

上一版是三页功能演示，尚未形成与社媒账号 V7 相当的产品交互全案。问题分为三层：

- **产品层：** 对象分工基本正确，但审核缺少内容判断支持，失败后缺少持续处理入口，策略能力取舍未经充分评审。
- **交互层：** 缺少可直接进入的状态场景；选择、批量、失败恢复、历史追溯尚有断点；“能点通一次”不足以证明流程完整。
- **视觉层：** 基础颜色接近，信息权重、行高、控件状态、页内节奏和批量结果中心尚未对齐。引用 common CSS 不能自动保证视觉合格。

参考 [社媒账号 V7](https://github.com/piqiu96/wt-media-cloud/blob/main/web/example/proto/social-accounts/index.html) 的**场景组织、任务聚焦、主体摘要、轻分区、主次操作、异常后的继续路径**。common 与 [正式前端规范](../standards/frontend/README.md)决定尺寸和行为；不复制社媒账号中与当前 common 不一致的旧筛选位置、字体档位等细节，也不照搬账号业务规则和统计卡。

依据为：本地 PRD、当前 Cloud Vue／Go 源码、两个离线原型，以及本次只读查看的运行中产品三页。前序表格的缺陷证据针对旧原型；不能直接说成正式软件缺陷。现有产品服务未在本轮重新构建，观察不代替当前源码的发布验收。

## 2. 原稿走查证据与产品核实

社媒账号有 **41 个直接进入的评审场景**。本轮实际打开日常维护、新增账号、只读详情、批量接入确认、批量结果五个代表场景，并查看场景目录；不声称已完整走查全部 41 个场景。

内容挖掘实际打开三个列表、发现输入、审核、来源、策略详情／编辑、批量部分失败／返回列表，并复现以下问题。

| 证据 | 观察 | 结论 |
|---|---|---|
| 相同 1600px 产品画面宽度；社媒账号 `#stage` 实际 transform 为 scale(1) | 社媒账号代表行约 69px，内容挖掘三页分别约 90／82／100px；正文均有 13px | 核心差异在组织与密度，不能靠整体放大／缩小字号修复 |
| 1600×1000 内容挖掘视口 | 表格容器 1326px；内容池表宽 1534px、策略 1520px、任务 1400px | “整页无横向溢出”掩盖了表内扫描成本；固定操作之外的时间等字段被默认裁在视野外 |
| 内容池搜“王者”后进入审核 | 列表当前有 3 条待处理匹配项，审核头仍显示全池“剩余 5 条” | 审核范围与计数不一致；队列必须冻结当前处理集合 |
| 两条内容批量转素材，手动给出部分失败结果 | 正文成功 1、失败 1，顶部仍写“2 项待核对／等待确认” | 过程与终态同时存在，结果缺少唯一视觉结论 |
| 上述失败后关闭批量弹窗 | 失败项回到普通“待处理”，列表无失败原因或继续处理标识 | 当前内存模拟没有保留失败原因；不满足失败可追溯体验，不能以弹窗里存在重试按钮代表完整恢复 |
| ID／链接发现初始弹窗 | 所属类目默认文案为“全部”，提交时却要求具体类目 | 查询筛选语义误用为写入归属；必填标记、占位与校验不一致 |
| 策略详情进入编辑，修改名称后取消 | 直接关闭编辑，返回详情，无未保存提醒 | 对有实质输入的长配置缺少离开保护；需按正式交互规范设计 |
| 内容审核画面 | 主要是 90×120px 示意封面和详情键值，没有可判断的内容预览 | 审核是业务决策，不应仅是详情换三个按钮 |
| 来源抽屉源码 | 通过 strategy id 查当前任务／当前策略拼接来源，而非该内容绑定的当次任务 | 当前模拟不能证明历史追溯正确；应提供“策略已修改、历史任务快照不变”的直接评审场景 |

纠正上一稿的判断：社媒账号当前 `scale()` 使用可用宽度自适应，并非一律固定 1600px 缩放；此前未经实际核对就将其概括为“旧固定舞台”不准确。视觉评审应区分外部评审目录与内部产品画面，按相同产品宽度比较。

脚本与中间截图仅放在会话临时目录。数字为本轮浏览器实际测量，不是新全局规范。


### 当前产品核实与本次取舍

只读查看 `/content-pool`、`/discovery-strategies`、`/crawl-tasks`：真实产品有大量长标题、无封面、历史记录；策略复制／删除、规则组与任务重试实际存在。本次保留这些功能，以新的层级、密度、抽屉与结果反馈表达，不复刻现有视觉。

核对当前复制逻辑沿用源策略配置；删除有独立确认，未擅自增加“存在历史任务即禁止删除”的新规则。来源按内容绑定任务追溯；当次关键词与执行周期来自任务快照，当前策略另行展示。原作品入口、审核备注、列表排序和任务发现内容的逐项追溯保留，虚构样本不执行真实外部跳转。未引入视频下载、自动播放或供应方可用性保证。

## 3. 逐页评审：内容池

### 产品与字段

保留 `source_content` 与 `material` 的边界，待处理／已忽略／已转素材三态不变。列表服务于“快速挑选值得处理的内容”；审核服务于“充分判断单条内容”；详情服务于“理解来源与处理事实”。三者可以复用数据摘要，不能复用成同一个画面。

当前 1534px 表宽是事实，不直接以删业务列解决。PRD 明确要求的 ID、封面标题、平台、类目、作者、互动、来源方式、来源、状态、发布时间与入库时间均保留；先控制内容列长度、互动换行、关系摘要和固定操作区。若仍需把字段移出列表，须标明 PRD 影响并评审，不能悄悄删掉。

默认高频条件建议为综合搜索、所属类目、处理状态；平台／来源方式／日期进入下方高级筛选。类目是运营选择工作的常用入口，不宜为了“基础区简洁”全部折叠。类目多选须显示已选摘要、清除与可搜索候选，不以需要 Ctrl／Cmd 的裸原生多行框作为最终视觉方案。默认负责类目与启用集合的交集、管理员团队范围按 PRD，不自行改变权限。

## 4. 逐页评审：挖掘策略

### 产品与配置

保留配置与执行分离。列表回答“找什么、多久执行、是否启用、如何进入配置／记录”；详情回答完整配置和历史；编辑回答本次要改哪些设置。不靠长条件全文和一排按钮把三项任务都挤进列表。

上一版平铺五项时省略复制／删除，尚未确认能力取舍，应撤回“已收敛”的结论：下一版必须把正式存在的操作纳入 review。若当前真实有七项，按 common 保留高频项并收纳其余，不能为避免更多菜单先删能力。启停是否列表内联编辑，依正式 AdminUI 的适用边界讨论，不默认改成开关。

## 5. 逐页评审：挖掘任务

### 任务主体与结果

任务不是另一张策略配置页。列表先识别任务与当前状态，再理解发现结果和来源；详情顶部先给本次执行结论与可处理问题，下方才是快照与阶段记录。100px 的平均行高目前没有换来更明确的结果，需控制计数换行与名称密度。

五项业务计数相互包含，不能做加总成功率；关键词级失败与作品级失败必须各按实际单位标注。列表状态仍为待执行、执行中、成功、失败、部分成功，不引入取消／暂停新状态。

| 场景 | 任务与现状问题 | 原型画面／交互建议 | 评审通过条件 |
|---|---|---|---|
| T01 列表／检索 | 名称、五项计数、来源、时间挤在高行里，仍默认横滚 | 名称可读、状态独立、结果五项按稳定布局；综合搜索与状态优先 | 名称和 ID 可搜；五项标签完整；失败不是只靠红色数值 |
| T02 待执行／执行中 | 当前样本可能显示阶段统计，但无未完成口径 | 顶部显示当前阶段与最新读回时间；未知未执行值不假装最终 0 | 不提供未支持的取消；未终态不显示“完成时间” |
| T03 成功／零新增 | 发现成功、重复多、没有素材是不同事实 | 成功结论＋五项结果＋必要重复说明；不暗示新增生产完成 | 全重复仍可执行成功，0 素材不等于失败 |
| T04 失败／部分成功 | 当前错误只有固定供应方超时，不覆盖错误层级 | 区分整体未执行与局部失败；保留已完成事实和失败单位 | 原因能指导重试；技术请求成功不直接等同业务成功 |
| T05 失败项重试与返回 | 已有 parent id 演示，但缺少完整受理／冲突分镜 | 失败范围说明 → 提交中 → 新任务受理／受理失败；原任务不变 | 重试只含失败目标、不能重复排队、受理不是完成、可进入新任务 |
| T06 当次快照与当前策略 | 部分模拟有复制快照，来源抽屉仍按策略查任务 | 直接展示“执行当时”关键词／规则／周期，策略链接另行进入当前配置 | 修改当前策略后回看旧任务仍一致；明确快照缺失而非补当前值 |
| T07 来源／阶段／日志失败 | 当前静态三行日志并不涵盖局部读取失败 | 有需要才分区／Tab；日志或快照读取失败只影响本区 | 保留任务状态与已知统计，提供局部重试，不伪造日志或全量作品历史 |
| T08 只读角色／自动更新 | 当前无专门受理失败和静默重读失败场景 | 普通运营只追溯，高级运营处理异常；操作时暂停自动刷新 | 不把权限拒绝变空列表；详情不随刷新跳动；刷新失败保留旧数据 |

## 8. 正式定义与实现差异：保留待裁定，不混作视觉问题

1. **自动转素材规则。** 第四章 §4.4.5–4.4.6 描述旧阈值和独立时间过滤；当前 `miningRules.js` 与 Go `model/material_rules.go` 已实现优先级、过滤／命中、全部／任一及发布时间／赞／藏条件。建议以当前可理解的规则组为评审基线，但正式确认后才同步 PRD／Contract／验收。不能把“代码存在”说成“业务获批”，也不能再笼统称日期条件尚未实施。
2. **策略操作保留范围。** 复制／删除当前存在，上一版为压到五项而省略缺乏依据。先纳入场景，按实际角色与生命周期确认；不得静默删能力或放宽删除规则。
3. **失败原因跨会话可追溯。** 原型的内存瞬时失败不能证明正式能力；正式 PRD 要求记录原因的部分按现有接口核对，接口不足时列缺口，不通过新增假字段绕过。
4. **来源与快照。** 当次任务必须按真实关联身份读取，不能按策略取“最新任务”补全历史；快照缺失应直接表达。

以上是少数会影响业务／数据正确性的重点。行距、标题层次、摘要、场景组织等设计细节由 AI 自主给出，不能因此把所有视觉判断重新转交用户。

## 9. 本轮重新设计的判断与实现

用户再次否定前次稿后，重新只读查看运行中的内容池、策略和任务三页，并核对 common 的视觉与交互规定。本轮判断：基础规范是底线；默认过宽的表格、重复常驻导航、详情信息堆叠、重复关键词输入都会降低体验，不能靠换色与缩字号修复。

`content-mining/index.html` 仍是唯一当前入口。没有新增运行时能力或修改正式产品；复制、删除、排序、来源追溯、审核备注、策略优先级及失败重试等已有功能保持可达。

### 当前视觉与体验方案

| 页面／场景 | 当前实现与判断 |
|---|---|
| 评审与产品外壳 | 外部只保留 48px 评审工具条，目录与说明按需展开，避免双侧栏压缩产品。产品使用 common 的基础布局、颜色与字体层级，复用正式品牌图形；宽屏 216px 侧栏，较窄桌面收为图标导航，支持手动切换。 |

| 批量处理 | 确认／处理中用中性进度语义，完成后才给成功或部分失败结论；正文与七项互斥计数一致。保留逐项原因、成功素材去向、仅重试失败项和处理中关闭保护。失败后返回列表仍有继续线索。 |
