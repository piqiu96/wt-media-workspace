## 1. 产品目标与导航结构

### 1.1 产品目标

让运营能够用少量配置完成一次或一组跨平台发布：

- 盘点账号支持的游戏和视频资源；
- 根据游戏、账号质量和视频质量给出分发建议；
- 集中配置平台标题、封面、标签和其他平台字段；
- 创建可独立执行的批次和单条任务；
- 按计划顺序组织多个批次与独立任务；
- 清楚查看执行进度、人工介入点、失败原因和恢复方式；
- 通过图片库和可编辑模板批量生产封面，而不是逐条手工排版。

### 1.2 导航结构

**用户已确认的菜单方向：**

| 菜单 | 页面组织 | 主要职责 |
|---|---|---|
| 发布任务 | 内部 Tab：任务批次、任务列表 | 创建、查找和执行批次及单条任务 |
| 发布计划 | 计划列表、规划详情 | 资源盘点、分发规划、关联批次和任务、执行编排 |
| 图片库 | 列表管理 | 管理现成封面和封面底图 |
| 封面模板库 | 列表管理、模板编辑器 | 管理可复用的封面设计结构 |

发布任务页右上角保留两个主要入口：

- **快速发布**：创建一个账号、一个视频、一个平台的独立任务。
- **批量发布**：创建一个平台、可包含多个游戏、多个账号和多个视频的批次。

发布计划独立存在，不应被降级成批次列表的别名。计划的核心价值是先规划账号经营范围、游戏和视频资源，再组织多个批次及独立任务，并能统一安排执行顺序。

互动管理不并入发布任务。发布成功后可提供跳转或关联入口，但点赞、评论、收藏等动作由互动工作流独立执行、重试和统计。

## 2. 核心业务对象与关系

### 2.1 对象定义

| 对象 | 核心粒度 | 负责什么 | 不负责什么 |
|---|---|---|---|
| 发布计划 | 一次运营行动的规划与调度集合 | 账号/游戏/视频资源盘点、分发建议、批次和任务组织、执行顺序、总体进度 | 不代替批次内容配置，不重复保存每条任务的执行结果 |
| 发布批次 | 单平台、多游戏、多账号、多视频的一组任务 | 具体分配、平台内容配置、批量生成任务、批次内执行控制和进度汇总 | 不把多个账号或多个视频压成一条发布任务 |
| 发布任务 | 一个平台 + 一个账号 + 一个视频 | 单条发布内容、身份、执行过程、尝试记录和最终结果 | 不允许在原任务上直接换平台、账号或视频 |
| 执行尝试 | 一条任务的一次实际执行 | 启动、重试、浏览器/API 步骤、日志、证据和最终结果 | 不作为用户需要额外创建或管理的第四层业务对象 |

### 2.2 计划、批次和任务的关系

**用户已确认：**

- 计划、批次、任务采用独立执行模型。
- 一个计划允许关联多个批次，也允许关联独立任务。
- 一个计划允许包含同平台多个批次。
- 一个批次只属于一个发布平台，但支持选择多个游戏。
- 一个批次确认创建时，批次内所有独立发布任务一起生成。
- 一条发布任务严格对应一个账号和一个视频。
- 同账号多条任务按账号维度串行；不同账号之间可以受控并发。

关系示意：

    发布计划 P
      ├── 百度批次 A
      │     ├── 账号 01 + 视频 01 → 任务
      │     ├── 账号 01 + 视频 02 → 任务
      │     └── 账号 02 + 视频 03 → 任务
      ├── 百度批次 B
      │     └── 多条独立任务
      ├── 小红书批次 C
      │     └── 多条独立任务
      └── 抖音独立任务 T

计划与批次不是互相排斥的入口：批次可以从计划中快捷创建，也可以在发布任务中独立创建。计划中的独立任务复用快速发布流程，不另造第二套任务表单。

### 2.3 创建与执行分离

**当前推荐的统一规则：创建不等于执行。** 创建时先形成业务对象和资源关系，启动时才开始真实发布。允许用户明确选择“创建并启动”，但不能因创建表单提交成功就静默执行。

| 操作 | 创建时发生什么 | 创建后默认状态 | 启动时发生什么 |
|---|---|---|---|
| 创建计划 | 保存资源规划、游戏范围、分发建议和执行顺序 | 规划中 | 计划启动后按顺序调度关联批次和独立任务 |
| 创建批次 | 创建批次、生成全部独立任务、取得视频占用 | 待执行 | 批次启动后启动所有符合条件的任务 |
| 快速发布 | 创建一条独立任务、取得视频占用 | 待执行 | 任务启动后创建一次执行尝试 |
| 重试任务 | 不创建新业务任务 | 原任务保持失败/可重试状态直至启动 | 对原任务新增执行尝试，保留任务 ID 和视频占用 |

建议入口：

- 计划：保存规划、启动计划。
- 批次：保存待执行、创建并启动、启动批次、暂停批次。
- 快速发布：创建待执行、创建并立即发布。
- 任务：立即执行、重试、取消、放弃并释放。

计划创建不自动创建批次和任务，也不占用视频。计划详情中由运营明确选择创建批次或独立任务；创建后关联回计划。

### 2.4 计划执行、批次衔接与独立启动冲突

计划、批次、任务继续采用独立执行模型；计划可以调度已关联的批次/任务，但不垄断它们的独立操作入口。所有启动最终经过同一执行控制，避免重复启动。

**计划项顺序与批次衔接规则：**

1. 计划按用户设定顺序调度批次和独立任务；批次内部采用受控并发，同账号任务串行。
2. 当前批次所有任务都已有明确的提交结果，且不存在执行中、排队中、等待人工或结果待确认任务时，才进入批次衔接判断。
3. 当前批次全部提交成功：自动启动下一批。
4. 当前批次部分成功、部分确认未发布：计算确认失败率。失败率不超过计划设定阈值（含等于阈值）时自动启动下一批；超过阈值时暂停计划调度，展示批次结果摘要，由运营选择继续下一批或先处理失败任务。
5. 存在执行中、排队中、等待人工或结果待确认任务时，不论当前已知失败率多少，都不能自动启动下一批。先完成当前任务或核实结果。
6. “平台已接收/审核中”代表本次提交已被平台接收，可作为批次衔接判断中的成功提交；它不计入计划的“已发布”目标完成数。
7. 取消/放弃任务不计入失败率分子或分母，但会使计划目标保留相应差额。若一个批次没有任何可用于计算的明确提交结果，不得把失败率当作 0% 自动放行；需要运营明确跳过该批次或结束该计划项。
8. 批次衔接时按当时已知的平台提交结果计算。下一批已经启动后，平台后续审核拒绝只更新最终结果和计划统计，不回溯撤销已经发生的批次启动。
9. 超过阈值时的人工确认只决定计划是否启动下一批，不会自动重试、取消或释放上一批失败任务；失败任务继续保留在原批次中，运营可以稍后处理。
10. 计划暂停只停止后续调度，不强制中断已经进入不可逆提交步骤的任务；已启动任务按安全节点完成或等待核实。
11. 如果用户要独立启动计划中尚未轮到的批次/任务，先暂停计划调度并确认人工接管；计划恢复时从第一个尚未处理的计划项继续。

**失败率口径：**

失败率 = 确认未发布/平台拒绝的任务数 ÷ 已明确提交结果的任务数。

已明确提交结果的任务包括：已发布、平台已接收/审核中、确认未发布/平台拒绝。取消和放弃不计入；执行中、排队中、等待人工、结果待确认不进入分母，并且会阻止批次自动衔接。

**阈值设置：**

- 阈值在计划层设置，一份计划内的批次使用同一阈值。
- 字段名称建议为“允许自动进入下一批的失败率上限”。
- 失败率小于或等于阈值自动继续；高于阈值才需要人工确认。
- 原型可用 5% 作为演示初始值，但该数值尚未由用户确认，正式默认值应结合实际运营数据校准。
- 计划启动后阈值保持稳定；如需调整，建议在计划暂停状态下修改，并明确影响后续尚未完成的批次。

同一个批次/任务同一时刻只接受一个有效启动指令。计划控制状态与下级任务执行状态分开展示，不能用“计划已暂停”覆盖“仍有任务执行中”的事实。

### 2.5 视频占用、唯一性与任务身份

**用户已确认：**

- 同平台同一个视频不能重复发布/分配。
- 不同平台允许使用同一个视频。
- 正式创建批次或快速发布任务时才取得视频占用；仅保存计划和预览分配时不占用。
- 任务取消默认保留占用。
- 用户可以明确选择“放弃并释放”，原任务永久结束并解除占用。
- 账号不可在原任务上直接修改；需要放弃释放后创建新任务。

进一步实施约束：

- 任务的平台、账号和视频应视为任务身份。除账号不可直接变更这一已确认规则外，视频或平台变更也建议采用“放弃原任务并创建新任务”，避免执行历史和占用关系被覆盖。
- 创建批次时应再次检查同平台视频是否已被其他有效任务占用，避免规划快照过期或并发创建造成重复占用。
- 失败任务保留占用；确认未发布且执行尝试已安全结束后允许重试原任务。
- 取消任务保留占用；只有明确放弃并释放才能解除。
- 发布结果未知时禁止直接重试或释放，必须先核实平台是否已经生成作品。
- 已发布任务保留平台作品证据和唯一性记录，不允许普通重试或释放。
- 任务重试增加执行尝试记录，不增加第二条发布任务。

**推荐技术不变量：** 以“平台 ID + 视频 ID”作为活动占用唯一键；占用创建与任务创建放在同一事务或等价的原子操作中。释放必须有明确业务动作和审计记录。具体数据库实现由运行仓现有数据层决定，不在 Workspace 原型中伪造。

### 2.6 账号、类目和视频质量分配

**用户已确认：** 账号质量为优质号、普通号、新号；视频质量为优质、普通。优质视频优先给优质号，优质号不足时给普通号；普通视频优先给普通号，剩余给新号。默认按账号顺序填满，运营可人工调整顺序、每号数量和具体视频。

类目沿用现有账号类目体系，不另建“游戏账号”关系。当前账号 PRD 一级类型为 game/ai/anime，二级选项来自现有类目配置；账号可以关联同一一级类型下多个二级类目。发布任务必须验证所选成片类目属于账号支持范围。

多类目批次规则：

1. 批次先选择平台和一个或多个类目，再筛选账号和成片。
2. 同一账号支持多个所选类目时，批次总账号数只计算一次；它可以承接其支持范围内多个类目的任务，但同账号任务串行。
3. 对可用账号更少的类目，分配建议先保护其候选账号范围，避免多类目账号被更容易满足的类目提前占满；每个类目内部仍按用户指定顺序和质量规则填充。
4. 资源不足时明确显示未分配视频、缺少合适质量账号或账号容量不足，不静默跨类目分配。
5. “每号本批次目标数量”与“账号每日可用容量”不同。若现有规则有每日容量，分配时扣除该账号其他批次/计划已安排任务；不新增复杂预测算法。

| 视频质量 | 默认分配顺序 |
|---|---|
| 优质视频 | 优质号优先；剩余给普通号 |
| 普通视频 | 普通号优先；剩余给新号 |

一条任务身份为平台 + 类目 + 账号 + 发布成片。类目通常从所选成片带出并校验账号支持范围。视频唯一性按平台 ID + 发布成片 ID 判断，不以原始素材 ID 或封面图片 ID 判断。

### 2.7 计划的资源规划职责

计划不能只是批次列表或进度汇总。它在创建批次前先回答：

- 这次运营涉及哪些游戏？
- 每个游戏有多少可用视频，优质/普通视频分别多少？
- 每个平台有多少支持这些游戏的账号？
- 账号质量分布如何？
- 哪些游戏资源不足或账号覆盖不足？
- 优质视频应该优先分给哪些账号？
- 应该创建哪些平台批次，是否同平台拆成多个批次？
- 批次和独立任务按什么顺序执行？

计划中的资源数字是规划快照；正式创建批次或任务时必须重新检查真实可用性。计划保存不占用视频，不锁账号，不生成发布任务。

## 3. 发布管理页面与交互

### 3.1 发布任务：任务批次 / 任务列表

**用户已确认的页面结构：**

- 发布任务菜单下有两个 Tab：任务批次、任务列表。
- 右上角提供快速发布、批量发布。
- 批次列表按批次展示平台、游戏范围、账号数、任务数、成功/失败/待处理数量和状态。
- 任务列表按单条任务展示平台、账号、游戏、视频、状态、占用和操作。
- 批次详情展示批次总体进度、账号队列、任务执行状态、失败和待人工处理入口。
- 任务详情展示身份、发布内容、执行尝试、步骤证据、失败原因、重试/取消/放弃操作。

列表遵循状态与操作分离：状态列只显示当前状态，按钮放操作列。高频筛选优先放平台、游戏、批次状态、任务状态、账号和搜索；低频条件进入高级筛选。

### 3.2 快速发布

一条快速发布任务必须选择：

- 一个发布平台；
- 一个账号；
- 一个视频；
- 该视频所属游戏；
- 平台标题、封面、标签及必要的平台字段。

创建后是一条独立发布任务，视频取得该平台占用。默认待执行，允许明确选择创建并立即发布。不能在快速发布中选择多个账号或多个视频后生成隐式组合；多账号、多视频组合统一进入批量发布。

### 3.3 批量发布 / 批次创建

批次只选择一个平台，但可以选择多个游戏。推荐向导：

| 步骤 | 运营动作 | 系统行为 |
|---|---|---|
| 1. 平台与游戏范围 | 选择平台、批次名称、多个游戏 | 按所选游戏盘点账号和视频 |
| 2. 资源与分配 | 查看账号去重结果、质量分层、视频质量；调整账号顺序和每号数量 | 按游戏匹配、视频质量规则和账号顺序给出建议 |
| 3. 内容配置 | 集中配置标题、封面、标签和平台字段 | 批量套用平台规则，允许单条覆盖 |
| 4. 任务预览 | 按账号查看每条视频将生成的任务，处理冲突和未分配项 | 检查平台视频唯一性、账号游戏范围和内容完整性 |
| 5. 确认创建 | 保存待执行，或明确选择创建并启动 | 创建批次、生成所有任务、取得视频占用 |

不要把所有账号、视频、平台字段平铺成一张超长表单。先选择范围和资源，再按游戏/账号分组查看分配，内容配置以批量应用为主、异常作品逐条调整为辅。

### 3.4 平台内容配置

平台字段可能不同，内容配置必须使用平台适配规则，不要用一套字段强行覆盖所有平台。

核心内容：

- **标题**：素材标题作为参考；AI 轻量润色；批量采用正常结果；异常项单独处理。
- **封面**：采用本文件第 5、6 节的两种模式。
- **标签**：固定标签模板自动继承，批次统一调整，个别作品允许覆盖。
- **分区/分类/其他字段**：按平台显示，不适用的字段不展示。
- **素材参考信息**：素材库通常已包含来源平台、标题、封面、视频、标签等信息；通常只作参考，不做大幅改写。

内容配置建议采用“批次统一值 + 单条覆盖值 + 内容版本快照”。创建任务时保存当时的标题、封面、标签和平台字段，避免以后模板或标签模板变更影响历史任务。

### 3.5 执行中心与人机协同

**用户已确认：浏览器发布自动为主、人工兜底；批次内默认受控并发。**

执行原则：

- 有可用 API 时按平台能力使用 API；无 API 或 API 不适用时使用浏览器。
- 浏览器自动完成打开页面、填写内容、上传视频和可安全自动化的步骤。
- 需要人工登录、微调或最终提交时，保留当前浏览器会话和执行步骤，明确提示人工处理原因。
- 人工完成后回到原任务继续，不重新创建任务、不丢失已完成步骤。
- 同一账号多条任务串行；不同账号受控并发。
- 批次详情要能看见整体进度、账号队列、当前任务、待人工处理、失败任务和结果待确认。
- 失败展示可读原因、发生步骤、可执行动作和最近执行尝试；不要只展示“失败”。
- 计划/批次暂停停止后续调度，不强制中断已进入不可逆步骤的提交或结果核验。

计划执行按计划顺序调度关联批次和独立任务；批次内部受控并发。人工处理只影响对应任务/账号队列，除非计划调度本身需要暂停，不默认冻结整个系统。

### 3.6 发布与互动分离

发布任务只负责发布本身和发布结果。拿号评论、置顶、批量点赞、评论、收藏等属于互动工作流。

发布成功后可以把作品 ID / URL 和发布任务关联，提供“去互动管理”的后续入口，但互动任务有自己的批次/任务、重试、限流、状态和结果；不得把互动失败改写成发布失败，也不得在发布任务重试时重复触发互动。

### 3.7 任务状态、发布结果与动作规则

任务的执行状态和发布结果分开表达。详细状态/动作矩阵见第 11.3 节。

- 执行状态描述系统当前/最后执行到哪一步；发布结果描述平台最终发生了什么。
- “执行失败”只能用于确认未发布；结果未知必须显示“结果待确认”。
- 结果待确认时不能重试、取消或释放，必须先核实平台结果。
- 平台审核中不等于已公开成功，但也不能重发。
- 重试复用原任务 ID，新增执行尝试；只有确认未发布且上一次尝试安全结束后才允许。
- 取消默认保留视频占用，取消后的原任务不提供恢复入口；如需重新发起，先对原任务执行“放弃并释放”，再通过“复制配置”创建新任务。放弃并释放是明确且不可逆的动作。
- 账号变更沿用已确认规则：放弃原任务后创建新任务。平台、类目、成片属于任务身份，建议同样通过放弃旧任务并创建新任务变更。
- 已发布任务保留作品证据和历史内容快照；不能普通重试或释放。

列表状态列与操作列分离；任务详情展示内容快照、当前动作、发布结果、执行时间线、尝试记录和失败诊断。

## 4. 图片库设计

### 4.1 图片库定位

图片库是统一的图片资源池，不拆成“AI 封面库”和“自由图片库”。所有图片由人工整理并上传；AI 生成图片可以提前批量生成，再由人工上传到同一个图片库。

图片来源与使用方式：

1. 素材自身已有封面：发布封面配置时可直接使用。
2. 图片库图片：作为现成封面，或作为封面底图。
3. 完全 AI 生成的图片：提前生成并上传图片库，发布时作为现成封面或底图使用。
4. 视频关键帧提取：当前不做。
5. 发布时实时 AI 生成底图：当前不做。

### 4.2 图片数据属性

图片库是统一图片资源池；“现成封面”和“可作底图”是图片用途，不是两套图片库。同一张图片可以同时具备多个用途，避免重复上传。

| 字段 | 规则 | 说明 |
|---|---|---|
| 图片名称 | 必填 | 可搜索、可重命名 |
| 用途 | 可多选 | 现成封面 / 可作封面底图 |
| 内容类目 | 可选或通用 | 复用现有类目体系 |
| 具体类目 | 可多选 | 用于筛选和推荐，不新增类目字典 |
| 图片预览 | 系统生成 | 列表缩略图 |
| 宽、高、比例 | 系统自动读取 | 像素尺寸和宽高比 |
| 格式、大小 | 系统自动读取 | PNG/JPEG/WebP 等 |
| 状态 | 必填 | 启用 / 停用 |
| 引用情况 | 系统统计 | 被模板、生成封面或历史任务引用 |
| 上传人、上传时间 | 系统记录 | 资源管理信息 |

图片底层文件复用现有文件管理/对象存储；图片库只管理用途、类目和运营可用性。人工完成的封面、人工准备的底图、提前生成并上传的 AI 图片都进入同一个图片库。被模板或正式任务引用的图片不能直接物理删除；可以停用，历史任务仍可查看当时使用的图片快照。

### 4.3 图片库列表交互

列表字段建议：

预览｜图片名称｜用途｜内容类目/具体游戏｜尺寸/比例｜状态｜引用次数｜更新时间｜操作

高频筛选：

- 搜索图片名称；
- 图片用途；
- 内容类目；
- 具体游戏；
- 启用/停用。

主要操作：

- 批量上传；
- 单条编辑；
- 批量修改用途/类目/游戏；
- 批量启用/停用；
- 查看详情和引用情况；
- 删除未被引用的图片。

已被正式任务或模板版本引用的图片不能直接物理删除。允许停用，停用后不再进入新的随机选择；历史任务仍能查看当时引用的图片版本。

管理页使用列表；发布配置中的选图弹窗使用缩略图浏览。不要让运营在列表管理页逐张打开图片，也不要把图片选择弹窗做成密集元数据表格。

### 4.4 随机底图规则

用户已确认随机选择即可，不需要复杂 AI 语义匹配。

推荐顺序：

1. 先按用途筛选为“封面底图”。
2. 再按内容类目筛选。
3. 有具体游戏时，优先选择该游戏的启用图片。
4. 对应游戏没有可用图片时，允许回退到“通用”类目。
5. 从符合条件的启用图片中随机选择一张。
6. 如果仍无可用图片，提示运营补充资源或改用素材封面，不要静默选错游戏。

随机选择应可重新抽取；批次确认生成任务后，需要把最终选中的图片 ID 和版本快照保存到任务内容中，不能每次查看都重新随机。

## 5. 封面模板库与模板编辑器

### 5.1 模板定位

模板不是一张不能编辑的固定图片，而是一套可重复使用的设计结构：

    背景图片占位 + 动态文字区域 + 固定装饰/Logo
      → 替换底图
      → 填入 AI 短标题
      → 按约束自动排版
      → 导出封面图片

模板的核心是画布尺寸、版式、对象位置、文字区域和文字样式。

**用户已确认：**

- 模板可以设置文字位置、区域、坐标和字体。
- 模板不强制绑定平台和内容类目。
- 平台和类目可以作为可选适用属性或推荐标签。
- 画布比例和实际宽高是模板的核心规格。
- 第一版不做复杂自由设计软件，保持小而美。

### 5.2 画布规格与坐标单位

| 类型 | 比例 | 默认示例尺寸 |
|---|---|---|
| 横版 | 16:9 | 1920 × 1080 |
| 竖版 | 9:16 | 1080 × 1920 |
| 竖版 | 3:4 | 1080 × 1440 |
| 方形 | 1:1 | 1080 × 1080 |

模板保存固定设计画布宽、高，编辑器中 X/Y/W/H 使用设计画布像素坐标。导出到同一比例的不同分辨率时，统一缩放位置、文字区域、字号、行高、描边、阴影和间距；不能只缩放坐标而保留原字号。不同宽高比使用对应模板或明确裁切适配，不直接拉伸变形。平台输出适配独立校验目标尺寸、比例、格式、文件大小和安全区域。

### 5.3 模板对象与图层

第一版只支持三类对象：

| 对象类型 | 作用 | 关键属性 |
|---|---|---|
| 背景图片 | 被素材封面或图片库图片替换 | 图片占位、填充方式、裁切/定位 |
| 动态文字区域 | 接收 AI 生成的短标题/副标题 | 文字槽位、坐标、尺寸、字体、排版约束 |
| 固定装饰 | Logo、栏目名、固定图形/色块 | 文字或图片内容、坐标、尺寸、样式、锁定 |

动态文字槽位建议：

- main_title：主标题，AI 短标题主要写入位置。
- sub_title：副标题，可选。
- fixed_text：固定文字，不随作品变化。

每个对象需要稳定的对象 ID，方便保存、编辑和批量填充。固定装饰可以锁定，防止运营误拖动。

### 5.4 文字区域可控属性

**位置和区域：**

| 属性 | 说明 |
|---|---|
| X | 左侧坐标 |
| Y | 顶部坐标 |
| W | 文字区域宽度 |
| H | 文字区域高度 |
| 对齐 | 左对齐 / 居中 / 右对齐 |
| 安全区域 | 文字不应进入的边缘区域或平台遮挡区域 |

画布上支持拖动和拖拽控制点调整大小；右侧属性面板支持精确输入 X、Y、W、H。画布坐标显示为实际像素值，内部存储可使用相对画布的归一化坐标，以保证同一比例不同输出分辨率下布局一致。

**字体与样式：**

- 字体家族；
- 字号；
- 最小字号；
- 字重；
- 字体颜色；
- 行高；
- 字间距；
- 对齐；
- 描边开关及参数；
- 阴影开关及参数；
- 副标题开关；
- Logo/固定装饰显示与锁定。

**文字约束：**

- 最大字数；
- 最大行数；
- 自动换行；
- 自动缩小字号；
- 最小可读字号；
- 溢出检测。

自动适配规则：先按模板字号排版；超出文字区域时自动缩小，但不得低于最小字号；仍然超出时显示异常，要求 AI 重新润色或人工修改。不得静默裁掉文字或缩到不可读。

### 5.5 模板编辑器页面布局与交互

编辑器使用三栏布局：

1. **左栏：图层列表**，负责选择、显示/隐藏、锁定/解锁和调整图层顺序；模板切换通过返回模板列表完成。
2. **中栏：设计画布**，显示真实比例画布、底图、文字区域、选中边框和缩放控制点；支持拖动对象和缩放区域。
3. **右栏：属性面板**，按选中对象显示 X/Y/W/H、字体、字号、颜色、对齐、行高、描边、阴影和文字约束；坐标支持直接输入像素值。

主要交互：

- 点击图层或画布选择对象；拖动对象调整位置；拖动控制点调整区域宽高。
- 背景图片可替换、裁切和调整填充方式。
- 动态文字区域可新增、复制、删除；支持主标题/副标题/固定文字槽位。
- 固定装饰/Logo 可锁定。
- 支持撤销/重做；离开未保存模板时提醒保存或放弃。
- 提供短标题、长标题、多行标题测试，检查自动排版和溢出。
- 提供画布尺寸预览和小尺寸缩略预览。
- 字体加载完成后再测量文字；预览与最终导出共用同一排版规则。
- 保存、重新打开、复制后，对象位置、样式、槽位和约束完整恢复。

标尺、参考线、自动吸附是后续辅助优化，不是第一版验收阻塞项。

### 5.6 模板列表管理

模板库采用列表，不以大卡片墙作为主要管理方式。

列表字段：

预览｜模板名称｜画布比例/尺寸｜版式｜字体/主标题样式｜内容类目（可选）｜适用平台（可选）｜状态/引用次数｜操作

操作：

- 新建模板；
- 编辑；
- 复制；
- 预览；
- 设置默认模板；
- 启用/停用；
- 查看引用情况。

平台和类目只是可选的适用范围或推荐属性。兼容判断以画布尺寸、比例、安全区域和输出要求为准。相同设计结构可以跨平台复用，不为每个平台复制一份相同模板。

默认模板建议按画布规格/比例维护；类目和平台可用于推荐，不强制形成“每平台 × 每类目 × 每比例”的模板矩阵。

### 5.7 模板数据结构建议

模板保存为版本化的设计 JSON，而不是只保存固定表单字段。示意：

    {
      "schemaVersion": 1,
      "name": "游戏横版大标题",
      "canvas": {
        "width": 1920,
        "height": 1080,
        "ratio": "16:9"
      },
      "layers": [
        {
          "id": "background",
          "type": "image",
          "role": "replaceable_background",
          "fit": "cover"
        },
        {
          "id": "main-title",
          "type": "text",
          "slot": "main_title",
          "x": 0.06,
          "y": 0.68,
          "width": 0.84,
          "height": 0.22,
          "style": {
            "fontFamily": "Source Han Sans",
            "fontSize": 64,
            "minFontSize": 42,
            "fontWeight": "bold",
            "color": "#FFFFFF",
            "align": "left",
            "lineHeight": 1.05,
            "stroke": true,
            "shadow": true
          },
          "constraints": {
            "maxChars": 18,
            "maxLines": 2,
            "autoFit": true
          }
        }
      ]
    }

上例的坐标应采用固定设计画布像素值（如 X=115、Y=730、W=1500、H=220），不要把 Fabric.js 对象 JSON 直接当作业务模板结构。正式模板业务结构与画布引擎对象格式分离，通过适配层互相转换；同一比例导出不同分辨率时，所有视觉属性按同一比例缩放。正式字段命名应结合现有项目编码规范确定，不要把示意 JSON 当作已批准的 API Contract。

模板被任务引用后应保存模板版本快照。模板后续修改不改变历史任务已生成封面的布局、文字或资源引用。

### 5.8 第一版明确不做

- 完整 Canva / Photoshop；
- 自由画笔和复杂矢量绘制；
- PSD 导入与编辑；
- 动画和视频封面动效；
- 复杂滤镜、蒙版和专业图层混合；
- 复杂插件系统；
- 任意无限画布；
- 发布时实时 AI 生成整张图片；
- 视频关键帧提取。

第一版只把图片、文字、固定装饰、坐标、尺寸、字体和排版约束做可靠。

## 6. 发布内容如何使用图片库和模板库

### 6.1 两种封面模式

**模式一：使用现成封面**

- 从图片库筛选“现成封面”。
- 按内容类目、具体游戏和比例筛选。
- 选择一张后作为当前视频封面。
- 不叠加模板文字，除非运营明确切换到模式二。

**模式二：底图 + AI 短标题 + 模板**

底图来源：

1. 优先使用素材自带封面。
2. 素材封面不适用或缺失时，从图片库符合条件的“封面底图”中随机选择。
3. 完全 AI 生成的底图需提前生成并上传图片库；发布过程中不实时生图。

生成流程：

    视频素材
      → 读取所属游戏和素材封面
      → 选择底图（素材封面优先 / 图片库随机）
      → AI 生成或润色短标题
      → 选择匹配画布比例的模板
      → 将主标题/副标题填入动态文字槽位
      → 自动换行与字号适配
      → 溢出检查
      → 生成封面预览
      → 人工检查异常项
      → 保存封面版本并关联发布任务

AI 负责短标题内容，不负责实时生成整张图片。模板负责布局、字体和文字样式；图片库负责提供底图或现成封面。

### 6.2 批次中的集中配置与封面生成时机

- 批次先确定平台和多个类目，再进行账号/成片分配。
- 标题按视频批量润色；正常结果可批量采用，异常结果逐条处理。
- 封面按视频类目、目标比例和模板推荐；同一批次不同类目可以使用不同模板。
- 固定话题/标签模板按平台继承，批次统一调整，单条可覆盖。
- 单条内容的标题、封面、话题和分区允许覆盖批次默认值。
- 生成结果在正式创建任务时保存为内容/封面快照。

**封面生成在内容配置阶段触发，而不是等任务执行时生成。**

1. 选择封面模式：现成封面，或底图 + AI 短标题 + 模板。
2. 确定底图：素材自带封面优先；不适用/缺失时从图片库选择或随机抽取符合类目的底图。
3. 确定模板：按画布比例优先匹配，类目/平台作为可选推荐条件。
4. 生成或润色短标题，并绑定模板中的主标题/副标题槽位。
5. 在内容配置页面点击“批量生成封面”，系统立即创建本批次封面生成请求；生成可以异步完成，不阻塞整个页面。
6. 每条内容独立显示封面生成状态；失败只重试该条，不重跑全批次。
7. 生成完成后进入全局预览，统一检查视频、账号、标题、封面、话题、分区和异常项。
8. 运营修正异常后再确认创建任务。

封面生成状态属于内容准备状态，不是发布任务执行状态：待生成、生成中、已生成、需重新生成、生成失败。修改某条内容的标题、底图或模板后，只将受影响条目标记为“需重新生成”；不重做其他封面。封面仍在生成或生成失败的条目不能显示为“可发布”。

全局预览采用列表/表格为主、封面缩略图为辅，支持按类目、账号和异常筛选；最终确认前必须看到每条任务候选的最终标题、封面、话题和分区。

### 7.3 技术方案推荐

**当前推荐：Fabric.js 作为画布引擎，参考 Vue Fabric Editor 的属性面板和对象管理交互；使用项目现有 Vue/TDesign 体系实现业务界面。**

理由：

- Fabric.js 是 MIT 许可，且直接解决图片、文字对象、坐标、缩放、换行和导出。
- Vue Fabric Editor 已经有接近需求的属性组件，可以参考其交互或复用明确 MIT 范围的实现。
- H5 Editor 只借鉴标尺/吸附等交互，不引入旧 Vue 技术栈。
- tldraw 等通用无限画布产品不适合这个固定画布、批量替换文字和底图的场景，也不作为第一版基础。

正式实现前仍需验证：
- Cloud Web 当前 Vue、Fabric.js 版本兼容性和构建方式；
- 字体文件授权、字体在预览和最终导出环境中的一致性；
- Fabric.js 对象 JSON 的版本迁移和向后兼容；
- 批量封面生成由浏览器、Cloud Worker 还是 Agent 执行更可靠；
- 是否能让编辑预览和最终导出共用同一套布局/字体测量逻辑。

不要在编辑器和后台批量导出中各写一套文字换行和字号计算规则，否则预览与最终封面会出现偏差。正式渲染位置应基于现有 Cloud/Agent 资源存储、队列和本地执行边界做技术验证后再定。

- 支持新建、编辑、复制、预览、设默认、启停。

**模板编辑器：**

- 三栏：图层/模板列表、中心画布、右侧属性。
- 背景图对象可替换。
- 文字对象可新增、选择、移动、缩放和删除。
- 精确编辑 X/Y/W/H。
- 字体、字号、最小字号、字重、颜色、行高、对齐、描边和阴影。
- 设置动态槽位、最大字数、最大行数和自动适配。
- 固定装饰/Logo 可锁定。
- 支持预览标题替换、长标题溢出检查和多标题批量预览。

- 百度有 50 个账号：10 个优质号、20 个普通号、20 个新号；账号可能支持多个类目。
- 小红书有 30 个账号。
- 账号可能同时支持多个类目；按账号 ID 去重统计，具体任务必须满足账号支持范围。
- 成片属于不同类目，质量有优质/普通。
- 同一个视频可以跨平台使用，但不能在同平台重复分配。
- 计划应先盘点资源，再建议创建百度/小红书/B站批次；小红书运行时能力仍需核验。
- 同一个账号统计去重，但其支持范围内的多个类目任务可以串行执行。

**场景 B：只有百度**

- 同一组账号和多个游戏视频。
- 创建一个百度批次或根据运营安排拆成多个百度批次。
- 查看分配顺序、任务数量和批次执行情况。

**场景 C：五个账号、十个视频**

- 按账号顺序填满。
- 每条任务对应一个账号和一个视频。
- 同账号多条连续执行，不要把同账号多条压成一个任务。
- 人工可以调整顺序和数量。

**场景 D：计划与独立启动**

- 计划创建不创建任务。
- 批次创建生成全部任务但默认不自动执行。
- 计划启动按顺序触发批次/任务。
- 单独启动批次不会重复启动计划。
- 计划执行期间越序启动需要暂停计划并确认接管。
- 已完成计划项跳过，正在独立执行的项目不重复启动。

**场景 E：视频占用和异常**

- 同平台同视频重复创建被阻止。
- 失败任务安全重试原任务。
- 取消保留视频占用。
- 放弃并释放后允许重新分配。
- 结果未知时禁止重试和释放，必须先核实。
- 账号变更需放弃原任务并创建新任务。

**场景 F：封面批量生产**

- 直接选现成封面。
- 素材封面 + AI 短标题 + 模板。
- 图片库随机底图 + AI 短标题 + 模板。
- AI 预生成底图提前上传图片库。
- 长标题自动换行/缩字号；仍溢出时提示异常。
- 同一模板批量替换不同标题和底图后，预览与导出布局一致。

### 8.8 Phase 6：真实运行时实现的前置路径

Workspace 只维护系统级产品/架构/Contract/Delivery 和离线原型，不承载运行时代码。

原型经用户评审后，若进入真实系统：

1. 从 config/repository-map.yaml 读取 Cloud、Agent、Desktop 仓库路径。
2. 读取各目标仓 AGENT-INDEX.md、CLAUDE.md 和相关目录映射。

   - Cloud：业务数据、权限、任务/批次/计划、图片和模板元数据、API、资源存储/队列；
   - Agent：本机浏览器、账号会话、平台页面操作及可能的本地文件/渲染执行；
   - Desktop：系统桥、文件选择/访问、Agent 生命周期等确实需要的桌面能力。
4. 不根据页面名称机械分仓；必须沿用现有对象存储、文件服务、账号/游戏关联、任务调度和审计机制。

## 11. 最新运营输入：产品主链路与页面职责

本节把 2026-11-09 的最新业务输入转成操作级原型规格。若与前文某个早期建议有表述差异，以本节明确的用户决策和当前推荐规则为准；不改变已确认的对象粒度、资源占用和发布/互动分离原则。

### 11.1 发布任务主链路

发布平台 → 发布类目 → 账号 + 视频/成片 → 平台内容配置 → 创建任务 → 启动执行 → 结果核验与诊断。

一条任务严格对应一个平台、一个类目、一个账号和一个发布成片。平台和类目先确定，账号和视频按资格互相筛选。任务创建后身份固定；内容字段按平台适配。

类目与平台分区不能混为一谈：
- 类目：内容和账号的业务归属，用于账号/成片资格匹配，复用账号 PRD 中现有类目体系。
- 分区：平台发布内容的栏目/频道/分类字段，只在平台支持时出现。
- 话题/标签：平台内容元数据，字段名称、控件和校验规则按平台定义。

### 11.2 平台内容字段配置模型

产品目标平台：百度、小红书、B站。核心内容维度是视频、标题、封面、话题、分区，但不要求每个平台都有全部字段，也不要求字段名称相同。

平台字段由配置描述驱动：

| 配置 | 用途 |
|---|---|
| field_key | 内部稳定字段标识 |
| label | 当前平台展示给运营的名称 |
| supported | 平台是否支持 |
| required | 当前平台是否必填 |
| input_type | 文本、文本域、单选、多选、资源选择等 |
| options | 分区/分类等平台选项 |
| validation | 长度、格式、数量、文件规格等校验 |
| help | 平台相关的简短提示 |
| order | 页面展示顺序 |

原型中先按百度、小红书、B站分别建立字段配置示意；真实必填项、选项、限制和可自动化能力必须核对现有平台适配/官方页面/账号权限后填写，不凭经验猜测。小红书当前运行时能力缺口已在 §3.4 标明。

快速发布与批量发布共用同一平台内容配置能力。快速发布显示单条编辑；批量发布在同一字段体系上增加批量默认值、单条覆盖和全局预览。

### 11.3 发布任务：状态、动作与反馈

任务状态是用户理解执行过程的入口；每个状态都必须明确用户能做什么，以及系统操作后发生什么。

| 当前状态 | 用户看到什么 | 可执行动作 | 动作后系统行为 |
|---|---|---|---|
| 待执行 | 任务身份、最终内容、尚未启动 | 启动、编辑未提交内容、取消 | 启动时做执行前检查；编辑生成新内容版本；取消保留视频占用 |
| 排队中 | 等待账号执行槽位/并发名额 | 查看队列、取消排队 | 取消后保留任务和视频占用；不产生执行尝试 |
| 执行中 | 当前阶段、进度、执行方式 | 查看详情/过程 | 不允许重复启动；按 API/浏览器步骤继续 |
| 等待人工 | 需要处理的原因、对应账号和窗口、当前页面阶段 | 打开窗口、完成人工动作、继续执行 | 继续前重新核验当前页面/账号状态；回到原任务和原尝试 |
| 结果待确认 | 已提交但平台结果未知、最近提交时间和账号 | 自动核实、打开账号窗口、补录作品链接/证据 | 明确成功则登记作品；明确未发布才允许重试/释放；仍未知继续保留 |
| 平台审核中 | 平台已接收、审核/可见状态和作品入口 | 查看作品、刷新状态 | 更新平台结果，不发起第二次发布 |
| 已发布 | 作品链接/ID、发布时间、账号和最终内容 | 查看作品、复制链接 | 只读查看，不允许普通重试或释放 |
| 执行失败（确认未发布） | 失败步骤、原因、执行尝试和建议动作 | 重试、编辑后重试、取消、放弃并释放 | 重试原任务并新增尝试；取消保留占用；放弃释放占用 |
| 已取消（确认未提交） | 取消原因、历史执行记录、仍占用提示 | 放弃并释放、复制配置创建新任务 | 不恢复原任务；放弃后释放视频占用，再从历史任务复制内容配置创建新任务 |
| 已放弃 | 放弃原因、释放时间和历史记录 | 查看历史 | 不可恢复，不再占用成片 |

发布结果与执行状态是两个维度：
- 执行状态描述系统当前/最后执行到哪一步。
- 发布结果描述平台最终发生了什么：未提交、平台已接收/审核中、已发布、平台拒绝、确认未发布、未知。

“执行失败”只能用于确认未发布的情况；结果未知必须显示“结果待确认”。平台审核中不等于已公开成功，但也不能重发。平台明确拒绝且确认未形成作品时，可编辑内容后重试原任务；如果平台状态不明确，先核实。

### 11.4 任务详情：运营需要看到的信息

任务详情采用固定信息顺序：

1. **任务摘要**：任务 ID、平台、类目、账号、成片、当前执行状态和发布结果。
2. **内容快照**：标题、封面、话题、分区及本次实际使用的内容版本。
3. **当前动作区**：只显示当前状态下可执行的操作；状态和操作分开呈现。
4. **发布结果**：平台作品 ID/URL、提交/审核/发布时间、结果核实依据。
5. **执行时间线**：按时间展示执行前检查、打开平台、上传视频、填写字段、提交、结果核验等阶段。
6. **尝试记录**：第几次尝试、开始/结束时间、执行方式（API/浏览器）、耗时、最终结果。
7. **失败诊断**：失败步骤、可读原因、影响范围、推荐处理方式、可用截图/证据入口。

执行信息的展示原则：
- 列表只展示帮助运营快速判断和行动的摘要；详情展示完整过程。
- 不展示 Cookie、密码、令牌或敏感请求头。
- 不把原始技术堆栈当作失败原因；先展示可读原因和下一步动作，必要时再展开技术诊断。
- “请求已发送”不等于“发布成功”；必须有真实平台结果或人工核验依据。

### 11.5 发布批次：状态、数据和批量动作

批次是任务的集合和批量控制中心，不另造一套独立发布状态机。

**批次控制状态：**

| 状态 | 含义 | 主要动作 |
|---|---|---|
| 待执行 | 批次和任务已创建，尚未启动 | 启动批次、查看任务 |
| 执行中 | 批次正在调度符合条件的任务 | 暂停后续调度、查看任务、处理异常 |
| 已暂停 | 不再启动新的任务，已运行任务按安全节点处理 | 恢复批次、查看在途任务 |
| 执行已结束 | 当前没有排队/执行/等待人工/结果未知任务 | 查看结果、重试可安全重试的失败任务 |

批次控制状态与任务状态分开。批次“执行已结束”不代表全部成功；成功数、失败数、取消数和放弃数仍分别展示。重试失败任务后，批次可以重新进入执行中。

**批次详情的关键数据：**
- 平台、所选类目；
- 去重后的账号数量、账号质量分布；
- 成片数量和视频质量分布；
- 任务总数；
- 已发布、排队中、执行中、等待人工、结果待确认、执行失败、已取消、已放弃数量；
- 内容准备通过/异常数量（创建前）；
- 批次执行控制状态。

任务状态计数必须互斥，总数与各状态计数相等。展示两个不同指标：
- 发布成功率 = 已发布任务数 / 正式任务总数。
- 处理进度 = 已进入终态的任务数 / 正式任务总数。

不能把失败、取消、未知或等待人工算作发布成功；不能用一个百分比同时表达处理进度和成功率。

**批次级动作：**

| 批次状态 | 动作 | 行为 |
|---|---|---|
| 待执行 | 启动批次 | 启动符合条件的待执行任务；同账号串行、不同账号受控并发 |
| 执行中 | 暂停批次 | 停止后续派发；在途任务不被强制中断 |
| 已暂停 | 恢复批次 | 从仍可执行的任务继续，不重复启动已成功任务 |
| 任意状态 | 查看任务 | 进入任务列表并保留批次筛选 |
| 存在安全失败项 | 批量重试 | 仅选择确认未发布且执行尝试已结束的任务；未知结果不纳入 |
| 存在等待人工项 | 处理人工事项 | 进入待人工任务筛选，逐项打开对应账号窗口 |
| 存在结果待确认项 | 核实结果 | 进入结果待确认筛选，逐项核实 |
| 有未启动任务 | 取消选中任务 | 只取消选中的未启动/安全任务，保留占用；不提供无差别整批释放 |

批次页面需要展示每个状态对应的任务数和入口，不要只显示状态标签。批量操作完成后展示成功、失败、跳过、待确认的实际数量和逐项原因。

### 11.6 发布计划：资源、目标和整体完成情况

发布计划在批次/任务之上，关注一次小型运营行动的目标是否完成。它不是每次发布的必经入口，也不是简单的批次汇总表。

**计划创建时配置：**
- 计划名称；
- 本次涉及的平台和类目；
- 目标发布量（建议按平台 + 类目配置目标任务数）；
- 账号资源盘点（去重后数量、优质/普通/新号分布、类目覆盖）；
- 成片资源盘点（按类目、优质/普通质量统计）；
- 分发建议和计划项顺序；
- 计划关联的批次和独立任务。

同一个视频发布到百度、小红书、B站，资源数量仍是一条成片；计划目标按实际发布任务/平台投放次数计算，最多是三个发布任务。资源统计和目标完成统计不能混用。

**计划列表/详情需要回答：**
- 这次计划要完成多少条发布任务？
- 当前有哪些平台/类目目标？
- 可用账号和成片资源是否够？
- 计划已创建多少批次/独立任务？
- 已发布多少、失败多少、还有多少待处理？
- 目标完成了多少，还差多少？

**计划状态与目标结果分开：**

| 计划控制状态 | 含义 | 主要动作 |
|---|---|---|
| 规划中 | 资源和目标尚在调整 | 编辑目标、刷新资源、创建批次/独立任务 |
| 待启动 | 已关联待执行批次/任务 | 启动计划、调整未执行项顺序 |
| 执行中 | 按计划顺序调度 | 暂停后续调度、查看当前批次/任务 |
| 已暂停 | 后续调度停止 | 恢复计划、调整剩余顺序 |
| 执行已结束 | 所有计划项均已处理或明确结束 | 查看结果、创建补充批次 |

目标结果独立显示：未达成/已达成，以及目标数、已发布数和差额。计划执行结束但部分任务失败时，应显示“执行已结束，目标未达成”，不能把“全部任务处理完”误显示为“目标完成”。

计划只做资源盘点、目标和组织。保存计划不创建批次/任务、不占用视频、不锁账号。用户可从计划详情按建议创建批次，也可创建单条任务；计划中的快速任务复用快速发布配置。一个计划可以关联同平台多个批次。

### 11.7 批量内容配置与全局预览

批量发布内容配置是本次重点交互，不采用几十条纵向长表单。

建议采用“批次默认值 + 逐条任务候选表 + 单条编辑侧栏”：
- 批次默认值集中设置话题/标签、分区、标题处理规则、封面模式和默认模板。
- 每条候选显示视频、账号、类目、标题、封面、话题、分区和内容准备状态。
- 批量操作可以作用于未修改项、选中项或全部项；覆盖前明确显示影响条数。
- 单条覆盖显示“已单独修改”，后续修改批次默认值不覆盖。
- AI 标题生成和封面生成可以批量触发；每条内容独立返回结果。
- 只看异常入口集中筛选标题过长、封面溢出、缺少必填字段、视频占用冲突、账号类目不匹配和封面生成失败。
- 内容准备未通过的候选不能被显示为“可创建”；默认先修正或移出本次批次，之后再正式创建任务。

**全局预览**是正式创建前的最后一道运营检查，不是发布结果页。每行至少显示：平台、类目、账号、视频/成片、最终标题、最终封面、话题、分区、检查结果。支持大图查看封面、按类目/账号筛选、只看异常、单条修改和重新生成封面。

### 11.8 图片库与封面生成的产品闭环

内容配置只有两种封面模式：

1. **现成封面**：人工已经制作/找好的封面，直接从素材自带封面或图片库选择，不再套模板生成。
2. **规则生成封面**：素材封面或图片库底图 + AI 生成/润色短标题 + 模板生成新封面。

图片库统一管理现成封面和可作底图的图片。用途可以多选；内容类目和具体类目用于筛选/推荐。随机选择只从符合用途、类目且启用的图片中抽取；优先匹配当前类目，没有可用图片时回退通用图片。随机抽取结果在内容配置和任务快照中固定，不因再次打开页面而重新随机。

素材封面优先作为规则生成的底图；不适用或缺失时使用图片库底图。完全 AI 生成的底图需要提前生成并上传图片库，不在发布时实时生图。视频关键帧提取当前不做。

### 11.9 封面模板编辑器：最小可用设计规格

模板是可复用的设计结构，不是固定背景图片。第一版支持背景图片、动态文字区域、固定装饰三类对象。

模板编辑器验收重点：
- 画布比例和设计宽高明确；
- 主标题/副标题文字区域可以拖动、缩放；
- X/Y/W/H 可以直接输入像素；
- 字体、字号、最小字号、颜色、字重、对齐、行高、描边、阴影可控；
- 最大字数、最大行数、自动换行、自动缩小和溢出检测可用；
- 图层可选中、显示/隐藏、锁定/解锁；
- 支持背景图片替换；
- 支持撤销/重做和未保存离开提醒；
- 保存后重新打开，所有对象和属性恢复；
- 字体加载后再进行文本测量；
- 小尺寸预览下文字仍清晰；
- 模板编辑预览与批量最终导出使用同一排版规则；
- 同比例不同导出分辨率时，位置、字号、描边、阴影等统一缩放。

模板列表采用列表管理。编辑器左侧只放图层，模板切换通过返回模板列表完成。平台和类目为可选适用属性，不强制绑定；默认模板优先按画布比例管理。

### 11.10 原型实现顺序与范围控制

建议按真实运营顺序实现，不按技术模块任意拆散：

1. **快速发布闭环**：平台/类目/账号/成片选择 → 平台内容配置 → 内容预检 → 创建待执行/创建并启动 → 任务详情。
2. **批量发布闭环**：单平台/多类目 → 资源盘点与账号/视频分配 → 批量内容配置 → 封面生成 → 全局预览 → 创建批次和独立任务。
3. **批次执行管理**：批次进度、状态计数、批量启动/暂停/重试、待人工和结果待确认筛选。
4. **计划资源与目标**：计划目标、资源盘点、分发建议、关联多个批次/任务、顺序调度、目标完成情况。
5. **图片库与模板库**：列表管理、缩略图选择、模板编辑、版本快照和批量生成接入。
6. **异常闭环回归**：提交后断线、未知结果、失败重试、取消保留占用、放弃释放。

发布管理不需要因为图片库/模板库而整体重写；但批次内容配置和全局预览如果无法承载几十条作品的批量处理，就应按上述工作区重新组织。保留已有成熟组件和交互，不保留与新业务模型冲突的旧页面行为。

#### C. 发布任务状态与动作

- [ ] 每个状态的意义、出现条件和允许动作明确。
- [ ] 执行状态与发布结果分开表达。
- [ ] 任务详情可看当前阶段、执行尝试、执行方式、失败原因和核实证据。

#### D. 批次管理与分配

- [ ] 批次只选一个平台，支持多类目。
- [ ] 账号跨类目去重，具体任务仍逐条校验类目资格。
- [ ] 优质/普通视频按既定账号质量顺序分配。
- [ ] 默认按账号顺序填满，人工顺序和数量调整不会被重算静默覆盖。
- [ ] 账号每日容量（如当前能力存在）与本批次每号目标数量分开。
- [ ] 批次列表和详情展示任务总数、状态分布和成功率。
- [ ] 批次暂停只停止后续派发，不强制中断在途任务。

- [ ] 批次结束不等于全部成功；处理进度和发布成功率分开。

- [ ] 计划有明确目标数，资源盘点按平台/类目展示。
- [ ] 账号总数去重，视频按类目和质量展示。
- [ ] 同一个视频投放到多个平台按多个发布任务统计目标完成。
- [ ] 计划保存不生成任务、不占用视频。
- [ ] 一个计划允许多个同平台批次。
- [ ] 计划顺序、暂停、恢复和独立启动冲突可理解。

- [ ] 批量应用明确显示“未修改项/选中项/全部”范围。
- [ ] 标题生成、封面生成按条目独立返回状态。
- [ ] 封面生成在内容配置阶段触发，不延迟到执行时。
- [ ] 批量生成不阻塞整个页面；单条失败可独立重试。
- [ ] 修改标题/底图/模板只使受影响封面失效。
- [ ] 全局预览展示最终视频、账号、标题、封面、话题、分区。
- [ ] 异常项可筛选、修正、重新生成。

- [ ] 随机底图按用途/类目匹配并允许通用回退。

- [ ] 字体、字号、描边、阴影和文字约束可控。

### 11.12 评审结论与进入实现的门槛

原型评审先检查上述清单中的业务闭环和动作合理性，不要求一次确认所有技术实现细节。以下属于进入真实运行时实施前必须有证据的事项：

- 百度/小红书/B站的真实发布能力和字段要求；
- 账号类目关联是否可直接复用当前 category_ids；
- 同平台成片占用的真实数据身份和并发原子性；
- 跨批次/跨计划账号执行锁；
- 浏览器人工接管和提交结果核验；
- 图片文件引用、模板版本和历史任务快照；
- 字体授权、字体加载、渲染位置和预览/导出一致性。

原型通过不代表这些运行时能力已实现。用户确认原型后，再按仓库 Ownership 将稳定产品规则回写 PRD，将跨仓 Contract/Architecture/Decision 和实施验收纳入对应 Delivery；不在本设计稿中伪造已完成状态。

## 11.14 最新补充：计划批次衔接阈值与统计字段

本节补充 2026-11-09 用户对计划执行衔接和计划统计的最新输入。若与第 11.6 节早期简述有差异，以本节为准。

### 11.14.1 批次结束后的自动衔接

- 全部提交成功：自动启动下一批。
- 部分成功、部分确认失败：按计划设置的失败率阈值判断；失败率不超过阈值（含等于）自动启动下一批，超过阈值暂停计划并等待人工确认。
- 仍有执行中、排队中、等待人工或结果待确认任务：无论当前失败率多少，都不自动进入下一批。
- 平台已接收/审核中视为本批次提交成功，可继续调度；但不计入计划公开发布目标的已发布数。
- 取消/放弃不计入失败率；目标差额仍保留。若批次没有任何明确提交结果，不把失败率视为 0%，需运营明确跳过批次或结束该计划项。
- 超阈值后的人工动作只决定是否继续下一批，不会自动重试上一批失败任务。

失败率 = 确认未发布/平台拒绝任务数 ÷ 已明确提交结果任务数。分母包括已发布、平台已接收/审核中、确认未发布/平台拒绝；排队、执行中、等待人工、结果待确认会阻止衔接，不计入分母。

阈值为计划级配置，一份计划统一使用一个失败率上限。字段建议命名为“允许自动进入下一批的失败率上限”。5% 可作为原型演示值，但尚未得到用户确认，正式默认值需结合运营数据校准。

### 11.14.2 计划统计视图

计划详情提供四种可切换视图，使用同一套指标口径：

1. **总览**：整个计划的目标、执行、资源和批次衔接情况。
2. **按平台**：将类目数据汇总到百度、小红书、B站等平台。
3. **按类目**：将不同平台的数据汇总到各业务类目。
4. **平台 × 类目**：查看每个平台在每个类目上的目标和实际完成情况，是最细的统计视图。

目标以“平台 × 类目”为最细粒度配置；按平台、按类目视图由该数据聚合，不重复录入目标。

### 11.14.3 计划总览展示字段

**基本信息**
- 计划名称、计划编号、计划状态；
- 涉及平台、涉及类目；
- 可选目标执行周期；
- 创建人、创建时间、最近更新时间；
- 当前批次、下一批次。

**目标完成指标**
- 目标发布任务数：各平台 × 类目目标数之和；
- 已创建任务数：正式创建的任务数；
- 已发布任务数：已确认公开发布成功的任务数；
- 目标完成率：已发布任务数 ÷ 目标发布任务数；
- 目标差额：max(目标发布任务数 - 已发布任务数, 0)；
- 超额完成数：max(已发布任务数 - 目标发布任务数, 0)。

**执行状态分布**
- 待执行/排队中；
- 执行中；
- 等待人工；
- 结果待确认；
- 平台已接收/审核中；
- 已发布；
- 确认未发布/平台拒绝；
- 已取消/已放弃。

等待人工和结果待确认应突出显示并提供直接处理入口；平台审核中与已发布分开统计。

**资源概况**

账号资源：
- 去重账号总数；
- 按平台和账号质量分层的数量（优质号、普通号、新号）；
- 按类目统计的合格账号数；
- 已安排任务的账号数、尚未安排的账号数；
- 只有在现有账号规则提供每日容量时，才展示可用容量。

成片资源：
- 去重后的可用成片总数；
- 按类目、视频质量（优质/普通）统计数量；
- 已分配成片数、未分配成片数；
- 因同平台任务占用而不可再次分配的数量。

同一成片投放到多个平台时，资源概况只计一条成片；目标和完成情况按各平台独立发布任务计数。

**批次执行概况**
- 批次数量、已结束批次、执行中批次、待执行批次、暂停批次；
- 当前批次名称/序号、下一批次名称/序号；
- 当前批次成功提交数、确认失败数、待人工数、结果待确认数；
- 当前批次失败率、计划阈值；
- 下一批衔接状态：自动继续、等待人工确认、等待当前任务核实。

### 11.14.4 维度视图表格字段

按平台、按类目、平台 × 类目三个视图使用一致指标：

| 字段 | 说明 |
|---|---|
| 平台/类目 | 当前分组维度 |
| 目标任务数 | 该维度计划发布任务目标 |
| 已创建任务数 | 正式创建的任务数 |
| 已发布 | 已确认公开发布成功 |
| 平台已接收/审核中 | 已提交成功但尚未确认公开 |
| 待执行/排队/执行中 | 尚未完成执行的任务 |
| 等待人工 | 需要人工继续处理 |
| 结果待确认 | 已提交但平台结果未知 |
| 确认失败 | 已确认未发布或平台拒绝 |
| 已取消/已放弃 | 主动结束的任务，不计成功 |
| 目标完成率 | 已发布 ÷ 目标任务数 |
| 目标差额 | 尚未完成的目标数量 |

默认突出目标数、已发布、待处理、异常和完成率；其他状态可展开或点击进入筛选，避免一次展示过多列。点击指标进入任务列表时，自动带入计划、平台、类目和状态筛选。

### 11.14.5 指标口径

- 目标完成率 = 已发布任务数 ÷ 目标发布任务数；平台审核中不计入已发布。
- 目标差额 = max(目标任务数 - 已发布任务数, 0)。
- 任务创建覆盖率 = 已创建任务数 ÷ 目标发布任务数，仅表示目标已安排程度。
- 批次衔接失败率 = 确认未发布/平台拒绝任务数 ÷ 已明确提交结果任务数。
- 资源统计按唯一账号/成片计数；发布目标和完成统计按发布任务计数。

### 11.14.6 本轮自审与待确认项

- 批次衔接只在提交结果明确且无执行中、排队中、等待人工、结果待确认任务时计算失败率；未知结果不会被阈值绕过。
- 平台已接收/审核中可以作为批次继续调度的成功提交，但不计入计划公开发布目标。
- 采用失败率而非固定失败条数，适应不同批次规模。5% 只是原型演示值，正式默认值待确认。
- 目标以平台 × 类目为最细粒度；资源统计使用唯一账号/成片，目标使用发布任务，避免重复计数。
- 本轮仍待确认：失败率阈值正式默认值；无有效提交结果的批次是否采用“跳过当前批次/结束计划项”交互。其余统计字段和衔接规则作为原型默认方案。
