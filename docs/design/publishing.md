### 0.3 本轮明确的范围边界

1. 发布管理不做大面积重构。保留现有发布管理中仍有价值的列表、内容配置、执行队列和异常处理交互，只吸收能降低运营成本的成熟方案。
2. 发布计划、批次、任务按不同职责管理；批次内任务默认受控并发；浏览器发布自动为主、人工兜底；发布与互动是两套独立工作流。
3. 图片库和封面模板库是本轮重点优化对象，均采用列表管理；发布时的图片选择器可以采用缩略图浏览。
4. 模板不是固定图片。模板必须允许编辑文字区域的位置、尺寸、坐标、字体和排版约束，才能被批量复用。
5. 不做完整 Canva / Photoshop，不建设复杂 DAM，不为未来可能出现的功能预先增加大量对象、字段和菜单。

## 1. 产品目标与导航结构

### 1.1 产品目标

让运营能够用少量配置完成一次或一组跨平台发布：

- 盘点账号支持的游戏和视频资源；
- 根据游戏、账号质量和视频质量给出分发建议；
- 集中配置平台标题、封面、标签和其他平台字段；
- 创建可独立执行的批次和单条任务；
- 按计划顺序组织多个批次与独立任务；
- 清楚查看执行进度、人工介入点、失败原因和恢复方式；
- 通过图片库和可编辑模板批量生产封面，而不是逐条手工排版。

### 1.2 导航结构

**用户已确认的菜单方向：**

| 菜单 | 页面组织 | 主要职责 |
|---|---|---|
| 发布任务 | 内部 Tab：任务批次、任务列表 | 创建、查找和执行批次及单条任务 |
| 发布计划 | 计划列表、规划详情 | 资源盘点、分发规划、关联批次和任务、执行编排 |
| 图片库 | 列表管理 | 管理现成封面和封面底图 |
| 封面模板库 | 列表管理、模板编辑器 | 管理可复用的封面设计结构 |

发布任务页右上角保留两个主要入口：

- **快速发布**：创建一个账号、一个视频、一个平台的独立任务。
- **批量发布**：创建一个平台、可包含多个游戏、多个账号和多个视频的批次。

发布计划独立存在，不应被降级成批次列表的别名。计划的核心价值是先规划账号经营范围、游戏和视频资源，再组织多个批次及独立任务，并能统一安排执行顺序。

互动管理不并入发布任务。发布成功后可提供跳转或关联入口，但点赞、评论、收藏等动作由互动工作流独立执行、重试和统计。

## 2. 核心业务对象与关系

### 2.1 对象定义

| 对象 | 核心粒度 | 负责什么 | 不负责什么 |
|---|---|---|---|
| 发布计划 | 一次运营行动的规划与调度集合 | 账号/游戏/视频资源盘点、分发建议、批次和任务组织、执行顺序、总体进度 | 不代替批次内容配置，不重复保存每条任务的执行结果 |
| 发布批次 | 单平台、多游戏、多账号、多视频的一组任务 | 具体分配、平台内容配置、批量生成任务、批次内执行控制和进度汇总 | 不把多个账号或多个视频压成一条发布任务 |
| 发布任务 | 一个平台 + 一个账号 + 一个视频 | 单条发布内容、身份、执行过程、尝试记录和最终结果 | 不允许在原任务上直接换平台、账号或视频 |
| 执行尝试 | 一条任务的一次实际执行 | 启动、重试、浏览器/API 步骤、日志、证据和最终结果 | 不作为用户需要额外创建或管理的第四层业务对象 |

### 2.2 计划、批次和任务的关系

**用户已确认：**

- 计划、批次、任务采用独立执行模型。
- 一个计划允许关联多个批次，也允许关联独立任务。
- 一个计划允许包含同平台多个批次。
- 一个批次只属于一个发布平台，但支持选择多个游戏。
- 一个批次确认创建时，批次内所有独立发布任务一起生成。
- 一条发布任务严格对应一个账号和一个视频。
- 同账号多条任务按账号维度串行；不同账号之间可以受控并发。

关系示意：

    发布计划 P
      ├── 百度批次 A
      │     ├── 账号 01 + 视频 01 → 任务
      │     ├── 账号 01 + 视频 02 → 任务
      │     └── 账号 02 + 视频 03 → 任务
      ├── 百度批次 B
      │     └── 多条独立任务
      ├── 小红书批次 C
      │     └── 多条独立任务
      └── 抖音独立任务 T

计划与批次不是互相排斥的入口：批次可以从计划中快捷创建，也可以在发布任务中独立创建。计划中的独立任务复用快速发布流程，不另造第二套任务表单。

### 2.3 创建与执行分离

**当前推荐的统一规则：创建不等于执行。** 创建时先形成业务对象和资源关系，启动时才开始真实发布。允许用户明确选择“创建并启动”，但不能因创建表单提交成功就静默执行。

| 操作 | 创建时发生什么 | 创建后默认状态 | 启动时发生什么 |
|---|---|---|---|
| 创建计划 | 保存资源规划、游戏范围、分发建议和执行顺序 | 规划中 | 计划启动后按顺序调度关联批次和独立任务 |
| 创建批次 | 创建批次、生成全部独立任务、取得视频占用 | 待执行 | 批次启动后启动所有符合条件的任务 |
| 快速发布 | 创建一条独立任务、取得视频占用 | 待执行 | 任务启动后创建一次执行尝试 |
| 重试任务 | 不创建新业务任务 | 原任务保持失败/可重试状态直至启动 | 对原任务新增执行尝试，保留任务 ID 和视频占用 |

建议入口：

- 计划：保存规划、启动计划。
- 批次：保存待执行、创建并启动、启动批次、暂停批次。
- 快速发布：创建待执行、创建并立即发布。
- 任务：立即执行、重试、取消、放弃并释放。

计划创建不自动创建批次和任务，也不占用视频。计划详情中由运营明确选择创建批次或独立任务；创建后关联回计划。

### 2.4 计划执行与独立启动冲突

**当前推荐的调度保护规则：**

1. 计划启动后，按用户设定的顺序调度批次和独立任务。
2. 计划层控制批次/任务之间的顺序；批次内部采用受控并发；同账号任务串行。
3. 已完成的计划项再次启动时自动跳过，不重复执行。
4. 如果计划中的批次已经独立启动且仍在执行，计划不能重复启动它；启动计划时提示等待该批次结束，或由用户先处理冲突。
5. 如果计划正在执行，用户要单独启动尚未轮到的批次，先暂停计划自动调度，再确认人工接管；当前已进入不可逆步骤的任务按安全节点完成，不强制中断。
6. 单独批次完成后，计划保持暂停；用户恢复计划时从第一个尚未完成的计划项继续。
7. 所有入口最终经过同一执行控制，避免计划、批次和任务重复启动同一任务。

这套冲突策略是当前推荐默认行为，Codex 应在原型中把冲突提示、暂停和恢复路径做出来，并在验收时重点验证。

### 2.5 视频占用、唯一性与任务身份

**用户已确认：**

- 同平台同一个视频不能重复发布/分配。
- 不同平台允许使用同一个视频。
- 正式创建批次或快速发布任务时才取得视频占用；仅保存计划和预览分配时不占用。
- 任务取消默认保留占用。
- 用户可以明确选择“放弃并释放”，原任务永久结束并解除占用。
- 账号不可在原任务上直接修改；需要放弃释放后创建新任务。

进一步实施约束：

- 任务的平台、账号和视频应视为任务身份。除账号不可直接变更这一已确认规则外，视频或平台变更也建议采用“放弃原任务并创建新任务”，避免执行历史和占用关系被覆盖。
- 创建批次时应再次检查同平台视频是否已被其他有效任务占用，避免规划快照过期或并发创建造成重复占用。
- 失败任务保留占用；确认未发布且执行尝试已安全结束后允许重试原任务。
- 取消任务保留占用；只有明确放弃并释放才能解除。
- 发布结果未知时禁止直接重试或释放，必须先核实平台是否已经生成作品。
- 已发布任务保留平台作品证据和唯一性记录，不允许普通重试或释放。
- 任务重试增加执行尝试记录，不增加第二条发布任务。

**推荐技术不变量：** 以“平台 ID + 视频 ID”作为活动占用唯一键；占用创建与任务创建放在同一事务或等价的原子操作中。释放必须有明确业务动作和审计记录。具体数据库实现由运行仓现有数据层决定，不在 Workspace 原型中伪造。

### 2.6 账号、游戏和视频质量分配

**用户已确认：**

- 账号有质量分层：优质号、普通号、新号。
- 视频有质量分层：优质、普通；普通视频不需要额外复杂分级。
- 优质视频优先分配给优质号；优质号不足时可以分配给普通号。
- 普通视频优先分配给普通号，剩余再分配给新号。
- 默认按账号顺序填满；运营人员可以调整账号顺序、数量和视频分配。
- 账号支持一个或多个游戏；这是账号经营规划的一部分。
- 视频素材记录所属游戏。

多游戏批次规则：

1. 批次先选择一个平台，再多选本次涉及的游戏。
2. 系统按所选游戏盘点可用账号、账号质量、可用视频和视频质量。
3. 一个账号即使支持多个所选游戏，在批次整体账号总数中也只能统计一次。
4. 分配具体任务时，视频所属游戏必须属于该账号支持的游戏范围。
5. 同一个账号可以承接其支持的多个游戏，但它的任务仍按账号串行执行。
6. 优质/普通质量匹配在游戏匹配范围内执行。
7. 资源不足时明确展示未分配视频或未满足的账号目标，不静默跨游戏分配。

分配顺序：

| 视频质量 | 默认分配顺序 |
|---|---|
| 优质视频 | 优质号优先；剩余给普通号 |
| 普通视频 | 普通号优先；剩余给新号 |

不增加复杂评分、收益预测、游戏相似度或自动调优系统。账号支持的游戏应复用现有账号分类/关联事实；实现前核验当前账号字段是否已能准确表达游戏关联，禁止平行创建第二套游戏关系。

### 2.7 计划的资源规划职责

计划不能只是批次列表或进度汇总。它在创建批次前先回答：

- 这次运营涉及哪些游戏？
- 每个游戏有多少可用视频，优质/普通视频分别多少？
- 每个平台有多少支持这些游戏的账号？
- 账号质量分布如何？
- 哪些游戏资源不足或账号覆盖不足？
- 优质视频应该优先分给哪些账号？
- 应该创建哪些平台批次，是否同平台拆成多个批次？
- 批次和独立任务按什么顺序执行？

计划中的资源数字是规划快照；正式创建批次或任务时必须重新检查真实可用性。计划保存不占用视频，不锁账号，不生成发布任务。

## 3. 发布管理页面与交互

### 3.1 发布任务：任务批次 / 任务列表

**用户已确认的页面结构：**

- 发布任务菜单下有两个 Tab：任务批次、任务列表。
- 右上角提供快速发布、批量发布。
- 批次列表按批次展示平台、游戏范围、账号数、任务数、成功/失败/待处理数量和状态。
- 任务列表按单条任务展示平台、账号、游戏、视频、状态、占用和操作。
- 批次详情展示批次总体进度、账号队列、任务执行状态、失败和待人工处理入口。
- 任务详情展示身份、发布内容、执行尝试、步骤证据、失败原因、重试/取消/放弃操作。

列表遵循状态与操作分离：状态列只显示当前状态，按钮放操作列。高频筛选优先放平台、游戏、批次状态、任务状态、账号和搜索；低频条件进入高级筛选。

### 3.2 快速发布

一条快速发布任务必须选择：

- 一个发布平台；
- 一个账号；
- 一个视频；
- 该视频所属游戏；
- 平台标题、封面、标签及必要的平台字段。

创建后是一条独立发布任务，视频取得该平台占用。默认待执行，允许明确选择创建并立即发布。不能在快速发布中选择多个账号或多个视频后生成隐式组合；多账号、多视频组合统一进入批量发布。

### 3.3 批量发布 / 批次创建

批次只选择一个平台，但可以选择多个游戏。推荐向导：

| 步骤 | 运营动作 | 系统行为 |
|---|---|---|
| 1. 平台与游戏范围 | 选择平台、批次名称、多个游戏 | 按所选游戏盘点账号和视频 |
| 2. 资源与分配 | 查看账号去重结果、质量分层、视频质量；调整账号顺序和每号数量 | 按游戏匹配、视频质量规则和账号顺序给出建议 |
| 3. 内容配置 | 集中配置标题、封面、标签和平台字段 | 批量套用平台规则，允许单条覆盖 |
| 4. 任务预览 | 按账号查看每条视频将生成的任务，处理冲突和未分配项 | 检查平台视频唯一性、账号游戏范围和内容完整性 |
| 5. 确认创建 | 保存待执行，或明确选择创建并启动 | 创建批次、生成所有任务、取得视频占用 |

不要把所有账号、视频、平台字段平铺成一张超长表单。先选择范围和资源，再按游戏/账号分组查看分配，内容配置以批量应用为主、异常作品逐条调整为辅。

### 3.4 平台内容配置

平台字段可能不同，内容配置必须使用平台适配规则，不要用一套字段强行覆盖所有平台。

核心内容：

- **标题**：素材标题作为参考；AI 轻量润色；批量采用正常结果；异常项单独处理。
- **封面**：采用本文件第 5、6 节的两种模式。
- **标签**：固定标签模板自动继承，批次统一调整，个别作品允许覆盖。
- **分区/分类/其他字段**：按平台显示，不适用的字段不展示。
- **素材参考信息**：素材库通常已包含来源平台、标题、封面、视频、标签等信息；通常只作参考，不做大幅改写。

内容配置建议采用“批次统一值 + 单条覆盖值 + 内容版本快照”。创建任务时保存当时的标题、封面、标签和平台字段，避免以后模板或标签模板变更影响历史任务。

### 3.5 执行中心与人机协同

**用户已确认：浏览器发布自动为主、人工兜底；批次内默认受控并发。**

执行原则：

- 有可用 API 时按平台能力使用 API；无 API 或 API 不适用时使用浏览器。
- 浏览器自动完成打开页面、填写内容、上传视频和可安全自动化的步骤。
- 需要人工登录、微调或最终提交时，保留当前浏览器会话和执行步骤，明确提示人工处理原因。
- 人工完成后回到原任务继续，不重新创建任务、不丢失已完成步骤。
- 同一账号多条任务串行；不同账号受控并发。
- 批次详情要能看见整体进度、账号队列、当前任务、待人工处理、失败任务和结果待确认。
- 失败展示可读原因、发生步骤、可执行动作和最近执行尝试；不要只展示“失败”。
- 计划/批次暂停停止后续调度，不强制中断已进入不可逆步骤的提交或结果核验。

计划执行按计划顺序调度关联批次和独立任务；批次内部受控并发。人工处理只影响对应任务/账号队列，除非计划调度本身需要暂停，不默认冻结整个系统。

### 3.6 发布与互动分离

发布任务只负责发布本身和发布结果。拿号评论、置顶、批量点赞、评论、收藏等属于互动工作流。

发布成功后可以把作品 ID / URL 和发布任务关联，提供“去互动管理”的后续入口，但互动任务有自己的批次/任务、重试、限流、状态和结果；不得把互动失败改写成发布失败，也不得在发布任务重试时重复触发互动。

### 3.7 任务状态与恢复规则

建议任务状态：

| 状态 | 含义 | 允许操作 |
|---|---|---|
| 待执行 | 已创建，尚未启动或等待计划调度 | 查看、启动、取消 |
| 排队中 | 已进入执行队列，等待账号/并发槽位 | 查看、按安全条件取消 |
| 执行中 | 浏览器/API 正在处理，包含上传、填写、提交和自动核验 | 查看进度；不能重复启动 |
| 等待人工 | 登录、页面微调、人工最终提交或人工核验 | 按原因打开对应窗口并继续 |
| 结果待确认 | 已提交但平台结果不明确 | 只能核实，不允许重试或释放 |
| 执行失败 | 已确认本次未发布且执行尝试结束 | 安全重试原任务，或取消/放弃 |
| 已取消 | 用户取消，视频占用默认保留 | 仅在确认未提交、无未知结果时恢复原任务 |
| 已成功 | 平台已确认发布，保留作品证据 | 查看作品；不可普通重试或释放 |
| 已放弃 | 用户明确放弃并释放视频 | 只读查看历史，不可恢复原任务 |

取消和放弃的关键区别：

- 取消默认保留视频占用；原任务记录和执行历史保留。
- 放弃并释放是显式、不可逆动作；原任务永久结束，视频可以重新分配。
- 结果未知时不能通过取消或放弃绕过核验；先确认平台是否已经发布。
- 账号变更需要放弃原任务并创建新任务；不得直接改写原任务身份。
- 重试必须复用原任务 ID，新增执行尝试记录。

批次和计划状态从真实下级对象汇总。已结束不等于全部成功；必须分别展示成功、失败、取消、放弃和结果待确认数量。

## 4. 图片库设计

### 4.1 图片库定位

图片库是统一的图片资源池，不拆成“AI 封面库”和“自由图片库”。所有图片由人工整理并上传；AI 生成图片可以提前批量生成，再由人工上传到同一个图片库。

图片来源与使用方式：

1. 素材自身已有封面：发布封面配置时可直接使用。
2. 图片库图片：作为现成封面，或作为封面底图。
3. 完全 AI 生成的图片：提前生成并上传图片库，发布时作为现成封面或底图使用。
4. 视频关键帧提取：当前不做。
5. 发布时实时 AI 生成底图：当前不做。

### 4.2 图片数据属性

图片管理采用列表。必需字段和推荐字段：

| 字段 | 规则 | 说明 |
|---|---|---|
| 图片名称 | 必填 | 可搜索、可重命名 |
| 图片用途 | 必填 | 现成封面 / 封面底图 |
| 内容类目 | 必填或默认通用 | 游戏 / 通用 / 其他，支持未来扩展 |
| 具体游戏 | 可选 | 游戏 A、游戏 B 等；通用图片不绑定具体游戏 |
| 图片预览 | 系统生成 | 小尺寸缩略图 |
| 宽、高 | 系统自动读取 | 像素尺寸 |
| 宽高比 | 系统自动计算 | 16:9、3:4 等 |
| 文件格式、大小 | 系统自动读取 | PNG/JPEG/WebP 等 |
| 状态 | 必填 | 启用 / 停用 |
| 引用次数 | 系统统计 | 帮助判断是否仍在被使用 |
| 上传人、上传时间 | 系统记录 | 审计和管理 |
| 备注/标签 | 可选 | 不作为复杂检索系统的前置条件 |

图片来源可以作为可选元数据（人工上传、AI 预生成等），但不新增独立图片库或来源管理模块。

### 4.3 图片库列表交互

列表字段建议：

预览｜图片名称｜用途｜内容类目/具体游戏｜尺寸/比例｜状态｜引用次数｜更新时间｜操作

高频筛选：

- 搜索图片名称；
- 图片用途；
- 内容类目；
- 具体游戏；
- 启用/停用。

主要操作：

- 批量上传；
- 单条编辑；
- 批量修改用途/类目/游戏；
- 批量启用/停用；
- 查看详情和引用情况；
- 删除未被引用的图片。

已被正式任务或模板版本引用的图片不能直接物理删除。允许停用，停用后不再进入新的随机选择；历史任务仍能查看当时引用的图片版本。

管理页使用列表；发布配置中的选图弹窗使用缩略图浏览。不要让运营在列表管理页逐张打开图片，也不要把图片选择弹窗做成密集元数据表格。

### 4.4 随机底图规则

用户已确认随机选择即可，不需要复杂 AI 语义匹配。

推荐顺序：

1. 先按用途筛选为“封面底图”。
2. 再按内容类目筛选。
3. 有具体游戏时，优先选择该游戏的启用图片。
4. 对应游戏没有可用图片时，允许回退到“通用”类目。
5. 从符合条件的启用图片中随机选择一张。
6. 如果仍无可用图片，提示运营补充资源或改用素材封面，不要静默选错游戏。

随机选择应可重新抽取；批次确认生成任务后，需要把最终选中的图片 ID 和版本快照保存到任务内容中，不能每次查看都重新随机。

## 5. 封面模板库与模板编辑器

### 5.1 模板定位

模板不是一张不能编辑的固定图片，而是一套可重复使用的设计结构：

    背景图片占位 + 动态文字区域 + 固定装饰/Logo
      → 替换底图
      → 填入 AI 短标题
      → 按约束自动排版
      → 导出封面图片

模板的核心是画布尺寸、版式、对象位置、文字区域和文字样式。

**用户已确认：**

- 模板可以设置文字位置、区域、坐标和字体。
- 模板不强制绑定平台和内容类目。
- 平台和类目可以作为可选适用属性或推荐标签。
- 画布比例和实际宽高是模板的核心规格。
- 第一版不做复杂自由设计软件，保持小而美。

### 5.2 画布规格

建议内置常用画布预设：

| 类型 | 比例 | 默认示例尺寸 | 说明 |
|---|---|---|---|
| 横版 | 16:9 | 1920 × 1080 | 常见横向视频封面 |
| 竖版 | 9:16 | 1080 × 1920 | 竖向短视频封面 |
| 竖版 | 3:4 | 1080 × 1440 | 笔记/海报式封面 |
| 方形 | 1:1 | 1080 × 1080 | 方形内容展示 |

尺寸是默认预设，不是对所有平台规格的永久承诺。自定义尺寸可作为后续能力；第一版优先覆盖已确认的比例。

模板不强制绑定平台。平台输出适配单独负责目标平台支持的尺寸、格式、文件大小和安全区域。模板比例与平台要求不兼容时，应提示选择兼容模板或明确裁切适配方案，不得直接拉伸变形。

### 5.3 模板对象与图层

第一版只支持三类对象：

| 对象类型 | 作用 | 关键属性 |
|---|---|---|
| 背景图片 | 被素材封面或图片库图片替换 | 图片占位、填充方式、裁切/定位 |
| 动态文字区域 | 接收 AI 生成的短标题/副标题 | 文字槽位、坐标、尺寸、字体、排版约束 |
| 固定装饰 | Logo、栏目名、固定图形/色块 | 文字或图片内容、坐标、尺寸、样式、锁定 |

动态文字槽位建议：

- main_title：主标题，AI 短标题主要写入位置。
- sub_title：副标题，可选。
- fixed_text：固定文字，不随作品变化。

每个对象需要稳定的对象 ID，方便保存、编辑和批量填充。固定装饰可以锁定，防止运营误拖动。

### 5.4 文字区域可控属性

**位置和区域：**

| 属性 | 说明 |
|---|---|
| X | 左侧坐标 |
| Y | 顶部坐标 |
| W | 文字区域宽度 |
| H | 文字区域高度 |
| 对齐 | 左对齐 / 居中 / 右对齐 |
| 安全区域 | 文字不应进入的边缘区域或平台遮挡区域 |

画布上支持拖动和拖拽控制点调整大小；右侧属性面板支持精确输入 X、Y、W、H。画布坐标显示为实际像素值，内部存储可使用相对画布的归一化坐标，以保证同一比例不同输出分辨率下布局一致。

**字体与样式：**

- 字体家族；
- 字号；
- 最小字号；
- 字重；
- 字体颜色；
- 行高；
- 字间距；
- 对齐；
- 描边开关及参数；
- 阴影开关及参数；
- 副标题开关；
- Logo/固定装饰显示与锁定。

**文字约束：**

- 最大字数；
- 最大行数；
- 自动换行；
- 自动缩小字号；
- 最小可读字号；
- 溢出检测。

自动适配规则：先按模板字号排版；超出文字区域时自动缩小，但不得低于最小字号；仍然超出时显示异常，要求 AI 重新润色或人工修改。不得静默裁掉文字或缩到不可读。

### 5.5 模板编辑器页面布局

推荐三栏结构：

1. 左栏：模板列表、图层列表。
2. 中栏：设计画布、缩放、标尺/参考线（按实现成本选择）、选中对象边框和拖拽控制点。
3. 右栏：对象属性面板，按所选对象显示坐标、宽高、字体和约束。

主要交互：

- 点击图层选择对象；
- 画布拖动对象调整位置；
- 拖动控制点调整区域尺寸；
- 在属性面板直接输入 X/Y/W/H；
- 添加或删除动态文字区域；
- 显示/隐藏和锁定/解锁图层；
- 替换背景图片；
- 修改字体、字号、颜色、描边、阴影；
- 修改最大字数、最大行数和自动适配；
- 输入测试标题预览效果；
- 保存模板、复制模板、预览模板；
- 使用多个示例标题进行批量效果预览。

### 5.6 模板列表管理

模板库采用列表，不以大卡片墙作为主要管理方式。

列表字段：

预览｜模板名称｜画布比例/尺寸｜版式｜字体/主标题样式｜内容类目（可选）｜适用平台（可选）｜状态/引用次数｜操作

操作：

- 新建模板；
- 编辑；
- 复制；
- 预览；
- 设置默认模板；
- 启用/停用；
- 查看引用情况。

平台和类目只是可选的适用范围或推荐属性。兼容判断以画布尺寸、比例、安全区域和输出要求为准。相同设计结构可以跨平台复用，不为每个平台复制一份相同模板。

默认模板建议按画布规格/比例维护；类目和平台可用于推荐，不强制形成“每平台 × 每类目 × 每比例”的模板矩阵。

### 5.7 模板数据结构建议

模板保存为版本化的设计 JSON，而不是只保存固定表单字段。示意：

    {
      "schemaVersion": 1,
      "name": "游戏横版大标题",
      "canvas": {
        "width": 1920,
        "height": 1080,
        "ratio": "16:9"
      },
      "layers": [
        {
          "id": "background",
          "type": "image",
          "role": "replaceable_background",
          "fit": "cover"
        },
        {
          "id": "main-title",
          "type": "text",
          "slot": "main_title",
          "x": 0.06,
          "y": 0.68,
          "width": 0.84,
          "height": 0.22,
          "style": {
            "fontFamily": "Source Han Sans",
            "fontSize": 64,
            "minFontSize": 42,
            "fontWeight": "bold",
            "color": "#FFFFFF",
            "align": "left",
            "lineHeight": 1.05,
            "stroke": true,
            "shadow": true
          },
          "constraints": {
            "maxChars": 18,
            "maxLines": 2,
            "autoFit": true
          }
        }
      ]
    }

上例中的坐标为归一化比例，编辑器显示时转换成像素。正式字段命名和结构应在实现前结合 Fabric.js 对象模型与现有项目编码规范确定，不要把示意 JSON 当作已经批准的 API Contract。

模板被任务引用后应保存模板版本快照。模板后续修改不改变历史任务已生成封面的布局、文字或资源引用。

### 5.8 第一版明确不做

- 完整 Canva / Photoshop；
- 自由画笔和复杂矢量绘制；
- PSD 导入与编辑；
- 动画和视频封面动效；
- 复杂滤镜、蒙版和专业图层混合；
- 复杂插件系统；
- 任意无限画布；
- 发布时实时 AI 生成整张图片；
- 视频关键帧提取。

第一版只把图片、文字、固定装饰、坐标、尺寸、字体和排版约束做可靠。

## 6. 发布内容如何使用图片库和模板库

### 6.1 两种封面模式

**模式一：使用现成封面**

- 从图片库筛选“现成封面”。
- 按内容类目、具体游戏和比例筛选。
- 选择一张后作为当前视频封面。
- 不叠加模板文字，除非运营明确切换到模式二。

**模式二：底图 + AI 短标题 + 模板**

底图来源：

1. 优先使用素材自带封面。
2. 素材封面不适用或缺失时，从图片库符合条件的“封面底图”中随机选择。
3. 完全 AI 生成的底图需提前生成并上传图片库；发布过程中不实时生图。

生成流程：

    视频素材
      → 读取所属游戏和素材封面
      → 选择底图（素材封面优先 / 图片库随机）
      → AI 生成或润色短标题
      → 选择匹配画布比例的模板
      → 将主标题/副标题填入动态文字槽位
      → 自动换行与字号适配
      → 溢出检查
      → 生成封面预览
      → 人工检查异常项
      → 保存封面版本并关联发布任务

AI 负责短标题内容，不负责实时生成整张图片。模板负责布局、字体和文字样式；图片库负责提供底图或现成封面。

### 6.2 批次中的集中配置

- 批次先确定平台和多个游戏，再进行资源分配。
- 标题按视频批量润色，正常结果批量采用，异常结果逐条处理。
- 封面按视频游戏和目标画布比例推荐模板。
- 同一批次不同游戏可以使用不同模板。
- 固定标签模板按平台继承，批次统一调整，单条可覆盖。
- 单条内容的标题、封面和标签允许覆盖批次默认值。
- 创建任务时保存内容和封面版本快照，避免后续修改影响历史发布。

### 7.3 技术方案推荐

**当前推荐：Fabric.js 作为画布引擎，参考 Vue Fabric Editor 的属性面板和对象管理交互；使用项目现有 Vue/TDesign 体系实现业务界面。**

理由：

- Fabric.js 是 MIT 许可，且直接解决图片、文字对象、坐标、缩放、换行和导出。
- Vue Fabric Editor 已经有接近需求的属性组件，可以参考其交互或复用明确 MIT 范围的实现。
- H5 Editor 只借鉴标尺/吸附等交互，不引入旧 Vue 技术栈。
- tldraw 等通用无限画布产品不适合这个固定画布、批量替换文字和底图的场景，也不作为第一版基础。

正式实现前仍需验证：
- Cloud Web 当前 Vue、Fabric.js 版本兼容性和构建方式；
- 字体文件授权、字体在预览和最终导出环境中的一致性；
- Fabric.js 对象 JSON 的版本迁移和向后兼容；
- 批量封面生成由浏览器、Cloud Worker 还是 Agent 执行更可靠；
- 是否能让编辑预览和最终导出共用同一套布局/字体测量逻辑。

不要在编辑器和后台批量导出中各写一套文字换行和字号计算规则，否则预览与最终封面会出现偏差。正式渲染位置应基于现有 Cloud/Agent 资源存储、队列和本地执行边界做技术验证后再定。

## 8. Codex 完整执行计划

### 8.1 总体交付目标

在不大面积重做发布管理的前提下，完成：

1. 发布计划/批次/任务模型与现有原型差异核验；
2. 图片库列表和图片选择器；
3. 可编辑的封面模板库与轻量模板编辑器；

### 8.3 Phase 1：原型信息架构和数据模型对齐

先做最小差异调整：

- 保留发布任务菜单和任务批次/任务列表两个 Tab。
- 保留快速发布、批量发布入口。
- 保留发布计划独立菜单和资源规划职责。
- 保留当前可用的发布列表、内容编辑、执行队列、任务详情和异常操作。
- 增加批次的多游戏选择和资源盘点。
- 计划详情展示游戏资源规划、分发建议、关联批次/任务和执行顺序。
- 批次确认创建时生成任务；快速发布确认创建时生成单条任务。
- 执行尝试只在实际启动/重试时创建。
- 计划、批次和任务使用统一任务执行控制，防止重复启动。

### 8.4 Phase 2：图片库原型

实现独立图片库页面和可复用图片选择器：

1. 列表管理，不以卡片网格作为管理主视图。
2. 支持批量上传本地图片预览；原型必须明确标注不上传真实服务器。
3. 上传时设置用途、内容类目和可选具体游戏。
4. 自动展示宽、高、比例、格式和文件大小。
5. 支持搜索、用途/类目/游戏/状态筛选。
6. 支持多选、批量修改属性、批量启用/停用。
7. 支持单张详情侧栏和编辑。
8. 引用次数大于零的图片禁止直接删除，允许停用。
9. 在发布封面选择器中提供缩略图浏览，复用同一套图片数据和筛选条件。
10. 实现随机底图演示：用途过滤 → 类目/游戏匹配 → 通用回退 → 启用资源随机选择。

图片库不新增文件夹系统，除非真实运营资料证明现有类目/游戏筛选不足。

### 8.5 Phase 3：封面模板库与编辑器原型

先完成列表，再完成编辑器。

**模板列表：**

- 模板名称、预览、画布比例/尺寸、版式、主标题字体摘要、可选类目、可选适用平台、状态、引用次数。
- 支持搜索、比例筛选、类目筛选。
- 支持新建、编辑、复制、预览、设默认、启停。

**模板编辑器：**

- 三栏：图层/模板列表、中心画布、右侧属性。
- 背景图对象可替换。
- 文字对象可新增、选择、移动、缩放和删除。
- 精确编辑 X/Y/W/H。
- 字体、字号、最小字号、字重、颜色、行高、对齐、描边和阴影。
- 设置动态槽位、最大字数、最大行数和自动适配。
- 固定装饰/Logo 可锁定。
- 支持预览标题替换、长标题溢出检查和多标题批量预览。
- 模板保存为版本化 JSON；重新打开后对象、位置、样式和动态槽位必须恢复。
- 坐标在 UI 中显示像素值，存储方式可采用归一化坐标；同一比例缩放时位置比例保持一致。

不要只做“修改字号/颜色”的表单，而没有画布对象移动和区域缩放。没有可控位置和区域，模板就失去本次要解决的核心价值。

### 8.6 Phase 4：批次创建与封面流程集成

批次创建最少增加：

- 单平台选择；
- 多游戏选择；
- 按游戏资源统计；
- 跨游戏账号去重；
- 账号支持游戏范围检查；
- 优质/普通/新号分配；
- 优质/普通视频质量分配；
- 按账号顺序填满；
- 允许人工调整；
- 创建前重复占用检查。

内容配置集成：

- 标题批量润色和异常项处理；
- 两种封面模式；
- 图片库缩略图选择器；
- 按比例和类目推荐模板；
- 多游戏使用不同模板；
- 固定标签模板；
- 单条内容覆盖；
- 任务创建时保存内容、模板和图片版本快照。

多游戏资源统计必须避免账号重复计数；具体任务必须验证账号支持该视频所属游戏。一个账号支持多个游戏时可承担多个游戏任务，但同账号任务保持串行。

### 8.7 Phase 5：原型行为与异常验证

至少覆盖以下场景：

**场景 A：多游戏混合发布**

- 百度有 50 个账号：10 个优质号、20 个普通号、20 个新号。
- 小红书有 30 个账号。
- 账号可能同时支持多个游戏。
- 视频属于不同游戏，质量有优质/普通。
- 同一个视频可以跨平台使用，但不能在同平台重复分配。
- 计划应先盘点资源，再建议创建百度/小红书等批次。
- 同一个账号统计去重，但其支持范围内的多个游戏任务可以串行执行。

**场景 B：只有百度**

- 同一组账号和多个游戏视频。
- 创建一个百度批次或根据运营安排拆成多个百度批次。
- 查看分配顺序、任务数量和批次执行情况。

**场景 C：五个账号、十个视频**

- 按账号顺序填满。
- 每条任务对应一个账号和一个视频。
- 同账号多条连续执行，不要把同账号多条压成一个任务。
- 人工可以调整顺序和数量。

**场景 D：计划与独立启动**

- 计划创建不创建任务。
- 批次创建生成全部任务但默认不自动执行。
- 计划启动按顺序触发批次/任务。
- 单独启动批次不会重复启动计划。
- 计划执行期间越序启动需要暂停计划并确认接管。
- 已完成计划项跳过，正在独立执行的项目不重复启动。

**场景 E：视频占用和异常**

- 同平台同视频重复创建被阻止。
- 失败任务安全重试原任务。
- 取消保留视频占用。
- 放弃并释放后允许重新分配。
- 结果未知时禁止重试和释放，必须先核实。
- 账号变更需放弃原任务并创建新任务。

**场景 F：封面批量生产**

- 直接选现成封面。
- 素材封面 + AI 短标题 + 模板。
- 图片库随机底图 + AI 短标题 + 模板。
- AI 预生成底图提前上传图片库。
- 长标题自动换行/缩字号；仍溢出时提示异常。
- 同一模板批量替换不同标题和底图后，预览与导出布局一致。

### 8.8 Phase 6：真实运行时实现的前置路径

Workspace 只维护系统级产品/架构/Contract/Delivery 和离线原型，不承载运行时代码。

原型经用户评审后，若进入真实系统：

1. 从 config/repository-map.yaml 读取 Cloud、Agent、Desktop 仓库路径。
2. 读取各目标仓 AGENT-INDEX.md、CLAUDE.md 和相关目录映射。
3. 根据实际 Ownership 确认：
   - Cloud：业务数据、权限、任务/批次/计划、图片和模板元数据、API、资源存储/队列；
   - Agent：本机浏览器、账号会话、平台页面操作及可能的本地文件/渲染执行；
   - Desktop：系统桥、文件选择/访问、Agent 生命周期等确实需要的桌面能力。
4. 不根据页面名称机械分仓；必须沿用现有对象存储、文件服务、账号/游戏关联、任务调度和审计机制。
5. 如果涉及中大型功能、跨仓、Architecture 或 Contract，建立 CHG 并按 AGENT-INDEX 流程执行；单仓小改动不强制创建 CHG。
6. 真实数据模型和 API 先完成设计评审，再实施；Workspace 原型的本地对象不等于正式 API Contract。
7. 图片上传、模板版本、渲染结果和任务内容快照必须有稳定引用；历史任务不能被模板更新或图片停用破坏。
8. 真实浏览器/API 发布必须有执行尝试、幂等保护、结果核验和审计证据；本地原型模拟不作为真实验收。

## 9. 尚需实现前核验的事项

以下不阻塞离线原型，但进入真实实现前必须根据证据收敛：

| 事项 | 当前建议 | 核验责任 |
|---|---|---|
| 平台能力矩阵 | 以正式支持的平台和真实账号适配为准，不按示例自动扩展 | Cloud/Agent 现有适配与产品确认 |
| 账号支持游戏 | 复用现有 category_ids/分类事实；若不能表达多游戏，再设计最小扩展 | 账号模型与账号管理产品事实 |
| 批次创建冲突 | 默认创建前完整校验并展示冲突，不静默部分创建 | 产品/Cloud 事务设计 |
| 创建后是否立即执行 | 默认仅创建待执行；“创建并启动”必须由用户明确选择 | 原型验收确认 |
| 计划越序启动 | 暂停计划并明确人工接管，避免两个调度器竞争 | 原型验收和执行调度验证 |
| 取消后恢复 | 只有未提交且结果明确的任务可以恢复；未知结果先核实 | 执行状态机和平台证据 |
| 封面导出规格 | 按真实平台核验比例、尺寸、格式、文件大小和安全区域 | 平台适配 |
| 字体许可 | 只提供已获许可的字体，导出环境确保字体一致 | 前端/设计资产管理 |
| 最终渲染位置 | 编辑预览和批量导出必须共用一致的布局/字体测量规则；选择浏览器、Cloud Worker 或 Agent 前先做技术验证 | Cloud/Agent 架构 |
| 图片存储和历史版本 | 复用现有文件/对象存储能力，不新建平行文件系统 | Cloud 资源工程设计 |

完成原型评审后，将用户确认的规则和仍未决的事项分别回写正式事实源；不要把所有待核验项直接升级为产品承诺。
