# 发布管理：任务、批次、计划及内容生产交互设计基线

> 更新日期：2026-11-10  
> 性质：当前产品与交互设计工作稿、GPT Work 产品 Review 和后续原型实施唯一交接入口；不是已验收原型、正式 PRD、运行时接口契约或 Delivery 状态。  
> 当前结论：计划负责资源盘点、投放目标、按平台拆批和整体调度；批次严格单平台，分目标/资源配置、内容配置、执行监控三阶段；任务负责单条发布、执行尝试与结果证据。计划首次启动后结构锁定；批次/任务在安全条件下局部处理。  
> 评审与实现状态：本文件完成设计收敛，**不代表现有原型已经实现或通过验收**。前轮多平台批次、将内容配置塞入计划、取消后恢复原任务及历史自评分均已退出当前设计基线。

## 0. 使用约定、事实来源与决策等级

- **已确认**：用户在协作中明确确定的产品关系、边界或操作结果，作为后续设计与原型约束。
- **推荐实现**：为使已确认目标真正可操作而补充的具体交互、字段或局部约束。GPT Work 第一轮 Review 应客观检查其合理性，不能把推荐伪称为用户决策。
- **待平台或代码核验**：平台字段、容量、自动发布能力、图片输出规格、真实后端支持等；页面观察不代表业务运行时已实现。
- **产品/设计事实源**：本文件承接当前未回写的产品交互结论；稳定规则经用户 Review 后由正式 Product Owner 回写既有 PRD。原型源码只在 Cloud 的 web/example/ 下维护，Workspace 不复制运行时代码。
- 必须遵守 [前端规范](../standards/frontend/README.md)、[AdminUI 页面规范](../standards/frontend/AdminUI页面规范.md)、[前端交互规范](../standards/frontend/前端交互规范.md)及 Cloud 公共组件能力。原型验证不代表真实发布平台联通。
- 本文直接描述**当前唯一有效方案**，不按旧稿章节号裁定优先级；旧建议、实施轮次和“96 分”等历史记录通过 Git 历史追溯，不继续混入正文。
- 本轮主要目标是高质量产品原型与交互闭环，不授权正式平台提交、后端部署、实际账号操作、发布或批量互动。

## 1. 业务对象、创建语义与关键不变量

### 1.1 三层业务对象（已确认）

| 层级 | 核心粒度 | 主要职责 | 明确不负责 |
|---|---|---|---|
| 发布计划 | 一次跨平台运营目标及其有序的批次集合 | 盘点资源、定义平台 × 类目目标、按平台拆成批次、整体进度、决定是否推进下一批 | 具体账号/成片配对、标题/封面编辑、任务重试与人工发布 |
| 发布批次 | **一个发布平台**下的一个或多个类目、多个账号/成片的任务集合 | 继承或自行确定各类目目标；选账号与成片、分配任务、批量内容配置、执行监控和异常处理 | 代替计划跨平台拆批或直接更改其他批次 |
| 发布任务 | **一个平台 + 一个类目 + 一个账号 + 一个成片** | 一次独立发布的内容快照、状态、尝试记录、平台证据、最终结果 | 一任务发多个账号/视频、把互动失败算作发布失败 |

执行尝试仅是任务下的一条历史记录；不新建第四层用户管理对象。发布后的点赞/评论/收藏属于互动管理，可关联作品但不混入发布状态机。

**统一结构**：一个计划含多个平台分组，组内含多个**单平台**批次；同一计划允许同平台多个批次。平台分组只是展示/排序分区，不是持久化的新业务对象。计划外的独立批次和快速发布任务合法。

### 1.2 计划确认、批次正式创建和任务创建不能混淆

| 用户动作 | 产生什么 | 不产生什么 | 占用成片 |
|---|---|---|---|
| 保存计划草稿 | 可继续编辑的计划草稿及其未确认的拆批方案 | 正式批次、正式发布任务 | 否 |
| **确认计划并生成批次** | 计划及 N 个带平台、类目分目标、执行顺序的**轻量批次骨架**（待资源配置） | 账号/成片映射、内容快照、正式任务 | 否 |
| 手动新建批次保存草稿 | 一个无计划关联的批次骨架，目标由用户输入 | 发布任务 | 否 |
| 批次阶段 1 / 2 保存 | 资源分配候选、内容候选与封面草稿 | 正式任务、执行尝试 | 否 |
| **批次最终确认** | 正式批次及其独立发布任务；保存已核对的内容/封面快照 | 自动执行发布 | **是，原子占用** |
| 快速发布确认创建 | 一条正式独立任务 | 批次、计划 | **是，原子占用** |
| 启动任务/批次/计划 | 调度符合条件的既有任务，产生真实执行尝试 | 新建同内容的新任务 | 保持原占用 |

统一原则：**创建不等于执行**。计划先生成轻量批次骨架，待批次资源和内容配置完成时才产生正式任务。批次进入第三阶段“执行工作台”时初始是待执行；需明确启动，或在计划调度到该就绪批次时按已授权调度启动。不得把“确认创建批次”误做成“正式上传发布”。

### 1.3 视频唯一性、任务身份与释放

- 同平台同一个**发布成片 ID**只允许一个有效发布任务；不同平台允许使用同一成片。按“平台 ID + 成片 ID”检查占用，不是按封面、标题或原素材 ID。
- 计划盘点、批次骨架和候选分配只计算可用性，不占用；正式创建任务时再次核验并原子占用，防止计划和草稿快照过期。
- 正式任务的平台、账号、成片与类目属于身份字段；变更身份须对旧任务执行合法终止/释放流程，再复制配置创建新任务，不能覆盖原执行历史。
- **取消任务保留占用，取消后不允许恢复原任务**；确认可安全释放时可明确“放弃并释放”，永久终结旧任务，再复制历史内容配置创建新任务。
- 结果未知、已接收/审核中或已发布不可释放/重发；确认未发布且执行尝试已安全结束才能在**原任务**上安全重试，重试只新增尝试记录。已发布任务和作品身份长期保留审计证据。

### 1.4 账号、类目、质量与容量约束

- 账号质量：优质号、普通号、新号。成片质量：优质、普通。优质成片优先优质号，剩余给普通号；普通成片优先普通号，剩余给新号。
- 默认按运营设定的账号顺序逐号填充，用户可调整账号顺序、每号本批次任务数和具体成片对应关系。
- 账号必须属于当前批次平台且支持所分配成片的类目；多类目账号跨类目去重统计，同账号任务串行、不同账号受控并发。
- **每号本批次计划数量 ≠ 该账号每天可发布额度**。只有真实账号容量配置明确时才计算/扣除当日剩余容量；否则展示未知/待核实，不假设每天发几条。
- 资源较少的类目可优先保留匹配账号作为系统分配建议，不强迫改变用户已确定的账号顺序；未满足分配量的原因明确展示。
- 同平台不同批次共用占用与容量校验，不能靠分批突破唯一性。同成片跨平台复用时资源总数去重，任务目标按平台分别计数。

## 2. 发布计划——资源盘点、规划拆批与整体调度

### 2.1 计划创建的四步流程（已确认方向）

**第 1 步：资源盘点（先看可用事实，再决定数量）**

首屏必须回答：
1. 每个平台账号总量、可用账号量、优质/普通/新号数量、支持类目的覆盖、失效/待登录数量。
2. 各平台**今天已公开发布任务条数**、涉及的去重账号数；已提交审核中与公开成功分开，今日已分配未发布的任务另列，不能混入“已发布”。
3. 若账号当日额度有真实配置，展示今天已用/已安排/剩余可执行量；无配置时显示“容量待核实”，不要捏造数字。
4. 每个类目全部成片、优质/普通成片、已占用/可安排成片；按平台 × 类目展示该平台仍可用的独立成片候选和预计可安排任务量。
5. 预计可安排任务数考虑成片同平台唯一性、账号平台/类目资格、账号已占用或可用容量；不能拿账号数 × 视频数作为自动任务总量。多类目共享账号造成重叠时需在分配算法中去重，并说明估算口径。
6. 展示刷新时间、资源不足原因和通往成片/账号管理的入口；资源读取失败不能显示为零。

此屏是**资源评估**，不是实际占用。展示的是事实和带口径的估计数，不能把计划数量视为今天可立即发布数量。

**第 2 步：平台 × 类目目标规划**

- 选本次涉及的平台、类目；用矩阵填写每一平台/类目的目标发布任务数，非负整数。
- 行列自动合计，总计划目标从矩阵计算，**不再独立填写可能冲突的总数**。
- 展示资源足够/风险/缺口及已分配、待分配；平台“已发布/可安排”的口径独立于目标。
- 允许目标先超过当前估算容量作为规划愿望，但保存/确认时需明确展示不足及风险，不得静默假装全部可落实。目标不是硬承诺今日完成的数量。

**第 3 步：按平台分组拆分具体批次**

- 计划创建时必须确定**创建几个批次、每批次哪个平台、包含哪些类目、各类目各多少任务、组内执行顺序**，不是只保存一个大目标再让批次重新规划。
- 页面按平台分组：百度组下百度 A、百度 B；小红书组下小红书 A；B站组下 B站 A。**不允许百度 A → 小红书 A → 百度 B 这样的混排主列表**。
- 每个批次只能有一个平台，但可含多个类目及每类目标数。支持添加/删除/复制批次、调整平台组顺序、调整组内批次顺序；不能从同平台组拖成混合平台批次。
- 逐格校验：同平台同类目各批次目标合计 = 第 2 步该组合的目标数；平台目标与批次分配量不一致时定位差额，禁止直接确认创建。
- 用户可以根据运营意图按账号质量、发布波次、类目等拆成多个批次；系统可建议拆分，但不自动强加固定“优质号批次”概念。

**第 4 步：确认计划并创建轻量批次**

- 预览：计划名称/说明/周期（可选）、目标矩阵、平台分组、批次名称/平台/类目分目标/执行顺序、资源风险和数量校验结果。
- 操作：保存草稿（不正式创建批次）；确认计划并生成全部批次骨架（批次进入待资源配置）。
- **批次骨架含 planId、batchId、platform、各类目 targetCount、groupOrder、batchOrder、batchName 和备注**；绝不生成任务、锁账号、占视频或执行。
- 创建后进入**计划详情/调度工作台**；每个批次提供“去资源配置”“去内容配置”“进入执行工作台”等符合阶段的快捷入口。

### 2.2 计划编辑与首次启动后锁定

**用户明确确认：计划一旦进入首次执行，之后不可编辑，即使暂停也不可重新编辑。**

| 阶段 | 可以操作 | 不允许 |
|---|---|---|
| 草稿 | 修改平台、类目、目标矩阵、分批方案、平台组顺序，保存/删除草稿 | 直接派发发布任务 |
| 已确认、尚未首次启动 | 调整计划目标与批次骨架、顺序，前提是校验对已有批次草稿的影响并明确确认；启动、取消计划 | 静默删除已配置草稿或覆盖已生成的正式任务 |
| **首次启动之后的执行中** | 查看进度、逐批快捷进入、暂停/取消计划、人工决定下一批 | 修改计划平台、类目、目标、批次数量、顺序或已确认目标 |
| 已暂停（已首次启动） | 恢复调度、取消计划、进入批次处理 | 以“暂停”为理由重新解锁计划结构 |
| 调度已结束 / 已取消 | 查看历史与最终结果，跳转批次 | 编辑、重新开始已取消计划 |

计划启动锁定的是**计划目标与批次骨架**，并不阻止后续尚未执行批次进入各自工作台补齐账号、成片与内容；这些批次从计划继承的平台、类目和目标数量仍锁定。计划启动前如果批次已有候选配置或正式任务，编辑需做受影响校验和显式提示；无安全方案时不允许直接修改该部分计划。

### 2.3 计划执行工作台——只管整体与衔接决策

**主屏只回答**：计划整体完成度多少、共几个批次、当前到哪批、各批次当前处于什么阶段、是否需要我确认进入下一批、整体最终结束/暂停/取消与目标达成情况。

建议页面区域：
1. **计划摘要**：名称、计划号、涉及平台与类目、执行状态、开始/截止日期（若配置）、只读失败率阈值 10%。
2. **整体 KPI**：目标任务数、正式已创建任务数、已公开发布数、目标完成率、批次总数/已处理数、当前第几批；审核中单独可见，不能算作已发布。
3. **平台分组批次列表/顺序面板**：按平台组排列，组内按计划顺序，每批次显示批次名、平台、类目目标摘要、目标数、创建任务数、已发布数、配置进度/执行状态、简洁异常提示和**一个直接操作入口**。允许查看组的目标与进度，不在此展开任务表。
4. **当前调度卡片**：当前批次、是否可衔接、为何停住、下一批准备状态和可执行的计划级决策。
5. **次级统计视图**：总览、按平台、按类目、平台 × 类目，复用同一个目标矩阵与任务结果聚合；不在计划主屏复制批次失败明细或任务重试操作。

计划中的“异常”只需说明“当前批次等待处理/无法衔接”，点击进入**批次工作台**；不在计划上直接编辑标题、重试失败任务、核实平台作品、处理账号登录。计划的快捷入口根据批次阶段显示“配置资源 / 配置内容 / 进入执行 / 查看结果”。

### 2.4 按平台分组后的调度次序

- 平台组之间有明确顺序；一个平台组中有多批次顺序。**计划顺序 = 平台组顺序 + 组内批次顺序**，首次启动后锁定。
- 默认按该顺序逐批调度，不暗中跨组抢跑、不把同平台多个批次合并计算或执行。
- 批次自己可以独立启动，但若计划已在控制该批次、或用户尝试提前启动尚未轮到的计划批次，先暂停计划调度并确认人工接管；统一派发锁保证同一任务/批次不可重复启动。
- 计划暂停只停止后续调度，不暴力中断当前已进入不可逆操作的任务；当前批次真实状态继续按结果更新。

### 2.5 计划调度衔接：已确认的 10% 规则

采用**当前单平台批次**的明确结果计算：

    失败率 = （确认未发布 + 平台明确拒绝且确定未形成可发布作品）任务数 / 有明确结果的任务数

明确结果包括：已公开发布、平台已接收/审核中、确认未发布/明确拒绝。取消/放弃不进分子分母；执行中、排队中、等待人工、结果待确认不入分母且阻止自动衔接。

| 当前批次条件 | 计划行为 | 计划可用操作 |
|---|---|---|
| 全部提交成功且无未决执行任务 | 自动衔接下一批 | 无需人工处理 |
| 失败率 **≤ 10%** 且无未决执行任务 | 自动衔接下一批 | 无需人工处理 |
| 失败率 **> 10%** 且无未决执行任务 | 暂停后续调度，提示人工判断 | **确认进入下一批** / **进入当前批次工作台** |
| 存在运行、排队、待人工或未知结果任务 | 不衔接，不允许绕过 | **进入批次工作台** |
| 没有可计算的明确结果，且不存在未决执行任务 | 不把分母为零当作 0% | **人工确认跳过当前批次** |
| 下一批未完成资源/内容配置 | 不自动启动未就绪批次 | **进入下一批配置工作台** |
| 所有批次均已处理/按规则跳过 | 调度结束 | 查看调度结论与目标结果 |

阈值默认 **10%**，由代码库集中配置，不向运营暴露阈值编辑控件；计划详情可只读显示生效值。建议在确认计划时保存阈值快照，后续修改代码默认值不改写已启动计划。

“确认进入下一批”与“人工跳过”仅推进**计划调度游标**，**不**把上一批次任务标记为成功、不释放成片、不取消原批次、不自动重试旧任务；必须写明后果。计划只做推进决策，真正异常处理在批次工作台。若已进入下一批，上一批后来被平台拒绝，只更新统计与明细，不倒退已发生的调度。

### 2.6 计划暂停、取消、最终结果

- **暂停计划**：停止后续批次派发；当前已运行批次及在途提交不强制停止。显示计划状态“已暂停”及原因（人工暂停、失败率超阈值、下一批未就绪等），原因不是另一套计划业务状态。
- **恢复计划**：从下一个合法、尚未处理的计划位置恢复，先核对当前批次与任务实际状态，不重启已提交成功的任务。
- **取消整个计划**：不可逆终止该计划之后的自动调度；不追溯删除已经创建的批次/任务，不替运营批量取消任务、撤销已发布作品或释放视频占用；在途任务仍完成必要的安全核实。确认弹窗需说明受影响的当前批次、尚未启动批次数、已有任务和历史结果。后续需要发布另建计划/批次，不恢复被取消计划。
- **计划调度结束 ≠ 发布目标达成**：分别显示调度结果（执行已结束/已取消）和目标结果（已达成/未达成/待最终核实）。已接收但审核中的投稿可以帮助批次衔接，但在公开确认前不计入目标已发布数。
- 计划不提供“取消批次”“批量重试任务”的快捷副作用按钮；进入对应批次工作台处理。

## 3. 发布批次——统一两入口、三阶段的完整闭环

### 3.1 一个批次只有一套工作区

| 属性 | 手动从“批量发布”创建 | 从计划生成的批次 |
|---|---|---|
| 入口 | 发布任务 → 任务批次 → 新建批次 | 计划详情 → 对应批次 |
| 所属计划 | 无，合法独立 | 关联 planId |
| 平台 | 用户选一个 | 从计划继承且锁定 |
| 类目与分目标任务数 | 用户选类目并填写各类目目标数 | 从计划的具体批次骨架继承且锁定 |
| 账号、成片、分配 | **统一资源配置工作区** | **同一工作区** |
| 内容、AI、封面、预览 | **统一内容配置工作区** | **同一工作区** |
| 执行、暂停、任务异常 | **统一批次执行工作台** | **同一工作区**，另外接受计划调度 |

不另建“计划批次类型”，只保留目标来源与 planId 区别。目标继承时不再要求运营重复填写平台、类目、数量。批次总目标数从其各类目 targetCount 求和，不能维护冲突的独立数字。

### 3.2 三阶段和可编辑区域

**阶段 1：批次目标与资源配置**

- 手动创建：先确定一个平台、多个类目、各类目目标任务数；计划继承：已带入目标且锁定。
- 显示平台、类目、目标数、可用账号、账号分层、可用成片、质量分层、同平台占用与账号覆盖，并能查看不足原因。
- 系统按质量偏好、账号顺序和类目资格产生配对建议；运营可选账号池/成片池、每号本批次数量、修改对应视频/顺序、排除候选。
- 目标量与已分配数量分开：例如三角洲 20/18、火影 10/10、总目标 30/已分配 28/缺口 2；绝不静默把计划目标改成 28。
- 资源配置可以保存草稿，支持后来补足；无资源不能伪装全部可用。计划资源统计只是快照，当前配置和最终创建都要重新校验。
- **阶段 1 只产生“候选任务分配行”，不生成正式任务，不取得平台视频占用。**

**阶段 2：批次内容配置**

- 显示当前单平台所需字段；批次默认值 + 逐字段继承 + 每条候选任务覆盖，不能因改一个字段而冻结整条任务。
- **统一 AI 批量生成一次返回**：发布标题、封面短标题、话题、标签（可选正文/简介）。细则见第 7 节。
- 配置现成封面或底图 + 短标题 + 模板的合成流程；在配置期异步生成封面并真实预览多展示比例，不等到执行上传时。
- 对任务候选表支持按类目、账号、内容状态、异常筛选、批量应用到未手改项、逐条编辑和单条预览。
- 全局预检：账号平台和类目、目标/分配缺口、同平台成片唯一性、必需发布字段、内容声明依据、各比例封面结果、AI/渲染异常。默认要求候选行全部通过才能最终确认；如需排除问题项，必须显示被排除数量和剩余目标缺口，由用户显式确认，不能静默部分创建。
- **只有运营最终确认批次后，才创建全部有效独立任务并取得占用/内容快照。**

**阶段 3：执行工作台**

- 配置已完成 → 批次待执行，允许明确“启动批次”；计划调度到达时仅启动已就绪批次。创建本身不立即执行。
- 执行界面展示批次汇总进度、账号队列、任务列表、待人工、结果待确认、确认失败和每条任务可执行动作。批次独立启动、暂停、恢复、查看结果。
- 批次未就绪不展示伪“执行中”，也不能被计划自动调度启动；计划提示进入该批次补齐配置。
- 执行信息与前两阶段表单切换明确，不能把所有表单和监控堆成一个超长页面。

### 3.3 批次状态：配置进度与执行状态分离

| 维度 | 用户可见状态 | 含义与入口 |
|---|---|---|
| 配置阶段 | 待资源配置 → 待内容配置 → 内容预检通过 | 确定目标与分配 → 标题/封面等内容准备 → 可正式创建任务 |
| 执行状态 | 待启动/待执行 → 执行中 ↔ 已暂停 → 执行已结束（或已取消） | 阶段 2 正式确认后进入待执行；执行控制与配置进度独立 |
| 结果摘要 | 全部成功提交 / 部分确认失败 / 无有效结果 / 未决待处理 | 决定是否可衔接，不替代逐条发布结果 |

前两阶段允许保存和返回，正式任务身份一旦产生不可因返回阶段而整体覆盖。执行中的内容修正受任务状态限制，不能将整个批次重新打开为无限制编辑模式。

### 3.4 批次执行工作台的具体布局

1. **顶部概要**：批次名称、ID、唯一平台、各类目分目标、所属计划（若有）、正式任务数、执行状态；主要操作“启动/暂停/恢复”“取消未执行任务”，有后果的操作需确认。
2. **进度与状态统计**：目标数、已正式创建数、待执行/队列中、执行中、等待人工、结果待确认、平台已接收/审核中、已公开发布、确认失败、已取消/放弃。按状态点击即筛选任务列表。
3. **任务表格**：任务 ID、账号、类目、视频缩略图/名称、标题、当前状态、最近步骤、失败原因/平台回执、最近操作时间、按状态动态变化的操作。
4. **异常处理区**：只看待处理、按账号/原因聚合，指向具体任务详情；不能用泛化的“失败 3 条”替代可恢复原因。
5. **任务详情入口**：查看每次尝试步骤、时间线、平台证据、人工处理卡点和安全动作。
6. **结果摘要**：明确提交成功率、公开成功数、确认失败率和未决数量；任务执行结束与目标达成分开。

### 3.5 任务异常是否阻塞整个批次（推荐实现）

- 单条确定失败 → 记录失败，**其他账号/安全可派发任务继续**；是否允许重试由任务详情判断，不强制整批停止。
- 登录失效/人工验证码 → 暂停该账号队列，其他账号继续；人工处理后回到原任务、安全节点恢复。
- 结果待确认 → 当前任务不可重发；对同账号后续有重复/顺序风险的任务先暂停，其他无关账号继续。
- 平台级故障或共享配置错误 → 只阻断受影响范围；真正涉及全平台的风险可暂停整个批次派发。
- 失败率高于阈值不代表批次内部立即停止；**10% 只用于计划边界的批次衔接**，不改变批次的任务级隔离策略。
- 批次“可结束”须确保没有仍在执行、排队中、等待人工、结果待确认的任务；取消/放弃和确认失败如有，依然保留真实数据。未完成目标不得被标成全部发布成功。

### 3.6 批次修改权限与确认动作

- **未生成正式任务**：手动批次允许改平台、类目、目标数（换平台应提醒已有资源/内容草稿受影响）；计划关联批次只改账号、成片分配及内容，不改继承的目标，需改目标则在计划首次启动前回计划合法调整。
- **任务已正式创建、待执行**：可按任务安全范围编辑尚未提交的发布内容；不能无痕更换账号/视频/平台或改变已确认批次目标，若要新数量另建补充批次/任务。
- **批次执行中/已暂停**：只编辑仍未进入不可逆提交的任务中安全可改内容；不得修改已提交/结果未知/已发布任务快照。取消任务保留占用；没有“恢复已取消任务”。
- **批次执行已结束**：结果与尝试记录只读；安全可重试的确认失败任务仍通过原任务重试，必要时反映批次实际进度/结果，不覆写旧尝试。
- **取消批次**：停止该批次以后派发，已启动任务安全收尾；不自动删除任务、不跨批次释放成片，不把取消等同于“全部发布失败”。如归属已启动计划，计划收到真实取消/结束信息后按已确认衔接规则等待必要决策。
- 变更会影响原手改内容的批量动作先预览影响条数和字段，明确“仅覆盖继承项/包括人工修改项”，默认前者。保存失败保留未保存编辑现场与重试入口。

## 4. 图片库设计

### 4.1 图片库定位

图片库是统一的图片资源池，不拆成“AI 封面库”和“自由图片库”。所有图片由人工整理并上传；AI 生成图片可以提前批量生成，再由人工上传到同一个图片库。

图片来源与使用方式：

1. 素材自身已有封面：发布封面配置时可直接使用。
2. 图片库图片：作为现成封面，或作为封面底图。
3. 完全 AI 生成的图片：提前生成并上传图片库，发布时作为现成封面或底图使用。
4. 视频关键帧提取：当前不做。
5. 发布时实时 AI 生成底图：当前不做。

### 4.2 图片数据属性

图片库是统一图片资源池；“现成封面”和“可作底图”是图片用途，不是两套图片库。同一张图片可以同时具备多个用途，避免重复上传。

| 字段 | 规则 | 说明 |
|---|---|---|
| 图片名称 | 必填 | 可搜索、可重命名 |
| 用途 | 可多选 | 现成封面 / 可作封面底图 |
| 内容类目 | 可选或通用 | 复用现有类目体系 |
| 具体类目 | 可多选 | 用于筛选和推荐，不新增类目字典 |
| 图片预览 | 系统生成 | 列表缩略图 |
| 宽、高、比例 | 系统自动读取 | 像素尺寸和宽高比 |
| 格式、大小 | 系统自动读取 | PNG/JPEG/WebP 等 |
| 状态 | 必填 | 启用 / 停用 |
| 引用情况 | 系统统计 | 被模板、生成封面或历史任务引用 |
| 上传人、上传时间 | 系统记录 | 资源管理信息 |

图片底层文件复用现有文件管理/对象存储；图片库只管理用途、类目和运营可用性。人工完成的封面、人工准备的底图、提前生成并上传的 AI 图片都进入同一个图片库。被模板或正式任务引用的图片不能直接物理删除；可以停用，历史任务仍可查看当时使用的图片快照。

### 4.3 图片库列表交互

列表字段建议：

预览｜图片名称｜用途｜内容类目/具体游戏｜尺寸/比例｜状态｜引用次数｜更新时间｜操作

高频筛选：

- 搜索图片名称；
- 图片用途；
- 内容类目；
- 具体游戏；
- 启用/停用。

主要操作：

- 批量上传；
- 单条编辑；
- 批量修改用途/类目/游戏；
- 批量启用/停用；
- 查看详情和引用情况；
- 删除未被引用的图片。

已被正式任务或模板版本引用的图片不能直接物理删除。允许停用，停用后不再进入新的随机选择；历史任务仍能查看当时引用的图片版本。

管理页使用列表；发布配置中的选图弹窗使用缩略图浏览。不要让运营在列表管理页逐张打开图片，也不要把图片选择弹窗做成密集元数据表格。

### 4.4 随机底图规则

用户已确认随机选择即可，不需要复杂 AI 语义匹配。

推荐顺序：

1. 先按用途筛选为“封面底图”。
2. 再按内容类目筛选。
3. 有具体游戏时，优先选择该游戏的启用图片。
4. 对应游戏没有可用图片时，允许回退到“通用”类目。
5. 从符合条件的启用图片中随机选择一张。
6. 如果仍无可用图片，提示运营补充资源或改用素材封面，不要静默选错游戏。

随机选择应可重新抽取；批次确认生成任务后，需要把最终选中的图片 ID 和版本快照保存到任务内容中，不能每次查看都重新随机。

## 5. 封面模板库与模板编辑器

### 5.1 模板定位

模板不是一张不能编辑的固定图片，而是一套可重复使用的设计结构：

    背景图片占位 + 动态文字区域 + 固定装饰/Logo
      → 替换底图
      → 填入 AI 短标题
      → 按约束自动排版
      → 导出封面图片

模板的核心是画布尺寸、版式、对象位置、文字区域和文字样式。

**用户已确认：**

- 模板可以设置文字位置、区域、坐标和字体。
- 模板不强制绑定平台和内容类目。
- 平台和类目可以作为可选适用属性或推荐标签。
- 画布比例和实际宽高是模板的核心规格。
- 第一版不做复杂自由设计软件，保持小而美。

### 5.2 画布规格与坐标单位

| 类型 | 比例 | 默认示例尺寸 |
|---|---|---|
| 横版 | 16:9 | 1920 × 1080 |
| 竖版 | 9:16 | 1080 × 1920 |
| 竖版 | 3:4 | 1080 × 1440 |
| 方形 | 1:1 | 1080 × 1080 |

模板保存固定设计画布宽、高，编辑器中 X/Y/W/H 使用设计画布像素坐标。导出到同一比例的不同分辨率时，统一缩放位置、文字区域、字号、行高、描边、阴影和间距；不能只缩放坐标而保留原字号。不同宽高比使用对应模板或明确裁切适配，不直接拉伸变形。平台输出适配独立校验目标尺寸、比例、格式、文件大小和安全区域。

### 5.3 模板对象与图层

第一版只支持三类对象：

| 对象类型 | 作用 | 关键属性 |
|---|---|---|
| 背景图片 | 被素材封面或图片库图片替换 | 图片占位、填充方式、裁切/定位 |
| 动态文字区域 | 接收 AI 生成的短标题/副标题 | 文字槽位、坐标、尺寸、字体、排版约束 |
| 固定装饰 | Logo、栏目名、固定图形/色块 | 文字或图片内容、坐标、尺寸、样式、锁定 |

动态文字槽位建议：

- main_title：主标题，AI 短标题主要写入位置。
- sub_title：副标题，可选。
- fixed_text：固定文字，不随作品变化。

每个对象需要稳定的对象 ID，方便保存、编辑和批量填充。固定装饰可以锁定，防止运营误拖动。

### 5.4 文字区域可控属性

**位置和区域：**

| 属性 | 说明 |
|---|---|
| X | 左侧坐标 |
| Y | 顶部坐标 |
| W | 文字区域宽度 |
| H | 文字区域高度 |
| 对齐 | 左对齐 / 居中 / 右对齐 |
| 安全区域 | 文字不应进入的边缘区域或平台遮挡区域 |

画布上支持拖动和拖拽控制点调整大小；右侧属性面板支持精确输入 X、Y、W、H。画布坐标显示为实际像素值，内部存储可使用相对画布的归一化坐标，以保证同一比例不同输出分辨率下布局一致。

**字体与样式：**

- 字体家族；
- 字号；
- 最小字号；
- 字重；
- 字体颜色；
- 行高；
- 字间距；
- 对齐；
- 描边开关及参数；
- 阴影开关及参数；
- 副标题开关；
- Logo/固定装饰显示与锁定。

**文字约束：**

- 最大字数；
- 最大行数；
- 自动换行；
- 自动缩小字号；
- 最小可读字号；
- 溢出检测。

自动适配规则：先按模板字号排版；超出文字区域时自动缩小，但不得低于最小字号；仍然超出时显示异常，要求 AI 重新润色或人工修改。不得静默裁掉文字或缩到不可读。

### 5.5 模板编辑器页面布局与交互

编辑器使用三栏布局：

1. **左栏：图层列表**，负责选择、显示/隐藏、锁定/解锁和调整图层顺序；模板切换通过返回模板列表完成。
2. **中栏：设计画布**，显示真实比例画布、底图、文字区域、选中边框和缩放控制点；支持拖动对象和缩放区域。
3. **右栏：属性面板**，按选中对象显示 X/Y/W/H、字体、字号、颜色、对齐、行高、描边、阴影和文字约束；坐标支持直接输入像素值。

主要交互：

- 点击图层或画布选择对象；拖动对象调整位置；拖动控制点调整区域宽高。
- 背景图片可替换、裁切和调整填充方式。
- 动态文字区域可新增、复制、删除；支持主标题/副标题/固定文字槽位。
- 固定装饰/Logo 可锁定。
- 支持撤销/重做；离开未保存模板时提醒保存或放弃。
- 提供短标题、长标题、多行标题测试，检查自动排版和溢出。
- 提供画布尺寸预览和小尺寸缩略预览。
- 字体加载完成后再测量文字；预览与最终导出共用同一排版规则。
- 保存、重新打开、复制后，对象位置、样式、槽位和约束完整恢复。

标尺、参考线、自动吸附是后续辅助优化，不是第一版验收阻塞项。

### 5.6 模板列表管理

模板库采用列表，不以大卡片墙作为主要管理方式。

列表字段：

预览｜模板名称｜画布比例/尺寸｜版式｜字体/主标题样式｜内容类目（可选）｜适用平台（可选）｜状态/引用次数｜操作

操作：

- 新建模板；
- 编辑；
- 复制；
- 预览；
- 设置默认模板；
- 启用/停用；
- 查看引用情况。

平台和类目只是可选的适用范围或推荐属性。兼容判断以画布尺寸、比例、安全区域和输出要求为准。相同设计结构可以跨平台复用，不为每个平台复制一份相同模板。

默认模板建议按画布规格/比例维护；类目和平台可用于推荐，不强制形成“每平台 × 每类目 × 每比例”的模板矩阵。

### 5.7 模板数据结构建议

模板保存为版本化的设计 JSON，而不是只保存固定表单字段。示意：

    {
      "schemaVersion": 1,
      "name": "游戏横版大标题",
      "canvas": {
        "width": 1920,
        "height": 1080,
        "ratio": "16:9"
      },
      "layers": [
        {
          "id": "background",
          "type": "image",
          "role": "replaceable_background",
          "fit": "cover"
        },
        {
          "id": "main-title",
          "type": "text",
          "slot": "main_title",
          "x": 0.06,
          "y": 0.68,
          "width": 0.84,
          "height": 0.22,
          "style": {
            "fontFamily": "Source Han Sans",
            "fontSize": 64,
            "minFontSize": 42,
            "fontWeight": "bold",
            "color": "#FFFFFF",
            "align": "left",
            "lineHeight": 1.05,
            "stroke": true,
            "shadow": true
          },
          "constraints": {
            "maxChars": 18,
            "maxLines": 2,
            "autoFit": true
          }
        }
      ]
    }

上例的坐标应采用固定设计画布像素值（如 X=115、Y=730、W=1500、H=220），不要把 Fabric.js 对象 JSON 直接当作业务模板结构。正式模板业务结构与画布引擎对象格式分离，通过适配层互相转换；同一比例导出不同分辨率时，所有视觉属性按同一比例缩放。正式字段命名应结合现有项目编码规范确定，不要把示意 JSON 当作已批准的 API Contract。

模板被任务引用后应保存模板版本快照。模板后续修改不改变历史任务已生成封面的布局、文字或资源引用。

### 5.8 第一版明确不做

- 完整 Canva / Photoshop；
- 自由画笔和复杂矢量绘制；
- PSD 导入与编辑；
- 动画和视频封面动效；
- 复杂滤镜、蒙版和专业图层混合；
- 复杂插件系统；
- 任意无限画布；
- 发布时实时 AI 生成整张图片；
- 视频关键帧提取。

第一版只把图片、文字、固定装饰、坐标、尺寸、字体和排版约束做可靠。

## 6. 发布内容如何使用图片库和模板库

### 6.1 两种封面模式

**模式一：使用现成封面**

- 从图片库筛选“现成封面”。
- 按内容类目、具体游戏和比例筛选。
- 选择一张后作为当前视频封面。
- 不叠加模板文字，除非运营明确切换到模式二。

**模式二：底图 + AI 短标题 + 模板**

底图来源：

1. 优先使用素材自带封面。
2. 素材封面不适用或缺失时，从图片库符合条件的“封面底图”中随机选择。
3. 完全 AI 生成的底图需提前生成并上传图片库；发布过程中不实时生图。

生成流程：

    视频素材
      → 读取所属游戏和素材封面
      → 选择底图（素材封面优先 / 图片库随机）
      → AI 生成或润色短标题
      → 选择匹配画布比例的模板
      → 将主标题/副标题填入动态文字槽位
      → 自动换行与字号适配
      → 溢出检查
      → 生成封面预览
      → 人工检查异常项
      → 保存封面版本并关联发布任务

AI 负责短标题内容，不负责实时生成整张图片。模板负责布局、字体和文字样式；图片库负责提供底图或现成封面。

### 6.2 批次中的集中配置与封面生成时机

- 批次先确定平台和多个类目，再进行账号/成片分配。
- 标题按视频批量润色；正常结果可批量采用，异常结果逐条处理。
- 封面按视频类目、目标比例和模板推荐；同一批次不同类目可以使用不同模板。
- 固定话题/标签模板按平台继承，批次统一调整，单条可覆盖。
- 单条内容的标题、封面、话题和分区允许覆盖批次默认值。
- 生成结果在正式创建任务时保存为内容/封面快照。

**封面生成在内容配置阶段触发，而不是等任务执行时生成。**

1. 选择封面模式：现成封面，或底图 + AI 短标题 + 模板。
2. 确定底图：素材自带封面优先；不适用/缺失时从图片库选择或随机抽取符合类目的底图。
3. 确定模板：按画布比例优先匹配，类目/平台作为可选推荐条件。
4. 生成或润色短标题，并绑定模板中的主标题/副标题槽位。
5. 在内容配置页面点击“批量生成封面”，系统立即创建本批次封面生成请求；生成可以异步完成，不阻塞整个页面。
6. 每条内容独立显示封面生成状态；失败只重试该条，不重跑全批次。
7. 生成完成后进入全局预览，统一检查视频、账号、标题、封面、话题、分区和异常项。
8. 运营修正异常后再确认创建任务。

封面生成状态属于内容准备状态，不是发布任务执行状态：待生成、生成中、已生成、需重新生成、生成失败。修改某条内容的标题、底图或模板后，只将受影响条目标记为“需重新生成”；不重做其他封面。封面仍在生成或生成失败的条目不能显示为“可发布”。

全局预览采用列表/表格为主、封面缩略图为辅，支持按类目、账号和异常筛选；最终确认前必须看到每条任务候选的最终标题、封面、话题和分区。

## 7. 批次 AI 内容配置与封面生成闭环

### 7.1 一次 AI 批量生成的输入和输出

用户已明确要求：**同一次 AI 内容理解与生成请求，按任务候选行关联返回发布标题、封面短标题、话题和标签**，可选返回正文/简介。不要要求运营对四个字段分别提交独立 AI 请求。

| 输入（逐候选任务） | 输出（逐候选任务） | 说明 |
|---|---|---|
| 平台、类目、账号标签（必要时）、成片标题/主题/已有描述、已确认的素材元数据、平台长度/字段规则、选择的风格 | 平台发布标题 | 平台适配，不静默截断，不把内部文件名当正式标题 |
| 同上 + 封面模板约束 | **封面短标题**（可选副标题） | 与发布标题独立，可短可读且适合文字槽位 |
| 同上 | 推荐话题/参与话题 | 按平台真实字段模型输出；内容相关，不强行推荐热门无关话题 |
| 同上 | 推荐标签 | 去重、数量/长度校验；B站独立标签与小红书正文话题不可混为一谈 |
| 同上（用户勾选） | 简介/正文 | 可选生成，不要求所有平台都有同名字段 |

返回必须绑定候选行 ID（不是靠标题文本匹配），并带逐字段状态：建议生成、已人工编辑、已采用、生成失败、需校验。平台必需的分区、声明、权利授权不是可被 AI 随意自信决定的字段：业务类目可映射分区建议，原创/转载/AI/营销声明必须依据真实内容来源及人工确认。

**一次用户操作 ≠ 单个大型后端调用。** 对大量任务系统可以分片处理、队列化和失败重试；用户只看到一轮 AI 内容生成任务，按行展示处理进度、成功/失败数量、适用范围和最终结果。

### 7.2 UI：批量控制 + 逐行编辑 + 审核采用

顶部：平台/类目/任务数量及已完成/缺失/异常数。控制区需提供：
- 选择范围：全部、勾选任务、仅缺失字段；显示将影响多少任务。
- 生成字段：发布标题、短标题、话题、标签，简介可选；默认全套内容。
- 生成风格/模板（可选，不强制重复选择），自动引用已有来源内容和当前平台字段规则。
- **覆盖策略默认“仅填充空白和继承值、保留已人工修改”**；强制覆盖需要先说明影响字段与条数并显式确认。
- 生成按钮及任务进度：运行中可继续浏览/修改其他行，失败可只重新生成失败行/字段。

下方任务内容表格每行展示：账号、视频缩略图/时长、类目、发布标题（可编辑）、短标题（可编辑）、话题、标签、正文/简介（展开）、封面缩略图及状态、平台校验结果、预览/编辑/重新生成按钮。支持只看异常、批量采用 AI 候选、逐条接受或改写；**AI 建议不是自动覆盖正式内容**。

若用户只想修改“封面短标题”，允许只重新生成该字段，保留发布标题、话题和标签；反之亦然。每次重生记录适用范围及其覆盖结果，保证人工输入不被非预期改变。

### 7.3 封面合成独立于 AI 语义生成

封面两种模式：
1. **现成封面**：从素材已有合格封面或图片库选择，直接预览并应用。
2. **底图 + AI 短标题 + 模板**：使用素材已有封面或图片库匹配底图，短标题填入模板动态文字槽位，按模板生成真实封面 PNG/图片输出。

AI 返回**文字**，模板负责渲染图片；首版不在发布过程中实时生成 AI 背景图片，也不承诺视频自动截帧。AI 背景图可事先人工生成后上传图片库。底图可按类目随机选择，但应用后固定，用户主动“换一张”才重新随机。

封面生成在批次**内容配置阶段**完成，可异步批量合成。实际预览支持适应窗口/小图/原始尺寸、模板标题溢出警告、多比例结果（B站推荐 4:3 与个人空间 16:9 等已观察规则），预览/应用/导出使用同一渲染结果；不能用两个 CSS 容器充当两张已经完成的裁切成品。

AI 短标题、底图、模板参数改变，只把受影响条目标记“需重生”，不重跑其他封面。某条渲染失败只重试此条；不丢已采纳的标题/话题/标签。底图不存在、字号溢出、平台比例不符必须显示定位原因。

### 7.4 平台适配与发布前预检

- **产品目标平台**：百度（百家号）、小红书、B站。抖音是当前素材来源，不是本轮发布目标。
- B站按已观察字段重点校验标题、封面多比例、分区、独立标签、创作声明；小红书使用标题及正文中的话题；百家号按已观察的作品描述、横竖封面和声明入口设计，尚未确认的独立标题/封面数值规格不能猜造。
- 动态字段/必填条件分为“页面已观察、运行时已验证、当前仍待核验”；平台已接收/审核中不等于作品公开成功。
- **完整预检**：账号身份与类目适配、视频文件、唯一占用、目标/分配差额、标题/短标题可读、封面可用与比例、话题/标签平台适配、声明事实来源、指定时间约束和运行时能力。只放行明确有效的候选任务，所有不合格行有修复入口。
- 默认值优先级：用户对本条的明确输入 > 已确认素材事实/内容模板 > 已确认账号默认值 > 系统推荐值；不允许推荐值覆盖用户已改字段；内容权利声明不能被低可信推荐覆盖。
- 平台内置付费 AI/推广功能与本系统的 AI 批量内容生成是两回事；不自动调用、不中途付费。

## 8. 独立发布任务——新建、详情、异常与结果

### 8.1 单条任务新建（快速发布）

“发布任务 → 快速发布”是一条任务，不是隐式批次。页面：
1. 基础：一个平台、一个类目、一个合格账号、一个成片；选择器需要显示可用性、该平台是否已占用、账号支持范围。
2. 内容：当前平台标题、封面两模式、短标题、话题/标签、必要平台分区/声明和发布时机；可调用**同一 AI 内容生成能力**，范围只有这一条，不建立第二套生成器。
3. 预检：实时显示账号、视频、标题、各比例封面、平台字段、可见范围、执行时间与阻断项，不能靠空字段假装已准备。
4. 创建：创建一条正式待执行任务并原子取得成片占用，展示任务详情；明确另选“创建并启动”时才执行，默认仅创建。

编辑途中保存的配置草稿不占用视频。账号身份不自动猜测，切换平台要验证已有输入并提示可能清除不兼容字段。

### 8.2 任务详情必须回答什么

固定信息：任务 ID、所属计划/批次（若有）、平台、类目、账号、成片及文件信息、正式创建时的标题/封面/话题/标签/分区/声明快照、计划/实际时间、当前状态、最后平台回执和作品链接。

操作与证据区域：
- **当前卡点**：操作建议、上一执行尝试阶段、明确的下一步；
- **执行时间线**：启动、登录/取文件、上传、填写、提交、收到回执、核实结果；
- **执行尝试列表**：尝试序号、发起人/方式、步骤结果、时间、失败码/原因、人工处理、证据；
- **平台结果**：未提交/确认未发布/已接收审核中/已公开发布/结果待确认等分开展示，并保留作品 URL、平台稿件 ID（有证据才显示）。
- **主按钮唯一**：根据真实状态显示“启动”“继续人工处理”“核实结果”“安全重试”“复制配置另建”，不把全部危险操作同时铺开。

### 8.3 任务状态、动作与可修改字段

| 情况 | 可操作 | 禁止或前置条件 |
|---|---|---|
| 配置草稿（尚未创建正式任务） | 改全部字段、AI 生成、保存或删除草稿 | 不能启动和占视频 |
| 正式待执行 | 编辑尚未锁定的安全发布内容、启动、取消 | 账号/平台/视频/类目身份不能直接改 |
| 排队/准备中 | 查看进度、在安全节点暂停后续准备；按是否已提交决定能否改内容 | 不覆盖不可逆的发布提交内容 |
| 等待人工（登录/手工提交） | 打开原账号窗口、继续处理、补证据 | 不在结果不明时再次发送 |
| 结果待确认 | **核实平台已有稿件**、补录唯一链接和证据 | 禁止重发、直接取消、释放视频 |
| 已接收/审核中 | 查看审核状态、核实公开结果 | 不把已接收算作已公开，不重新投稿 |
| 已发布 | 查看作品及证据、去作品管理 | 不重试、普通释放、改写任务身份与历史快照 |
| 确认未发布/平台拒绝 | 查看失败步骤、修复**允许改变的内容字段**后在原任务安全重试、或符合条件时放弃并释放 | 未证实未发布不能重试；不可直接换账号/视频 |
| 已取消 | 查看原因、放弃并释放后复制旧配置创建新任务 | 取消后没有“恢复原任务”；仍占用成片 |
| 已放弃 | 查看历史或从历史复制配置创建新任务 | 原任务永久结束，不复活 |

**任务可编辑不是“状态是失败就全部可改”**：身份一旦生成始终锁定，正式已提交的内容快照不可追溯改写；仅在确认未提交或确认未发布、再次提交前的安全阶段允许修改合规内容并保留版本/尝试历史。

### 8.4 失败/未知/人工异常的安全闭环

- 平台明确失败且证实未投稿：显示原因及对应步骤；允许处理可修正内容，原任务新建安全重试尝试，建议默认有界重试次数（如原型最多两次，**演示参数不是已确定生产配置**），避免无限重试。
- 登录失效/验证码：保留账号会话和任务现场，运营完成验证后从安全节点继续，不能随意重新上传。
- 提交按钮点击后断连/超时：结果待确认，先到同账号作品管理核实是否存在稿件，确认成功则登记作品，确认失败才可重试；仍不明确继续保持未知，保留占用。
- 审核拒绝：依据平台是否形成投稿及可编辑性判断，保留平台回执；不能简单把所有审核拒绝都作为可重复上传。
- 执行终点必须有明确结果/证据或注明未决原因；不以演示按钮点击就宣称平台公开成功。
- 复制配置只复用标题、封面等合规可复用内容；新任务必须重新校验账号/视频/平台唯一占用及内容时效，不能复用旧执行尝试或稿件 URL。

## 9. 可编辑性、指标与统计口径的统一矩阵

### 9.1 生命周期操作权限（Review 主检查点）

| 对象与阶段 | 可修改范围 | 锁定字段或禁止行为 |
|---|---|---|
| 计划草稿 | 平台/类目目标、资源规划、批次拆分、顺序 | 不触发执行 |
| 计划已确认未首次启动 | 可安全调整计划与批次骨架，前置影响检查 | 不暗改已配置候选或已生成任务 |
| **计划首次启动后（执行中/暂停/结束）** | 仅调度控制与只读统计、跳批决策 | **平台、目标、批次数、顺序完全锁定** |
| 批次骨架/阶段 1 | 手动来源可改目标；计划继承目标只读；两者都可改候选账号/成片/配对 | 不把候选行当正式任务 |
| 批次阶段 2 | 批量/逐条改尚未正式创建的内容，封面生成 | 不越权变更继承目标 |
| 批次正式待执行 | 安全修改未执行任务的内容 | 不能无痕改身份、数量、占用 |
| 批次执行中/已暂停 | 暂停/恢复、处理未决、局部可安全修正项 | 不覆盖已提交快照，未知结果不能重发 |
| 批次执行结束/取消 | 查看历史、安全重试（符合条件的原任务） | 不直接改写结论或释放其他任务 |
| 任务已创建、未提交 | 内容字段安全修改、取消（保留占用） | 平台/账号/视频/类目身份锁定 |
| 任务已提交/结果未知/已发布 | 查看和核实 | 不改提交快照、不重复投稿 |

### 9.2 计划与批次统计口径

| 指标 | 口径 |
|---|---|
| 计划目标 | 按平台 × 类目矩阵求和，等于按平台分组的批次各类目分目标之和；可独立任务若计入目标必须单独标识来源，不能重复计算 |
| 批次目标 | 当前单平台批次各类目目标之和，来自计划或手动输入 |
| 已分配候选 | 阶段 1 完成的有效账号/成片候选行数；不等于正式已创建任务 |
| 已创建任务 | 批次最终确认时真实生成的正式任务数 |
| 成片资源数 | 唯一成片 ID 去重；同一个成片跨平台只计一条资源 |
| 已提交成功 | 平台明确已接受/审核中或已公开发布，可用于计划批次衔接 |
| **已发布（目标完成）** | **确认公开发布成功**的任务数，审核中不算 |
| 目标完成率 | 已发布 ÷ 目标任务数；目标 0 时显示“不适用”，不以除零得到完成率 |
| 目标差额 | max(目标任务数 − 已发布, 0) |
| 批次失败率 | 确认未发布/明确拒绝数 ÷ 明确结果任务数；分母为 0 显示“暂无有效结果”，不能记作 0% |
| 未决任务 | 队列/执行/等待人工/结果待确认数量，阻断计划自动衔接 |
| 计划调度进度 | 计划有多少批次、当前哪批、已处理/跳过多少批，不直接等于发布目标完成率 |

计划四种统计维度：总览、按平台、按类目、平台 × 类目；点击分组统计可进入相应批次或带筛选任务列表，但不能在计划详情直接开展任务级操作。发布计划“调度已结束”与“目标已达成”分别展示。

## 10. 最终原型必须完整呈现的六个页面 + AI 工作区

以下是**独立完整页面的交互规格**；不可用单一流程信息图、卡片碎片或只有按钮的局部草图冒充产品原型。每个页面都必须有公共导航、页头、主要内容、状态/空态/异常态、主次操作、反馈和页面跳转。

### 10.1 任务新建

左侧公共菜单“发布任务”；右上按规范提供退出/保存草稿。主体依次为单任务平台与账号/类目/成片选择、平台内容字段和封面、单任务 AI 生成及预览、执行时机、唯一性/必填校验；底部明确“创建待执行任务”与可选显式“创建并启动”，默认不上传。切换平台/账号需保护已编辑内容并解释失效字段。

### 10.2 任务详情

页头真实任务身份与平台结果；上部当前状态、卡点及唯一主动作；中部“执行时间线 / 每次执行尝试 / 平台反馈 / 内容快照”；安全处理区只对当前状态允许动作开放。失败展示可读原因、证据和原任务安全重试入口；未知结果只有核实，取消不恢复、放弃并释放需要确认。

### 10.3 批次新建 / 配置

统一两个来源的工作台；显示来源说明（独立/计划）、单一平台、各类目目标以及配置进度。阶段 1 用账号池 + 成片池 + 质量/顺序建议 + 候选映射表；阶段 2 进入 AI 内容配置和封面生成；正式预检后生成任务。底部操作“保存草稿、上一步、下一步、确认创建”，不同阶段不可提前触发发布。计划继承的目标只读，不重复规划一次。

### 10.4 计划新建

必须是完整四步工作区：**资源盘点 → 平台 × 类目目标矩阵 → 按平台分组拆批 → 确认创建轻量批次**。资源首屏显示平台账号、今日已发布与容量、类目可用成片及预计可安排数；目标矩阵合计一致；平台组内可多批次并显示每类数量及组内顺序；最终确认只创建批次骨架，未分配账号/视频，也不执行。

### 10.5 批次执行工作台

页头批次唯一平台、目标、配置/执行状态与操作；KPI 和进度条；任务列表按状态筛选；异常任务快捷入口；单账号执行队列；每任务链接详情；运行/暂停/恢复/安全取消，批次完成与确认失败率汇总。计划所关心的只有是否满足衔接条件，不应在这里编辑计划目标。

### 10.6 计划执行工作台

页头计划名称与只读目标、锁定状态、暂停/恢复/取消操作；整体目标数、公开已发布数、当前批次序号/总批次、已处理批次；**按平台分组**的批次顺序列表与每批次“进入配置/进入执行/查看结果”快捷入口；当前调度决策卡根据 10% 规则只提供“确认进入下一批”“人工跳过”“进入批次处理”。计划上不能有任务级失败重试和内容编辑；调度结束与目标是否达成分开展示。

### 10.7 批次 AI 批量内容配置工作区（阶段 2 的完整子页）

必须是可独立打开的完整工作区：批量生成范围/字段/覆盖策略、一次 AI 多字段生成进度、可编辑内容候选表、封面模板与底图设置、真实合成大图/缩略图预览、错误定位、批量采用与逐字段重新生成、全局预检/返回批次/最终确认。快速发布嵌入同一能力的单条模式，不提供第二套 AI 数据模型。

### 10.8 列表与导航入口

- 发布任务菜单保留“任务批次 / 任务列表”两个 Tab；右上为“快速发布 / 批量发布”；批次列表每行仅一个平台，任务列表每行仅一个执行身份。
- 发布计划菜单保留计划列表及计划详情，计划列表操作仅进入调度、暂停/恢复、取消或查看，不因执行中展示“编辑计划”。
- 图片库和封面模板库继续使用既有列表/编辑工作区，不强制变成发布计划内的配置步骤。
- 对象间提供返回上下文（计划 → 批次 → 任务 → 原批次/计划），保留筛选、分页和滚动；状态列与操作列分离，高频动作直接可达，危险动作只在必要时二次确认。
- 原型必须体现点击后状态/统计的变化与安全阻断，而不是静态截图中显示按钮即算已实现。

## 11. Review、原型执行与可验收标准

### 11.1 先独立评审，后实施

GPT Work 第一轮只做**产品 Review**：先复述任务/批次/计划对象、全部入口、两类创建后果、计划锁定、各层编辑权限、10% 衔接、AI 批量生成、封面生成、任务异常局部隔离；逐项指出是否与本文冲突、是否缺用户确认、是否过度设计。交付“理解复述 + 产品判断 + 冲突表 + 修正提议”，**不自行把建议改成已确认结论，不改原型**。用户完成 Review 再执行实现提示词。

### 11.2 实施边界与工程顺序

1. 确认当前 Workspace/Cloud 根路径、Git 现状、仓库 AGENTS/AGENT-INDEX 与文件 Ownership，按仓库既有 CHG/单仓任务规范执行；不要沿用已失效的本地路径。
2. 确定当前浏览器打开的原型由哪个 Cloud web/example 入口加载；旧多平台批次/混合计划代码只作查漏，不做回退事实源。
3. 统一对象结构与状态/动作矩阵：计划 → 平台分组（视图）→ 单平台批次骨架 → 候选行 → 正式任务 → 尝试/平台结果；同一平台多批次、单平台约束、无双重调度。
4. 完成六页面和 AI 内容子页：优先覆盖产品操作与业务后果，再细修视觉；统一已确认的 common 公共规范，不复制第二套组件库。
5. 编写真实行为测试：计划目标矩阵相加、拆批合计、确认生成骨架但不占用、手动/计划批次共用一套资源/内容配置、最终创建占用、AI 多字段/人工覆盖保护、错误/恢复、任务唯一性、计划一旦启动后不可编辑、计划暂停取消、10% 阈值边界和无结果手工跳过。
6. 使用本地浏览器完成创建—配置—执行—异常—回到计划—最终结果场景走查，包含桌面/窄屏和刷新恢复。记录通过/失败/未验证及页面截图；仅代码构建成功不能证明交互验收。
7. 不接通真实平台提交，不假装发布成功；发布能力需另按工程设计/权限/账号与平台验证。

### 11.3 关键验收路径（任何一个 P0 失败均不能宣称完成）

| 场景 | 必须观察到的事实 |
|---|---|
| 独立快速任务 | 单平台/账号/成片，内容准备可用 AI 单条，创建待执行且有占用；执行尝试与平台结果分离 |
| 计划资源盘点 | 平台账号、类目成片、今日已发、预计可安排量分开；容量未知不虚构 |
| 计划拆批 | 百度 A + 百度 B 归在百度组，小红书 A 在小红书组；每批含各类目目标，汇总严格等于目标矩阵 |
| 计划确认 | 生成独立批次骨架（待配置），**没有创建正式任务，没有视频占用** |
| 计划关联批次 | 继承平台/类目/每类数量，不再填一次目标；可继续选账号/成片，任务候选不占用 |
| 手动批次 | 自选一个平台/类目分目标；后续使用**同一**资源/内容工作区 |
| 批次正式创建 | 内容预检后才生成任务和占用，默认不执行；所有任务均是单平台同类目合格配对 |
| AI 内容配置 | 一轮 AI 批量操作每行返回发布标题+封面短标题+话题+标签，手改字段不被覆盖；封面批量渲染与逐条错误恢复 |
| 计划锁定 | 首次启动后编辑入口与接口安全验证同时锁定目标、批次数、顺序；暂停后仍不能编辑 |
| 批次异常 | 一个账号等待人工时其他合格账号继续；未知结果不得重新发布；批次未决不触发计划下一批 |
| 10% 规则 | 确认失败率 = 10% 自动下一批；>10% 人工确认；分母为 0 人工跳过；未决任务阻断 |
| 计划终止 | 暂停不强停在途任务；取消只终结后续调度，不自动删除/释放任务；“执行结束”和“目标达成”可分别展示 |
| 任务取消 | 取消后仍占用且不能恢复；符合安全条件时放弃释放，再复制配置创建新任务 |
| 回归 | 图片库/模板预览和导出一致；快速任务、批次、计划互不创建隐藏的重复任务 |

### 11.4 禁止误认已完成的情况

- 原型页面可点击 ≠ 后端已支持真实资源分配/发布执行；浏览器页面可上传 ≠ WT Media 适配已通过。
- AI 设计稿 ≠ AI 服务和封面渲染已接通；模拟状态必须显式标注，不能把固定假数据标成真反馈。
- 旧原型历史自评分、历史视频截图或过期 Git 路径 ≠ 当前新版交互已验收。
- 图片/模板模块仍沿用现有资源管理方向，本轮不额外建设复杂 DAM、Canva 式编辑器、实时 AI 生图、额外审批中心或跨模块互动编排。
- 最终交付需明确源码所在仓库/路径、改动、测试、浏览器操作截图、未覆盖能力与后续需要用户判断的问题，而不只是“原型完成”。

### 12.4 对新原型的直接输入（建议，待原型评审）

1. **分别编辑平台内容。** 视频、标题、正文、封面可作为初始内容来源，各平台提供覆盖值和自己的长度提示；小红书话题与 B站标签／参与话题分别表达。百家号按截图使用「作品描述」表达，不强行复制 B站的标题＋简介结构，独立标题能力待核验。
2. **补齐声明、权限及条件字段。** 配置除字段名、必填、选项外，还应表达何时出现、依赖哪些已选值、账号是否支持，以及未核验状态。账号不支持的能力显示原因，不提供无法完成的操作。
3. **预览最终效果。** 展示实际发布账号、视频、标题、正文、各比例封面、标签、声明、可见范围和发布时间；默认值也必须进入预览。本次 B站默认标签出现与视频无关的“学习／手帐／记录”，百家号截图中出现“科研新发现”话题，均需核对。百家号的挂载、地点、水印及横竖封面也应纳入预览。
4. **执行时允许人工介入。** 登录失效、短信或其他平台校验暂停当前操作，人工处理后复核账号再继续。上传失败、内容未完成、提交结果未知应有不同提示；不能仅凭按钮点击就报告发布成功。
5. **检查实际内容与业务类目。** 本次样片标题和画面为三角洲，素材业务类目却记录为火影忍者；正式发布前应纠正或确认，不能将业务类目直接当作平台分区。

这些观察用于当前第 2、3、7、8、10 节的页面字段与预检设计；未验证项不得被当作平台已接通能力。

### 12.5 一次发布的验收路径与未覆盖项

三平台最终都需要验证：**确认账号 → 获取成片与封面 → 上传完成 → 填写必要字段 → 检查最终预览 → 正式提交 → 作品管理中找到对应作品 → 确认审核结果 → 核对公开链接**。平台接收、审核中、审核拒绝和公开可访问分别记录；提交后断线先查作品，避免重复提交。

小红书和 B站可先使用已检查的视频截帧封面，验收一次立即、公开发布。自定义图片、定时发布及其他扩展能力另行核验，不作为这次基础发布的前置条件。当前测试素材及文案仅用于调研，正式发布仍需确定实际内容并获得提交授权。

| 平台 | 后续核验与配置补齐 | 完整发布闭环的验收依据 |
|---|---|---|
| 小红书 | 确认正式内容、声明与可见范围；验证自定义图片封面；补查定时限制（仅启用定时时） | 提交反馈、笔记管理中的唯一作品及审核状态、公开链接对应的视频与文案 |
| B站 | 使用 41 号账号；选择真实适用的创作声明和标签；复核双比例封面；验证自定义图片封面；如转载则核对追加字段 | 投稿反馈、稿件管理中的对应稿件及 BV号／链接、审核状态、公开页面内容 |
| 百家号 | 已有上传后基础信息截图。基础发布可先核对账号、视频、横竖封面与作品描述，移除无关话题，确认创作声明；活动、挂载、地点按实际需求选择，水印按发布意图确认。补查完整字段校验、封面规格及声明选项；定时和挂载条件字段仅在启用时核验 | 由可操作该页面的用户完成提交及结果检查，取得提交反馈、对应作品标识、审核状态和公开链接；Codex 本轮只能依据截图评审，不能执行该站点自动操作验收 |

本轮授权为上传检查并停在正式提交前；Codex 未点击发布／立即投稿，也未通过“存草稿”验证平台草稿恢复。**目前不能宣称三平台都能完整自动发布一次。** 小红书和 B站已证明提交前主要页面路径可走通；百家号已通过用户截图补齐主要配置项，但缺少直接操作与提交后证据；WT Media 的资源获取、自动操作、人工恢复和结果回收仍需在实际适配中验收。

### 12.6 字段取舍与默认值的综合判断（产品建议，待新原型评审）

推荐采用“核心内容＋预填默认值＋按条件出现”的方式。全量复制平台表单会增加重复配置；只保留视频和文案又会遗漏 B站分区、标签、声明等必要值。**必须有值不等于必须手工填写；从基础界面去掉不等于向平台提交空值。** 系统应生成或继承确定的值，只有缺失、冲突或内容性质不明时才要求补充。

下表是产品侧建议；平台必填的证据仍以 §12.2 为准。小红书和百家号未做空值提交校验，不能把建议必填写成已确认的平台硬性规则。

| 平台、账号、视频 | 必须确定，可从入口继承 | 已选资源直接带入；不随机选账号、不猜测账号归属，最终预览显示真实账号和视频 |
| 小红书标题 | 产品侧必有值 | 用成片的业务标题或已准备的发布文案预填，按 20 上限适配；文件编号不能直接作为正式标题 |
| B站标题 | 平台明确必填 | 同上，按 80 上限适配；超限先改写／提示，不静默截断语义 |
| 百家号作品描述 | 产品侧必有值 | 预填简短、贴合视频的发布文案，按页面 50 计数提示适配；计数折算待核验。不额外要求用户填截图中未出现的独立标题 |
| 小红书正文、B站简介 | 建议可空，保留选填入口 | 有合适文案则带入，没有可留空；是否允许空值仍需平台校验，不使用文件名凑内容 |

| 平台内置 PK封面／AI 改标题或改封面／一键填写／付费推广入口 | 不复制为本系统基础发布步骤 | 不主动调用平台内部的辅助 AI 或产生付费操作；本系统自建的批量 AI 标题、封面短标题、话题、标签生成与封面模板合成是独立能力，见第 7 节 |

普通发布的最小配置可以收敛为：**账号／视频 → 发布文案 → 封面 → 必要的平台值与内容声明 → 最终预览**。B站补齐分区、标签和创作声明；小红书优先保留标题与封面、正文选填；百家号优先保留作品描述与横竖封面，挂载关闭、地点和活动不选、水印建议不添加，创作声明按真实内容确认。发布时间和可见范围显示默认摘要，有需要时展开修改。

默认值建议按“本条明确配置 → 已确认的素材信息／内容模板 → 已配置的账号默认值 → 系统推荐值”取值，且以具体字段的事实来源为准：内容声明来自内容事实，账号默认值不能覆盖它；平台不支持的字段不发送；历史页面残留值不作为默认来源。上述可选字段一旦被平台实时校验要求填写，应提示补充并修正字段规则，不能静默忽略。
