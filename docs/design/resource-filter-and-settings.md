# 运营资源与文件管理、个人信息、桌面设置与日志：评审稿

> 状态：个人信息、桌面设置及文件管理的已确认部分已实施并提交CHG106审核；其他筛选行为建议待review。2026-11-23。安装版验证范围以对应CHG evidence为准。

## 1. 结论与范围

本次分为两类：运营资源及文件管理按既定规范整改；个人信息与桌面环境功能重新设计。文件管理保留现有整体布局和功能，入口命名“新建文件 / 编辑”，复制链接由行操作移到文件名旁的复制图标。个人信息保留右上角头像菜单的独立入口，默认只读、按区编辑，不放进系统设置。桌面环境下建议保留名称“桌面设置”，页内为“下载与存储、本地日志”两个页签；下载页直接分组，日志页采用来源分组的文件列表与正文双栏，均无额外搜索；保留现有业务导航。所有页面延续当前颜色、字体、留白、公共组件和权限。

本稿依据当前 Cloud 共用 Vue 源码和现行规范做静态审查，未以本轮逐页 GUI 验收代替。页面功能实现以代码为事实；高低频条件的排序是本次运营体验建议，尚无线上使用频次数据。

规范入口：[AdminUI §2–3](../standards/frontend/AdminUI页面规范.md)、[视觉 §4.1.4、§4.4](../standards/frontend/前端架构与视觉规范.md)、[交互 §4、§9](../standards/frontend/前端交互规范.md)、[用户反馈](../standards/frontend/用户反馈规范.md)。权限基线：[用户与账号管理](../product/prd/详细文档/第三章_用户与账号管理.md)。

## 3. 筛选区统一方案

### 3.1 结构与行为

```text
页面标题                                      页面主操作
┌ 同一个列表管理面板 ────────────────────────────────┐
│ 综合搜索        高频条件       高频条件    查询 重置 │
│ [输入框]        [选择器]       [选择器]              │
│ 高级筛选 · 已生效 2 项  ⌄                           │
│ （展开后：低频条件，完整字段组自然换行）               │
├───────────────────────────────────────────────────┤
│ 有选中项才出现批量操作                              │
│ 表格                                               │
│ 分页                                               │
└───────────────────────────────────────────────────┘
```

示意表达区域关系；实际标签全部在控件上方。控件36px；标签13px/500，值与按钮14px/400；字段横向24px、换行20px、标签到控件8px；卡片内边距24px。高级入口独占基础条件下方一行，左对齐，展开内容距入口16px，无额外上分隔线。筛选、表格、分页共用外边界，不再嵌套白卡。

普通条件修改仅改输入草稿；查询/搜索框Enter提交全部条件并回第一页。重置恢复本页明确默认范围，不扩大角色授权。高级展开/收起只改可见性，未查询的草稿不算“已生效”；日期范围算一项，多选字段算一项。切页只用已应用条件，返回列表保留筛选与分页。团队变更时可清空已不合法的成员选项，但不把普通筛选误做权限开关。

窄屏整组换行，查询/重置保持相邻且顺序不变；不将标签和控件拆到两行不同列，不为维持单行缩小字号或横向撑出页面。基础条件数量按任务价值决定，不机械规定所有页面三项。

### 3.2 推荐条件分层

| 页面 | 基础区 | 高级区 |
|---|---|---|
| 浏览器窗口 | 综合搜索、窗口状态、本人Desktop运行状态 | 代理方式、启用状态；授权范围选择保留原角色可见性 |
| 代理管理 | 综合搜索、检测结果、到期状态 | 运营团队（有权限时）、资源启停、地区 |
| 社媒账号 | 综合搜索、平台、登录状态 | 使用人、运营团队、类目、启用状态、标签，按原角色显示 |
| 图片库 | 图片名称、内容类目、用途、使用状态 | 图片比例、来源 |
| 内容池 | 综合搜索、类目、处理状态；平台在确有多平台选择时保留 | 发布时间、来源方式、运营团队等条件 |
| 素材库 | 综合搜索、类目、我的使用、加入状态 | 发布时间、团队使用、运营团队；只有单一平台时不堆不可选择的条件 |
| 合成任务 | 综合搜索、状态、负责人（有权限时） | 团队、创建时间、合成策略、触发方式；原团队与负责人联动不变 |
| 成片管理 | 综合搜索、类目、视频状态、适用平台 | 负责人、运营团队、生成时间；保留从批次/素材进入的来源上下文 |
| 作品列表 | 沿用现有高频条件 | 保留类目、发布时间，并补计数/区域关联 |

高级运营查看成员、管理员团队范围属于有权限约束的上下文，具体放置以现有规则和可用空间为准；不能因折叠条件而恢复成本人以外的默认范围，也不能删除原有可用筛选能力。

## 4. 文件管理：规范整改与命名统一

用户已明确本页不作大面积设计调整。保留当前列表、筛选、列结构、短表单和新标签预览方式；仅调整指定命名与复制入口，撤回此前新增预览弹窗、调整列结构及突出复制链接等设计建议。

### 4.1 统一命名

| 位置 | 统一文案 |
|---|---|
| 页头“上传文件”按钮 | 新建文件 |
| 新建弹窗标题 | 新建文件 |
| 新建弹窗提交按钮 | 保存 |
| 行操作“改名” | 编辑 |
| 编辑弹窗标题 | 编辑文件 |
| 编辑弹窗提交按钮 | 保存 |

“编辑”仍只修改现有显示名称，不增加替换文件或其他编辑字段，原链接保持不变。文件选择区继续准确使用“选择文件”，传输中的“正在上传”等状态文案保留真实动作含义，不机械替换成“新建中”。保存成功统一为“文件已创建 / 文件已保存”。

复制入口移至文件名右侧，使用公共复制图标按钮，不再占用行操作中的“复制链接”文字按钮。按保留原能力、仅移动入口理解：点击复制文件链接；悬停提示与无障碍名称均为“复制文件链接”，成功Toast“文件链接已复制”。长文件名截断不能挤掉图标；图标保留公共可点击热区与键盘焦点。复制失败沿用现有手工复制链接弹窗。

本页已确认命名与复制入口已回写[交互规范](../standards/frontend/前端交互规范.md)及[素材生产 §5.10](../product/prd/详细文档/第五章_素材生产.md)，不将此次命名要求扩展成其他业务入口的全局替换。

### 4.2 保留的规范整改

- 筛选标签、控件、间距和按钮遵循公共规范；保留搜索及文件类型两项条件。
- 输入与已查询条件分开，翻页只使用已查询条件；默认10条，可选10/20/50。
- 区分暂无文件、筛选无结果和读取失败；新建空态入口同样使用“新建文件”。
- 文件名旁提供复制图标；行操作保留“预览 / 下载 / 编辑 / 删除”四项平铺，按钮层级与危险操作沿用规范。后台待删除项仍仅保留“重试删除”，不展示不可用的复制入口。
- 字段错误就近显示，一次性操作结果使用Toast；不新增常驻说明区或独立反馈样式。

## 5. 当前设计方向

以用户提供的四区参考图为本轮设计基础：个人信息保持右上角独立入口，桌面设置管理当前电脑的下载、存储和日志，工作环境承接检查与恢复。现有规范和公共组件继续生效，图中的示意状态、容量和控件不直接转成业务事实。原型外层以Cloud既有内容生产/发布管理统一工作台为基础，复用其OperationsNavigation、路由与演示身份，不重写侧栏、品牌区或顶栏。

已确认：个人信息不放进设置；资料默认只读，点击编辑才出现保存；左侧不需要搜索。已确认：侧栏左下固定“桌面设置”入口，不设“桌面环境”普通菜单分组；内部仅“下载与存储、本地日志”两个页签。下载页内容量小，直接连续分组，取消上一稿额外的页内定位栏；日志的左栏用于选择文件，不再叠一套分类导航。命名与具体分组仍为待review设计。

```text
右上角头像菜单 → 个人信息（我的账号）
                 ├ 账号资料：只读 / 原位编辑
                 └ 比特浏览器：账号提示 + 绑定信息 + 本机四项

侧栏左下常驻区 → 桌面设置
                 ├ 下载与存储
                 │ ├ 系统配置文件
                 │ ├ 下载目录
                 │ ├ 历史文件查找目录
                 │ ├ 整理已有文件
                 │ └ 存储与清理
                 └ 本地日志
                   ├ 左：按来源分组的日志文件
                   └ 右：文件信息、原文与诊断导出

既有工作环境   → 当前电脑检查结果与处理入口
```

只读展示与编辑、账号持久关系与本机检查、查找目录与下载目录分别表达。个人信息是用户级资料，桌面设置只作用于当前电脑，不暗示它会跨电脑同步。按既有权限，Web可查看个人信息和绑定；桌面设置及本机信息仅对本人Desktop普通/高级运营开放，管理员不因此获得本机能力。

## 6. 个人信息（我的账号）

### 6.1 账号资料

当前头像和昵称是主体；用户名、UID、角色、团队、类目范围使用公共只读字段。采用紧凑上下分区，不做两张等宽大卡。入口、页面标题、面包屑保持同名；当前沿用“个人信息”，“我的账号”说明功能定位，不在页面并列放两个名称。

| 状态 | 展示与操作 | 结果与恢复 |
|---|---|---|
| 默认 | 当前头像、昵称及只读资料，分区右侧“编辑” | 不展示输入框、全部头像、保存按钮 |
| 编辑 | 昵称输入、当前头像及“更换头像”；保存/取消同组 | 用户名、UID和授权资料只读；头像按需展开现有系统预设，无上传或裁剪扩展 |
| 未改动 | 保留编辑态 | 保存禁用，取消可用 |
| 保存中 | 当前表单Loading并防重复提交 | 提交期间保护当前输入与离开；不锁死无关只读信息 |
| 成功 | 退出编辑，展示服务端回读结果 | 同步右上角头像与昵称，Toast一次；未保存草稿不改变顶栏 |
| 失败/取消 | 失败保留输入，字段问题贴字段；取消恢复原值 | 有未保存修改时离开页面才确认，无修改直接离开 |

昵称长度及空值处理沿用现有资料接口规则，不在视觉稿新增一套校验。布局保持公共标签、字段组合和按钮规范，不因只有两个可编辑项就另开完整配置工作区。

### 6.2 比特浏览器绑定与本机检查

比特浏览器区域融合公共规范与用户现有卡片：与账号资料同级，统一使用ResourceSection详情标题，字号、字重、蓝色标记和标题间距完全同源，不单独定制大标题；绑定状态在标题右侧。本机子区使用ResourceSection表单分区标题，不增加同级蓝色标记。保留浅蓝账号提示块、绑定比特账号/绑定时间/最近验证逐行展示，底部“本机”保留设备ID、系统、Agent状态与版本。保留原顺序与信息量，不改成紧凑摘要或折叠详情。只统一字体、间距、分隔线、对齐与公共状态样式；“已绑定”标签禁止换行和收缩。绑定信息和本机信息均采用112px标签列、16px列间距，内容左对齐；不使用整行两端贴边对齐拉大阅读距离。完整比特主账号ID不外露，不让用户手工输入主账号ID。

绑定状态回答“这个系统账号关联谁”；最近验证回答“上次何时核对”；当前电脑状态回答“此刻能否执行”。不能以已绑定或历史已验证推断当前环境正常，不使用一个新的“已验证”状态覆盖三种含义。

| 场景 | 主要信息 | 用户下一步 |
|---|---|---|
| 未绑定，Desktop已读到账号 | 脱敏当前比特账号、未绑定 | 绑定账号，确认实际读到的对象后执行 |
| 未绑定，当前账号未读到 | 未绑定；本机检查的真实原因 | 先检查工作环境，不展示可用的绑定动作 |
| 已绑定，尚未检查本机 | 已绑定账号；本机未检查/未读取 | 去工作环境检查，不能误报账号冲突 |
| 已绑定且账号一致 | 已绑定账号、本机检查结果与时间 | 沿用账号提示块与绑定信息，不叠加成功Alert或Toast |
| 已绑定但当前账号不一致 | 就近持续阻断，原绑定与当前账号分别脱敏展示 | 切回原比特账号后重查，或明确确认“换绑为当前账号” |
| Cloud Web | 云端保存的绑定与验证事实 | 一行说明绑定/换绑在桌面端操作，不读取本机或显示本机错误 |

换绑沿用PRD：不删除、迁移或失效旧主账号的窗口记录，切回原账号可恢复；不新增个人解绑入口。读取状态不改变绑定关系，换电脑登录也不改绑定关系。

本机保留原有设备ID、系统、Agent状态与版本四项，不再以新增检查摘要替代。设备ID仅在本机区域展示，运行Token不展示；完整排障仍进入既有工作环境。账号提示依据实际读取结果，不能以历史已验证推断当前已登录。分区读取失败不影响资料查看与编辑。

### 6.3 全部原型与评审入口

### 7.1 下载与存储

标题下仅两个页签，正文紧凑连续分组。分组不为了凑数量分别包大卡；动作跟随对象，技术路径不抢主体空间。没有跨分区全局保存。

| 分区 | 内容与动作 | 必须说明的边界 |
|---|---|---|
| 系统配置文件 | 放在下载与存储首项，仅展示当前完整路径 | 不支持修改或切换配置文件，不提供文件选择入口 |
| 下载目录 | 当前完整路径；未配置时“设置目录”，已配置时“更改目录”；打开目录 | 新下载写入此处；更改不自动搬运已有文件。路径只展示一次，长路径可读完整值 |
| 历史文件查找目录 | 实际已登记目录列表，添加、打开、移除 | 用于识别旧文件；不改变下载位置。当前下载目录不重复列为可移除历史项 |
| 整理已有文件 | 一行摘要和“整理文件”入口 | 先看待处理文件，再选择搬运/保留/删除，不以“开始迁移”直接执行未核对的文件操作 |
| 存储与清理 | 下载磁盘可用空间；缓存、控制台日志、执行服务日志实际占用 | 对象逐项清理；两类日志分别说明，不能把总占用误当可释放量 |

**配置文件：** 按用户最新决定，仅查看当前本机配置文件位置；不提供修改、路径输入、文件选择、引用切换或安装时自定义位置。本轮不实施这些能力，也不列为待补齐项。

**目录选择：** 推荐“更改目录 → 系统目录选择器 → 确认选择后保存并应用”，取消选择不变更。不再套一个内容相同的保存表单。现有选择器确认后即保存，不能将它当作“只选择、稍后另存”的纯选择器。现有保存校验检查绝对路径与目录存在性，不隐式新建目录；执行服务另行返回可写事实，不能将保存成功等同于已经验证可写。

保存设置与执行服务应用分别反馈：应用成功才表达新位置可用；配置保存但执行服务未收到时，保留已保存路径并就近说明“已保存，待执行服务应用”，提供现有重试/工作环境入口，不能误报全部成功或全部失败。对正在执行任务的路径使用遵循既有执行规则，不承诺变更会重定向其已开始的文件操作。

**历史目录：** 列表只展示真实登记数据，按稳定顺序展示；重复添加不增加第二行。无法访问的目录保留记录并说明，不能当作空目录或自动删除。移除需说明“不再查找此处，旧文件可能显示未找到；实际文件不删除，重新添加可恢复”，不使用“删除目录”文案。没有对应能力时不能用空列表冒充已接通。零目录只显示一处空态和添加入口。

**整理文件：** 使用现有逐文件处理能力。对话框显示文件名、原位置、大小、实际状态与处理选择，默认保留。搬运到当前下载目录；删除必须单独明确确认。冲突或不存在的文件显示具体原因，不暗中覆盖或重命名。空间不足、不支持操作的文件不得显示为可执行。结果区分完成、跳过、失败，显示实际成功数量与失败项；重试只针对可重试的未完成项，关闭不宣称整个任务成功。

更改目录后不自动弹出迁移窗口；把“整理已有文件”作为用户主动进入的下一步，避免一次设置演变成连续弹窗。

**存储清理：** 只清可再生缓存及已轮转日志，保留素材、成片和正在写入的日志。清理日志执行前说明会失去对应排障历史；需要删除确认时遵循公共风险确认。清理结果展示实际释放量，部分失败保留失败对象与重试，重新读取占用，不把“占用量”写成“预计全部释放”。未知不填0；无可清理内容明确反馈，重复点击不并发执行同一清理。

磁盘只有获得可靠总量时才画占用条，现有可用空间可直接展示。缓存和日志没有配额分母时用真实大小，不绘制任意比例条。系统配置文件作为上方首项设置展示，不再在清理区底部放“打开设置文件夹”入口。

### 7.2 本地日志

采用参考图的文件列表与原文双栏。左侧按本机控制台、本机执行服务分组；正在写入和轮转文件放在各自来源下，名称、类型及必要修改时间紧凑展示。不在文件树外再叠来源导航或文件选择器。

右侧以原文阅读为主，保留文件名、一次路径查看入口和必要文件事实；不把完整路径重复放在多处。长文件名不挤掉日志正文，容器内部滚动，长行按可读规则换行或横向查看，不能逐字拆碎。

- 工具栏：最低级别、读取尾部行数、刷新、打开当前来源日志文件夹；“导出诊断包”作为明确输出动作。当前文件及筛选在操作后保留。
- 行数：默认500，建议提供500/1000/5000固定选项。现有读取命令最多5000行，500是默认值而非上限，仍受底层字节截取限制；展示真实读取、显示及截断事实，不保证一定读满指定行数。
- 筛选：沿用现有最低级别语义，保留未分级行和续行；不将正文重新解析成臆造的时间/模块字段。无匹配提供重置级别，不能写成文件为空。
- 刷新：默认手动；保留当前文件和过滤条件，避免频繁跳到其他文件或强制打断正在阅读的位置。文件已轮转或消失时刷新列表并说明，不能把另一个文件悄悄放在旧标题下。
- 切换：选文件后读取对应正文，失败与重试留在阅读区；旧响应不得覆盖新文件。列表失败、目录无文件、文件读取失败、筛选无匹配分别表达，不堆重复Alert。
- 导出：归档包含版本、组件状态、脱敏日志及失败任务摘要，适合提交排障。取消不是失败；成功显示真实输出位置，部分内容未能收集时说明缺失项，不能把“不完整诊断包”写成全部成功。普通导出不重新执行任务。
