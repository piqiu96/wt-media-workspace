# 服务部署说明书

一本写给所有人的结论手册:本地怎么起、线上是什么样、新版本怎么发、出问题看哪里。
数值规则以配置文件为唯一权威落点,本文只告诉你「用哪个、去哪改」。

## 1. 本地开发:一条命令

```bash
bin/control.sh all      # 起全套:数据库迁移 → Cloud → Worker → Agent 替身 → 两个 dev server → 打 DMG 并自动打开
bin/control.sh stop     # 全部停止
bin/control.sh status   # 查看各服务状态
```

起好后只需要记三个地址:

| 地址 | 是什么 |
| --- | --- |
| http://localhost:5173/home | 官网(无需登录) |
| http://localhost:5173/ | Cloud 业务端(要登录) |
| http://localhost:5174/ | 桌面端页面(要登录;打包 DMG 由 Rust 接管,不走这个) |

## 2. 端口表

| 端口 | 谁在用 | 值改在哪里 |
| --- | --- | --- |
| 8188 | Cloud API + 网页(本地与线上同值) | `wt-media-cloud/config/app.toml`(本地)/ `config_online/app.toml`(线上) |
| 5173 | Cloud 网页 dev server | `wt-media-cloud/web/vite.config.js` |
| 5174 | 桌面端页面 dev server | `wt-media-cloud/web/vite.config.desktop.js` |
| 8765 | Local Agent(用户电脑本机 API) | Desktop 启动时注入,不用手改 |
| 54345 | BitBrowser(本机浏览器程序) | `wt-media-agent/config/agent.toml` |
| 3306 | MySQL | `wt-media-cloud/config/database/primary.toml` |
| 443 | 线上 HTTPS 入口 | 宝塔站点配置 |

## 3. 线上架构

- 宝塔托管三个进程:**Server、Worker、Scheduler**,程序目录 `/home/www/wt-media-cloud/current`。
- Cloud 单进程监听 `127.0.0.1:8188`,**同时**提供 API 和网页;nginx 只做 HTTPS 转发,域名 `https://wt.longyanyue.cn`。
- 桌面安装包和 Agent 包**出厂就写死了** Cloud 地址(`https://wt.longyanyue.cn`),部署后改配置无效,换地址必须重新打 Tag 发版。

## 4. 发布新版本(五步)

详细命令见 `wt-media-cloud/deploy/DEPLOYMENT.md`,这里只给顺序:

1. **发版**:Workspace 提交 Manifest 后 `uv run scripts/release/submit_tag.py vX.Y.Z --push --verify`,CI 自动构建并公开发布正式 Release。
2. **下载包**:从 CI run 的 artifact 下载 `wt-media-cloud_<tag>_linux-amd64.tar.gz`,宝塔上传到 `/home/www/wt-media-cloud/output/` 并解压。
3. **预检**:包内 `./bin/wtmctl` 依次跑 `artifact verify`、`doctor`、`deploy plan`(都带 `--profile /home/www/wt-media-cloud/output/online-deploy.toml`)。
4. **切换**:宝塔**先停** Server/Worker/Scheduler → `sudo ./bin/wtmctl deploy apply --profile ...` → 宝塔**再启动**三个进程。
5. **验收**:浏览器打开 `https://wt.longyanyue.cn/home`;`curl -s https://wt.longyanyue.cn/desktop-downloads.json` 的 `version` 应等于新 Tag;登录一个真实账号。

## 5. 出问题先看哪里

| 症状 | 看哪里 |
| --- | --- |
| 本地起不来 | `bin/control.sh status`;探针 `curl http://127.0.0.1:8188/healthz` |
| 线上打不开 | 宝塔三个进程是否在运行;`curl -i https://wt.longyanyue.cn/api/v1/health` |
| 线上登录 401 | 宝塔项目日志搜 `module=auth result=denied`,其 `reason=` 字段直接给出原因(缺凭证/凭证失效/无权限) |
| 官网下载 404 | GitHub Release 是否已公开(草稿状态资产不可下载) |
| 桌面端连不上 Cloud | 桌面包里的地址是出厂写死的,先确认线上 Cloud 本身健康,再重装对应版本的桌面包 |

## 6. 改端口要一起动的地方

把 8188 改成别的值时,逐项过一遍(漏一项就会出现「探针说健康、实际没起」这类错位):

- [ ] `wt-media-cloud/config/app.toml:8`、`config_online/app.toml:8`(权威落点)
- [ ] `wt-media-cloud/web/` 三份 `vite.config*.js` 的代理 target
- [ ] `wt-media-cloud/scripts/local-env.sh`、`scripts/verify-health.sh`、`scripts/dev/build-release-linux.sh`
- [ ] `wt-media-desktop/src-tauri/resources/desktop.production.toml`(`base_url`、`csp_connect_src`)
- [ ] `wt-media-desktop/src-tauri/src/bootstrap.rs`(CSP 形状断言)、`src/config.rs`(`.replace()` 测试锚)
- [ ] `wt-media-agent/config/agent.toml`、`config_online/agent.toml`、`runtime/constants.py`
- [ ] `wt-media-workspace/scripts/m2b_local_acceptance.py`、`scripts/verify_m3_acceptance.py`、`config/release-matrix.yaml`、`skills/common/environment-bring-up/SKILL.md`、`tests/test_release_stage_config.py`
- [ ] `bin/control.sh restart` 后 `status` 确认新端口 `health=ok`

**不用动**:`releases/manifests/*.yaml` 的 `cloud_origin`(只写公开域名,不含端口)。
