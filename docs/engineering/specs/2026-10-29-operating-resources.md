# 运营资源：Cloud 事实与本机执行

本规格描述社媒账号、浏览器窗口、代理在 CHG099 收口后的稳定边界。业务字段与接口以 [契约映射](../../contracts/contract-map.md) 指向的 Cloud 提供方 OpenAPI 与业务 Schema 为准；取舍见 [ADR-0027](../../decisions/0027-operating-resource-data-and-local-execution.md)。本文件不记录实施进度。

## 数据归属

- Cloud 保存社媒账号、窗口、代理、正式绑定、当前同步快照和必要的当前代理操作回执。Agent SQLite 不保存这些业务事实。
- `bit_` 字段是比特最近一次观测；`platform_` 字段是平台账号事实；`last_check_` 字段是代理最近检测事实。运营备注、业务启停及窗口与代理的正式关系由 Cloud 管理。
- `browser_profiles.proxy_id` 是正式托管关系；`reserved_proxy_id` 是进行中的目标额度预留。列表展示正式关系和比特实际代理时应分别标注，不能由地址相同推断认证一致。
- 代理列表不返回认证字段；只有有权限的详情和待执行操作返回所需连接信息。认证比较在本机完成，Cloud 只接收一致、不一致或不可核实的结论。
- 启停统一 `enabled`；窗口缺失使用 `local_state`；代理可用性由启停、到期、最近检测和额度分别判断，不合成一个模糊状态。

窗口页面按事实来源分开展示状态：窗口存在性为“比特中可见 / 最近同步未找到”，放在列表“窗口状态”列、窗口详情、同步结果与缺失清理流程；运行状态为“已打开 / 已关闭 / 未知”，只代表本机读取结果；业务启停为“启用 / 停用”，是 Cloud 配置。代理信息列只展示连接方式、代理地址及代理自身的问题，例如配置不一致、代理已到期、检测异常、资源不可用或操作结果待核实。“直连”是连接方式，不是异常。“最近同步未找到”不能直接推断窗口已在比特永久删除，清理前仍须人工核实账号与权限。缺失期间不显示伪装成已核实的代理配置结果。代理信息中的资源名称或地址可打开只读详情：系统托管用侧栏展示资源字段与当前窗口关系；比特自管且有地址时用居中弹窗展示上次同步字段；直连无详情入口。详情不触发检测或写入，不展示认证密码。

## 角色与执行位置

普通运营在本人 Desktop 操作本人窗口，高级运营查看成员窗口时只读，管理员跨团队查看窗口但不代执行本机操作。代理按团队共享：普通运营可查看、录入、检测并使用本团队代理；高级运营维护本团队代理公共设置，管理员维护全局资源。Cloud 在接口层再次校验身份、团队、目标归属和额度，页面控件不是权限边界。

Cloud 创建代理操作意图并结算结果，不访问运营电脑的本机 Agent 地址。Desktop 经 Tauri 调用 Agent，Agent 与比特通信。Cloud 检测代理连接。动态地址由本人 Desktop 调 Agent 从运营本机网络提取，Cloud 接收、保存并检测提取结果；网页端和查看他人资源的视图不提供本机提取动作。

## 窗口同步

每个用户只有一个当前同步快照。本人 Desktop 读取比特窗口后提交快照；Cloud 比对新增、字段变化、首次缺失和归属冲突。新增窗口默认不认领，用户勾选后才建立 Cloud 关联；已有窗口变化在确认时保存，预览须展示每个变更字段的原值和新值；归属冲突不能自动转移。首次确认缺失只标记 `local_missing`，暂保留窗口、账号关联和历史。日常列表默认展示已找到与未找到的窗口，增加独立“窗口状态”列和可清空筛选，选项仅“已找到 / 未找到”，不选择表示全部；独立“清理已删除窗口”入口列出缺失记录供批量处理，缺失行可单项删除。运营确认窗口确已在比特删除后，单项或批量清理；每条独立事务锁行复核 `local_missing` 和代理预留，解除账号关联并重置登录/检查结论，物理删除窗口记录释放代理名额，同时写入无凭据审计。普通窗口无删除入口，账号及历史保留；未清理的缺失窗口再次出现时恢复正常展示，已清理的窗口再次出现时作为新窗口待认领。已确认的缺失下一次扫描不重复要求确认。同步结果将“本次待处理”和“历史待处理”分开计数与标识；历史缺失仍可核实或删除，不算作本次新增异常；没有新变化时显示“窗口信息已是最新”并保留历史待处理入口。当前比特本机接口的主账号 ID 来自窗口记录，零窗口时无法核实身份，须拒绝整批缺失标记并提示人工核实；读取失败或身份不符也不把已有窗口标成缺失。

新版确认携带 `sync_id`。Cloud 在事务中校验快照编号和状态，并防止同步覆盖有代理预留的窗口；同编号重复确认返回已保存回执，不重复写入镜像。确认后的当前记录保留最近回执供响应丢失时核实；下一次扫描覆盖。确认结果未知时先读取同一快照：已确认则展示结果，仍待确认才允许继续确认，已替换或过期则重新扫描。

进入本人 Desktop 窗口页面或刷新页面，读取一次运行状态。唯一手动入口是页面右上角“刷新运行状态”；列表表头与逐行不放刷新入口，不轮询、不自动重试。自动读取成功静默，手动成功显示实际读取数量；失败仅 Toast 提示具体原因。资料刷新、筛选、翻页、查看详情不触发扫描；同步过程复用进行中的读取。状态未知时禁止打开或关闭，后续由用户手动刷新。离开本人视图后丢弃迟到的本机结果。

编辑既有未分组窗口时允许保持未分组；Desktop 不用空分组覆盖既有值，仅提交该编辑表单管理的比特字段。Agent 向比特写入名称、备注等元数据前，先从本机读取并保留现有指纹、代理方式、代理类型、地址和认证信息；缺少必要字段则拒绝写入，避免编辑备注时重置代理。

## 代理应用与异常恢复

代理写入分为开始、执行、结算三个阶段。开始时 Cloud 校验本人窗口、团队、代理启停/到期/检测和可用额度，生成操作编号并占用目标额度。相同窗口的第二次操作不得越过未结算的预留；多个窗口争抢最后名额时只能有一个成功。

正常写入以比特接口的明确成功响应为依据，不额外读回；Cloud 在成功结算事务中同步正式代理关系与窗口最近确认的代理连接字段，让列表和后续同步以本次写入为基准。开始操作时在当前回执保存非秘密的目标连接快照，结算不得读取可能已经变更的代理资源来推算当时写入内容。明确拒绝结算失败并释放预留。请求可能已送达而结果未知、结算响应丢失或旧 Agent 缺少能力时，保留预留与操作编号，不能直接重试写入。本机读取比特实际配置并比较协议、地址、端口和认证：一致结算成功，不一致结算失败，不完整或掩码认证保持待核实。Agent 不把密码比较值传回 Cloud。

结算必须携带当前操作编号、动作与目标；重复提交相同结果返回既有回执，旧编号或不同结果不能覆盖新的预留。待核实事实不会按时间自动释放。关闭并重进本人窗口页面时可读取当前操作恢复；没有拿到开始编号时，旧的终态回执不能证明本次请求已执行。Cloud-only 的“改为比特自管”释放正式关系后也保存终态回执，便于核实响应丢失。

## 页面与批量处理

窗口和代理页面沿用 Workspace [前端规范](../../standards/frontend/前端架构与视觉规范.md) 和 [交互参考](../../../example/proto/browser-proxy/index.html)。原型是交互与状态参考，不作为运行时数据或样式来源。ID 独立列，代理 ID 是自增整数主键及接口整数值（ADR-0029），操作按公共规范呈现；少字段使用居中弹窗，复杂详情或长表单使用合适宽度的侧栏。跨团队查询仅管理员显示团队名称或 ID 输入筛选，运营和高级运营固定在授权范围内，不显示团队筛选。

批量操作逐项给出真实结果和原因。明确失败项可重试；待确认项先核实。处理时保持现场进度，结束后可查看结果；不得把成功、失败和待核实混成一个固定成功提示。批量运行中阻止站内切页，并在浏览器允许时提示刷新离开；非正常卸载后不继续发出尚未开始的逐项请求。只可选择当前页中本人可操作、状态已知的窗口与当前页中有连接地址的代理。

代理导入支持 TXT、CSV、XLSX 和粘贴输入，每次最多 1000 行，文件最多 5 MB；文件表格须采用公开模板。先预览无效与重复行并保留原文件行号，仅提交勾选行。导入响应缺失的行保持待核实，核实重复时仍不能假定它是本次导入产生的记录；页面保留本次会话的结果入口，不建立持久批量任务中心。

## 验证边界

自动化与隔离 MySQL 可证明迁移、权限/配额并发、回执幂等、前端状态转移和构建。真实比特开关、字段写入、代理应用及目标网络效果必须使用获授权的安全测试窗口和可达代理现场读回；测试桩、HTTP 200 或静态原型不能代替这些验收。
